# FORTH/Σ移植の決定事項と保留事項

資料に明記された仕様、Zig移植で選んだ動作、資料だけでは決められない点を分けて記録します。ソースページの対応は[FORTH/Σ仕様書](SPEC.md)、実装上の値と未実装機能は[実装ノート](IMPLEMENTATION.md)を参照してください。

## 資料から採用した動作

| 項目 | 採用内容 | 根拠 |
| --- | --- | --- |
| 数値幅 | 16ビット、2の補数。比較とMIN/MAXは符号付き。 | SPEC §3.1、PDF pp. 17, 22, 24–25, 29 |
| 真偽値 | 偽は0、真は1。 | SPEC §3.4、PDF p. 30 |
| 初期基数 | 10進。誌面で示す切替は8進・10進・16進。 | SPEC §3.5、PDF pp. 11, 22, 31 |
| 名前の識別 | 名前の長さと先頭5文字で照合。 | SPEC §3.3、PDF pp. 15, 28, 30 |
| トークン区切り | 空白とキャリッジリターン。タブは資料上の区切りではない。 | SPEC §3.2、PDF p. 16 |

## 移植版で選んだ動作

| 項目 | 現在の決定 | 理由・影響 |
| --- | --- | --- |
| 名前の大小文字 | ASCII英字は大小を区別しない。 | 資料で確定しないため、一般的なForth処理系との比較を参考にした移植判断。 |
| 数値入力の大文字小文字 | 16進数のa〜fも受け付ける。 | 入力の便宜を優先。原版のNTEST動作を示す根拠にはしない。 |
| 基数 | 2〜16を受け付ける。 | 原資料の8/10/16に加え、ポータブル版の拡張として他の基数を許す。 |
| セル演算 | 加算・減算・乗算は16ビットで折り返す。 | 固定幅セルをホスト環境に依存させない。 |
| 除算ゼロ | 診断を出し、/は7FFFH、MODは0、/MODは余り0・商7FFFHを返す。 | 例外でホスト処理系を停止させない実装判断。原版互換の主張ではない。 |
| ループ脱出 | LEAVEで現在のループを脱出待ちにし、LOOP/+LOOPで終了する。 | 資料の説明を保ちながら、ループ枠は利用者のリターンスタックと分離する。 |
| +LOOP境界 | 符号付き増分の方向に終値を横切ったら終了する。 | Z80リストの比較部分を確定できないため選んだ移植規則。 |
| ?DO, J, K | ?DOは同値範囲を飛ばす。J/Kは外側ループ添字を返す。 | 便利な追加機能。原版の必須ワードとは扱わない。 |
| 実行トークン | ホスト側の辞書インデックスを使う。 | Z80機械語アドレスを持ち込まずEXECUTEを提供するため。 |
| 入力行・容量 | 入力4096バイト、名前255バイト、スタック1024セル、辞書1024語、コード8192操作。 | ポータブル版の現行上限。歴史的機種の容量を再現する値ではない。 |
| 論理メモリ | 64 KiB、データ領域は4000Hから開始。 | 実装上の配置。PC-8001やCP/Mのメモリマップとは別。 |

## 上限・境界・エラー復帰

- データ領域は4000HからFFFFH未満までを割り当て可能とします。終端ポインタFFFFHを超えるALLOT、変数、配列、文字列、カンマ、Cカンマは失敗し、データ領域ポインタを進めません。FFFFHは終端を表すために予約します。
- 16ビットセルの読書きは、アドレスFFFFHの次バイトを0000Hとして扱います。セルアドレスは16ビットで折り返します。配列アクセスは要素数を検査せず、計算した16ビットアドレスを使います。
- データスタックとリターンスタックは各1024セル、辞書は1024語、コンパイル済み操作列は8192操作、制御構造のネストは128段までです。端末入力行は4096バイト、ワード名は255バイトまでです。
- スタックのアンダーフロー／オーバーフロー、領域超過、辞書／コード超過はエラーです。制御ネスト超過はNESTING ERRORとして報告します。エラー報告時にデータ・リターン・ループ・制御スタックを初期化します。
- コンパイル中のエラーは、作成中のワード、追加コード、当該定義中に確保したデータ領域を巻き戻します。既に完了した定義は残します。トップレベルのALLOT失敗では、割り当て位置は失敗前の値を保ちます。
- FORGETは指定語以後の辞書語をすべて削除し、削除対象内の最初のコンパイル済み定義までコード位置を戻します。データ位置も指定語の割り当て前へ戻し、その後の定義で領域を再利用します。

## 資料だけでは確定できない点

| 項目 | 現状 | 次に判断する条件 |
| --- | --- | --- |
| NORの論理定義 | 解説文とZ80リスト／マニュアルの記述が一致しない。現行版はNOT(a OR b)を実装。 | 誌面画像の再確認、または対象とする版の特定。 |
| 1-の原版での位置付け | サンプルにはあるが、語一覧での扱いが一貫しない。現行版には実装済み。 | 機種版ごとの完全な語一覧を特定。 |
| 負の+LOOP | 終値との比較規則を判読できない。現行版は符号付き方向判定を採用。 | 対象版のソースとCPU条件分岐を再読解。 |
| NTESTの小文字16進 | Z80リストから確定できない。現行版は小文字a〜fを許す。 | 数値変換ルーチンの対象版と文字コードを確定。 |
| 大文字小文字の名前照合 | 原資料の共通規則として確定できない。現行版は大小同一視。 | 版固有の辞書検索コードまたはユーザーズマニュアルの明確な記述。 |
| 版間の共通範囲 | SORD M200、CP/M、PC-8001の差を全ワードについて整理できていない。 | 対象とする原版を明示し、各版の資料を分離して照合。 |

保留事項は推測で確定しません。実装の現行動作は選択済みであっても、資料から確認できた原版仕様とは区別して扱います。
