# FORTH/Σ移植の決定事項と保留事項

資料に明記された仕様、Zig移植で選んだ動作、資料だけでは決められない点を分けて記録します。ソースページの対応は[FORTH/Σ仕様書](SPEC.md)、実装上の値と未実装機能は[実装ノート](IMPLEMENTATION.md)を参照してください。

## 方針の変更（2026-10-28）

利用者の指示により、Gforthの挙動に近づけ、教材ForthBasicMasterのサンプルが動くことを目標にしました。作業は6段階に分け、段階1（コアの変更）、段階2（浮動小数点）、段階3（文字列・数値書式）を実装済みです。意味が衝突する部分はGforthに合わせ、衝突しないFORTH/Σ固有のワードは残しています。GforthはGPLv3のため、挙動だけを参照し、コードは移植していません。

| 段階 | 内容 | 状態 |
| --- | --- | --- |
| 1 | 64ビットセル、1 MiBメモリ、真=-1、床関数除算、全文字の名前照合、TYPE ( addr u )、基本標準ワード | 実装済み |
| 2 | 浮動小数点スタックとF系ワード（教材Level 17の範囲） | 実装済み |
| 3 | 文字列・数値書式（S"、<# #>、倍長整数など） | 実装済み |
| 4 | ローカル変数 | 実装済み |
| 5 | 例外・ファイル・動的メモリ（Level 14の `$!` などの動的文字列を含む） | 5a（THROWと主なファイル語）、5b（ALLOCATEと動的文字列）、CATCHを実装済み |
| 6 | 語彙・条件付きコンパイル | 実装済み |

| 項目 | 現在の決定 | 理由・影響 |
| --- | --- | --- |
| 名前の大小文字 | ASCII英字は大小を区別しない。 | Gforthと同じ。資料では確定しない。 |
| 数値入力 | 基数2〜36、小文字も受け付ける。`$` `#` `&` `%` 接頭辞と `'c'` を認識する。 | Gforthの数値認識に合わせた。 |
| 浮動小数点リテラル | 基数が10のときだけ、`e`/`E` を含むトークンを浮動小数点数とする。 | Gforthの `rec-float`。 |
| 倍長整数リテラル | 数字の間のどこかに `.` を含む整数は倍長整数（128ビット）。`1.5` は15、`12345.123` は12345123。`DPL` は未実装。 | Gforthの `s>unumber?`（`kernel/int.fs`）。 |
| 倍長整数の格納順 | スタックでは上位セルが上。`2!` は上位セルを低いアドレスに格納する。 | Forth 2012。教材Level 18の `BIGNUM 2!` の例と一致する。 |
| 数値書式の保持領域 | `<#` `<<#` の保持領域は1000H〜1FFFH（下向きに伸びる）。`<<#` の入れ子は16段まで。あふれ・対応しない `#>>` は `PICTURED NUMERIC OUTPUT ERROR !`。 | Gforthの `holdptr`/`holdend`（`kernel/nio.fs`）。領域の位置と大きさはポータブル版の判断。 |
| PAD | 2000Hからの4096バイト。 | Gforthは84バイト以上を保証。位置と大きさはポータブル版の判断。 |
| 実行時のS" | 解釈中の `S"` `S\"` は3000Hからの256バイト×4個のバッファを順に使う。定義内ではデータ領域にコンパイルする。最大255バイト。 | 同時に4個まで有効。FORTH/Σの `"` と `."` は127バイトのまま。 |
| エスケープ文字列 | `S\"` `.\"` は `\a \b \e \f \l \m \n \q \r \t \v \z \" \\ \xHH` を解釈する。`\n` はLF。 | Gforthの `S\"`。 |

| 浮動小数点の表示 | `F.` は有効15桁・指数なし・末尾空白。`F.S` は深さの後に上の9個を、それぞれ `14 0 17 F.RDP` と同じ形（`3.0000000000E0`）で表示する。`.S` も上の9個だけを表示する。どちらも2進数の値から正確に丸める（`0.5e FTAN F.` は `0.54630248984379`）。桁位置は `log10` の見積もりを切り捨ての計算で確かめてから決める（10の累乗に近い値で1桁失わないため）。無限大・NaNは `infinity` `-infinity` `NaN`。 | Gforthの `f.`、`f.s`、`engine/support.c` の `represent`。教材の出力例とは一部異なる。 |
| 浮動小数点のゼロ除算 | IEEE 754に従い無限大またはNaN。エラーにしない。 | Gforthの `f/` はCの除算 `r3 = r1/r2` をそのまま使う（`prim`）。浮動小数点例外を有効にした環境のGforthの挙動は未確認。 |
| F>S | 0方向へ切り捨て。NaNは0、範囲外は最小値・最大値。 | 範囲外の扱いはポータブル版の判断。 |
| セル演算 | 加算・減算・乗算は64ビットで折り返す。最小値÷-1は最小値、余り0。 | ホスト環境に依存させない。 |
| SWAB | セル全体の8バイトを反転する。 | 16ビット時代の意味を64ビットへ広げた移植判断。資料に根拠はない。 |
| C. | 下位8ビットを符号なしで表示し、末尾に空白。 | ゼロ埋めなしの方針に合わせた。 |
| ループ枠 | ループ枠は利用者のリターンスタックと分離する。 | `I` と `R@` は別の値になる。 |
| +LOOP境界 | 符号付き増分の方向に終値を横切ったら終了する。 | Z80リストの比較部分を確定できないため選んだ移植規則。 |
| ?DO, J, K | ?DOは同値範囲を飛ばす。J/Kは外側ループ添字を返す。 | 便利な追加機能。 |
| <BUILDS/DOES>, CREATE | <BUILDSとCREATEは入力ストリームから作成語名を読み、DOES>から定義末尾までの操作列を作成語に結び付ける。 | 誌面の2ARRAY例を踏まえて、Z80コードではなく操作列で実装。 |
| 定義用語の辞書位置 | 作成した語は、その時点のデータ領域位置を保持する。FORGETは後続の作成語も削除し、データ領域を回収する。 | 既存の辞書とデータ領域管理に合わせた移植動作。 |

| 辞書イメージ | 形式を `SIGIMG14` に変更。`SIGIMG13` 以前（16ビット版の `SIGIMG01` を含む）は読み込めない。 | `SIGIMG02` はセル幅・メモリ量・操作列の形式の変更、`SIGIMG03` はグループA、`SIGIMG04` は段階5aで組み込み語が増え、利用者定義語の番号がずれるため。`SIGIMG05` は段階5bの組み込み語と2 MiBのメモリ、`SIGIMG06` は語にローカル変数の領域の大きさを持たせたため、`SIGIMG07` は `CATCH`、`SIGIMG08` は #153 の語と入力バッファ、`SIGIMG09` は #154 の語と語ごとの定義位置、`SIGIMG10` は語彙と語ごとの所属語彙、`SIGIMG11` は `F.RDP` 系、`SIGIMG12` は定義語・`;`・`PI` を組み込み語にしたため、`SIGIMG13` は `'` `>BODY`、`SIGIMG14` は `LITERAL` `FLITERAL` を組み込み語にしたため。 |
| ヒープ | `ALLOCATE` の領域は100000H〜1DFFFFH（896 KiB）。ブロックごとに大きさと使用中フラグの2セルを前に置き、先頭から順に空きを探す（first fit）。管理情報は論理メモリ内にあるため、`SAVESYS` の実行ファイルや完全な復元ではヒープの内容と割り当て状態がそのまま残る。`LOAD` による追加読み込みではヒープを引き継がないため、読み込んだ変数がヒープを指していても無効になる。 | データ領域の上限を変えずにヒープを持つため、論理メモリを2 MiBに広げた。 |
| ALLOCATE / FREE / RESIZE | 失敗時のiorはメモリ不足が-524（ENOMEM）、確保していないアドレスが-534（EINVAL）。`FREE` と `RESIZE` は0を受け付ける（`0 n RESIZE` は確保）。`RESIZE` に失敗したときは元のアドレスを返し、内容は変えない。 | Gforthで `-1 allocate` が `-524` を返すことを確認した。無効なアドレスはGforthでは未定義のため、ポータブル版の判断。 |
| 動的文字列の形式 | 文字列変数は0か、ヒープ上のバッファのアドレスを持つ。バッファは長さ1セルの後に文字が続く。`$@` は空の変数で `0 0` を返す。伸ばした部分は0で埋める。 | Gforthの `$@` `$!` `$!len`（`kernel/stringk.fs`）と同じ形式。教材の `hab` の例もこの形式で動く。 |
| 自分自身を元にした操作 | `$+!` `$INS` `$OVER` で元の文字列が同じ文字列の中にあるときは、先に別の領域へ写してから操作する。`$!` は新しいバッファに写してから古いバッファを解放する。 | 伸ばすとバッファが移動するため。Gforthでは保証されない操作を安全側にした。 |
| $DEL | 削除する数を残りの文字数までに制限する。 | Gforthは削除数が残りより多いと、残すべき文字まで切り詰める（`s" abcdef" s $! s 4 5 $del` で `a`）。不具合と判断し、`abcd` になるようにした。 |
| $OVER, $INS | `$OVER` は末尾より後ろの位置なら、間を空白で埋めて伸ばす。`$INS` は末尾より後ろの位置なら末尾に追加する。 | Gforthの `$over`、`$ins`（`safe/string`）と同じ。 |
| $SPLIT, $ITER | `$SPLIT` は区切り文字がなければ2つ目を長さ0（アドレスは末尾）にする。`$ITER` は残りが空になるまで分割し、連続した区切り文字の間の空の部分にもxtを実行する。 | Gforthの `$split`、`$iter`。 |
| $TMP | xtの実行中の出力を文字列に集め、その文字列を返す。結果は16個の一時文字列を順に使い、16回後の `$TMP` で解放される。入れ子にできる。エラーのときは出力先を元に戻す。`SYSTEM` で起動したコマンドや `STDOUT` へのファイル書き込みは集めない。 | Gforthの `$tmp`（一時文字列は16個）。 |
| ローカル変数の構文 | `{ ... }` と `{: ... :}`。`--` から閉じ括弧まではコメント、`\|` の後の名前は0で始まる。最後の名前がスタックの一番上の値を受け取る。`LOCALS\| a b \|` は最初の名前が一番上を受け取る。型指定は `W:` `D:` `F:` `C:` `XT:`（値）と `W^` `D^` `F^` `C^` `XT^`（アドレス）。型指定なしは `W:`。 | Gforthの `{ }`（`glocals.fs`）とForth 2012の `{: :}`、`LOCALS\|`。Gforthで `LOCALS\| x y \|` が `y` に下の値を入れることを確認した。 |
| ローカル変数の参照 | 値の型は名前で値を積み、`TO` で変更できる。`XT:` は名前で実行する。アドレスの型は名前でアドレスを積み、`TO` はエラー。名前は辞書の語より優先する。名前を使えるのは、必ずその宣言を通ってからたどり着く場所だけ：`IF` の中で宣言した名前は `ELSE` の側と `THEN` の後で、`WHILE` の後で宣言した名前は `REPEAT` の後で、`?DO` の本体の名前は `LOOP` の後で、`OF` の中の名前は `ENDOF` の後で見えなくなる。`DO ... LOOP` の本体の名前は、それより前に `LEAVE` がなければ `LOOP` の後でも見える。`BEGIN ... UNTIL` の本体の名前も `UNTIL` の後で見える。`DOES>` 以降では前の名前は使えない。定義の外の `{` は `COMPILE MODE ERROR !`。`EXIT` などで到達できない経路は考えないので、Gforthより見える範囲が狭くなる場合がある。 | 利用者の指示（2026-10-29）でGforthの規則（文書の「Where are locals visible by name?」）に合わせた。Gforthでの確認結果（IF・ELSE・THEN、BEGIN・UNTIL・WHILE・REPEAT、DO・?DO・LOOP・LEAVE、CASE・OF、同名の語）と15例すべてで一致することを確かめた。ANS Forthは制御構造の中の宣言を認めないが、教材Level 29がループの中で宣言しているためGforthに合わせた。 |
| ローカル変数の領域 | 論理メモリの1F0000H〜1FFFFFH（64 KiB）に、呼び出しごとの領域を取る。定義が最初に `{` を実行したときに確保し、ループ内で同じ宣言を実行しても確保し直さない（値だけ入れ直す）。定義を抜けるとき（`EXIT`、エラーを含む）に解放する。足りなければ `RETURN STACK OVER FLOW !`。リターンスタック（`>R` など）とは別なので、併用しても干渉しない。 | アドレスの型（`W^` など）のアドレスを論理メモリ内に持たせるため。ヒープはその分減って100000H〜1EFFFFH（960 KiB）。 || 文字列配列 | 配列変数が持つ文字列の中身を、文字列変数（セル）の並びとして使う。`$[]` と `$[]!` は必要に応じて空の要素で伸ばす。`$[]@` は範囲外なら `0 0`。`$[].` は各要素の後に改行する。`$[]SLURP` は配列を先頭から上書きし、余った要素は解放する。 | Gforthの `$[]` `$[]@` `$[]slurp`（`string.fs`）。 |
| 入力行の置き場所 | 端末から読んだ行は論理メモリの入力バッファ（TIB、1E0000H〜1E0FFFH、4096バイト）に写してから解釈する。`EVALUATE` の文字列はその場所のまま解釈する。4096バイトを超える行は `STRING TOO LONG !`。1E1000H〜1E8FFFHは `INCLUDE` の行バッファ（入れ子8段分）、1E9000H〜1ECFFFHは読み込んだファイル名の表。 | `PARSE` が入力内のアドレスを返せるようにするため（Gforthと同じ）。 |
| 入力の読み足し | 次の行を読み足すのは端末入力のときだけ。`EVALUATE` の文字列が尽きたら、それ以上は読まない（`CREATE` や `{` の続きを端末から読まない）。`VARIABLE` や `:` などの名前待ちのまま文字列が尽きた場合は `DEFINITION ERROR !` にし、呼び出し元の次の語を名前にしない。直前に `CREATE` した語の記録は、ファイルや `EVALUATE` の中の行では消さない（`CREATE` と `DOES>` の間で `INCLUDE` や `EVALUATE` を使える）。 | Gforthでは `EVALUATE` の入力は読み足せない（`kernel/input.fs`）。 |
| 語の後の区切り | 語を読むと、その後ろの区切り文字（空白、タブ、CR、LF）を1文字消費する。`PARSE` はその次から読む。`S"` などの後の文字列も同じ位置から始まる（`S"  x"` は ` x`）。 | Gforthの `parse-name`（`kernel/int.fs`）。 |
| WORD, PARSE | `WORD` は区切り文字を読み飛ばしてから次の区切り文字までを数え付き文字列（255バイトまで、C00H）にして返し、区切り文字を消費する。区切りが空白のときは、タブ・CR・LFも区切りとみなす。`PARSE` は読み飛ばさずに区切り文字までを入力内のアドレスで返す。どちらも現在の行をまたがない。 | Forth 2012。`WORD` の結果は次の `WORD` まで有効。 |
| FIND, FIND-NAME | `FIND` は即時語なら1、それ以外は-1。構文語（`TO` `[']` `{` `S"` など）は辞書にないので見つからない。名前トークン（nt）は辞書番号+1（0は「なし」）。`NAME>STRING` は名前を400H〜BFFHの8個のバッファへ順に写して返す（8回後に上書き）。 | Gforthは辞書内の名前を返す。この移植版は名前を論理メモリ外に持つための判断。 |
| SEE | `: 名前` の次の行から命令列を表示し、最後に `;`。`IF ELSE THEN`、`BEGIN UNTIL`、`BEGIN AGAIN`、`BEGIN WHILE REPEAT`、`DO LOOP` 系は元の語で表示する。それ以外の分岐は `BRANCH n` `?BRANCH n`（定義先頭からの位置）。`CASE` は `OVER = IF DROP ... ELSE ... THEN` の形になる。ローカル変数は `L#番号`。組み込み語は `BUILT-IN 名前`、変数・定数・`VALUE`・`CREATE` はその種類を表示する。 | 教材Level 10の `SEE SQUARE` の出力と同じ形。命令列から元のソースを完全には復元できない。 |

| SYSTEM | Cライブラリの `system` で実行する（Windowsは `cmd.exe /c`、それ以外は `/bin/sh -c`）。コマンドは4095バイトまで。NULを含むコマンドは実行せずに `HOST FUNCTION ERROR !`（Cの `system` はNULの手前までしか実行しないため）。0以外の終了コードはエラーにしない。起動に失敗した場合は `HOST FUNCTION ERROR !`。終了コードを返す `$?` は未実装。 | 引用符を含むコマンドをシェルの規則どおりに渡すため。`$?` は教材で使われていない。 |
| PAGE | `ESC[2J ESC[1;1H` を出力する。Windowsでは起動時にコンソールのVT処理を有効にする。 | Gforthの `page` と同じ出力。 |
| 入力行・容量 | 入力4096バイト、名前255バイト、データ・リターン・浮動小数点スタック各1024、辞書1024語、コード8192操作。 | ポータブル版の現行上限。 |

## 上限・境界・エラー復帰

- データ領域は4000Hからヒープの先頭（100000H）までを割り当て可能とします。末尾を超えるALLOT、変数、配列、文字列、カンマ、Cカンマ、Fカンマは失敗し、データ領域ポインタを進めません。負のALLOTは4000Hまで戻せます。
- セル・浮動小数点数は8バイトのリトルエンディアンで読み書きします。アドレスが0未満、または読み書きが論理メモリ末尾を越える場合は `INVALID MEMORY ADDRESS !` になります。アドレスの折り返しはしません。配列アクセスは要素数を検査しません。
- スタックのアンダーフロー／オーバーフロー、領域超過、辞書／コード超過、ゼロ除算はエラーです。制御ネスト超過はNESTING ERRORとして報告します。エラー報告時にデータ・リターン・浮動小数点・ループ・制御スタックを初期化します。
- コンパイル中のエラーは、作成中のワード、追加コード、当該定義中に確保したデータ領域を巻き戻します。既に完了した定義は残します。トップレベルのALLOT失敗では、割り当て位置は失敗前の値を保ちます。
- FORGETは指定語以後の辞書語をすべて削除し、削除対象内の最初のコンパイル済み定義までコード位置を戻します。データ位置も指定語の割り当て前へ戻し、その後の定義で領域を再利用します。

## 資料だけでは確定できない点

| 項目 | 現状 | 次に判断する条件 |
| --- | --- | --- |
| NORの論理定義 | 解説文とZ80リスト／マニュアルの記述が一致しない。現行版はNOT(a OR b)を実装。 | 誌面画像の再確認、または対象とする版の特定。 |
