# CHIP-8 エミュレータ仕様書

作成日：2026-11-28
管理タスク：tque 1468（実装と自動検査は 1469、OS ごとの実機確認は 1470〜1472）

## 1. 対象と範囲

CHIP-8 のプログラムを Sigma の上で実行するインタープリターである。Forth のスクリプト `emu/chip8/chip8.fs` だけで構成し、Sigma 本体（`src/`、`include/`）は変更しない。

対象は原型の CHIP-8 である。COSMAC VIP のマニュアルの表 I にある31命令に、表に載っていないが VIP のインタープリターで動作する `8XY3`、`8XY6`、`8XY7`、`8XYE` を加えた35命令を実行する。

次のものは対象に含めない。

- SUPER-CHIP、XO-CHIP、CHIP-8E、CHIP-8X、CHIP-8I の追加命令
- 64×48、64×64、128×64 の画面
- 機械語サブルーチン `0NNN`（読み飛ばす）
- 1802 の命令ごとの実行時間の再現

CHIP-8 は、1978年の COSMAC VIP 用のインタープリターと、1990年以降の HP48 用の CHIP-48 とで、いくつかの命令の動作が異なる。この違いは6個の変数で切り替える（5章）。既定は CHIP-48 系の動作である。

## 2. ファイルと起動

| ファイル | 内容 |
| --- | --- |
| `emu/chip8/chip8.fs` | インタープリター本体 |
| `emu/chip8/test-chip8.fs` | 自動検査。窓を開かず、音を出さない |
| `emu/chip8/README.md`、`README.ja.md` | 使い方 |
| `emu/roms/c8games/` | 利用者が用意した ROM 23本。拡張子はない |
| `emu/chip8/docs/SPECIFICATION.md` | この文書 |

リポジトリの直下から起動する。

```
zig-out/bin/sigma.exe emu/chip8/chip8.fs emu/roms/c8games/PONG
zig-out/bin/sigma.exe emu/chip8/chip8.fs emu/roms/c8games/PONG vip
```

引数1が ROM のパスである。引数2は省略でき、`vip` または `chip48` で動作の組（5.2節）を選ぶ。大文字と小文字は区別しない。それ以外の文字列なら使い方を表示し、窓を開かずに終了する。

引数1がないとき、または引数1が `-` で始まるときは、語を定義するだけで何も実行しない。`-e` で語を呼ぶ使い方と自動検査のための動作である。

```
zig-out/bin/sigma.exe emu/chip8/chip8.fs -e 'S" emu/roms/c8games/MAZE" CH8-LOAD 300 CH8-TICKS CH8-DUMP BYE'
```

## 3. 機械の状態

### 3.1 メモリ

4096バイト。プログラムは `$200` から読み込む。プログラムの大きさは最大3584バイトで、それより大きいファイルは読み込まずにエラーにする。

`$000`〜`$1FF` は、VIP ではインタープリター自身が置かれていた領域である。このエミュレータでは `$050` から80バイトに数字パターンを置き、残りは 0 で埋める。

メモリを読み書きする命令は、アドレスを `$FFF` でマスクする。

### 3.2 レジスタ

| 名前 | 幅 | 内容 |
| --- | --- | --- |
| V0〜VF | 8ビット | 汎用。VF は桁上がりと衝突のフラグを兼ねる |
| I | 16ビット | メモリのアドレス。`FX1E` の加算は 16ビットで折り返す |
| PC | | 次に実行する命令のアドレス。初期値 `$200` |
| SP | | スタックに積んだ戻り番地の数。初期値 0 |
| DT | 8ビット | 遅延タイマー |
| ST | 8ビット | 音のタイマー |

### 3.3 スタック

戻り番地を16個まで積む。17個目の `2NNN` と、空のときの `00EE` はエラーにする。

VIP のメモリマップは「12段まで」と記している。16段は Cowgod の資料と SUPER-CHIP v1.1 の文書の値で、12段を前提にしたプログラムも動く。

### 3.4 タイマー

DT と ST は、0 でない間、60分の1秒ごとに 1 ずつ減る。ST が 0 より大きい間、ブザーが鳴る。

### 3.5 画面

64×32 画素の白黒。原点は左上で、X は右へ 0〜63、Y は下へ 0〜31。1画素を1バイト（0 または 1）で持つ。

### 3.6 キー

16個。番号は 0〜F。各キーの状態を1バイト（0 が離れている、1 が押されている）で持つ。

### 3.7 数字パターン

16進数字 0〜F の絵。1字が 8×5 画素（5バイト）で、数字 n のパターンは `$050 + 5n` にある。`CH8-RESET` が書き込む。

既定のパターンは Cowgod の資料と Mastering CHIP-8 が載せているものである。

```
0: F0 90 90 90 F0   1: 20 60 20 20 70   2: F0 10 F0 80 F0   3: F0 10 F0 10 F0
4: 90 90 F0 10 10   5: F0 80 F0 10 F0   6: F0 80 F0 90 F0   7: F0 10 20 40 40
8: F0 90 F0 90 F0   9: F0 90 F0 10 F0   A: F0 90 F0 90 90   B: E0 90 E0 90 E0
C: F0 80 80 80 F0   D: E0 90 90 90 E0   E: F0 80 F0 80 F0   F: F0 80 F0 80 80
```

`CH8-VIP-FONT` が真なら、VIP のマニュアルの付録 C にあるパターンを書き込む。1、4、7、B、D の形が違う。

```
0: F0 90 90 90 F0   1: 60 20 20 20 70   2: F0 10 F0 80 F0   3: F0 10 F0 10 F0
4: A0 A0 F0 20 20   5: F0 80 F0 10 F0   6: F0 80 F0 90 F0   7: F0 10 10 10 10
8: F0 90 F0 90 F0   9: F0 90 F0 10 F0   A: F0 90 F0 90 90   B: F0 50 70 50 F0
C: F0 80 80 80 F0   D: F0 50 50 50 F0   E: F0 80 F0 80 F0   F: F0 80 F0 80 80
```

VIP ではパターンが ROM の `$8110`〜`$8142` にあり、数字どうしがバイトを共有して51バイトに収まっている。このエミュレータは形だけを再現し、アドレスと共有は再現しない。プログラムは `FX29` でアドレスを得るので、動作は変わらない。

## 4. 命令

命令は2バイトで、上位バイトが先にある。`X` は上位バイトの下位4ビット、`Y` は下位バイトの上位4ビット、`N` は下位4ビット、`KK` は下位バイト、`NNN` は下位12ビットである。

1命令の実行は、2バイトを読み、PC を 2 進めてから、命令を実行する。読み飛ばし（スキップ）は PC をさらに 2 進める。

| 命令 | 動作 |
| --- | --- |
| `00E0` | 画面を消す |
| `00EE` | サブルーチンから戻る |
| `0NNN` | 何もしない（上の2つを除く） |
| `1NNN` | NNN へ飛ぶ |
| `2NNN` | 戻り番地を積み、NNN へ飛ぶ |
| `3XKK` | VX = KK なら次の命令を飛ばす |
| `4XKK` | VX ≠ KK なら次の命令を飛ばす |
| `5XY0` | VX = VY なら次の命令を飛ばす |
| `6XKK` | VX = KK |
| `7XKK` | VX = VX + KK（256 で折り返す。VF は変えない） |
| `8XY0` | VX = VY |
| `8XY1` | VX = VX OR VY |
| `8XY2` | VX = VX AND VY |
| `8XY3` | VX = VX XOR VY |
| `8XY4` | VX = VX + VY。VF は桁上がりがあれば 1、なければ 0 |
| `8XY5` | VX = VX − VY。VF は VX ≥ VY なら 1、VX < VY なら 0 |
| `8XY6` | 右へ1ビットずらす。VF はずらす前の最下位ビット |
| `8XY7` | VX = VY − VX。VF は VY ≥ VX なら 1、VY < VX なら 0 |
| `8XYE` | 左へ1ビットずらす。VF はずらす前の最上位ビット |
| `9XY0` | VX ≠ VY なら次の命令を飛ばす |
| `ANNN` | I = NNN |
| `BNNN` | NNN + V0 へ飛ぶ |
| `CXKK` | VX = 乱数（0〜255） AND KK |
| `DXYN` | 絵を描く（4.2節） |
| `EX9E` | VX の下位4ビットの番号のキーが押されていれば、次の命令を飛ばす |
| `EXA1` | そのキーが押されていなければ、次の命令を飛ばす |
| `FX07` | VX = DT |
| `FX0A` | キーを待つ（4.3節） |
| `FX15` | DT = VX |
| `FX18` | ST = VX |
| `FX1E` | I = I + VX（VF は変えない） |
| `FX29` | I = VX の下位4ビットの数字のパターンのアドレス |
| `FX33` | VX の10進3桁を、百の位から順に I、I+1、I+2 のメモリへ書く。I は変えない |
| `FX55` | V0〜VX を I から順にメモリへ書く |
| `FX65` | I から順にメモリを読み、V0〜VX へ入れる |

上の表にない命令（`5XY1`、`8XY8`、`EX00`、`FXFF` など）は、命令コードとアドレスを16進で表示してエラーにする。

### 4.1 フラグを書く順

`8XY4`、`8XY5`、`8XY6`、`8XY7`、`8XYE` は、演算の入力を先に読み、結果を VX に書き、最後に VF を書く。X が F のときは、VF にフラグが残る。

VIP のインタープリター（付録 C のリスト、`$01CE` 以降）がこの順で書いている。`8XYN` の処理は 1802 の命令 `FN` を実行して結果を VX に入れ、その後で 1802 のキャリーを VF に入れる。

`8XY5` の VF は、Cowgod の資料では「VX > VY なら 1」である。VX = VY のときの値が、VIP の表 I（「VX ≥ VY なら 01」）と食い違う。このエミュレータは VIP の表 I に従う。

### 4.2 `DXYN`

メモリの I から N バイトを読み、1バイトを横8画素の1行として、(VX, VY) を左上にして描く。各バイトは最上位ビットが左端である。

- 絵のビットが 1 の画素を反転する（排他的論理和）。
- 点いていた画素を消したら VF = 1、1つも消さなければ VF = 0。
- I は変えない。
- VX と VY を読んでから VF を書く。X または Y が F でも、描く位置は命令の実行前の値で決まる。
- 開始位置は折り返す。X は VX AND 63、Y は VY AND 31 である。
- 開始位置から右端または下端を越えた画素は、既定では描かない（5章の `CH8-WRAP`）。

開始位置の折り返しと、越えた分を描かない動作は、Mikolay の CHIP‐8 Technical Reference（「Graphics」の節）と VIP のリストによる。`$0070` 以降で VX を `$3F`、VY を `$1F` でマスクしている。`$00C2` では、開始位置が右端の列（X が 56 以上）のとき、8画素のうち右へはみ出す側のバイトを書かない。`$00D7` では、画面の最後の行を過ぎると描くのをやめる。

### 4.3 `FX0A`

キーが押され、そのキーが離されるまで、プログラムの実行を止める。離されたとき、そのキーの番号を VX に入れて次の命令へ進む。待つ間もタイマーは減る。

実装は PC を進めない。`FX0A` を実行するたびにキーの状態を調べ、条件が満たされるまで PC を `FX0A` のアドレスに戻す。同時に複数のキーが押されているときは、番号の小さいキーを採る。

VIP のマニュアル（16ページ）は「キーが押されるのを待ち、VX に値を入れ、キーが離されると実行を続ける」と記している。押した時点で進む実装では、数字を続けて入力するプログラムが、1回の押下を複数回の入力として読む。

## 5. 動作の切り替え

### 5.1 変数

どれも `VARIABLE` で、真か偽を入れる。`CH8-SPEED` と `CH8-BLEND` は数である。

| 変数 | 偽のとき（CHIP-48 系） | 真のとき（VIP） |
| --- | --- | --- |
| `CH8-SHIFT-VY` | `8XY6`、`8XYE` は VX をその場でずらす。VY は使わない | VY をずらした値を VX に入れる。VY は変えない |
| `CH8-LOAD-INC` | `FX55`、`FX65` は I を変えない | 実行後 I = I + X + 1 |
| `CH8-LOGIC-VF` | `8XY1`、`8XY2`、`8XY3` は VF を変えない | VX に結果を書いた後、VF = 0 |
| `CH8-DISPLAY-WAIT` | `DXYN` の後も、同じ tick の残りの命令を実行する | `DXYN` を実行したら、その tick の命令の実行を終える |
| `CH8-VIP-FONT` | 3.7節の既定のパターン | VIP のパターン |
| `CH8-WRAP` | 右端、下端を越えた画素を描かない | 越えた画素を反対側の端に描く |
| `CH8-BLEND` | 数値1〜4、既定3。1は合成なし。使用時に範囲内へ丸める | どちらのプロファイルにも属さない |

`CH8-SPEED` は、1 tick（60分の1秒）に実行する命令の数で、既定は 10 である。VIP のマニュアルに速度の記載はなく、10 は原機の値ではない。

各変数の根拠は次のとおりである。

- `CH8-SHIFT-VY`：VIP の `8XYN` は 1802 の命令 `FN` を、VY の値を入力にして実行する。`F6` と `FE` は入力をずらす命令なので、ずらされるのは VY の値である。CHIP-48 の命令表（SUPER-CHIP v1.1 の文書に転載されたもの）は「VX := VX shr 1」と記し、Cowgod の資料も VX をずらすと記す。
- `CH8-LOAD-INC`：VIP の表 I は「I = I + X + 1」と記し、リスト（`$0155`、`$0165`）も I を進めながら転送する。Cowgod の資料に I の変化の記載はない。
- `CH8-LOGIC-VF`：VIP の表 I は `8XY1` と `8XY2` に「VF changed」と記す。リストでは、論理演算の後にも 1802 のキャリーを VF に入れる。命令の解読の最後にある加算（`$003C` の `ADI 0F`）が桁上がりを起こさないので、キャリーは 0 である。リストの読み取りは手作業の逆アセンブルによる。
- `CH8-DISPLAY-WAIT`：VIP の `DXYN` は、描く前に 1802 の `IDL` 命令（`$00AC`）で画面の割込みを待つ。割込みは 60分の1秒ごとなので、1回の割込みの間に描ける絵は1つである。このエミュレータは「描いた後で tick を終える」形で近似する。待つのが描く前か後かの違いは再現しない。
- `CH8-WRAP`：越えた画素を反対側に描く動作は Cowgod の資料だけが記している。VIP は描かない（4.2節）。

### 5.2 動作の組

| 語 | 設定 |
| --- | --- |
| `CH8-CHIP48 ( -- )` | 6個の変数をすべて偽にする。`chip8.fs` を読み込んだときの状態である |
| `CH8-VIP ( -- )` | `CH8-WRAP` を偽、ほかの5個を真にする |

どちらも `CH8-SPEED` と `CH8-BLEND` を変えない。数字パターンは `CH8-RESET` が書き込むので、パターンの切り替えは次の `CH8-RESET` または `CH8-LOAD` から効く。

既定を CHIP-48 系にしたのは、利用者の決定（2026-11-28）による。`c8games` の各 ROM がどちらの動作を前提にしているかは、ROM ごとには確かめていない。

## 6. ホスト側

### 6.1 画面

64×32 の画像を作り、640×320 の窓に表示する（`64 32 GFX-INIT`、`640 320 WINDOW-SIZE`）。画面のバッファを `GFX-INDEXED` で画像に写し、`SHOW` で表示する。色は、0 が黒、1 が明るい色である。

CHIP-8 のプログラムは、動く絵を XOR で消し、新しい位置に描き直す。消去と再描画の間で tick が終わると、絵が消えた画面を表示する。PONG では消去と再描画が1 tick より長く離れることもある。利用者の測定では、パドルを動かさず600 tick 実行したとき、599表示フレームのうちパドルが欠けたのは合成なしで265、直近2フレームの論理和で68、直近3フレームの論理和で0であった。

ちらつきを抑えるため、対話ループでは画面の変更の有無にかかわらず毎 tick の終わりに画面の写しを保存する。過去3枚を保持し、現在の画面と直前の `CH8-BLEND - 1` 枚の論理和、つまり直近 `CH8-BLEND` フレームを表示する。既定値は3であり、1なら合成しない。使用時には1〜4に丸める。最大 `CH8-BLEND - 1` tick（既定では約33ミリ秒）の残像が生じる。CHIP-8 自体の画面状態は変えず、表示だけを合成するので、衝突判定は変わらない。

`CH8-BLEND-FRAME` はホスト出力なしで履歴を更新し、`CH8-SHOWN` を作る。合成画像を最後に表示した画像の写しと2048バイト比較し、異なるときだけ `CH8-DIRTY` を真にする。履歴の画素が期限切れで消える場合も表示を更新し、変わらなければ `SHOW` を呼ばない。`CH8-PAINT` は `CH8-SHOWN` を描く。`00E0` と `CH8-RESET`（`F5` を含む）は履歴と合成画像も消去し、次の表示に古い絵を残さない。

専用のコマンドライン引数は追加しない。変数の初期値を編集するか、次のように `-e` で設定する。

```powershell
zig-out/bin/sigma.exe emu/chip8/chip8.fs -e '1 CH8-BLEND ! S" emu/roms/c8games/PONG" CH8-PLAY BYE'
```

### 6.2 キー

| CHIP-8 | | | | PC | | | |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 2 | 3 | C | 1 | 2 | 3 | 4 |
| 4 | 5 | 6 | D | Q | W | E | R |
| 7 | 8 | 9 | E | A | S | D | F |
| A | 0 | B | F | Z | X | C | V |

`KEY-HELD?` で読む。英字は大文字と小文字のどちらでも受け付ける。

| キー | 動作 |
| --- | --- |
| Esc | 終了する |
| F5 | リセットする。読み込んだときの ROM の写しからメモリを作り直す |
| 窓を閉じる | 終了する |

リセットで ROM の写しを使うのは、CHIP-8 のプログラムが自分のメモリを書き換えるためである。

### 6.3 時間

`UTIME` で時刻を読む。1 tick は 16667 マイクロ秒である。1 tick に次の順で処理する。

1. `CH8-SPEED` 個の命令を実行する（`CH8-DISPLAY-WAIT` が真なら、`DXYN` の後で打ち切る）。
2. DT と ST を、0 でなければ 1 減らす。
3. ブザーの音を送る（6.4節）。
4. 画面を合成して履歴を更新し、表示済み画像と異なれば表示する。

tick の予定時刻になっていなければ `1 MS` で待つ。遅れたときは、待たずに続けて tick を実行して追い付く。遅れが 5 tick（83335 マイクロ秒）を超えたら、追い付かずに予定時刻を現在の時刻に合わせ直す。

乱数の種は、対話ループの開始時に `UTIME` から取る。`CH8-RESET` と `CH8-TICK` は種を変えないので、自動検査の結果は実行のたびに同じになる。

### 6.4 音

48000 Hz、モノラル、符号付き16ビットの PCM ストリームに、440 Hz、振幅約3000 の矩形波を書く。波の位相はブロックの間で続ける。

ストリームは `48000 1 4096 PCM-OPEN` で開く。`PCM-OPEN` の容量は2の冪（256〜65536）で、周波数以下、かつ周波数の25分の1以上でなければならない（`docs/PCM_STREAM_DESIGN.md`）。範囲外の値は ior を返さずに -24 を `THROW` する。

tick ごとに、ST が 0 より大きければ、ストリームの残量（`PCM-QUEUED`）が 1600 フレームを下回る間、800 フレームのブロックを書く。1回の書き込みが 0 フレームしか受け付けなければ、その tick の書き込みをやめる。ST が 0 なら何も書かない。

残量を 1600 フレーム（約33ミリ秒）までにするので、ST が 0 になってから音が止まるまでに、最大で約33ミリ秒の遅れがある。

音の語がないビルド、`AUDIO?` が偽のとき、`PCM-OPEN` が 0 でない ior を返すか `THROW` したときは、音を出さずに動く。Ctrl+C（-28）だけは `THROW` し直す。

ストリームは、終了、エラー、Ctrl+C のどの場合も閉じる（`CATCH` で受け、閉じてから `THROW` し直す）。

`include/chip8-audio.fs` の音源モデル（`C8-` で始まる語）は使わない。SUPER-CHIP と XO-CHIP を対象に加えるときに使う。


### 6.5 ゲームパッド

パッド0のmapped（標準配置）とraw（未割当て）の両方を使える。`CH8-INPUT` ごとに `GAMEPAD-POLL` を1回呼び、負の戻り値なら次の `CH8-RUN` まで止める。パッドがなくてもキーボードを使える。`CH8-PAD-KEYS` と `CH8-PC-KEYS` を論理和で `CH8-KEYS` に合成し、`Fx0A` もこの状態で押下と解放を待つ。

入力は36個であり、`up down left right` が番号0〜3、`b0`〜`b31` が番号4〜35である。方向はハット0（上1・右2・下4・左8）と軸0（X）・軸1（Y）の論理和である。mappedではさらにボタン11〜14の十字キーを合わせる。軸が `-16384` 未満なら左または上、`16384` を超えれば右または下とする。`GAMEPAD-HATS`、`GAMEPAD-AXES`、`GAMEPAD-BUTTON-COUNT` で数を確認し、存在しない入力を問い合わせない。rawの軸は、その実行中に `-32768` 以外の値を受け取るまで無視し、その後は `-32768` も通常の値として使う。XとYは独立して判定する。

`bN` はSigmaのボタン番号Nであり、mappedなら標準配置、rawなら機器の番号である。別名 `a b x y back start l r` は順に `b0 b1 b2 b3 b4 b6 b9 b10` を表す。rawでは単にその番号を指し、機器に印刷された文字と一致するとは限らない。

割当て先は `-`（なし）、16進1桁の `0`〜`F`、`reset`（`F5`）、`quit`（`Esc`）である。`reset` と `quit` は各入力を押した瞬間だけ働く。既定値は `up=2 down=8 left=4 right=6 b0=5`、残りはなしである。mappedだけはさらに `b6=reset b4=quit` とする。rawでもファイルに明示した操作は有効である。

設定は作業ディレクトリ基準の `emu/chip8/pads.txt` に置き、リポジトリ直下から実行する。形式は `NAME input=target ...` である。`NAME` はROMのファイル名で、スラッシュとバックスラッシュの両方からディレクトリを除く。`*` は全ROMに適用する。英字は大小文字を区別しない。空行は無視し、`#` から行末まではコメントとする。1行は255文字までである。不正なトークンはファイル名・行番号・トークンを警告して無視し、残りを読む。ファイルがなければ警告しない。

適用順は組込み既定値、すべての `*` 行（ファイル順）、一致するすべてのROM行（ファイル順）である。行ごとに初期化せず、指定した入力だけを上書きする。同じ入力は最後の正しい指定を使う。ファイルを2回読み、設定を36セルの `CH8-PAD-OVERLAY` に蓄積する。`-2` は未指定である。実行中にパッドを初めて検出した際にmapped/rawの既定値を選び、その上に設定を重ねる。

`CH8-PLAY` とコマンドライン起動は設定を読む。`CH8-LOAD` 単独では設定を消去してraw用の既定値に戻し、最初の検出時に種類を選び直す。`CH8-RESET` は割当てと入力履歴を保つ。`CH8-RUN` は検出・押下端・軸の履歴を初期化する。

rawのボタン番号は次のコマンドで調べる。

```powershell
sigma emu/chip8/chip8.fs padtest
# リポジトリの既存実行ファイルを使う場合:
zig-out/bin/sigma.exe emu/chip8/chip8.fs padtest
```

引数1が大小文字を問わず `padtest` と完全一致すると、`CH8-PAD-TEST` を実行して終了する。窓は開かず音も鳴らさない。約100ミリ秒ごとにmappedフラグ、押している方向、ボタン番号を1行で表示する。キーボードのキーを押す（`INKEY`）か30秒経過すると終了する。空の項目は `-`、複数の入力はコンマで区切る。例えば `mapped=0 directions=- buttons=-`、`mapped=0 directions=up,left buttons=0,9` である。表示された番号を使い、例えば `* b9=reset b8=quit` と設定する。

| 語・領域 | 動作 |
| --- | --- |
| `CH8-PAD-DEFAULT ( mapped -- )` | 種類に応じた組込み既定値を設定する。設定の上書きは行わない |
| `CH8-PAD! ( target input# -- )` | 入力0〜35に `-1`〜17を設定する。範囲外の引数は無視する |
| `CH8-PAD-LOAD ( rom-addr rom-u -- )` | 共通・ROM設定を読む |
| `CH8-PAD-LOAD-FILE ( rom-addr rom-u file-addr file-u -- )` | 指定ファイルから同じ規則で読む |
| `CH8-PAD-MAP` | 36セル。`-1` はなし、0〜15はキー、16はリセット、17は終了である |
| `CH8-PAD-KEYS`、`CH8-PC-KEYS` | 各16バイトのキー状態である |
| `CH8-MERGE-KEYS ( -- )` | 両配列を `CH8-KEYS` に合成する。ホスト入力は読まない |
| `CH8-PAD-STATE ( dirs buttons mapped -- )` | 方向ビット0〜3と32ビットのボタンマスクからキーと押下端を処理する。ホスト入力は読まない |
| `CH8-PAD-DIRS ( hat x y buttons mapped -- dirs )` | 方向を合成する |
| `CH8-PAD-AXIS-VALUE ( value axis mapped -- value )` | 軸0・1のraw初期値を抑制する |
| `CH8-PAD-PRINT ( dirs buttons mapped -- )` | 診断の1行を表示する |
| `CH8-PAD-TEST ( -- )` | 最大30秒間、窓なしで入力を表示する |

入力数・番号の根拠は `docs/WORD_REFERENCE.ja.md` の `GAMEPAD-HAT`、`GAMEPAD-HATS`、`GAMEPAD-AXES`、`GAMEPAD-AXIS`、`GAMEPAD-BUTTON-COUNT`、`GAMEPAD-BUTTONS` である。raw軸の初期値は `docs/GRAPHICS_AND_SOUND.ja.md` の366行による。添付した6個のROM設定の方向の意味は未確認である。自動検査はホスト入力なしの状態変換、設定解析・累積・優先順、別名、押下端、軸初期値、固定値の表示を対象とする。実機操作と診断の待機ループは実行していない。

## 7. 語

内部の語を含め、すべて `CH8-` で始まる。

| 語 | スタック | 動作 |
| --- | --- | --- |
| `CH8-LOAD` | ( c-addr u -- ) | ROM のファイルを読み込み、リセットする |
| `CH8-RESET` | ( -- ) | メモリを 0 で埋め、数字パターンと ROM の写しを書き、レジスタ、スタック、タイマー、画面、キーの状態を初期値にする |
| `CH8-STEP` | ( -- ) | 1命令を実行する |
| `CH8-TICK` | ( -- ) | 1 tick 分の命令を実行し、タイマーを減らす。キーの読み取り、表示、音は含まない |
| `CH8-TICKS` | ( n -- ) | `CH8-TICK` を n 回実行する |
| `CH8-BLEND-FRAME` | ( -- ) | 履歴と `CH8-SHOWN` を更新し、表示済み画像との差を `CH8-DIRTY` に入れる。ホスト出力は行わない |
| `CH8-PAINT` | ( -- ) | `CH8-SHOWN` を描く。`SHOW` は呼ばない |
| `CH8-DUMP` | ( -- ) | 画面を `#` と `.` の32行で表示する |
| `CH8-RUN` | ( -- ) | 読み込み済みの ROM を、窓を開いて実行する |
| `CH8-PLAY` | ( c-addr u -- ) | `CH8-LOAD` の後に `CH8-RUN` を実行する |
| `CH8-CHIP48`、`CH8-VIP` | ( -- ) | 動作の組を選ぶ（5.2節） |
| `CH8-PAD-DEFAULT` | ( mapped -- ) | 種類に応じた既定値を設定する（6.5節） |
| `CH8-PAD!` | ( target input# -- ) | 36入力の割当てを設定する |
| `CH8-PAD-LOAD` | ( rom-addr rom-u -- ) | 共通・ROM設定を読む |
| `CH8-PAD-LOAD-FILE` | ( rom-addr rom-u file-addr file-u -- ) | 指定ファイルから設定を読む |
| `CH8-PAD-STATE` | ( dirs buttons mapped -- ) | ホスト入力なしでキーと押下端を処理する |
| `CH8-MERGE-KEYS` | ( -- ) | PCとパッドのキーを合成する |
| `CH8-PAD-TEST` | ( -- ) | 窓を開かずにボタン番号を表示する |

状態を持つ領域と変数：`CH8-MEM`（4096バイト）、`CH8-V`（16バイト）、`CH8-SCREEN`（2048バイト）、`CH8-SHOWN`（2048バイト）、`CH8-LAST-SHOWN`（表示済み画像の写し、2048バイト）、`CH8-HISTORY`（過去3 tick、6144バイト）、`CH8-BLEND`、`CH8-KEYS`（16バイト）、`CH8-I`、`CH8-PC`、`CH8-SP`、`CH8-DT`、`CH8-ST`。

## 8. エラー

メッセージを表示して `THROW` する。

| コード | 原因 |
| --- | --- |
| -4100 | ROM が 3584 バイトを超える |
| -4101 | ROM を最後まで読めなかった |
| -4102 | 定義されていない命令 |
| -4103 | スタックが空のときの `00EE` |
| -4104 | 17段目の `2NNN` |

ファイルを開けないときは、`OPEN-FILE` の ior をそのまま `THROW` する。

## 9. VIP と違う点

`CH8-VIP` を選んでも、次の点は VIP と違う。

| 項目 | VIP | このエミュレータ |
| --- | --- | --- |
| `FX0A` の間の音 | キーを押している間、音が鳴る | 鳴らない |
| ブザーの最小値 | ST が 02 以上でないと鳴らない | 1 でも鳴る |
| スタック | 12段 | 16段 |
| `0NNN` | 1802 の機械語サブルーチンを呼ぶ | 何もしない |
| 命令の実行時間 | 命令ごとに違う | 1 tick に `CH8-SPEED` 個 |
| `DXYN` の待ち | 描く前に割込みを待つ | 描いた後で tick を終える |
| 数字パターンの場所 | ROM の `$8110` 以降、51バイト | `$050` 以降、80バイト |
| メモリ | 2048 または 4096 バイト。末尾を画面とスタックと変数に使う | 4096 バイトすべてをプログラムが使える |

## 10. 検査

`emu/chip8/test-chip8.fs` は `chip8.fs` を読み込み、`$200` に短いプログラムを書き、`CH8-STEP` または `CH8-TICK` で実行して、レジスタ、メモリ、PC、SP、I、画面のバイトを手で計算した値と比べる。リポジトリの直下から実行する。

```
zig-out/bin/sigma.exe emu/chip8/test-chip8.fs
```

失敗した検査ごとに、検査の名前、期待した値、実際の値を1行で表示する。最後に `passed N failed M` を表示する。

検査する項目：

- 4章のすべての命令
- 5章の6個の変数それぞれの真と偽、`CH8-CHIP48` と `CH8-VIP` が設定する値
- X が F のときにフラグが残ること（`8XY4`、`8XY5`、`8XY6`、`8XY7`、`8XYE`）
- I のマスク
- `DXYN` の衝突、消去、開始位置の折り返し、端での切り捨てと折り返し
- `FX0A` の「押す、離す」の順
- スタックのあふれと空、定義されていない命令、大きすぎる ROM
- 表示合成の保持期間、範囲への丸め、消去とリセット、画像の差による再描画判定
- `CH8-TICK` によるタイマーの減少
- 数字パターンのアドレスと内容
- `c8games` の MAZE と PONG が、窓を開かずに数百 tick の間エラーなく動くこと。ROM はリポジトリに含めない（`emu/roms/` は Git の対象外）。ファイルがなければこの検査を飛ばし、`INFO skipped, ROM not found:` の行を表示する
- 音の語があるビルドで、標本を書かずにストリームを開いて閉じられること、ST が 0 のとき何も書かないこと

自動検査が確かめないもの：窓への表示、キーの読み取り、実時間での速度、音、Ctrl+C のときの後始末。これらは 1470〜1472 で人が操作して確かめる。

## 11. 確かめていないこと

- VIP の動作のうち、マニュアルの本文にないもの（`8XY6` と `8XYE` が VY をずらすこと、`8XY1`〜`8XY3` の VF の値、`DXYN` の待ち）は、付録 C の16進のリストを手作業で逆アセンブルして読んだ。リストはスキャン画像であり、読み違いを機械で確かめていない。端での切り捨ては Mikolay の CHIP‐8 Technical Reference にも記載がある。
- VIP の ROM にあるタイマーの割込み処理とキーボードの読み取り（`$8195`）は、リストがこのマニュアルの付録 B にあり、読んでいない。
- CHIP-48 が画面の端を越えた画素をどう扱うかは、参照した資料に記載がない。
- `c8games` の23本それぞれが、どちらの動作の組で正しく動くか。
