# LOGO・タートルグラフィックス仕様書

作成日：2026-11-28
管理タスク：1475（タートルの実装は1476、LOGOの実装は1477）

## 1. 対象と根拠

全機能版の ForthSigma 上で動く、外部の Forth スクリプトである。
Sigma 本体には組み込まない。
UCBLogo のタートル命令と、手続き・制御・数値計算の一部を扱う。
UCBLogo 全体との互換性は要求しない。

`docs/DECISIONS.md` の「LOGOとタートルグラフィックスの仕様（2026-11-28、利用者の決定）」を優先する。
UCBLogo の動作については `docs/LOGO_TURTLE_STUDY.md` の2.4節に記録された事実だけを根拠とする。
以下の「仕様選択」は、決定事項が定めていない細部を本仕様で選んだものである。
UCBLogo の動作を確認したという意味ではない。
仕様選択の一覧と理由は12章にまとめる。

## 2. ファイルと起動

| ファイル | 内容 |
| --- | --- |
| `emu/logo/turtle.fs` | `TURTLE` 語彙、状態、画像への描画、表示と入力 |
| `emu/logo/logo.fs` | `LOGO` 語彙、字句解析、二段階の変換、実行と起動入口 |
| `emu/logo/test-turtle.fs` | 窓なしの状態・画素検査 |
| `emu/logo/test-logo.fs` | 窓なしの翻訳・実行・エラー・後始末の検査 |
| `emu/logo/examples/*.lg` | 自作の LOGO プログラム |
| `emu/logo/README.md`、`emu/logo/README.ja.md` | 英語と日本語の利用説明、保存実行体の作り方 |
| `emu/logo/docs/SPECIFICATION.md` | この仕様 |

このタスクで作成する成果物は本仕様だけである。
上表の実装・検査・README は後続タスクで作成する。
作業ディレクトリはリポジトリ直下とする。

```powershell
sigma emu/logo/logo.fs prog.lg
zig-out/bin/sigma.exe emu/logo/logo.fs prog.lg
sigma emu/logo/logo.fs --emit-forth generated.fs prog.lg
LOGO.EXE prog.lg
LOGO.EXE --emit-forth generated.fs prog.lg
```

仕様選択として、`--emit-forth 出力先` は実行する Forth を UTF-8・LF で保存してから実行する。
変換専用の意味にはしない。
入力と出力の綴り、または `FILE>REALPATH` で得る正規化パスが同じ場合は、書き込む前にエラーにする。
異なるハードリンク名の同一性は判定の対象外とする。
Sigma の公開 API にはファイルIDを比べる語がないためである。
ハードリンクの別名を出力先に指定してはならない。
オプションは入力ファイルより前に1回だけ置ける。
入力ファイルは1個である。
未知のオプション、入力の不足、余分な引数は使用法エラーとする。
`NEXT-ARG ( -- addr u )` で消費し、LOGO ファイルを Sigma の Forth 入力として処理させない。

`logo.fs` は引数なし、または先頭引数が Sigma の `-e` の場合、ライブラリを読み込むだけにする。
保存アプリの入口 `LOGO-MAIN ( -- )` は、引数なしを使用法エラーにする。
これにより、次の保存手順と、引数なしの検査用読込みを両立する。

```forth
INCLUDE emu/logo/logo.fs
ALSO LOGO
' LOGO-MAIN APP-ENTRY!
PREVIOUS
SAVESYS LOGO.EXE
BYE
```

上記を例えば Sigma の対話入力で実行する。
起動スクリプト、実行体、インストーラーは配布しない。
保存前には LOGO プログラムを実行せず、プログラム用の `MARKER` も残さない。
`APP-ENTRY! ( xt -- )` に登録するのは完成したコロン定義である。
登録済みの保存実行体は入口から正常復帰すると終了し、Forth のプロンプトには入らない。
保存実行体の通常引数はアプリのデータとなる。
この点は検討文書の古い起動説明ではなく、`docs/EXTENSION.ja.md` の8章に従う。
保存時の `-m` と `-l` を維持する。
本仕様では既定の32 MiBと64 KiBで検査を始めるが、深い一般再帰の容量保証はしない。

## 3. タートルの状態と座標

| 状態 | 初期値 | 表現 |
| --- | --- | --- |
| 位置 x、y | 0、0 | 浮動小数点数 |
| 向き | 0度 | 浮動小数点数、0以上360未満に正規化 |
| ペン | 下ろす | 真偽値 |
| ペン色 | 7、白 | 24ビット RGB |
| ペン幅 | 1 | 整数画素 |
| 背景色 | 0、黒 | 24ビット RGB |
| 亀 | 表示 | 真偽値 |
| 端の扱い | `WRAP` | 3種類の内部定数 |
| 速度 | 1 | 整数0〜1000 |
| 画像の寸法 | 640×480 | 整数 |

原点は画像の中央である。
x は右、y は上を正とする。
1単位を画像の1画素とする。
0度は上で、正の角度は時計回りである。
距離 d の移動量は `dx = d sin(h)`、`dy = d cos(h)` である。
三角関数には角度をラジアンへ変換して渡す。
`FSINCOS ( F: rad -- sin cos )` を使える。

仕様選択として、画素中心の座標範囲を x は `-(w-1)/2`〜`(w-1)/2`、y は `-(h-1)/2`〜`(h-1)/2` とする。
この値を `X-RANGE` と `Y-RANGE` に設定して `MLINE` を使う。
両語は `( F: lo hi -- )` である。
`MLINE` は `( F: x1 y1 x2 y2 -- )` である。
これにより縦横とも倍率は1となる。
画素への丸めは Sigma の `FROUND` と同じとする。
ちょうど中間の場合は偶数側へ丸める。
偶数寸法では原点が中央の4画素の間にある。
仕様選択として、窓のリサイズではキャンバスの寸法を変えない。
`WINDOW-FIT ( n -- )` に0を設定し、縦横比を保って表示する。
1単位1画素はキャンバスの規則であり、OS の DPI や拡大表示の物理画素数を保証しない。

### 3.1 端の扱い

仕様選択として、幾何学上の領域は `[-w/2,w/2) × [-h/2,h/2)` とする。
ペン幅や亀の形ではなく、亀の中心を判定する。

| モード | 動作 |
| --- | --- |
| `WINDOW` | 位置を領域外にも保持する。線は画像の端で切る |
| `WRAP` | 周期 w、h の平面として移動する。位置は上記の半開区間へ正規化する |
| `FENCE` | 終点が領域外なら `-4200 THROW` とする。メッセージは `turtle out of bounds` とする |

`FENCE` の失敗では、その移動の線も位置も変更しない。
ペンを上げていても検査する。
`WINDOW` から `WRAP` への切替では位置だけを正規化し、接続線は描かない。
`FENCE` への切替時に現在位置が領域外なら、状態を変えずに同じエラーにする。

`WRAP` の線は、始点から終点へ進むパラメーター t の小さい順で分割する。
各区間で、進行方向の x 境界と y 境界へ達する最小の t を求める。
境界までの線を描き、残りの移動の始点と終点を、その軸の周期だけ反対側へ移す。
角に同時に達した場合は両軸を同時に移す。
反対側との間を横切る線は描かない。
残りがなくなるまで繰り返すため、1命令で何周しても同じ規則となる。
境界から外向きに始まる場合は、長さ0の区間を繰り返さず、先にその軸を移す。
ちょうど正の境界で終わる位置も負の境界へ正規化する。
境界上の線分は画像でクリップされる。
太線は各分割区間を描いてクリップするため、太さだけが端を越えた部分は反対側に写さない。
以上の分割方法と失敗時の原子性は仕様選択である。

### 3.2 消去、円弧、文字、太線

`HOME` は現在のペン状態で原点へ移動し、その後で向きを0度にする。
`CS` は背景色で全キャンバスを消し、位置と向きを0にする。
`CLEAN` は全キャンバスを消すだけである。
両消去命令は色、ペン幅、ペン上下、亀の可視性、端モード、速度を保つ。
`SETBG` は背景色を変更して `CLEAN` を行う。
`SETSCREENSIZE` は画像を作り直し、寸法以外の全状態を初期値に戻す。
これらの保持規則は仕様選択である。

`ARC angle radius` は現在位置を中心に円弧を描く。
位置と向きは変えない。
ここまでは検討文書に記録された UCBLogo の意味である。
開始方向は記録されていない。
仕様選択として、中心から現在の向きへ radius 進んだ点を始点とする。
正の angle は時計回りとする。
radius は0以上とし、ペンを上げていれば描かない。
angle が0なら描かない。
円弧は `max(1,ceil(abs(angle) × pi/180 × max(radius,1)))` 区間の折れ線にする。
各区間は同じ角度差を持つ。
端モードは各弦に適用するが、亀の位置は更新しない。
`FENCE` は全弦の端点を先に調べ、1点でも領域外なら全体を描かずに失敗する。

仕様選択として、ペン幅 s の線は Sigma の1画素の `LINE` が描く各画素に、s×s の正方形を重ねた集合とする。
正方形の各軸のオフセットは `-floor((s-1)/2)`〜`ceil((s-1)/2)` である。
実装は同じオフセットの平行な `LINE` を s² 本描いてよい。
偶数幅は画素の正方向へ1画素多く広がる。
端点も同じ正方形になる。
アンチエイリアスは付けない。

`LABEL "word` は亀の位置を文字行の左上として、現在のペン色で `TEXT ( addr u x y -- )` を呼ぶ。
仕様選択として、文字は常に画像の右へ横書きする。
ペン上下、向き、ペン幅には依存しない。
位置と向きは変えない。
画面外は切り、文字の折返しはしない。
日本語を含む UTF-8 の1語を渡せるが、表示できる字形は Sigma のフォントに依存する。

### 3.3 色

番号の名前は検討文書の UCBLogo 欄に従う。
RGB 値は互換値を確認していないため、次の本実装の値を仕様選択とする。
色名そのものを LOGO の色指定には使わない。

| 番号 | 名前 | RGB（16進） |
| ---: | --- | --- |
| 0 | black | `000000` |
| 1 | blue | `0000FF` |
| 2 | green | `00FF00` |
| 3 | cyan | `00FFFF` |
| 4 | red | `FF0000` |
| 5 | magenta | `FF00FF` |
| 6 | yellow | `FFFF00` |
| 7 | white | `FFFFFF` |
| 8 | brown | `A52A2A` |
| 9 | tan | `D2B48C` |
| 10 | forest | `228B22` |
| 11 | aqua | `7FFFD4` |
| 12 | salmon | `FA8072` |
| 13 | purple | `800080` |
| 14 | orange | `FFA500` |
| 15 | grey | `808080` |

`SETPC` と `SETBG` は整数番号0〜15、または百分率3個のリテラル `[r g b]` を受け取る。
仕様選択として100を含む0〜100を許す。
各成分は `floor(p × 255/100 + 0.5)` で整数化する。
範囲外は丸めずエラーにする。
この角括弧は色指定専用の構文であり、リスト値を生成しない。
各成分は、任意の単項符号1個を付けられる数リテラルとする。
成分に式は書けない。
符号を適用した後の値で0〜100の範囲を検査する。

### 3.4 表示と速度

永続する線と文字はキャンバス画像に描く。
表示時には `SCREEN DRAW-TO` の後、キャンバスを `0 0 PUT-IMAGE` で写す。
コピーの設定は透明色なし、反転なし、コピー、倍率1とする。
その上に亀の三角形を現在のペン色の1画素線で描く。
仕様選択として、三角形の頂点を亀から前方10、後方6かつ左右5の3点とする。
亀はキャンバスに描かない。
亀が領域外にあるときは画面で切り、端をまたいだ複製は作らない。
画面の合成後は描画先をキャンバスへ戻す。
画像保存・画素検査に亀を含めない。

仕様選択として、速度1〜1000は表示間隔のミリ秒数とする。
既定1では状態を変える各命令の完了時に合成し、`FRAME ( ms -- )` で表示する。
`FRAME` は前回から指定時間まで待って表示する語である。
「1歩」は1回のタートル命令であり、距離1ごとのアニメーションではない。
`ARC` は全弦を描いた後で1回表示する。
速度0では途中の合成・表示を省略し、プログラム正常終了時に1回合成・表示する。
速度を0から正へ変更した場合は、その命令の完了時に表示する。
いずれも入力の確認は省略しない。
長い分割線と円弧は区間ごと、太線は各平行線ごとに中断を確認する。

`GFX-INIT ( w h -- )` と `NEW-IMAGE ( w h -- img )` は起動時に実行する。
画像ハンドルは `SAVESYS` を越えて有効ではない。
保存済みのハンドルを解放することもせず、起動時に無効値へ初期化してから作成する。
ヒープのバッファ、ファイル ID、入力状態も起動時に作り直す。
仕様選択として、窓なしの初期化と表示ありの実行を分ける。
窓なしでは `SHOW` と `FRAME` を一度も呼ばない。

## 4. `TURTLE` の公開語

`F:` の値は浮動小数点スタックを使う。
整数・アドレス・フラグはデータスタックを使う。
同じ行にある別名は同じ効果を持つ。
公開語は次の一覧に限る。
状態の変数と実装補助語は公開 API にしない。

| 語 | スタック | 動作 |
| --- | --- | --- |
| `FD`、`FORWARD` | `( F: d -- )` | 前進 |
| `BK`、`BACK` | `( F: d -- )` | 向きを保って後退 |
| `RT`、`RIGHT` | `( F: a -- )` | 時計回り |
| `LT`、`LEFT` | `( F: a -- )` | 反時計回り |
| `PU`、`PENUP` | `( -- )` | ペンを上げる |
| `PD`、`PENDOWN` | `( -- )` | ペンを下ろす |
| `HOME` | `( -- )` | 原点へ移動して0度 |
| `SETXY` | `( F: x y -- )` | 位置を指定して移動 |
| `SETH`、`SETHEADING` | `( F: a -- )` | 向きを指定 |
| `CS`、`CLEARSCREEN` | `( -- )` | 消去して原点・0度 |
| `CLEAN` | `( -- )` | 消去だけ |
| `SETPC`、`SETPENCOLOR` | `( n -- )` | 色番号 |
| `SETPENCOLOR-RGB` | `( F: r g b -- )` | 百分率 RGB |
| `SETBG`、`SETBACKGROUND` | `( n -- )` | 背景の番号 |
| `SETBACKGROUND-RGB` | `( F: r g b -- )` | 背景の百分率 RGB |
| `SETPENSIZE` | `( n -- )` | 幅1〜64 |
| `ST`、`SHOWTURTLE` | `( -- )` | 亀を表示 |
| `HT`、`HIDETURTLE` | `( -- )` | 亀を隠す |
| `WRAP`、`WINDOW`、`FENCE` | `( -- )` | 端の扱い |
| `SETSPEED` | `( n -- )` | 速度0〜1000 |
| `SETSCREENSIZE` | `( w h -- )` | 各寸法2〜4096 |
| `LABEL` | `( addr u -- )` | UTF-8 の文字 |
| `ARC` | `( F: angle radius -- )` | 円弧 |
| `TURTLE-INIT` | `( w h -- )` | 窓なしの初期化。全状態を初期化 |
| `TURTLE-PAINT` | `( -- )` | 合成だけ。窓を開かない |
| `TURTLE-RUN` | `( xt -- )` | 表示ありで xt を実行し、終了後に窓を保持 |
| `TURTLE-SAVE-PNG` | `( addr u -- )` | キャンバスを保存 |
| `TURTLE-IMAGE` | `( -- img )` | 検査用のキャンバスハンドル。解放は禁止 |
| `TURTLE-DISPOSE` | `( -- )` | 所有する画像を解放。繰り返し呼べる |

`TURTLE-INIT` は起動時の入口であり、保存した辞書に残る古いハンドルを解放せずに無効値にしてから画像を作る。
同じプロセスで再び呼ぶ場合、呼出元は先に `TURTLE-DISPOSE` で現在の画像を解放する。
`TURTLE-RUN` は初期化済みの画像を使う。
表示実行中以外は、各語は画像と状態だけを変更する。
`TURTLE-RUN` の中の整数設定・消去・向き変更も3.4節の表示対象とする。
寸法・幅・速度の上限は資源消費を制限する仕様選択である。
実数入力と計算結果の NaN、無限大は `-4201` とする。
移動距離、座標、円弧の角度・半径の絶対値は1000000以下とする。
この上限は分割描画の処理量を制限する仕様選択である。
`FORWARD` の名前は `TURTLE` が検索順の先頭にあるとタートルを指す。
Sigma の前方宣言を行う間は `TURTLE` を検索順から外す。
`PREVIOUS` は定義先を戻さないため、定義先も `SET-CURRENT` で指定する。
変換器はタートル呼出しを内部の別名へ結び、生成コードの検索順に `TURTLE` を入れない。
この共存規則を Sigma で実測した（11章）。

## 5. LOGO の字句と値

### 5.1 字句

入力は UTF-8 とする。
先頭の BOM は1個だけ取り除く。
LF と CRLF を改行とし、行番号は1から数える。
空白とタブは区切りである。
`;` から行末まではコメントである。
識別子は ASCII の英字か `_` で始まり、その後に英数字、`_`、`?` を許す。
識別子、命令、手続き、変数の ASCII 大小文字は区別しない。
原綴りは診断用に保持する。

`:name` は変数参照である。
`"word` は引用符から次の空白、改行、`;`、`[`、`]`、`(`、`)` の直前までの非空の語である。
閉じる引用符とエスケープはない。
名前を表す引用語には識別子の制限を課す。
`LABEL` の引用語だけは UTF-8 の文字列を許す。
`"word` は `MAKE`、`THING`、`LABEL`、`LOCAL` の直接の入力位置だけで許す。
変数、手続きの引数、戻り値には格納できない。

数は十進の `digits[.digits]`、`.digits` と、任意の `e` または `E` に続く符号付き十進指数を許す。
小数点の左右の少なくとも一方に数字を必要とする。
16進数、NaN、無限大の綴りは許さない。
符号は単項演算として解析する。
指数内の符号だけは数トークンの一部である。
`[`、`]`、`(`、`)`、`+`、`-`、`*`、`/`、`=`、`<>`、`<`、`>`、`<=`、`>=` は独立したトークンである。
2文字の演算子を先に切り出す。

マイナスは検討文書の空白規則に従う。
直前が空白で直後が空白でなければ単項とする。
入力先頭と開き括弧の直後も単項を許す位置とする。
式の入力を待っている位置では、後ろに空白があっても単項を許す。
それ以外は二項である。
例えば `FD :A - 10` は減算である。
`FD :A -10` は `FD :A` の後に使われない値が残るためエラーである。
`FD - 10` は負の10を入力する。
単項プラスは入力を待っている位置だけで許す。

改行はトップレベルと手続き本体の文の区切りである。
括弧内と角括弧内では空白として扱う。
1行に複数の命令を書ける。
引数不足を次の行で補わない。
`TO name :p ...` は行頭から行末までを宣言とし、`END` は単独の行に置く。
コメントは同じ行に置ける。
`TO` の入れ子、重複手続き、組込み命令・演算と同名の手続きは拒否する。
変数名には `IF`、`EXIT` なども許す。
以上の識別子・改行・重複規則は仕様選択である。

### 5.2 値と演算

数は Sigma の浮動小数点数とする。
仕様選択として、真は `-1e`、偽は `0e` の数値表現と同一視する。
`TRUE`、`FALSE` は引数0の演算である。
比較結果は Sigma のセルフラグを `S>F` で浮動小数点数へ変換する。
条件入力は0または-1だけを許し、それ以外は型・値エラーにする。
演算に使った真偽値は、それぞれ数の-1、0として扱う。
別の型タグは持たない。
これにより手続きの引数、変数、`OUTPUT` の1値をすべて浮動小数点スタックで渡せる。
ゼロ除算、非有限の演算結果は実行時エラーとする。

| 優先順位（高い順） | 演算 | 結合 |
| --- | --- | --- |
| 1 | 括弧、変数、リテラル、引数0の演算 | 最内側から |
| 2 | 単項 `+`、`-` | 右 |
| 3 | `*`、`/` | 左 |
| 4 | `+`、`-` | 左 |
| 5 | `=`、`<>`、`<`、`>`、`<=`、`>=` | 連鎖禁止 |

入力を持つ前置演算・手続きは、表の式を宣言個数だけ左から取り込む。
演算結果の後ろの二項演算も外側の式に続けられる。
曖昧さを避けたい場合は `(operation inputs...)` で呼出し全体を囲む。
例えば `FD (RANDOM 10) + 1` と `FD RANDOM 10 + 1` は、前者では上限10、後者では上限11となる。
括弧は通常の式のグループ化にも使う。
括弧を付けても入力数は変えない。
`(SUM 1 2 3)` のような可変入力は対象外である。
優先順位と固定入力の解析規則は仕様選択である。

## 6. LOGO の命令と手続き

以下が受け付ける命令と演算の全一覧である。
入力数には命令ブロックと名前の構文も数える。
`RGB` の角括弧は入力1個と数える。
表にない命令と別名はエラーにする。
`SETPENCOLOR-RGB` など Forth 専用の語は LOGO 命令としては公開しない。
`LOGO` 語彙にもタートルの正式名と略称を登録し、Forth からのスタック効果は4章と同じにする。
制御構文は LOGO の変換器が解析し、Sigma の `IF` などを `LOGO` 語彙で上書きしない。

| 命令・演算 | 入力数 | 値を返すか | 意味 |
| --- | ---: | --- | --- |
| `FD`、`FORWARD`、`BK`、`BACK` | 1 | いいえ | 距離 |
| `RT`、`RIGHT`、`LT`、`LEFT` | 1 | いいえ | 角度 |
| `PU`、`PENUP`、`PD`、`PENDOWN` | 0 | いいえ | ペン上下 |
| `HOME`、`CS`、`CLEARSCREEN`、`CLEAN` | 0 | いいえ | 3章の移動・消去 |
| `SETXY` | 2 | いいえ | x、y |
| `SETH`、`SETHEADING` | 1 | いいえ | 向き |
| `SETPC`、`SETPENCOLOR`、`SETBG`、`SETBACKGROUND` | 1 | いいえ | 番号または RGB リテラル |
| `SETPENSIZE`、`SETSPEED` | 1 | いいえ | 整数値。小数はエラー |
| `SETSCREENSIZE` | 2 | いいえ | 幅、高さ。整数値 |
| `ST`、`SHOWTURTLE`、`HT`、`HIDETURTLE` | 0 | いいえ | 可視性 |
| `WRAP`、`WINDOW`、`FENCE` | 0 | いいえ | 端モード |
| `ARC` | 2 | いいえ | 角度、半径 |
| `LABEL` | 1 | いいえ | 引用語だけ |
| `TO`、`END` | 宣言構文 | いいえ | 固定個数の必須引数だけ |
| `REPEAT` | 2 | いいえ | 回数、`[命令列]` |
| `REPCOUNT` | 0 | はい | レキシカルな繰返し番号 |
| `IF` | 2 | いいえ | 条件、`[命令列]` |
| `IFELSE` | 3 | 文脈による | 条件、真のブロック、偽のブロック |
| `STOP` | 0 | いいえ | 現在の手続きを終了 |
| `OUTPUT` | 1 | 制御として終了 | 1値を返して手続きを終了 |
| `MAKE` | 2 | いいえ | `"名前`、値 |
| `LOCAL` | 1 | いいえ | `"名前` による局所宣言 |
| `THING` | 1 | はい | `"名前` の変数参照 |
| `TRUE`、`FALSE` | 0 | はい | -1、0 |
| `RANDOM` | 1 | はい | 正の上限を切捨てた整数 n に対する0以上 n 未満 |
| 単項 `+`、`-` | 1 | はい | 符号 |
| `+`、`-`、`*`、`/` | 2 | はい | 四則演算 |
| `=`、`<>`、`<`、`>`、`<=`、`>=` | 2 | はい | 数の比較 |
| 利用者の手続き | 宣言個数 | 下記の規則 | 固定入力 |

`RANDOM` の n は1〜2147483647とする。
有限性を検査し、0方向へ切り捨てた後の整数に上限を適用する。
例えば `RANDOM 2147483647.9` は n = 2147483647 として受け付ける。
0へ切り捨てられる値と負数はエラーにする。
Sigma の `RANDOM ( u1 -- u2 )` と `F>S`、`S>F` を使う。
乱数列の UCBLogo との一致は要求しない。
上限・拒否規則は仕様選択である。

### 6.1 変数

仮引数と `LOCAL "name` で宣言した変数は、宣言された手続きだけから見える。
呼出元の局所変数は見えない。
同名の局所がなければ大域変数を参照する。
`MAKE` も同じ名前解決を使う。
`THING "X` と `:X` は同じ参照である。
存在するが未代入の変数と、未作成の大域変数の参照は実行時エラーにする。

仕様選択として、`LOCAL "name` は手続き内のどこにあっても全体の宣言として先に収集する。
その実行位置では何もしない。
呼出し開始時には未代入である。
`LOCAL` より前にある `MAKE` もその局所へ代入する。
条件分岐の中の宣言も同じである。
同名の二重宣言と仮引数の再宣言は変換エラーとする。
トップレベルの `LOCAL` は許さない。
`LOCAL` の入力は、UCBLogo と同じく引用語の名前とする。
入力は引用語1個に限り、リストによる複数名の宣言は扱わない。
大域名も全文から収集して領域を確保するが、実行中に `MAKE` されるまでは未作成とする。

### 6.2 繰返し、分岐、終了

`REPEAT` の回数は有限値を必要とする。
小数を0方向に切り捨て、負は0回とする。
仕様選択として上限2147483647を設け、超過はエラーにする。
上限は、有限性を検査し、0方向へ切り捨て、負を0とした後の整数に適用する。
例えば `REPEAT 2147483647.9` は2147483647回として受け付ける。
0回には Forth の `?DO` を使い、`DO` は使わない。

`REPCOUNT` はソース上で最も内側に囲む `REPEAT` の番号を1から返す。
囲む `REPEAT` がなければ-1を返す。
呼出先の手続きは呼出元の番号を引き継がない。
呼出先で `REPEAT` の外に書かれた `REPCOUNT` は-1である。
その手続き自身の `REPEAT` の中なら、その番号を返す。
`REPEAT` の回数式にある `REPCOUNT` は、新しい繰返しではなく外側を参照する。
入れ子の本体を `I 1+ S>F` に、範囲外を `-1e` に変換できる。
動的に呼出元の番号を見る UCBLogo とは異なる。

`IF` は命令としてだけ使う。
`IFELSE` は命令位置なら選んだ側の命令列を実行する。
値の位置なら各ブロックをちょうど1個の値式とし、その片方だけを評価する。
その場合、ブロック中の命令列、`OUTPUT`、値が複数ある式は許さない。
`IFELSE TRUE [7] [9]` は値7を返す。
`IF` を値の位置に置いた場合は変換エラーにする。
この制限は仕様選択である。

`STOP` と `OUTPUT` は手続き内だけで使える。
トップレベルでは変換エラーにする。
開いているその定義の `?DO` 1段ごとに `UNLOOP` を生成してから `EXIT` する。
呼出元のループは片付けない。
`OUTPUT` の値はループを片付ける前に評価する。

### 6.3 値を返す手続きと誤用

仕様選択として、手続き本体に `OUTPUT` が1つでもあれば値を返す手続きと分類する。
到達不能な枝も数える。
呼出先の `OUTPUT` は数えない。
`OUTPUT` がなければ命令手続きとする。
値を返す手続きが末尾へ到達した場合、または `STOP` を実行した場合は `-4204` とする。
値のある経路とない経路が混在すること自体は拒否せず、実行された経路で検出する。
命令手続きを値の位置に置くことは変換エラーである。
値を返す手続きや数式を命令位置に置くことは、値の未使用として変換エラーにする。
宣言した数より入力が少ない場合は、閉じ括弧、行末、`END`、ファイル末尾で入力不足として報告する。
余分な値は勝手に捨てない。

## 7. Forth への変換

### 7.1 二段階と名前

第1段階は全文の字句解析と宣言収集である。
手続き名、入力数、本体の範囲、`OUTPUT` の有無、仮引数、局所名、大域名を記録する。
第2段階で固定入力数に従って本体とトップレベルを構文解析し、値位置を検査して Forth を生成する。
すべての宣言を知ってから本体を処理するため、後方定義と相互再帰を扱える。

仕様選択として、手続きは `LG@P0`、仮引数は `LG@A0`、局所は `LG@L0`、大域領域は `LG@G0` のような種類別の十進番号に変換する。
未代入フラグ、末尾更新用の一時値も異なる種類番号にする。
利用者の名前を Forth の定義名・ローカル名に直接出力しない。
LOGO の識別子には `@` を許さない。
`LG@` はライブラリ予約接頭辞とし、処理開始時に生成予定名との衝突があれば失敗させる。
補助語は `LG@AT`、`LG@POLL`、`LG@FD` など別の予約名にする。
ローカル変数は辞書より先に検索されるため、ローカルにも必ず変換名を使う。
`IF`、`DO`、`EXIT`、`FORWARD` などと大文字小文字の違いで区別する設計にはしない。

すべての手続きに、同じ定義先で Sigma の `FORWARD` を先に生成する。
通常の自己再帰には `RECURSE` を使う。
他手続きへの呼出しには番号名を使う。
全トップレベル命令を1個の `:NONAME ... ;` にまとめ、全手続きの完成後に `EXECUTE` する。
ソース中で手続き宣言の前後にあるトップレベル命令は、元の順で連結する。
これはコンパイル専用の制御語をトップレベルでも使うための仕様選択である。

### 7.2 局所、大域、末尾呼出し

仮引数は `{ F: LG@A0 ... -- }` で受け取る。
局所は入口で0を値領域に入れ、別のセルローカルに未代入フラグを持つ。
この0は LOGO の初期値ではない。
参照はフラグを検査してから値を積む。
`MAKE` は `TO` と代入済みフラグの更新へ変換する。
大域は `FVARIABLE` とセルの存在フラグを持ち、`F@`、`F!` で扱う。
仮引数・局所・フラグ・一時値を合わせて Sigma の1定義64ローカルを超える場合は変換エラーにする。
大域変数はプログラムを終了するたびに消し、次回へ引き継がない。

自分自身の呼出しが命令手続きの最後の操作なら、その手続きの `BEGIN ... AGAIN` へ戻す。
末尾の `IF`・`IFELSE` の各枝も末尾位置を引き継ぐ。
値を返す手続きの `OUTPUT self inputs...` も対象とする。
呼出し後の演算がある式と、`REPEAT` 本体の途中は対象にしない。
他手続きへの末尾呼出しは通常呼出しとする。
再呼出しの全入力は左から評価し、一時領域へ保存してから全仮引数へ同時に代入する。
更新前の引数値を後ろの入力から参照できる。
局所の未代入フラグを入口の状態へ戻す。
外側の末尾ループは `BEGIN` であり、`UNLOOP` の対象にはしない。
自然に末尾へ到達する経路は命令手続きなら `EXIT`、値手続きなら `-4204 THROW` にする。
これらの最適化対象の細部は仕様選択である。

### 7.3 語彙と寿命

常駐する `TURTLE`、`LOGO`、描画・変換補助語をすべて先に読み込む。
ライブラリ読込みの開始時に `GET-ORDER`、`GET-CURRENT`、`BASE @` を保存する。
正常時と例外時の両方で `SET-ORDER`、`SET-CURRENT`、`BASE !` により復元する。
`GET-ORDER ( -- wid... n )` の結果は専用の領域へ保存し、データスタックに載せたまま実行しない。

プログラムの開始時にも呼出元の環境を保存する。
検索順は先頭から `LOGO`、`FORTH`、`Root` とし、定義先は `LOGO`、基数は十進とする。
`TURTLE` と `GRAPHICS` は生成コードの検索順には入れない。
タートルの補助別名は、常駐ライブラリの読込み時に正しい実行先へ結び付けておく。
`LOGO` の公開 `FORWARD` も衝突するため、前方宣言を生成する区間だけ検索順を `FORTH`、`Root` とし、定義先は `LOGO` のままにする。
宣言後に `LOGO` を先頭へ戻して本体をコンパイルする。
別途、制御語名が常駐の `LOGO` 語彙で上書きされていないことを読込み時に検査する。

各プログラムの定義の直前に `MARKER LG@PROGRAM` を作る。
翻訳表・バッファの所有者とエラー処理は、このマーカーより前の常駐定義に置く。
プログラム実行中に別のライブラリを読み込まない。
成功、実行中止、変換・コンパイル・実行エラーのいずれでもプログラムのフレームを抜けてからマーカーを実行する。
マーカーをプログラム自身の定義内から実行しない。
これにより次のプログラムまで定義が蓄積しない。
外部の Forth 利用者が並行して定義を追加する使い方は対象外とする。
以上の環境管理と寿命は仕様選択である。

### 7.4 変換の具体例

次は自作の LOGO プログラムである。

```logo
TO BOX :SIDE
  REPEAT 4 [FD :SIDE RT 90]
END

BOX 3
```

`LG@AT ( line -- )` は現在の LOGO 行番号を保存する補助語である。
`LG@POLL ( -- )` は中断を検査する。
`LG@FD ( F: d -- )` と `LG@RT ( F: a -- )` はタートルへ結んだ補助語である。
環境保存とマーカー作成を済ませた後、次の本体を生成する。
次は、同じ行の位置設定、定数回数の検査、重複する中断検査を省いた代表的な形である。
実際の出力には、8章の位置設定と9章の中断検査が同じ意味のまま追加され、この例とバイト単位では一致しない。
実際の出力は `emu/logo/docs/IMPLEMENTATION-1477.md` の7.4節の項に示し、検査はその出力と照合する。
前方宣言の1行だけは7.3節の検索順で評価する。

```forth
FORWARD LG@P0
: LG@P0 { F: LG@A0 -- }
  2 LG@AT LG@POLL
  4 0 ?DO LG@A0 LG@FD 90e LG@RT LOOP ;
:NONAME 5 LG@AT LG@POLL 3e LG@P0 ; EXECUTE
```

行2の1行に複数命令があるため、各命令の間にも同じ行番号を再設定する必要はない。
実際には各ループ反復の先頭にも `LG@POLL` を生成する。
上記の定数4のループでは、各反復の `LG@FD` の入力確認で同じ中断検査を行うため、重複する検査を省いている。
11章の実験は描画補助を計数用の補助に置き換えたものを実行した。
生成される定義・呼出し・浮動小数点ローカル・制御構造そのものを確認した。
LOGO の解析器を実装して生成した結果ではない。

## 8. エラーと後始末

表示は `filename:line: category: message` の1行を基本とする。
category と message は英語とする。
例えば `prog.lg:8: runtime: turtle out of bounds (-4200)` である。
行番号不明は `?` とする。
ファイルを開けない場合も入力として指定された名前を示す。

| 分類 | 検出対象 |
| --- | --- |
| `lexical` | 不正 UTF-8、不正文字、不正数、未完の区切り |
| `translation` | 未知命令、重複宣言、入力不足、値の未使用、値でない手続き、構文制限 |
| `forth-compile` | `EVALUATE` 中の Sigma のコンパイル失敗、資源不足 |
| `runtime` | 領域外、値の範囲、未代入、出力なし、算術、描画・ファイル失敗 |
| `usage` | コマンドラインの誤り |

| LOGO 固有コード | メッセージ |
| ---: | --- |
| -4200 | `turtle out of bounds` |
| -4201 | `invalid input` |
| -4202 | `translation failed` |
| -4203 | `variable has no value` |
| -4204 | `procedure did not output` |
| -4205 | `drawing cancelled` |

語彙衝突、64ローカル超過も `translation` とする。
Sigma と OS のエラー番号は変更せず、必要なら同じ形式に付加する。
Forth 単独利用時のタートルは、同じコードを `THROW` する。
LOGO のファイル名がない場合は `<turtle>:?` とする。

仕様選択として、生成コードの失敗し得る操作の直前に `LG@AT` を入れる。
入力式を評価した後、命令本体を実行する直前には命令の行番号を再設定する。
呼出先へ入ればその手続きの位置に更新する。
呼出しが正常に戻れば呼出元の次の操作で位置を更新する。
出力なしの検査では手続きの `END` または `STOP` の行を設定する。
これにより、最も内側で実行していた LOGO の位置を報告する。
生成断片と LOGO の開始行の対応表も保持する。
`EVALUATE` が断片の内部位置を返さない場合、`forth-compile` は断片の先頭行と「生成された定義の範囲」を示す。
Sigma の `*evaluated string*` だけを LOGO の行番号として扱わない。
起動中・待機中など LOGO の操作位置がない場合は行番号を `?` とする。

常駐側で変換・実行を `CATCH ( xt -- 0 | n )` に包む。
開いた入力・生成出力ファイルは、所有権を記録し、成功・失敗のどちらでも閉じる。
ヒープの翻訳表とバッファは解放する。
所有する画像を解放し、表示ありなら窓を閉じる。
マーカーを実行してから検索順・定義先・`BASE` を元へ戻す。
マーカー自体が検索環境を復元しても、保存した呼出元の状態を最後に適用する。
最初のエラーを保存し、後始末のエラーで上書きしない。
最初にエラーがなければ後始末のエラーを報告する。
`CATCH` はスタックの深さを戻すが内容の完全な復元とは扱わない。
管理用の保存値をそのスタックに依存させない。
失敗した画像や途中まで書いた生成出力を正常な成果物とは扱わない。
強制終了・OS によるプロセス終了の後始末は保証しない。

## 9. 窓と終了

表示ありの開始時に `640 480 WINDOW-SIZE` 相当の希望寸法を設定する。

速度0、描画を含まない再帰、計算だけの繰返しでも確認を続ける。

## 12. 仕様選択の一覧

次の各行は、利用者の決定で固定されていなかった選択と理由である。

| 番号 | 選択と理由 |
| --- | --- |
| S01 | `--emit-forth` は保存後に実行する。実際に実行した変換結果を確認できるためである |
| S02 | ソースの無引数・`-e` は読込みだけ、保存入口の無引数は使用法エラーとする。保存と検査を可能にするためである |
| S03 | 当初は既定のメモリ容量を使い、一般再帰の深さを保証しない。容量測定を行っていないためである |
| S04 | 画素中心の範囲を幅・高さから1を引いて定める。`MLINE` の縦横倍率をともに1にするためである |
| S05 | リサイズは画像を変えず縦横比を保つ。LOGO の座標を窓操作で変えないためである |
| S06 | 境界を半開区間とし、交点で `WRAP` を分割する。重複した位置と画面横断線を避けるためである |
| S07 | `FENCE` は -4200、移動全体を未変更とする。失敗後の状態を一定にするためである |
| S08 | 消去の保持規則、背景変更時の消去、寸法変更時の全初期化を定める。画像と状態の関係を単純にするためである |
| S09 | `ARC` は現在方向から時計回りの折れ線とする。記録にない開始方向を明示し、線描画を共用するためである |
| S10 | 太線は正方形の筆跡、偶数幅は正方向へ偏らせる。画素の期待値を厳密に定めるためである |
| S11 | `LABEL` は横書きでペン上下と幅を無視する。Sigma の `TEXT` を直接利用するためである |
| S12 | 16色の RGB と百分率100の受入れ・四捨五入を定める。UCBLogo の未確認値に依存しないためである |
| S13 | 亀は前10・後6・左右5の輪郭三角形とし、端で複製しない。キャンバスを汚さず表示するためである |
| S14 | 速度1〜1000を表示間隔 ms、既定1、1歩を1命令とする。`FRAME` の意味と対応させるためである |
| S15 | 窓なしの初期化・合成・画像参照 API を分ける。表示なしで画素検査するためである |
| S16 | 寸法2〜4096、幅1〜64、幾何値の絶対値1000000、非有限値拒否を定める。倍率の特異点と過大な処理を避けるためである |
| S17 | UTF-8、識別子、引用語、固定入力、改行、重複名の規則を限定する。二段階解析の受理範囲を確定するためである |
| S18 | 真偽値を数の-1・0と同一視し、条件はその2値だけとする。すべての値を浮動小数点スタックで渡すためである |
| S19 | 演算の優先順位と前置入力の式範囲を固定する。変換結果の曖昧さをなくすためである |
| S20 | `LOCAL "name` を全手続きの宣言として収集する。Forth のローカル宣言は定義の先頭にまとめる必要があるためである |
| S21 | `RANDOM` と `REPEAT` に2147483647の上限を置く。整数変換の飽和を仕様に漏らさないためである |
| S22 | `REPCOUNT` は字句上の最内側だけを見る。レキシカルな今回の指定を、呼出先まで含めて確定するためである |
| S23 | 値位置の `IFELSE` は各枝1式、`IF` は命令だけとする。値数を変換時に検査するためである |
| S24 | `OUTPUT` の構文上の有無で値手続きを分類し、出力しない経路は実行時に失敗させる。相互再帰でも先に署名を決めるためである |
| S25 | 番号付きの `LG@` 名、全手続きの前方宣言、トップレベル全体の無名定義を使う。名前衝突とコンパイル専用構文に対応するためである |
| S26 | 自己末尾位置の枝・直接 `OUTPUT` を最適化し、入力を同時更新する。他の再帰を変えず自己ループの意味を保つためである |
| S27 | 局所・大域の未代入フラグと64ローカルの検査を設ける。未初期化値と資源制限を検出するためである |
| S28 | 生成時の検索順、宣言区間の隔離、マーカーと常駐管理領域の寿命を定める。同名語と後始末による破損を防ぐためである |
| S29 | 英語診断、操作前の行番号保存、断片単位のコンパイル位置を採用する。得られる情報以上の位置を断定しないためである |
| S30 | 最初のエラーを優先し、終了時に画像・ファイル・定義・環境を回収する。次の実行に失敗状態を残さないためである |
| S31 | Esc・閉じる操作は状態0、その他の失敗は状態1、失敗時は窓を保持しない。利用者の中止と失敗を区別するためである |
| S32 | 小画像の全画素を手計算配列と比較し、自作例6種を用意する。実装同士の比較だけで正しさを判断しないためである |

## 13. 対象外

リスト値、リスト処理、`RUN`、実行時のプログラム生成、動的スコープ、対話プロンプトは扱わない。
可変入力、任意入力、残余入力、括弧による入力数変更、利用者による組込みの再定義は扱わない。
`FILL`、`FOREVER`、`SUM`、多亀、消しゴム、反転ペン、画像の LOGO からの読込み・保存命令は扱わない。
色指定と命令ブロックの角括弧はリスト機能に含めない。
互いに呼び合う末尾呼出しの最適化は行わない。
Forth 専用の検査・保存 API は LOGO の言語機能には加えない。
