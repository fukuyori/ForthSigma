# 実例の段階別命令計数（#836・途中結果）

追記：この文書は段階別計数の途中記録。後続の[時間・I/O診断と省略経路の照合](VM_WORKLOAD_NATIVE_DIAGNOSTIC.md)により、限定入力の初回調査#836を完了した。以下は計数実施時点の記録。

2026-11-16。既存の計測専用実行体を使い、前回除外していた段階と追加キー操作を12ケースに分けて実行した。速度測定ではなく、compiled operationの計数である。本体コード・配布設定は変更していない。#836は未完了で、I/O・コンパイルの負担と時間の分離を残す。

| 実例 | ファイル読込み・定義 | BAKE-ALL | 決定的な開始状態生成 | 追加キー操作10反復 |
| --- | ---: | ---: | ---: | ---: |
| pinball | 0 | 246,204,502 | 46,866 | 4,134 |
| waterworks | 576 | 85,549,515 | 6,112 | 66,304 |
| klondike | 0 | 163,008,831 | 26,000 | 680,999 |

読込み列の0は負担がないことを意味しない。直接解釈・コンパイラー・native内部の実行はcompiled-PC計数の対象外である。src/main.zigはファイル引数をincludeFileへ渡し、src/core/source_input.zigではopen後にinterpretIncludedFile、終了後にcloseする。したがって、この引数境界の観測は読込みと解釈・コンパイルが混ざっており、それぞれの時間は分離できていない。REQUIRE-GRAPHICSによる埋込みライブラリーの処理も含む。

BAKE-ALLの計数は前回の6ケースから除外されていた。資産生成で多数のVM命令が実行されることは確認したが、通常操作より時間を使うという結論ではない。各段階の実行回数も異なるので、合算平均や速度効果の順位は算出しない。

開始状態生成は前回と同じBUILD-WALLS/固定SEED/NEW-GAME、固定SEED/NEW-RUN、固定番号START-DEALであり、NOWを含むINIT-GAME全体ではない。追加キー操作はpinballのpause/restart、waterworksの移動/配置/pause/restart、klondikeのdraw/undo/hint/draw-mode/restartをKEY!経由で実行した。実入力のpolling、マウス、表示、音声、FRAME待ち、勝利等の全分岐は対象外。

初回のklondike追加操作はD-SRCの初期値0によりKEY!が早期終了し、1,114命令だった。INIT-GAMEにある-1 D-SRC !と-1 HOVER !をsetupへ補い、680,999命令となった。初回script・結果を証拠へ残す。これで全キー分岐の網羅性を証明したとは扱わない。

全12ケースで採用済みWindows基準版と計測版のstdoutが一致し、計測版2実行の全PC回数も一致、各exit0。深さの出力は全件0。stdoutには従来同様の名前重複警告がある。状態確認は限定的で、全資産・ゲーム状態の一致検査ではない。計数方法・resetの対照確認・限界は[前回の記録](VM_WORKLOAD_OPERATION_PROFILE.md)を引き継ぐ。

2R@/2R>/DNEGATEは今回のcompiled call siteでも0。-ROTはBAKE-ALLで905/49/1,572回、それぞれ0.000368%/0.000057%/0.000964%であり、他の9ケースは0だった。native内部や動的経路までの不使用は保証しない。今回の追加範囲から、これら局所特殊化を最優先へ戻す根拠は得られていない。
