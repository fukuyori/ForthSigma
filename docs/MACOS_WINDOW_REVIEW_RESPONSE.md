# macOSネイティブウィンドウ（#975・#922）のレビュー対応

2026-11-17。[Codexレビュー原文](MACOS_WINDOW_CODEX_REVIEW.md)への対応。指摘はソースと照合してから採否を決めた。

| 指摘 | 照合 | 対応 |
| --- | --- | --- |
| 1 キュー満杯時にキー解放を捨てる | 指摘どおり。親の`enqueueInputLine`は満杯なら種別を見ずに捨てていた。満杯になるのは、親が読まない間に子の通知がパイプにたまり、次の`SHOW`の応答待ちでまとめて取り込むとき | 修正。マウスの移動は直前の移動に上書きしてキューを埋めない。満杯のとき新しいキー・文字は捨てるが、キー解放とマウスボタンの変化は、解放以外で最も古いイベントを外して入れる |
| 2 子の入力通知の部分書き込み | 一部相違。`INPUT`行は最長495バイトでPIPE_BUF（512）以下なので、待たない書き込みは行の全体か失敗のどちらかになり、行が途中で切れることはない。ただしパイプが満杯のとき行ごと捨てていたのは指摘どおりで、キー解放も失われうる | 修正。キー解放、マウスボタンの変化、閉鎖時の通知は、書けなかったら子が保持し、次の通知やフレーム応答の前に順番どおり送る。移動・文字・変換中文字列は従来どおり捨てる |
| 3 HANDOFFの要約に合成試験の限定がない | 指摘どおり。制限は別の項に書いていたが、要約の箇条からは読み取れなかった | 修正。要約の箇条に、閉じる操作と`SHOW`の競合は合成クリックの試験で確認したものと書いた |
| 4 旧辞書を拒否する検査が特定されていない | 指摘どおり。記録は推定だった | 確認して記録を直した。`src/core/image_format.zig`の`layoutSignature`は`Builtin`の全項目の名前と値をハッシュに含め、`parse`がヘッダーのオフセット104の値と比べて違えば`InvalidImage`を返す。直前のリリースと今回のビルドで保存した辞書は、この8バイトがすべて違っていた |
| テストの抜け（親子プロトコルの異常、満杯キュー、部分書き込み） | 指摘どおり、自動テストはない。`src/host_window_macos.zig`は実ウィンドウと子プロセスが要り、単体テストの偽ホストでは動かない | 自動テストは追加していない。下の合成イベントの試験で確かめた |

修正後の確認（macOS 27.2 arm64、`zig build`の作業ツリー）：

- 親が14秒計算する間に、合成イベントでマウス移動9,000回と左クリック200回を送り、その後の`SHOW`の後で`MOUSE-EVENT`を数えた。修正前の比較ビルドは押下0・解放0（すべて失われた）、修正後は押下32・解放32（コアが保持する64件の上限）で、ボタンの状態はどちらも0。
- 同じ試験でキー`a`を押したままにして最後に離した。`KEY-HELD?`は修正前も修正後も偽で、キー解放の取りこぼしそのものは修正前のビルドでも再現できていない。
- `zig build test`、`-Dgraphics=false`とx86_64 macOSのビルド、親のシグナル終了・`BYE`・期限切れ後の再表示、閉じる操作と`SHOW`の競合、Tkとのパイプ継承の試験をやり直し、結果は修正前と同じだった。
- 利用者によるIMEと物理マウスの確認は、この修正の前に行ったものである。修正後は合成イベントでクリックの押下・解放が届くことを確かめ、その後、利用者の操作でホイールの通知と、計算中に閉じたウィンドウが開き直ることを確かめた（検討書10.13）。IMEも修正後のビルドで利用者が確認し直した（「日本語」9 bytes、`E6 97 A5 E6 9C AC E8 AA 9E`が端末ログに出て、変換中の表示は利用者の回答「問題なし」）。
