# リポジトリ内実例のVM命令頻度（#805）

2026-11-16。実例のロジックと描画を分けた6ケースを実行した。**速度測定ではない。compiled operationの頻度から、次に負担を調べる対象を選ぶための限定的な調査である。** 実際の利用全体を代表するとは扱わない。

各実例の既存NO-AUTORUN/NO-SOUNDを使い、GUIの入力・表示・FRAME待ち・音声を実行しない。既存の処理関数を操作模擬のスクリプトで呼んだ。ロジックはpinball 600tick、waterworks 600tick、klondikeのHINT/AUTO-STEP/STEP-FLIGHTSを120反復。描画は各20フレーム相当のRENDERと状態更新で、表示はしない。RENDERに必要な画像生成は実行前のsetupで完了させた。

採用済みWindows実行体による出力と、作業用計測版による出力を全ケースで比較し一致した。計測版は各2回実行し、全PCの回数と出力が同一だった。出力はスコア・位置・状態・ピクセル等の限定したチェックサムとDEPTHであり、全状態・全画面の一致を保証しない。

## 計数方法と検証

既存--profileのop_countsをPC別に出力する処理と、host引数境界でのresetを作業用コピーに追加した。通常--profileが強制するplain_callsを外し、通常のコンパイル時インライン選択を維持するコードへ変更した。これはコード読解による確認で、基準版と全コンパイル結果を比較した検査ではない。ただしProfileを有効にするので実行はcounted経路となり、通常の非counted実行の速度を表すものではない。本体は変更していない。

ファイル読込み、コンパイル、画像・初期状態生成が済んだ引数境界でresetし、その後のWORKLOADと終了行のcompiled命令を計数した。直接native組込みとして実行される終了処理はcompiled-PC計数対象外。終了行がcolon語を呼ぶ場合はそのcompiled命令も入るため、WORKLOADのみという範囲は終了行の実装に依存する。全PC回数合計とProfile.operationsの一致は、同じ加算処理から得る値の整合確認であり、出力・解析の欠落検知に使った。独立した計数の正しさの証明ではない。2回一致も決定性の確認で、系統的な誤りを否定しない。最初の専用プローブは2R@/2R>/DNEGATE/-ROT各10回でラベルと出力を確認したが、reset前にcompiled命令を実行していないためresetの実証ではなかった。レビュー後、reset前7回と後10回を実行する対照を追加し、resetなし各17回、resetあり各10回になることを実測した。

集計するのはprimitiveタグ、およびcall_builtin/builtinタグから分かる組込み語のcompiled call siteである。native関数内部の呼出し、直接の解釈実行、動的呼出しからnative組込みへ入る全経路の回数を網羅するものではない。SYNONYM/DEFERから組込みに入るcallタグは語別に分離していない。0という値もこの計数範囲での結果に限定する。今回の6ケースではexecute/local_executeの実行は0であったが、他の動的経路がないことの保証にはしない。ゲームの起動・コンパイル・資産生成・I/Oの時間や、表示付きの実操作性能は測っていない。

## 次の調査対象

表のメモリーprimitive5語だけで各ケースの2.496〜14.407%を占めた。全メモリー操作の集計ではない。よく実行されるという根拠はあるが、範囲検査・登録アドレス照会のどの処理が時間を使うかは未確認である。既定の小規模候補の順を維持し、次は#792でfetch/store等の実装と検査の経路を調べる。これが全ケースで最頻という意味ではなく、全候補の効果順位を確定した判断でもない。local_fetch/call等を含む順位比較は#806に残す。検査の省略を前提にせず、頻度と検査コストを分けて確認する。

またlocal_fetchやcall/call_colonも多い。callにはデータ語とinline marker等が含まれ得るため、単にcallの全数をヘルパー呼出し数と見なさない。これらの負担は候補台帳の再順位付け#806で比較する材料とする。

2R@/2R>/DNEGATEの0と-ROTの低い比率を根拠に、今回の範囲では局所試作の追加を後回しにする。使用頻度や特定の利用での遅さが新たに確認されれば再評価する。実例の追加経路、起動・資産生成・I/Oの分離計測は残件で、#805全体の調査完了とはしない。

## レビュー後の確認

全ケースのstdoutには名称重複の警告が2〜3回あり、基準/計測版で同じだった。対象名は警告本文から特定していない。stderrのprofileや終了コードのエラーとは区別して保存した。計数scopeより前のsetupにある語の使い方や、選んでいない操作では結果が変わり得る。
