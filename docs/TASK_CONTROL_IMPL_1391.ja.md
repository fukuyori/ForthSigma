# tque 1391・1392・1393：単一VM実行時間の本測定と判定

2026-11-26、main `333f8af`〜`4c666ee`（runnerは1402・1403の変更を含む。製品のsrc/・build.zigは`333f8af`から変わっていない）。時間の測定はレモンの指示（2026-11-26「時間測定は、いつ開始してもよい」）で行い、他のアプリは止めていない。[英語版](TASK_CONTROL_IMPL_1391.md)も参照。

## 1. 判定の方法（レモンの決定、2026-11-26、案1）

時間の比較は、配置とrunによる揺れ（±2〜10%）が目安の中央値+1%・p95+2%より大きく、[1390の手順書](TASK_CONTROL_IMPL_1390.ja.md)の規則で**判定不能**とする。合否は、通常ループの機械語をB（現在のソース）とA'（Bからworkerの入口の判定だけを除いた対照）で比べて判断する。Linuxでは、レモンが`kernel.perf_event_paranoid`を2にした後、命令数（`perf stat -e instructions:u`）を補助の材料として採った。

## 2. 時間の測定（判定不能）

5負荷（CALC、XT、DEFERRED、INTERPRET、byte-scan）、各対照warmup 5回・本標本100回・反復10,000,000回、独立2run。区間は親の解放からDONE行の受信まで。B/Aの中央値の増加率は次のとおり。

| OS・配置 | CALC | XT | DEFERRED | INTERPRET | byte-scan |
|---|---:|---:|---:|---:|---:|
| Windows base run1/run2 | +0.10 / −0.56 | −3.4 / −3.6 | −2.2 / −2.3 | −2.0 / −1.7 | −4.3 / −4.2 |
| Linux base | +5.6 | −13.7 | −6.6 | −1.1 | +0.3 |
| Linux hot16 | −5.2 | −13.2 | +7.3 | +4.0 | −10.6 |
| Linux hot32 | +2.5 | −12.4 | −4.7 | +1.4 | −5.3 |
| Mac base run1/run2 | +2.1 / −2.3 | −2.5 / −1.7 | −4.6 / −3.9 | −1.2 / −1.6 | −5.4 / −4.3 |
| Mac tail64 run1/run2 | −1.1 / −2.1 | −1.6 / −1.4 | −4.3 / −5.2 | −0.6 / −1.0 | −5.2 / −6.0 |

（単位%。Linuxはrun1の値で、run2もほぼ同じ値だった。tail64はbaseとほぼ同じ値のため省いた）

- Linux：配置を変えると符号が入れ替わり、run1とrun2で同じ値が再現した。揺れは配置で決まる。
- Mac：同じ配置でもrunでCALCの符号が入れ替わった。配置は2通り（runOperationsの64byte境界からの位置20と28）しか作れなかった。
- Windows：全負荷が目安内だったが、配置の変種でもコードの位置が動かなかった（[1403](TASK_CONTROL_IMPL_1403.ja.md)）。A'はBと同じ通常ループを160 bytesずれた位置に持ち、CALCで+50%遅かった。配置の影響は目安よりはるかに大きい。

証拠：Windows `.work/1391-prepared`・`.work/1391-run{1,2}`、Linux `.work/1391-prepared-linux`・`.work/1392-run{1,2}`・`.work/1392-layout-*-run{1,2}`、Mac `.work/1393-prepared`・`.work/1393-run{1,2}`・`.work/1393-layout-*-run{1,2}`。

## 3. 通常ループの機械語の比較

[single-vm-compare-function.py](../tests/scripts/single-vm-compare-function.py)で、関数の範囲を逆アセンブルし、番地・記号名・即値の数字を置き換えてから、命令の並びを比べた。違うはずの組（LinuxのAとBのrunOperations）では2,531行の差を検出し、道具が違いを見落とさないことを確かめた。

| OS | executeWordMode（通常） | runOperations（通常） | executeBuiltin |
|---|---|---|---|
| Windows | 497命令、差0 | 1,905命令、差0 | 4,777命令、差0 |
| Linux | 454命令、差0 | 2,200命令、差0 | 4,787命令、差0 |
| Mac | 353命令・438命令、差0 | 1,813命令・105命令、差0 | 6,098命令、差0 |

Linuxで全関数（1,717個）の大きさを比べると、BでA'と違うのは、独立した関数になった`executeWord`（Windows 81 bytes、Linux 97 bytes）と、それを呼ぶ解釈系の関数（`handleWord`、`wordInLoop`、各語群の`execute`など）、およびworkerのループ（単一VMでは通らない）だけだった。

## 4. 命令数（Linux、補助）

[single-vm-count-instructions.py](../tests/scripts/single-vm-count-instructions.py)で、N=1,000と10,000,000を各3回数え、差から1反復あたりの命令数を求めた。起動と定義の分は打ち消し合う。3回の値の揺れは数命令以内。証拠は`.work/1392-perf/instructions-tool.json`（Linux機）。

| 負荷 | A | A' | B | B/A | B/A' |
|---|---:|---:|---:|---:|---:|
| CALC | 223 | 214 | 214 | −4.0% | 0 |
| XT | 220 | 204 | 204 | −7.3% | 0 |
| DEFERRED | 214 | 197 | 197 | −7.9% | 0 |
| INTERPRET | 1,624 | 1,618 | 1,630 | +0.37% | +0.74%（+12命令） |
| byte-scan | 293 | 276 | 276 | −5.8% | 0 |

入口の判定が実行されるのは、解釈を通るINTERPRETだけで、1反復（`S" 1+" EVALUATE`）あたり12命令だった。時間ではBがAより5.6%遅かったCALCも、命令数ではBが4.0%少ない。時間の差が配置によることの裏付けになる。

## 5. 判定

- 3 OSとも、workerの入口の判定は通常ループの機械語に何も加えていない。単一VMの通常の経路は、案1の基準で**合格**とする。
- 時間の比較は**判定不能**（配置とrunの揺れが目安より大きい）。
- 判定の範囲：AとBの通常ループは機械語が大きく違う（W1以後の他の変更を含む）。案1の基準はBとA'の比較なので、この差は判定に含めない。Linuxの命令数では、B/Aは全負荷で+0.37%以下だった。
- Windows・Macの命令数は採っていない。機械語が一致しているので、通常ループで実行される命令の数はA'とBで同じになる。
