# Zig implementation notes

## Architecture

The runtime uses 64-bit cells, a separate 64-bit (IEEE binary64) floating-point stack, and a 2 MiB logical byte memory whose upper half holds the `ALLOCATE` heap and the local-variable frames. Cell and float reads and writes use little-endian 8-byte layout. The dictionary is a bounded host-side table; colon definitions compile into a small host-independent operation stream. The operation stream represents calls, integer and float literals, branches, loops, and string output. No Z80 opcodes or machine addresses are executed.

`State` owns the interpreter and receives output through a callback. The command-line adapter uses C standard input and output so the language core does not depend on a particular terminal API. File storage, cassette commands, the PC-8001 line editor, and CP/M monitor calls are outside this scope.

The FORTH/Σ source articles define a 16-bit system. Since stage 1 of the gforth-alignment work (2026-10-28), cell width, truth values, division, output spacing, name identity, and `TYPE` follow gforth instead; see [DECISIONS.md](DECISIONS.md). FORTH/Σ-specific words that do not conflict with gforth are retained.

## Z80 listing correspondence

The June 1982 source article describes the main path used for the port:

- `START` establishes the parameter stack and system pointers.
- `READ` obtains a token, `DSRCH` searches the linked dictionary, and the numeric-check/conversion routines (`NTEST`, `CNVRT`) recognize numbers using `BASE`.
- `MAKE` adds a dictionary header for a new definition. `CCOLON` and the control-word handlers compile calls, literals, and patched branch destinations.
- `FLER` handles parse/compile errors and abandons an incomplete definition.
- The compiler emits Z80 subroutine calls and machine-code branches. This implementation preserves the language-level call and branch behavior in a host-independent operation stream instead.

These routine names and relationships come from the source-list explanation in the June–July 1982 source articles, magazine pages 92–99 and 178–185 (*Encyclopedia ASCII* Vol. 12, ASCII, June and July 1982). The byte-for-byte Z80 layout is intentionally not reproduced.

- `SAVE filename` writes a versioned dictionary image (`SIGIMG33`, or `SIGIMG34` once the graphics words were loaded). `LOAD filename` appends its user definitions to the current dictionary. These portable dictionary operations differ from the magazine editor-buffer commands with the same names. `SIGIMG32` images (0.4.0) are still read. Images written by earlier versions (`SIGIMG01` to `SIGIMG31`) are rejected with `INVALID IMAGE !`. ## Deliberate implementation choices

### Behavior aligned with gforth

The gforth source tree (`D:\home\source\forth\gforth`, GPLv3) was read for behavior only; no gforth code is copied into this MIT-licensed project.

- Cells are 64-bit two's-complement and wrap on overflow. A true flag is `-1` (all bits set); false is `0`.
- `/`, `MOD`, and `/MOD` use floored division, matching gforth's default aliases (`kernel/main.fs`: `/f`, `modf`, `/modf`). Division by zero is an error (`DIVISION BY ZERO !`). The minimum integer divided by `-1` returns the minimum integer with remainder 0.
- Tabs separate tokens like spaces, CR, and LF, as in gforth; the magazine lists only space and CR as delimiters.
- Names are matched by their full length without ASCII case distinction. The FORTH/Σ five-character identity rule is no longer used.
- `.`, `U.`, `?`, and `C.` append one space. Numbers are signed in every base and are not zero-padded. `.S` prints `<depth> ` followed by each item.
- `TYPE` takes `( addr u )`. The original `"` word therefore now pushes the address followed by the length.
- `LEAVE` is compile-only and leaves the loop immediately. `UNLOOP` drops the innermost loop frame so that `EXIT` can be used inside a loop.
- Number input accepts the prefixes `$` (hex), `#` and `&` (decimal), `%` (binary), and `'c'` character literals. `BASE` may be 2 through 36.
- Floating-point literals follow gforth's `rec-float` (`float.fs`): `BASE` must be decimal and the token must contain `e` or `E` (`1E`, `1.5e0`, `.5E`, `-2.25E+1`, `0.e`).
- Integers containing a `.` anywhere among their digits are double-cell numbers, following gforth's `s>unumber?` (`kernel/int.fs`): `1.5` is the double 15 and `12345.123` is 12345123. The position of the dot is not recorded (`DPL` is not implemented). A `-` may precede or follow a base prefix (`-$10`, `$-10`).
- Single-cell literals that exceed 64 bits wrap; double-cell literals wrap at 128 bits.
- Pictured numeric output uses a hold area at `0x1000`–`0x1FFF` that grows downward, like gforth's `holdptr`/`holdend` (`kernel/nio.fs`). `<<#` and `#>>` nest up to 16 levels; `<#` resets all levels. Overflowing the area or an unmatched `#>>` raises `PICTURED NUMERIC OUTPUT ERROR !`.
- `PAD` is a fixed 4096-byte area at `0x2000`.
- `S"` and `S\"` used while interpreting store each text in a block of its own in the `ALLOCATE` heap, which is never freed, as gforth 0.7.9 keeps them: every interpreted string stays valid (the four 256-byte buffers at `0x3000` that an earlier version used in turn are no longer used, and stay so that `PAD` keeps its size). Inside a definition they compile the text into the data area. These strings, `.\"`, and `.(` may be up to 255 bytes; the FORTH/Σ `"` word and `."` keep the 127-byte limit.
- `S\"` and `.\"` accept the gforth escapes `\a \b \e \f \l \m \n \q \r \t \v \z \" \\` and `\xHH`; `\n` is a line feed. Other escaped characters stand for themselves.
- `2!` stores the high cell at the lower address, as in Forth 2012, so `CREATE X 2 CELLS ALLOT 12345678901234567890 1 X 2! X 2@ D.` prints `30792422974944119506`.
- `S>NUMBER?` returns a double and a flag for single and double syntax. `>FLOAT` accepts decimal text with or without an exponent and treats a string of blanks as zero.
- `ACCEPT` reads one line from the host input. `KEY` reads one byte; `KEY?` reports whether a byte is available. The command-line host implements `KEY?` by reading one byte ahead, so in an interactive terminal it waits for input instead of returning false immediately. With piped input it returns false at end of input.
- `F.` prints 15 significant digits without an exponent, removes trailing zeros, and appends a space (`3.`, `0.5`, `0.00001`, `100000000000000000000.`), following gforth's `f.` with the default precision 15. Infinity and NaN print `infinity`, `-infinity`, and `NaN`, following the portable `represent` in `engine/support.c`. gforth cuts these names to `PRECISION` characters (`infini` for `1e 0e F/ F.` with a precision of 6, `Na` for NaN with 2), also in `FE.` and `FS.`; Sigma prints them whole. With the default precision of 15 the output is the same. The user accepted this difference on 2026-11-02.
- `F.S` prints `<depth> ` and each item with up to 14 significant digits and an `e` marker (`1e`, `.5e`, `1e-7`, `-3.25e`, `1e30`), following gforth's `f.s` / `e.p` (`stuff.fs`, `edot.fs`). Older gforth releases and the ForthBasicMaster book show a different `F.S` format.
- Float comparisons push `-1`/`0` on the data stack. `F/` follows IEEE 754 (division by zero yields infinity or NaN; no error).
- `WITHIN ( n lo hi -- flag )` compares `n-lo` and `hi-lo` as unsigned numbers, like gforth (`kernel/prim.fs`), so ranges may wrap around.
- `PLACE` stores at most 255 bytes, like gforth's `place` (`stuff.fs`). It copies with overlap handling and writes the length byte afterwards; a negative length is treated as 0.
- `ABORT` clears the stacks without any message or ` OK`, as gforth's interactive `abort` does. It also unwinds out of `EVALUATE`.
- `STATE` is the cell at `0x0208`. Every change of the compiler state (`:`, `:NONAME`, `;`, `[`, `]`, error recovery, image restore) writes `-1` or `0` there, so a saved `STATE` address reads the current state. Storing into it does not change the compiler state.
- `:NONAME` creates an unnamed colon definition and pushes its execution token when it starts. Unnamed definitions are skipped by `WORDS` and by name lookup.
- `PAGE` writes `ESC[2J ESC[1;1H`, the same sequence as gforth. On Windows the host enables virtual-terminal processing on the console at startup.
- `MS`, `UTIME`, `GETENV`, and `SYSTEM` call host callbacks; without them they raise `HOST FUNCTION UNAVAILABLE !`, and a failing host raises `HOST FUNCTION ERROR !`. `MS` treats a negative count as 0. `UTIME` returns microseconds since the Unix epoch as a double. `GETENV` copies the value to `0x3400`–`0x3FFF` (3072 bytes, valid until the next `GETENV`) and returns `( c-addr u )`; an unset variable gives `0 0`, and a longer value raises `STRING TOO LONG !`. `SYSTEM` uses the C library's `system` (`cmd.exe /c` on Windows, `/bin/sh -c` elsewhere) for commands up to 4095 bytes; a command containing NUL is rejected before it runs, because `system` would execute only the text before the NUL; a non-zero exit status is not an error, and gforth's `$?` is not implemented.
- `THROW` does nothing for 0 and acts as `ABORT` for -1. A code that belongs to an interpreter error raises that error again; any other uncaught code is reported as an error and clears the stacks. `-13` prints `UNDEFINED WORD !`, I/O results name the C error (`NO SUCH FILE OR DIRECTORY !`), and other codes print `ERROR #n !` in decimal, like gforth's `error #n`.
- `CATCH` runs an execution token and pushes 0, or the code of the exception it caught. It restores the depths of the data, float, return, loop, and control stacks, the pending parse state, and the compiler state; values below the restored depths are not restored, as in gforth. A definition started inside the caught word is abandoned. Interpreter errors are caught too and return Forth 2012 codes where one exists (-4 stack underflow, -9 invalid address, -10 division by zero, -13 undefined word, -45 float stack underflow, …) and system codes from -256 down otherwise. The results matched gforth for the cases in the core tests.
- File words use host callbacks (C stdio in the command-line host). Results follow gforth: `ior` is 0 or -512 minus the C `errno` (-514 for a missing file). `R/O`, `R/W`, and `W/O` are 0, 2, and 4 as in gforth; other values give -534. `STDIN`, `STDOUT`, and `STDERR` are the ids 1, 2, and 3, and opened files are numbered from 4 (up to 64 at once). `OPEN-FILE` with `W/O` does not truncate an existing file; `CREATE-FILE` creates or truncates. `WRITE-LINE` appends CR LF on Windows and LF elsewhere, as the Windows gforth build does. `READ-LINE` accepts LF, CR, and CR LF, splits lines longer than the buffer, returns a last line without a terminator, and then returns `0 0 0`, following gforth's `read_line` (`engine/support.c`). `STDIN` reads through the same terminal input as the interpreter. `READ-FILE` and `SLURP-FILE` read the bytes as they are. On Windows, piped or redirected standard input is switched to binary mode at startup, so `READ-FILE` and `KEY` see CR, Ctrl+Z, and every other byte as on the other systems; a console keeps text mode, where Enter gives a single LF. Open files are closed when the program exits. Non-ASCII file names on Windows have not been verified.
- `ALLOCATE`, `FREE`, and `RESIZE` manage a heap at `0x100000`–`0x1DFFFF`. Each block is preceded by a size cell and a used cell; allocation is first fit, freed neighbours are merged, and a free block at the end returns to the heap top kept at `0x0210`. Because this bookkeeping lives in logical memory, a `SAVESYS` executable or a full image restore keeps heap contents; `LOAD` does not bring heap contents into the target dictionary. Failures return gforth's `-524` (ENOMEM); an address that was not allocated gives `-534`. `FREE` accepts 0, and `0 n RESIZE` allocates.
- Dynamic strings use gforth's layout (`kernel/stringk.fs`): a string variable holds 0 or the heap address of a buffer whose first cell is the length. `$!`, `$@`, `$@LEN`, `$!LEN`, `$+!`, `C$+!`, `$.`, `$DEL`, `$INS`, `$OVER`, `$FREE`, `$INIT`, `$SPLIT`, `$ITER`, and `$TMP` follow gforth, as do the string arrays `$[]`, `$[]!`, `$[]@`, `$[]#`, `$[].`, `$[]MAP`, `$[]FREE`, `$[]SLURP`, and `$[]SLURP-FILE` (`string.fs`). Growing a string zero-fills the new bytes. A source that lies inside the destination string is copied out first, so `S $@ S $+!` works. `$DEL` limits the count to the remaining characters; gforth instead truncates more than it deletes when the count is too large. `$TMP` collects the output of TYPE, EMIT, and the number words into one of 16 rotating temporary strings; output of `SYSTEM` commands and `STDOUT` file writes is not collected.- Every word belongs to a word list (Forth is 1, Root is 2, `WORDLIST` and `VOCABULARY` allocate 3 and up to 64). Lookup goes through the search order (up to 16 entries, first-searched first, each list searched once); new words go into the current list. The start-up order is gforth's `Forth Forth Root` with Forth current. `FORTH`, `FORTH-WORDLIST`, `ONLY`, `ALSO`, `PREVIOUS`, `ORDER`, `DEFINITIONS`, `GET-ORDER`, `SET-ORDER`, and `WORDS` are in both Forth and Root; `ONLY` leaves `Root Root`. `ORDER` prints the order, four spaces, and the current list in gforth's format, naming lists `Forth`, `Root`, a `VOCABULARY`, or a constant that holds the id. `WORDS` lists the first-searched list. Overflow and underflow raise -49 and -50. The count, current list, and order live at `0x0220`-`0x02B7`, so images keep them; `LOAD` renumbers the loaded image's own lists. Parsing words such as `:` and `TO` belong to no list and always work. `MARKER` also restores the current list and the search order.
- `[IF]` skips words up to the matching `[ELSE]` or `[THEN]` when its flag is zero, counting nested `[IF]`s and reading further lines; `[ELSE]` skips to the matching `[THEN]`. They are immediate and work while compiling. An `[IF]` left open at the end of an `EVALUATE` string is a control-structure error.
- `INCLUDED` opens a file read-only through the host file operations and interprets it line by line, with one 4096-byte line buffer per nesting level at `0x1E1000` (8 levels). File names are relative to the current directory; gforth's `fpath` search is not implemented. A parsing word that needs another line reads it from the same file. Each file is closed exactly once on every path, and an error is reported with the innermost file name and line (`b.fs:2: MISSING ?`). A definition or parsing word left unfinished at the end of a file raises `DEFINITION ERROR !`; the check compares the word being defined, so a file that ends the caller's definition and starts another is caught. A parsing word such as `VARIABLE` left waiting for its name at the end of an `EVALUATE` string is an error too, and nested files and `EVALUATE` strings keep the word that a pending `DOES>` attaches to. Like gforth, `INCLUDE` and `REQUIRE` record a file in the REQUIRE history when it opens; `REQUIRE`, `REQUIRED`, and `NEEDS` skip names already recorded, compared as written. The table of up to 64 names lives in logical memory at `0x1E9000` (count at `0x0218`), so `SAVESYS` keeps it, and `LOAD` merges it and renumbers word locations. `SOURCEFILENAME` gives `*the terminal*` or `*evaluated string*` outside files; `SOURCELINE#` is 0 there.
- Each word records the file and the lines where its definition starts and ends; `LOCATE` prints `file:line` and up to 20 lines read again from the file. `MARKER name` keeps the set of loaded files as a 64-bit mask; running it removes itself and later words and restores that set, so `REQUIRE` loads later files again. Table entries are never removed, so the file names that words and open input frames refer to stay valid; the heap is not restored.- Terminal input lines are copied to a 4096-byte terminal input buffer at `0x1E0000` before they are interpreted, so `PARSE` can return an address inside the input as gforth does; an `EVALUATE` string is interpreted where it lies. Only terminal input reads further lines when a parsing word (`CREATE`, `{`, ...) needs one; an `EVALUATE` string never reads past its end. A token consumes the one separator after it, as gforth's `parse-name` does, so `PARSE` and the text of `S"` and `."` start right after that separator.
- `WORD` skips leading delimiters and returns a counted string of up to 255 bytes in a buffer at `0x0C00`, valid until the next `WORD`; a blank delimiter also matches tabs and line ends. `PARSE` returns the text up to the delimiter as an address in the input. Neither crosses the current line. `FIND` returns 1 for immediate words and -1 otherwise; parsing words such as `:`, `TO`, and `{` are not dictionary entries and are not found. A name token is the dictionary index plus one. `NAME>STRING` copies the name to one of eight 256-byte buffers at `0x0400`, used in turn.
- `SEE` decompiles a colon definition from its operations into the form shown in the book (`: SQUARE` / `  DUP *` / `;`). Branches that form `IF ELSE THEN`, `BEGIN UNTIL`, `BEGIN AGAIN`, and `BEGIN WHILE REPEAT` are shown as those words, the `DO` loop words come from their own operations, other branches appear as `BRANCH n` or `?BRANCH n`, `CASE` appears as nested `IF`s, and locals as `L#n`. Built-in words show `BUILT-IN name`; variables, constants, values, and `CREATE`/`DOES>` words show their kind.- Locals follow gforth's `{ ... }` (`glocals.fs`), the standard `{: ... :}`, and `LOCALS| ... |`. In `{ }` the last name takes the top of the stack, names after `|` start at zero, and `--` starts a comment. The type prefixes `W:` `D:` `F:` `C:` `XT:` give value-flavoured locals (the name pushes the value, `TO` changes it, and an `XT:` name executes its token); `W^` `D^` `F^` `C^` `XT^` give variable-flavoured locals whose name pushes an address. `LOCALS|` gives its first name the top of the stack, as in gforth. Locals may be declared anywhere in a definition, also inside loops (the slot is reassigned each time). Names shadow dictionary words and follow gforth's visibility rule: a name is visible only where every path passes its declaration. So names declared inside `IF` are not visible in the `ELSE` part or after `THEN`, names declared after `WHILE` or inside `?DO` are not visible after the loop, a `LEAVE` before a declaration hides it after the `LOOP`, an `OF` branch's names end at `ENDOF`, while names declared in a `BEGIN ... UNTIL` or `DO ... LOOP` body stay visible after the loop. The check follows the structured words; `EXIT` and the like are not taken into account, so a name may be hidden where gforth would still show it. `DOES>` starts a new scope. Each invocation gets its own frame in `0x1F0000`–`0x1FFFFF`, allocated when it first runs a declaration and released on every exit path, so recursion works and `>R`/`R>` do not interfere with locals. Running out of frame space raises `RETURN STACK OVER FLOW !`.- `F.RDP` ( rf +nr +nd +np -- ), `F>STR-RDP` ( rf +nr +nd +np -- c-addr nr ), and `F>BUF-RDP` ( rf c-addr +nr +nd +np -- ) format into a field of nr characters. Fixed-point notation with nd digits after the point is used when nd plus the decimal exponent of the value reaches np (always when np is 0) and the integer part and sign fit; the result is right-aligned and the leading 0 of a value below 1 is dropped when there is no room (`.500`). Otherwise exponential notation (`1.23E5`) fills the field exactly, or asterisks when no mantissa digit fits. Rounding is exact on the binary value with ties to even (`2.675` gives `2.67`), computed with big integers because `std.fmt` rounds the shortest decimal form; a value whose first digit lies below the last shown place rounds to one unit only when twice the value exceeds that unit, as gforth does (`0.0005` shows as `0.000` with 3 places). Infinity and NaN are truncated or padded on the right. `F>STR-RDP` writes below the pictured numeric output in the hold area. Fields are limited to 4096 characters. These rules come from gforth's documentation and 79 observed gforth outputs; no gforth code was copied.
- `F>S` truncates toward zero; NaN converts to 0 and out-of-range values saturate to the minimum or maximum integer. This range handling is a portable choice; gforth leaves it to the C conversion.

### FORTH/Σ behavior retained

- Decimal is the source-defined initial base. `HEX`, `DEC`, and `OCT` remain; `DECIMAL` is an alias of `DEC`.
- The original `"` word is compile-only and stores strings up to 127 bytes. `."` is retained as a convenience extension.
- `DO` always enters the body once, including when start equals limit. For regular `LOOP`, the implementation stops on index equality. For `+LOOP`, it stops when the signed index crosses the limit in the step direction. The source article's Z80 loop comparison is difficult to read, so this directional crossing rule is the portable design choice, not a confirmed historical detail.
- `MINUS`, `COM`, `NAND`, `NOR`, `SWAB`, `END`, `VAR`, `CONST`, `ARRAY`, `A@`, `A!`, `OSET`, `1+!`, `1-!`, `C.`, `ECHO`, `SPCES`, `INPUT`, and `<BUILDS` remain available. `SWAB` now reverses all eight bytes of a cell; this widening is a portable choice. `C.` prints the low byte as an unsigned number followed by a space.
- `NOT` remains the FORTH/Σ logical not (same as `0=`) and now returns `-1` for true.
- `ARRAY` and `FARRAY` allocate eight bytes per element; `A@`/`A!` and `FA@`/`FA!` take `( index base )`.
- `F+!`, `F?`, `FA@`, `FA!`, `FARRAY`, `FINPUT`, and `FMINUS` are float counterparts of FORTH/Σ words added for this port; they are not gforth words.

### Other portable choices

- Loop frames remain in a separate runtime stack instead of sharing the user-visible return stack. `I` and `R@` therefore differ.
- `CHAR` and `[CHAR]` both read the next token; inside a definition either one compiles the character as a literal.
- Words defined by the user shadow built-in words and the parsing words (`VALUE`, `TO`, `VARIABLE`, …) of the same name.
- Stack capacities and immediate underflow checks favor a bounded portable runtime. Errors clear the data, return, float, and loop stacks and abandon an incomplete definition.
- Multi-line colon definitions remain enabled for source input. The keyboard interpreter's one-line behavior and the editor `EXEC` path in the original material differ; this implementation does not reproduce the machine-specific editor.
- The `,`, `C,`, and `F,` words share the logical data area with variables, arrays, and strings. `FORGET` restores the data pointer to the removed word's allocation mark.
- `'` produces an opaque dictionary token for this portable runtime; `EXECUTE` consumes it. This replaces machine addresses and is an implementation extension.
- `?DO` skips an equal start and limit. `J` and `K` expose the second and third nested loop indices.
- The logical memory is 2 MiB; the variable/allocation area begins at `0x4000` and may grow up to the heap at `0x100000`; the heap ends at `0x1DFFFF`, the input buffers and the source file table use `0x1E0000`–`0x1EFFFF`, and the local-variable frames use the last 64 KiB. Addresses outside `0`–`0x1FFFFF` (or an access that would cross the end) raise `INVALID MEMORY ADDRESS !`.
- The data stack, return stack, and float stack hold 1024 entries each; the dictionary holds 8192 words (526 built-in) with their names in a 256 KiB area; compiled code holds 65535 operations; names are limited to 255 bytes; an input line is limited to 4096 bytes.

These choices are implementation behavior, not claims about every historical FORTH/Σ version.

### Graphics and Tcl/Tk

The magazine has no graphics words; these are extensions of the port, specified in the [user manual](USER_MANUAL.md). The design decisions and their reasons are in [DECISIONS.md](DECISIONS.md).

- The core keeps only small `GFX-` built-in words; the rest is Forth in `src/graphics/graphics.fs` (and `graphics_float.fs` with floating point), which `REQUIRE-GRAPHICS` loads into the `GRAPHICS` vocabulary. New `GFX-` words are added at the end of the built-in list, so earlier dictionary images keep their execution tokens. A dictionary that has had the graphics words is saved as `SIGIMG34`; one that never had them stays `SIGIMG33`.
- The image (24-bit colors, up to 8192 pixels a side and 64 MiB) is a buffer the host gives (`framebuffer_fn`), outside logical memory and outside the dictionary image; restoring an image forgets it.
- `SHOW` sends the image to the display `DISPLAY-...` chose: the terminal with half blocks and 24-bit color escapes or as Sixel (made smaller by averaging to fit the terminal, and drawn over the last picture), the window of the Windows host (a thread of its own), or the Tk window (a PNG in base64). `WINDOW-SIZE` gives the window's client area (`window_fn` gets it with each image); the image keeps its proportions in it with black around it (`PatBlt`), also when the window is resized, and the mouse is mapped back to the image's pixels. The Tk side zooms or subsamples a copy of the image by whole factors (`photo copy`) to fit its label, again on `<Configure>`. `DISPLAY-COLORS` and `DITHER` change only what is shown, by the nearest color of a palette or a 4 × 4 Bayer matrix.
- Input comes from the host without waiting as `InputEvent`s: bytes from a terminal (decoded in the core: escape sequences, SGR mouse reports, a sequence waiting at most 50 ms, the cursor's place from a DSR request), keys and mouse positions from a Windows console or window already decoded, keys and the mouse of the Tk window, and a restart of raw input, which drops what the terminal sent before. Ctrl+C throws `USER INTERRUPT !` (-28), also from the Tk window while a script runs. `KEY-HELD?` keeps up to 16 keys held: those of the Windows console (key-up records, and its focus events), the window (`WM_KEYUP`, `WM_KILLFOCUS`), and the Tk window (`KeyRelease`, `FocusOut`) until they are released; those of a terminal, which does not tell, for 0.6 s after they were last pressed. A restart of the terminal forgets its keys.
- `TEXT` mixes coverage (0 to 255) of one glyph at a time: the built-in Misaki font (95 ASCII glyphs), a BDF file read twice (sizes, then glyphs) into a buffer the host gives, or on Windows a system font GDI draws. `FONT ERROR !` is -272.
- The TCL words do not link Tcl: the host starts `wish` with `sigma_tk.tcl` and talks through its standard input and output. Sigma sends `<length>\n<script>`; Tcl answers `R <code> <length>\n<result>` (code 1 is an error, `TCL ERROR !`, -273) and sends events (`E`), keys (`K`), keys released (`U`), and the mouse (`M`) whenever they happen, with code 0. Headers are checked strictly, and a message is at most 64 MiB. Messages are read in parts without waiting (`INKEY`, `MOUSE`, `TCL-EVENT`): the state remembers the header so far, the message whose text is coming, and the bytes left of a message given up. Results, error messages, and up to 64 events are kept in the heap; `SAVE` and `SAVESYS` free them first, and the rest of a message still coming is read and dropped. A script cut short (Ctrl+C, no memory) stops the program, so the next script does not take its result. Tcl's standard output does not block, so neither side waits for the other; while more than 4 MiB wait for Sigma, Tcl drops new events, keys, and mouse reports, but never results.
- The host writes the script to a new temporary file (a unique name, created exclusively; 0600 and not following links on POSIX) and removes it when the program stops. The program is `TCL-PROGRAM`'s, `SIGMA_WISH`, `wish` on the `PATH`, or on Windows the `wish` of Git for Windows. Stopping closes both pipes, waits 2 s, then ends the program (`TerminateProcess` and up to 5 s more on Windows; `SIGTERM`, 1 s, and `SIGKILL` on POSIX); `TCL-STOP` gives -265 when the host could not see it end. On POSIX the child moves its pipes above descriptor 2 before `dup2`, and `SIGPIPE` is ignored only while Sigma writes to the program.
- What has been checked by hand, and what has not (macOS, a real `wish` on Linux and macOS, how real terminals show 16 and 256 colors and Sixel), is recorded in [DEVELOPMENT_SCHEDULE.md](DEVELOPMENT_SCHEDULE.md).

### Sound

The magazine has no sound words either; these are extensions of the port, specified in the [user manual](USER_MANUAL.md#sound), with the research in [SOUND_RESEARCH.md](SOUND_RESEARCH.md) and the decisions in [DECISIONS.md](DECISIONS.md). No emulator's or player's code is used: the chips follow their data sheets and published descriptions, and the AY's volume table is a public-domain measurement.

- The core keeps the `SND-` built-in words (`src/core/words_audio.zig`); the rest is Forth in `src/audio/audio.fs`, which `REQUIRE-AUDIO` loads into the `AUDIO` vocabulary through the same loader as `REQUIRE-GRAPHICS` (`src/core/library_loading.zig`). A dictionary that has had the audio words is saved as `SIGIMG35`.
- The synthesis is freestanding Zig in `src/core`: the PSG by its registers (`sound_psg.zig`, stepped at clock / 8 and averaged over each output sample), MSX BASIC's MML (`sound_mml.zig`), the common parts (`sound_parts.zig`: instruments, the SID's ADSR table, PolyBLEP pulses, equal-temperament pitch rounded to each chip's period registers), the NES, the C64, the SCC, and the Amiga (`sound_nes.zig`, `sound_c64.zig`, `sound_scc.zig`, `sound_amiga.zig`), samples and WAV files (`sound_pcm.zig`), and ProTracker modules (`sound_mod.zig`). Everything runs at the output's rate (48 kHz) and gives the same samples for the same input, so the tests compare the waves.
- `sound_engine.zig` joins them for two threads: the Forth program puts notes into one lock-free single-producer, single-consumer queue per voice (8, 32 places each) and commands into another; the audio thread takes them in `render`, which never locks, allocates, or waits. Each `PLAY` ends every voice with a mark, and the next one starts only when all voices have reached theirs. `PLAY` waits through the host while the queues are full; Ctrl+C is caught only during those waits.
- Samples and modules are in one pool of 16 MiB that the host gives once; the program only adds to its end, so the audio thread never reads a part that changes, and `FREE-SAMPLES` empties it after the music has stopped.
- The host (`src/host_audio.zig`) runs the audio thread: waveOut on Windows (eight 10 ms buffers), PulseAudio or ALSA loaded at run time on Linux builds that can load libraries, and otherwise `pacat`, `pw-play`, or `aplay` through a pipe; without any, the thread makes the samples in time and drops them. Outside Windows the thread is started with `pthread_create` and its default attributes, since glibc 2.39 refuses the attributes Zig 0.17's `std.Thread.spawn` sets.

### Bounded inlining of short colon definitions (2026-11-04)

Completed, non-immediate colon definitions with one to four operations before their final EXIT can now be copied into a compiled call site. Eligible bodies contain only literal values, execution tokens, specialized primitives, and already-inlined call guards. Recursive or branching bodies, locals, dynamic calls, DOES>, early EXIT, and larger bodies retain their ordinary calls. If the expansion would leave no spare operation slot, compilation falls back to an ordinary call. This only checks the current expansion, not the remaining definition: a previously fitting definition can run out of code space at a later operation or its final EXIT. Expansion increases code-area consumption; the four-operation limit includes nested guards and bounds the growth per call site. Saved images retain those slots as padding, so combinations of images that previously fitted can also exhaust code space during LOAD.

The existing `call_colon` tag represents an inline guard when its operand encodes the original word id, expansion span, and required call-depth headroom. It checks the original call limit at the original position, then continues into the copied instructions without saving a frame. Nested guards retain their relative depths and error order. No new dispatch tag is added. SEE shows the original callee name and skips its copied body; redefinition appends a new word and does not change existing expansions.

SAVE writes an ordinary call to the original word followed by branches over the reserved expansion slots. This keeps code positions stable and preserves SIGIMG33 compatibility. Restore reconstructs only exact padding spans whose earlier callee is eligible, with no branch destination or word/DOES> boundary inside the span. LOAD relocates the word ids packed in guards, as well as execution tokens copied into their bodies. Old calls without a matching following span remain ordinary calls. An old image's empty ELSE or forward branch can coincidentally match the padding pattern, allowing reconstruction and changing SEE output as described above.

Five added tests cover nested guards, redefinition and SEE, stack effects and error ordering near the call-depth limit, excluded definitions, code-capacity fallback, save/restore and repeated LOAD relocation, and a branch entering the padding. Windows Debug and fast passed 237 tests (230 core, 7 host); fast without floating-point words passed 192 with 19 skipped. Cortex-M0+ compilation and real-pipe checks passed.
