## 目的と既存計画との境界

ゲームやTUIの入力・描画を続けながら、計算・I/Oの進行、終了・失敗の通知、取消しと回収を扱えるようにする。[もとの企画](ASYNC_OVERVIEW.md)にある独立ワーカーVMの案を引き継ぎ、具体的な検討・実装・検証の作業へ分割する。

652は実行回数の制限と中断を扱う。`EXEC-LIMITED`の案は予算が尽きると入口へ戻すもので、中断位置からの再開を提供するものではない。今回のタスク制御は別の項目とし、652がデバッグ機能なしのビルドで除外される既存の決定を変更しない。子プロセス管理643、OSの補助スレッド、Forthのタスクも区別する。

## 設計で埋める条件

- **通知と状態**：通知を取りこぼしても現在状態・結果を再取得できるかを定義する。完了と取消しが競合した場合の最終状態、結果の重複取得、通知順序を決める。
- **待機**：すでに成立した条件、登録直後の成立、複数条件と期限・取消しが同時に成立した場合を扱う。現在の900の「Forthを実行するスレッドは1つ」「待機は同時に1つ」という案を、メインVMとワーカーごとの適用範囲へ整理する。共有の信号ハンドラーや入力をワーカーが取り合わない設計を選ぶ。
- **停止と再開**：途中で戻るジョブ、継続の一時停止、取消し、652の上限到達を別の操作として定義する。任意の同期OS呼出しを期限内に中断できるとは保証しない。共有状態を触るスレッドの強制終了を取消し手段とせず、停止不能時の通知・隔離・回収方針を決める。
- **資源**：取消しで自動解放する資源と呼出し側へ返す資源を区別する。タスク終了と子プロセス終了・出力終端・表示完了は別条件とする。親の終了時に子を待つか取り消すか、切り離しを認めるかは未決とする。
- **辞書とデータ**：共有辞書の同時変更を前提にしない。ワーカー案ではVMごとの論理アドレスをそのまま受け渡さず、コピーするデータと有効な識別子を定義する。FORGET・MARKER・辞書復元中の実行、古い辞書の実行トークン、実行後に届く古い結果を扱う。
- **ビルド**：通常のアプリで必要なタスク管理と652のデバッグ専用機能を分ける。拡張モジュールを候補とし、時計と同様にgraphics単独構成の利用可否を設計する。既存の3語群の分割方針を保ち、追加のビルドオプションを採用済みとして扱わない。
- **性能と制約**：協調方式で処理が戻らない場合の制約、ワーカー方式でGUI・入力を操作できる範囲を明記する。性能測定は既存の利用者確認の方針に従い、測定条件と結果を分けて記録する。プリエンプティブ切替やハードリアルタイム保証は今回の採用事項にしない。
