# ForthワーカーのState隔離監査表

作成日：2026-11-19。レビューR02への設計補足。対象は現作業ツリーのsrc/forth.zig。
状態：初期化方針の案。ワーカー方式の採用・実装・スレッド安全性の証明ではない。

Stateを値コピーせず、新しいStorageとState.initから構築する。次の表はStateの直下フィールドをソースから列挙し、既定をコピー禁止の初期化としている。構造体内のポインター・グローバル参照の再帰監査は1053の必須成果物であり、この直下表だけで完了しない。

スナップショットは明示取得した辞書と保存対象のデータを検査・再配置して再構成する案。実行中のスタック・継続・入力・ホスト資源を複製するものではない。変数や値のワーカーからの変更はメインへ返らない。論理設定のうち何を保存対象から復元するかはイメージの復元規則と照合する。

## ホスト側の監査と禁止条件

| 領域 | 初期方針と試験 |
|---|---|
| Writer.context / write_fn | タスク専用の上限付きバッファ。メインのoutput_bufferへ触れない。満杯時の失敗をタスク結果へ記録 |
| ファイル・パイプ・プロセス | メインのopen_files・先読み・OSハンドルを渡さない。初期許可しない |
| 端末入力・時計待機 | host_input・host_waitのプロセス共有状態へ到達させない。取消しは専用の印と起床。同期MSは禁止 |
| ウィンドウ・ゲームパッド・Tk・音 | ホストの共有資源へ到達する語とcallbackを禁止。画像や標本のsliceを共有しない |
| ログ・profile・lint・capture | タスク専用へ再構成できる場合だけ許可し、メインのポインターを渡さない |
| 辞書・xt・アドレス登録 | スナップショット版で解決。メインの実行トークンや論理アドレスを移植可能な識別子として使わない |
| 組込み語・静的コード・インライン展開・間接呼出し | 投入前に到達コードと展開済みOpを走査し、worker専用経路で直接builtin OpとEXECUTE・DEFER等の動的先も検査する案を比較。入口語とnull callbackだけに依存しない |

State直下以外のコンテナ変数、関数内static相当、Cライブラリ・OSのプロセス共有状態も監査する。許可する各語について到達先を確認し、未監査の語は実行を許可しない。画像解放、出力、NS、ファイル操作、辞書復元、タスク再利用でメインへの干渉がないことを差替え試験と実機で確認する。

2026-11-19、1056で追加したextension_libraryを含めState直下168項目を列挙に照合した。これは直下の列挙照合であり、ポインター・グローバル参照の再帰監査と1053の完了を意味しない。

637のWriterにterminal_mode_set_fn・terminal_mode_get_fn・input_error_fnを追加した。端末と信号はホストスレッドの共有資源なので、ワーカーへメインの操作口をそのまま渡さない。1053の再帰監査でこの3口も分類し、通常のState直下168項目の列挙照合と区別する。

638でState直下へstandard_inputを追加し、169項目とした。Writer.standard_event_fn・standard_clock（Clock.context/now_fnを含む）・standard_interruptsも1053の再帰監査対象。メインの入力/時計contextや保留イベントをワーカーへ借用しない。

638のchecked押し戻しWriter.unread_byte_fnと、standard_input.legacyの旧pendingキャッシュも再帰監査に含める。Decoder全体は純粋な値だが、ワーカーへメインの未読入力やEOF/paste状態をコピーしない。


997でWriter.physical_key_opsを追加した。メインのウィンドウのTracker、supported bitmap、contextをワーカーへ借用しない。ワーカーWriterではnullにし、SCAN-INPUT?・SCAN-SUPPORTED?・SCAN-HELD?・KEY-EVENT・KEY-RESYNCを入力/UI禁止語として将来の静的・動的検査に加える。State直下のフィールド追加はなく169項目のまま。ホストTrackerとMac Sender/Receiverはイメージに含めない。

652でexecutionを追加しState直下は170項目。Writer.execution_opsのbegin/poll/endとcontextはワーカー専用に検査し、メインの信号所有者やVMポインターを借用しない。

1068でsystem領域0x0dd0へ保存アプリの起動登録（word ID+1）を追加した。State直下は170項目のまま。新規Stateは未登録、完全復元は明示画像の登録を検査し、appendは追加先の設定を保持する。実起動時の自動dispatchはhost mainだけで行い、復元自体では実行しない。1053ではworker snapshotへのこの永続設定の取込み方、APP語/SAVE/SAVESYSの許可、host callbackとmainの起動IDを共有しないことを再帰監査する。
