# small最適化レビューへの対応

[Read/Grep/Globによるレビュー原文](VM_OPTIMIZE_SMALL_CLAUDE_REVIEW.md)は重大指摘なし。SHAはレビュー内で再計算しておらず、計時も未完了時点だったため、確定した速度数値は別の自前集計として記録する。

凍結済みprotocol/scriptは変更せず、結果確定後の解釈を別記録にした。passed=falseだけでは同等/悪化を意味しない点を明記し、今回は正のCPU時間変化＋138.383%/＋137.329%という観測と、既存10%短縮目標の未達から速度施策として不採用とした。サイズ目的の採用は別判断で、今回決めていない。新しい事後閾値は設けていない。

A/Aのδは0.231535%、2δ約0.463%で実質的に10%条件が強い。事後A/AやA/B中ドリフト上限の検証はしていない。群内先行順の偏り、同一セッション、CPU0/ホスト負荷未記録も明記した。

画像SHA差は原因未調査。サイズと生byte差分位置を記録し、1定義の読込み/実行プローブから全画像型の同等性を主張しない。初回SAVE引数形式ミスはwindows-fastの最初の反復で停止したスクリプトと保持ファイルのcreation時刻を記録。移動前の未追跡確認とstdout/stderrは別ファイルに記録していなかった。root生成物を.workへ移し、現在rootに残っていないことも確認した。

5ファイルSHA照合と、fastが採用済み実行体SHAを再現した根拠を区別。Linux CLIのsmall SHA一致、引数なしELF実行、smallによるC側への影響、固定smallのfreestandingが比較対象でないことを追記した。検証範囲外の機能無効構成/他OS間画像/デバイス受入/他時間項目は未実行のまま。

レビューの「結果確定前に解釈を追記」は、今回は結果が確定した後にレビューを読んだため実施していない。その事実を隠さず、元の計画と事後解釈を分離して保存した。本体・配布設定は未変更。
