# LOGOのタートルグラフィックスの検討

2026-11-19 作成。**仕様の検討段階の文書で、実装は決まっていない。** LOGOのプログラムを解釈してタートルグラフィックスを描く仕組みを、FORTH/Sigmaの上にForthで作る場合の方式、決める項目、問題点を整理する。

- Sigmaについてコードと文書で確かめたことは、ファイル名を付けて書いた。確かめていないことは「未確認」、推測は「※推測」と書いた。
- LOGOの仕様は、Codexが2026-11-19にWebの一次資料（UCBLogoの利用者マニュアル、UCBLogoの実装の解説、FMSLogoのマニュアル）と照らし合わせた結果を[2.4 節](#24-logoの仕様で確かめたこと)に記す。資料で確かめたもので、UCBLogoとFMSLogoを実際に動かして確かめてはいない。
- この文書の内容は、Codexによる2回のレビュー（Sigmaの事実と文書の構成、LOGOの仕様）を反映した。
- 本文の方式案だけで採用を決めない。利用者が決めた配置と共通基盤の範囲は1章に記録する。残る判断点は[4 章](#4-決める項目)に挙げた。決まったら[決定事項](DECISIONS.md)に記録する。

## 1. 前提（利用者の決定）

| 項目 | 内容 |

## 2. 既存の機能で使えるもの

### 2.1 描画（`src/graphics/graphics.fs`、`src/graphics/graphics_float.fs`）

| 語 | 用途 |
|---|---|
| `LINE ( x1 y1 x2 y2 -- )` | 画素の座標で線を引く。画像の端で切る |
| `MLINE ( F: x1 y1 x2 y2 -- )` | 数学の座標（y軸は上向き）で線を引く。範囲は `X-RANGE`・`Y-RANGE` で決める。x方向とy方向の倍率は、幅と高さから別々に計算する（`graphics_float.fs` の `(M>PX)`・`(M>PY)`） |
| `COLOR ( r g b -- )`、`COLOR! ( rgb -- )` | 描く色 |
| `CLS`、`PSET`、`CIRCLE`、`TEXT` | 消去、点、円、文字 |
| `SHOW`、`FRAME ( ms -- )` | 表示。`FRAME` は待ってから表示する（アニメーション用） |
| `NEW-IMAGE`、`DRAW-TO`、`PUT-IMAGE`、`TRANSPARENT` | 画面のほかの画像（256個、合わせて1 GiBまで）への描画と重ね合わせ（`graphics.fs` の「Images」） |

`docs/DECISIONS.md` の「描画の分担」に、`LINE` `RECT` `CIRCLE` `PLOT`、タートルなどはForthで書く、と記されている。

`REQUIRE-GRAPHICS` は語を `GRAPHICS` 語彙に登録し、読み込んだ後は検索順・定義先・`BASE` を元に戻す（`graphics.fs` の冒頭）。

### 2.2 Forthの語と規則

`src/core/help_text.zig` に次の語の登録があることを確かめた。

`FSIN`、`FCOS`、`FSINCOS`、`EVALUATE`、`INCLUDED`、`OPEN-FILE`、`READ-LINE`、`>FLOAT`、`FVALUE`、`:NONAME`、`SLITERAL`、`POSTPONE`、`WORDLIST`、`SEARCH-WORDLIST`、`EXECUTE-PARSING`、`ALLOCATE`、`REFILL`、`SOURCE`、`RECURSE`、`RECURSIVE`、`FORWARD`、`UNLOOP`、`MARKER`、`CS-VOCABULARY`。`F:` のローカル変数は `graphics_float.fs` で使われている。

変換器の作りに関わる規則を、次のとおり確かめた。

| 規則 | 根拠 |
|---|---|
| 定義している最中の名前は、以前の同名の語を指す。自分自身を呼ぶには `RECURSE` か `RECURSIVE` を使う | `docs/USER_MANUAL.ja.md` の `RECURSIVE` の項、`src/core/wordlists.zig` の `lookupIn`（定義中の語を検索から除く） |
| 後で定義するコロン定義は、`FORWARD` で同じ語彙に前方宣言できる。未解決のまま実行すると -259 | `docs/USER_MANUAL.ja.md` の `FORWARD` の項 |
| コンパイル中は、ローカル変数を辞書のどの語よりも先に検索する | `src/forth.zig` の `handleToken` |
| ローカル変数の名前は、ASCIIの大文字と小文字を区別しない | `src/core/local_variables.zig` |
| 普通の語彙は大文字と小文字を区別しない。区別する語彙は `CS-VOCABULARY` で作る | `src/core/wordlists.zig` の `lookupIn`、`help_text.zig` の `CS-VOCABULARY` |
| 1つの定義のローカル変数は64個まで | `src/core/memory_map.zig` の `max_locals` |
| `IF`・`DO` などの制御構造はコンパイル専用で、解釈状態では使えない | `src/forth.zig` の `handleToken`（`error.CompileOnly`） |
| ループの中で `EXIT` するときは、先に `UNLOOP` が必要 | `help_text.zig` の `UNLOOP` |
| `F>S` は0の方向に切り捨て、範囲外は飽和し、NaNは0になる | `help_text.zig` の `F>S` |
| `MARKER` で作った語を実行すると、その語より後のすべての語と、その後に読み込んだファイルが消える | `help_text.zig` の `MARKER` |
| `EVALUATE` 中の `SOURCE` は文字列全体で、入力源の名前は `*evaluated string*` | `help_text.zig` の `SOURCE`、`src/core/memory_map.zig` の `evaluate_source_name` |

### 2.3 SAVESYSについて確かめたこと

- `SAVESYS` の実行ファイルは保存した辞書を持って起動する（`docs/USER_MANUAL.ja.md` の「辞書の保存と単独実行ファイル」）。
- 画像（フレームバッファ）は辞書に保存されない。起動後に `GFX-INIT` で作り直す（`docs/GRAPHICS_MODES.ja.md`）。
- `SAVE`・`SAVESYS` より前に作った画像のハンドルは無効になる（`graphics.fs` の「Images」）。
- `ALLOCATE` の返したアドレスを普通の変数に入れたものは、`SAVE`・`SAVESYS` をまたいで有効でない（`docs/USER_MANUAL.ja.md`）。
- 実行ファイルは保存したときの `-m` と `-l` の大きさで起動する（`docs/USER_MANUAL.ja.md`）。

### 2.4 LOGOの仕様で確かめたこと

出典は、UCBLogoの利用者マニュアル（<https://people.eecs.berkeley.edu/~bh/usermanual>、HTML版 <https://people.eecs.berkeley.edu/~bh/docs/html/usermanual.html>）、UCBLogoの実装の解説（<https://github.com/jrincayc/ucblogo-code/blob/master/plm>）、FMSLogoのマニュアル（<https://fmslogo.sourceforge.io/manual/>）。

**命令**：4章で挙げた命令は、すべてUCBLogoにある。

| 命令 | UCBLogoでの意味 |
|---|---|
| `FD` / `BK` | 前進／後退。`BK` で向きは変わらない |
| `RT` / `LT` | 時計回り／反時計回りに回る |
| `PU` / `PD` | ペンを上げる／下ろす |
| `HOME` | 原点へ移動し、向きを0度にする |
| `SETXY` | 2つの入力で位置を指定する |
| `SETH` | 向きを指定する |
| `CS` | 描いたものを消し、位置と向きを初めの状態に戻す |
| `SETPC` | ペンの色を指定する |
| `ST` / `HT` | 亀を表示／非表示にする |
| `ARC` | 亀の位置を中心とする円弧を描く。亀は動かない。描き始める位置はFMSLogoと違う |
| `LABEL` | 亀の位置から文字を描く |
| `FILL` | 亀を含む、線で囲まれた領域を塗る。機種による違いがマニュアルに書かれている。FMSLogoは塗る色（`FLOODCOLOR`）が別にある |
| `SETPENSIZE` | ペンの太さ。整数か、2つの要素のリストで指定する |
| `LOCAL` | 手続きの中に局所変数を作る。初期値はない |
| `THING` | 名前で指定した変数の値を返す。`:X` は `THING "X` と同じ |
| `WINDOW` | 描画領域の外へ出られる |
| `WRAP` | 端を越えると反対側から出てくる。**UCBLogoの既定** |
| `FENCE` | 端を越えようとするとエラーにする |

**制御と変数**

| 命令 | 確かめた内容 |
|---|---|
| `TO` / `END` | `TO` の行、本体、`END` だけの行に分かれる。任意引数と残余引数も宣言できる |
| `REPEAT` | 指定した回数繰り返す |
| `REPCOUNT` | 実行中のいちばん内側の `REPEAT` か `FOREVER` の回数を1から数える。どちらも実行中でなければ -1。呼び出した手続きの中からも参照できる |
| `IF` / `IFELSE` | 条件は `TRUE` / `FALSE`。`IFELSE` は選んだ方の値を返す使い方もある |
| `STOP` | 値を返さずに、囲んでいる手続きを終える（繰り返しの中でも手続きを終える） |
| `OUTPUT` | 値を呼び出し元に返して手続きを終える |
| `MAKE` | 同じ名前の変数があればそれを変え、なければ大域変数を作る |

**座標系と向き**：UCBLogoは描画ウィンドウの中央が `[0 0]`、xは右、yは上が正、角度はy軸の正の方向から時計回り。FMSLogoも同じ規則で、中央は描画面の中央（スクロールすると表示の中央と一致しないことがある）。

**末尾呼び出し**：UCBLogoは末尾呼び出しを最適化する。自分自身の呼び出しに限らず、`OUTPUT` の入力の式も末尾として扱う（実装の解説の2.2節、3.1節、3.2節）。

**動的スコープ**：UCBLogoとFMSLogoの局所変数は、そこから呼び出した手続きからも見える。

**マイナス記号**：直前が空白で直後が空白でなければ、単項のマイナスになる。

| 記述 | 意味 |
|---|---|
| `FD :A - 10` | `:A` から10を引いた距離だけ進む |
| `FD :A -10` | `FD` の入力は `:A` で終わり、`-10` は別の式として残る |
| `FD - 10` | 単項のマイナスで、-10だけ進む |

**括弧による引数の数の指定**：`(SUM 1 2 3)` は6になる。括弧で指定できる引数の数は、手続きごとに決まった最小と最大の範囲だけ。

**色番号**

| 番号 | UCBLogo | FMSLogo |
|---:|---|---|
| 0 | black | Black |
| 1 | blue | Blue |
| 2 | green | Lime |
| 3 | cyan | Cyan |
| 4 | red | Red |
| 5 | magenta | Magenta |
| 6 | yellow | Yellow |
| 7 | white | White |
| 8 | brown | Brown |
| 9 | tan | Tan |
| 10 | forest | Olive |
| 11 | aqua | Sky Blue |
| 12 | salmon | Salmon |
| 13 | purple | Medium Purple |
| 14 | orange | Orange |
| 15 | grey | Dark Gray |

- UCBLogoで共通なのは0〜7で、8〜15は環境が対応していれば使える初期設定。両者のRGBの値が同じかは確かめていない。
- RGBで指定するときの尺度が違う。UCBLogoは百分率の3つの要素のリスト、FMSLogoは各0〜255。
- 背景の既定が違う。UCBLogoは黒の背景に白のペン、FMSLogoは白の背景に黒のペン。

**ライセンス**：UCBLogoはGPL version 3以降（開発元のREADME）。利用者マニュアルの冒頭にもGPL v3以降の通知がある。Brian Harveyの教科書 *Computer Science Logo Style* は、著者のサイトで個人の利用に向けて公開されており、再販売と再配布は認められていない（<https://people.eecs.berkeley.edu/~bh/logo.html>）。

## 3. 方式の案

### 3.1 構成

外部の `.fs` ファイルを2つ作る。

| ファイル（名前は仮） | 内容 |
|---|---|
| `turtle.fs` | タートルのライブラリ。`MLINE`、`FSINCOS` などを使って `FD`、`BK`、`RT`、`LT`、`PU`、`PD`、`HOME`、`SETXY`、`SETH`、`CS`、`SETPC` などを定義する。Forthからも直接使える |
| `logo.fs` | LOGOからForthへの変換器 |

### 3.2 変換器の処理

1. LOGOのソース（文字列またはファイル）をバッファに置く。バッファは実行時に確保する。
2. 字句解析：語、数、`:変数`、`"語`、`[`、`]`、演算子に分ける。マイナス記号は2.4節の空白の規則で単項と二項を分ける。
3. 第1段階：`TO … END` を集め、手続きごとの引数（必須・任意・残余）を表にする。
4. 第2段階：構文を解析し、Forthのソースの文字列を組み立てる。
   - LOGOの手続き名、引数、局所変数、大域変数は、すべてForthでの内部名に変える（名前の衝突を避ける。8-2）。
   - 手続きの定義の前に、全手続きの内部名を `FORWARD` で前方宣言する（後で定義する手続きの呼び出しと、互いに呼び合う手続きのため。8-6）。
   - 手続きの外の命令は、`:NONAME … ;` に包んでコンパイルしてから実行する（制御構造がコンパイル専用のため。7-7）。
5. 組み立てた文字列を `EVALUATE` する。

変換の例（内部名の形 `L.TREE`・`l.len` は仮。8-2で決める）：

```logo
TO TREE :LEN
  IF :LEN < 5 [STOP]
  FD :LEN LT 30 TREE :LEN * 0.7
  RT 60 TREE :LEN * 0.7
  LT 30 BK :LEN
END
```

```forth
FORWARD L.TREE
: L.TREE { F: l.len -- }
   l.len 5e0 F< IF EXIT THEN
   l.len FD  30e0 LT  l.len 0.7e0 F* RECURSE
   60e0 RT  l.len 0.7e0 F* RECURSE
   30e0 LT  l.len BK ;
```

この例の2つの `TREE` の呼び出しは、後に処理が続くので末尾呼び出しではない。生成したコードをSigmaで動かして確かめてはいない（未確認）。

| LOGO | Forthへの変換の方針 | 検討の要点 |
|---|---|---|
| `TO 名前 :a :b … END` | `: 内部名 { F: a F: b -- } … ;` | `F:` は次の1つの名前だけに効くので、引数ごとに付ける。任意引数と残余引数の扱い（7-1） |
| `REPEAT n [ … ]` | 回数を整数にして `0 ?DO … LOOP` | 負の数・小数・NaN・大きすぎる数の扱い。`REPCOUNT` は呼び出した手続きからも見えるので、ループの添字だけでは足りない（7-6） |
| `IF 条件 [ … ]`、`IFELSE 条件 [ … ] [ … ]` | `IF … THEN`、`IF … ELSE … THEN` | 真偽値の表し方（2-4）。値を返す `IFELSE` |
| `STOP` | `EXIT` | ループの中では、抜けるループの数だけ `UNLOOP` してから `EXIT` |
| `OUTPUT 値` | 値を返して `EXIT` | ループの中の `UNLOOP`。呼び出し側が値を使うことの確認（2-4） |
| `MAKE "X 10` | 同じ名前の変数があれば代入、なければ大域変数を作る | 局所変数と大域変数の区別（7-2） |

変換の中心は「LOGOのソースを受け取って解釈・描画する語」とする。起動の仕方が決まったら、その語を呼ぶ部分を加える。

### 3.3 解釈の方式の比較

| 方式 | 長所 | 短所 |
|---|---|---|
| Forthのソースに変換して `EVALUATE` する | 変換結果を読んで確かめられる。名前付きのローカル変数を素直に書ける | この案では、実行時にリストを組み立てて実行する機能（`RUN` など）は実装しない |
| Forthで書いたインタプリタが直接実行する | `RUN` やリストまで扱える | 規模が大きい |

速さの違いは測っていない（※推測では変換方式の方が速い）。`EVALUATE` は実行時にも文字列を解釈できるので、`RUN` などを扱えないのは `EVALUATE` の制約ではなく、この案で対象外にしたためである。

### 4.6 起動の方法

`SAVESYS` で作った実行ファイルを、どのように起動してLOGOのプログラムを解釈させるかを決める。

| 番号 | 項目 | 内容 | 関連 |
|---|---|---|---|
| 6-1 | 起動の形 | 実行ファイルを起動したときに、何が始まり、LOGOのプログラムをどこから受け取るか（LOGOの命令を打ち込むプロンプト、Forthのプロンプトから語で読み込む、ウィンドウの中で入力する、など） | 7-3 |
| 6-2 | 起動語の仕組み | 共通基盤1066の登録・自動起動を利用し、LOGO側はForthの起動語を用意する。共通APIは1067で設計予定、未実装。現状の代替は`logo.exe -e "起動語"`や起動用`.fs`の指定 | [共通基盤](SAVED_APPLICATION_STARTUP_PLAN.md) |
| 6-3 | 描き終わった後 | 描き終わった後に、ウィンドウを開いたまま待つか、終了するか | |
| 6-4 | 起動時の初期化 | 起動後に作り直すもの：画像（`GFX-INIT`）、キャンバスや亀の画像のハンドル、変換器の表とバッファ（2.3節） | 問題12 |

2026-11-19の利用者指示により、LOGO機能はSigmaへ組み込まず、共通の保存アプリ起動基盤を1003で整備する。[決定事項](DECISIONS.md)に記録した。以下は基盤追加前の現状として確かめた事実であり、自動起動が実装済みという意味ではない。

- `SAVESYS` の実行ファイルは、Sigmaと同じようにコマンドラインの引数を処理する。辞書を戻した後、引数はそれぞれForthのソースファイルとして左から順に `INCLUDED` し、`-e 文字列` はその文字列をForthとして実行する。引数がなければ対話プロンプトになる（`src/main.zig` の引数のループ、`docs/USER_MANUAL.ja.md` の「起動と入力」と「辞書の保存と単独実行ファイル」）。
- 引数は、プログラムから `ARGC`、`ARGV`、`ARG`、`SHIFT-ARGS`、`NEXT-ARG` で参照できる。ファイルが `NEXT-ARG` で取った引数は、ファイルとして処理されない（`docs/USER_MANUAL.ja.md`）。

## 5. 問題点

影響の大きい順に並べた。

### 5.1 動作が変わる、または動かない問題

| 番号 | 問題 | 内容 | 対応の項目 |
|---|---|---|---|
| 1 | 末尾呼び出し | LOGOでは手続きの最後で自分を呼ぶ形（`SPIRAL` が `FD :N RT 90` の後に `SPIRAL :N + 2` を呼ぶなど）を、終わらない繰り返しとして使う。UCBLogoは末尾呼び出しを最適化する（2.4節）。Forthにそのまま変換すると、呼ぶたびにリターンスタックが積み上がり、いずれあふれる | 8-1 |
| 2 | 動的スコープ | 呼び出し元の変数に頼るLOGOのプログラムは、レキシカルスコープに変換すると、違う値を参照するか、エラーになる | 2-2、7-2 |
| 3 | リストをプログラムとして扱う機能 | この案では、`RUN`、変数に入れたリストの実行、実行時に組み立てたリストの実行を実装しない。リテラルの `[ ]` だけを扱う | 1-2 |
| 4 | 語の名前の衝突 | 生成したForthのコードは `IF`、`DO`、`LOOP`、`I`、`EXIT` などを使う。LOGOの手続きの名前が `LOOP` や `I` だと、検索順によっては生成したコードが利用者の手続きを呼ぶ。ローカル変数は辞書の語より先に検索されるので、LOGOの引数の名前が `IF` や `EXIT` だと、生成したコードの制御語が使えなくなる。どちらも大文字と小文字を区別せずに衝突する。`FORWARD` はSigmaの前方宣言の語としてすでにある | 8-2、8-7 |
| 18 | 手続きの外の制御構造 | `IF`・`DO` などはコンパイル専用なので、手続きの外の `REPEAT` や `IF` を変換した文字列を、そのまま `EVALUATE` しても実行できない | 7-7 |
| 19 | ループの中の終了 | ループの中の `STOP`・`OUTPUT` は、`UNLOOP` してから `EXIT` しないと正しく抜けられない | 3.2節 |
| 20 | 値の種類 | 数を実数にそろえても、真偽値と語の表し方、値を返す手続きの扱いが決まらないと、`IF` の条件や `OUTPUT` の値を正しく変換できない | 2-4 |

### 5.2 構文解析の問題

| 番号 | 問題 | 内容 | 対応の項目 |
|---|---|---|---|
| 5 | 引数の数と参照の解決 | 構文解析：`TREE :LEN * 0.7` を区切るには、`TREE` の引数の数（任意引数と残余引数を含む）を知っている必要がある。全体を先に読む2段階の処理にするか、別の構文解析の方針をとる。1行ずつ入力する場合は、まだ定義していない手続きを含む行を区切れない。参照の解決：Forthはコンパイルするときに辞書を検索するので、後で定義する手続きと、互いに呼び合う手続きには前方宣言が必要 | 7-3、8-6 |
