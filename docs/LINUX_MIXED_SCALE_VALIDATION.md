# Linuxの混在倍率確認（1336・1345）

2026-11-23、GNOME Wayland / XWayland、Linux x86_64、Zig 0.17.1。Mutterの一時設定（ApplyMonitorsConfigのmethod 1）で副画面を2倍にし、主画面1倍と組み合わせて確認した。永続設定は変更していない。物理接続・切断の確認ではない。

## 再実行

`python3 tests/scripts/verify-linux-mixed-scale.py --output-dir .work/1037/mixed-scale-new`

出力先には新しいディレクトリを指定する。同名の復元計画を上書きしない。両画面1倍から始め、回転・ミラーのない横並び2画面に限定する。元の構成と2倍の候補の両方をmethod 0で検証してから適用する。色モード・RGBレンジ・underscanningも復元計画に保存する。扱いを確認していないモニター属性があれば適用前に止める。

独立プロセスのwatchdogが準備できてから適用する。親側の検証には全体75秒、watchdogには150秒の期限を設け、親の終了でパイプが閉じた場合も復元する。復元失敗時は30秒の間再試行する（個々のDBus呼出しの期限は5秒で、最後の試行はこの30秒を越えうる）。45秒の回収期限に間に合わない場合も失敗のreport.jsonを残し、watchdogの復元処理は止めない。通常終了、検証失敗、SIGTERM/SIGHUPでは親も復元を試み、元の構成への一致を確認してからwatchdogに復元済みを通知する。パイプEOFによるwatchdog単独の復元経路も、元の構成を対象に実行して成功した。

構成変更時にMutterが他のアプリの窓を動かす場合があり、元の配置と倍率へ復元しても、他の窓の位置まで元に戻るとは限らない。

## 実測で分かったこと

1倍同士では、主画面DP-2のモード2560×1440に対しDISPLAY-RECTは2560×1440、副画面DP-3は1920×1080だった。副画面を2倍にすると、同じSigmaプロセスの次のDISPLAYSで主画面は5120×2880、副画面は1920×1080となった。主画面を原点とする副画面のxは-1920のまま。DISPLAY-WORKも新しいXサーバーの作業領域へ変わる。DISPLAY-SCALEは両方とも不明（0 0）のままである。

これはXWaylandの座標であり、主画面の物理モードが5120×2880に変更されたという意味ではない。Mutterが返す現在のモード・論理配置・倍率とexperimental-features、独立X接続でのRandRと作業領域、起動中のSigmaの変更前・混在中・復元後の一覧を記録する。XWaylandの矩形と作業領域の両方が、候補の論理配置×2に反映されるまで待ってから配置検証を始める。RandRの矩形が更新されても_NET_WORKAREAは旧構成を一時的に返すことを実測した。

この構成ではWMの位置が2 Xピクセル刻みとなり、中央の計算結果から1 Xピクセル丸められる場合があった。検証は呼び出し元が明示するcoordinate-quantum 2に限ってその丸めを認め、通常の1倍の検証は完全一致を求める。サイズと全画面の矩形は完全一致を求める。本体の復帰完了確認も、位置の1ピクセルの丸めを許容する。

初回は中央の完全一致を求めた検証が1ピクセル差で失敗した。元のMutter構成と、同じSigmaプロセスの画面一覧が戻ることは失敗時にも確認できた。丸めを明示した次の試行では32段階が成功した。その後、期限・設定保持・追加ケース・作業領域の反映待ちも補強した。最終実行体では38段階が成功し、Mutter構成と同じSigmaプロセスの画面一覧が元へ戻ることを確認した。
