# PC分離版のWindows測定と最終判断（2026-11-15）

2026-11-15 最終追記：この文書の不採用判断はPC分離だけの旧案に対するもの。その後、データ語の呼出し経路分離を加えた別候補が[両OS全34条件を通過し、本体へ採用された](VM_ALL_VALIDATION.md)。旧案単独の不採用判断は変更していない。

## 最終判断

**PC分離版は、全OSで使う共通実装として不採用に変更し、VM本体を実験前へ戻した。** Windowsの定数・変数カーネルが、独立2系列で約2.04倍／2.10倍に悪化したためである。当初Linux/WSLで確認した改善の測定結果は維持するが、Windowsの他項目の悪化上限3%を超えており、共通版としての採用条件を満たさない。

Windowsでも整数演算は17.39〜18.31%、LOOPは17.68〜19.05%短縮し、各10%以上・2δ超という最低条件を満たした。通常8項目中7項目は両系列で短縮した。しかし一部の短縮で定数・変数の悪化を相殺する判定はしない。

対象はtque 764配下の765〜767。[Linux単独の実験記録](VM_PC_SCALAR_EXPERIMENT.md)、[Claude Codeレビュー](VM_PC_SCALAR_CLAUDE_REVIEW.md)、[指摘への対応・校正の経緯](VM_PC_SCALAR_REVIEW_RESPONSE.md)、[Windows生データ](measurements/2026-11-15-vm-pc-windows.json)を分けて保存した。

## 測定条件と記録

- Windowsネイティブ、Zig 0.17.0、x86_64-windows-gnu、fast、baseline CPU、stripを統一。VERSION・埋込み資源を含む製品入力の実バイト列を維持した。
- 今回ビルドした基準版・候補版は、それぞれ保存済みのWindows実行体とバイト単位で一致した。対象ソースと実行体のハッシュを生データに記録した。
- GetProcessTimesのkernel+userをREADY/DONE間で測り、起動・コンパイル・終了処理を除外した。FILETIMEの100nsという表現単位を実際の分解能とは扱わない。各項目は基準が約1秒以上となる反復数へ校正した。
- A/Aは同一基準をA1/A2として比較。5回で不安定な項目は反復数を2倍にしたが、安定しない項目が残った。次に独立プロセスの試行数を15回、必要な項目は31回へ増やした。正常CATCHだけはCPU4を選び、15回でδ≤2%を確認した。過去の系列も生データに残した。
- スタック操作の初回δは、比を引く浮動小数点演算で2.0000000000000018%となった。中央値の差から計算し直した値は正確に2.0%で、上限以内だった。元の値と補正を記録した。判定値を緩めていない。
- A/Aのδは観測した中央値差の目安で、信頼区間でも全試行の最大偏差でもない。最終比較の最小・最大は次表と生データに保存した。
- 整数演算・LOOPは先行比較、残る15項目は後続比較。各項目・系列で独立した計測プロセスを起動した。ビルド・テスト・レビュー・Callgrindは時間測定と同時実行していない。
- 校正pass 2の終了コード75は、次の反復数増加の前に主要項目を確認するための意図したチェックポイント。pass 2の提案反復数では測定していない。実測条件は採用したA/Aと最終各項目に記録している。

計測器のWindows対応とプロトコルのテスト各3件（Windows／WSL）はレビュー対応記録に示した。APIの出典は同記録のMicrosoft公式GitHub資料を参照する。
