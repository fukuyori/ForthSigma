# Windows ETW解析レビューへの対応

2026-11-16。[レビュー](VM_WINDOWS_ETW_CLAUDE_REVIEW.md)にHigh/Blockerはなかった。以下を補正して集計を再実行した。実ETW再取得と速度比較は行っていない。

| 指摘 | 対応 |
| --- | --- |
| M1 API粒度が幅に含まれない | APIの全12値が15.625ms刻みと明記。ETW側の丸め・照会bracket幅にAPI量子化は含まない。行2の差は1刻み未満と説明 |
| M2 clock確認の範囲 | 解析環境での実装確認と、取得時clock情報の未記録を分けて明記。UTC近似窓との16〜33us一致は間接確認として説明 |
| L3 parser照合許容 | 最大13usは今回の実測値。コードが13usを保証したとは記載していない。slice単位の丸めを許容する既存検査を維持 |
| L4 DPC行対応 | QPC解析側でもtimestamp/CPUとstart差最大1usを再検査するassertを追加 |
| L5 警告時刻 | 警告が全対象の最終switch-outより後とassertで確認。warningのschema情報は実tool出力からの転記とし、検出器一般化はしていない |
| L6 API列名 | 区間表はprocess CPUと明記。primaryとの差は6回とも0と併記 |
| L7 時系列 | UTC近似・全生存期間の段階と、続けて実施した生QPC区間照合を区別。測定JSONへQPC解析も格納 |

最終補正後、全723,767件のraw/xperf対応、全CPU old/new連鎖、対象sliceとDPC行の対応、全6区間集計が通過した。表の主要数値と残差は変わらない。最終補正後の再々レビューは行っていない。

#861の取得・停止・照合と親#855の診断範囲を完了した。原因の特定や速度改善の採用を完了したという意味ではない。次は#862（auto、121配下、855後）で、同一区間に残るAPI/ETW残差の対照診断を設計する。CPU0と別logical CPUの負担、観測方式、取得時clock情報を比較できる条件を固定し、主指標・OS設定・採用条件は維持する。
