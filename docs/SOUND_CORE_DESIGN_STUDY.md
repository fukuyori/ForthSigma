# 本体のサウンド機能の設計検討（1184）

2026-11-21、基点main b5e25e4。これは検討の記録で、実装はしていない。名前はすべて仮。

## 1. 方針（利用者の指示、2026-11-21）

- 本体は機種を持たない。語の名前にも値にも機種名を入れない。
- 本体には、単独でも使いやすい語を用意する。
- 機種らしさは、エフェクトとしてライブラリで用意する。
- `examples/`はデモの置き場所で、ライブラリを置かない。
- ライブラリは`include/`フォルダを作って、そこへ入れる。

## 2. 構成

| 置き場所 | 持つもの |
| --- | --- |
| 本体（`AUDIO`語彙） | 演奏、音色、効果音、曲、PCM、出力。単位は機種によらない（Hz、ミリ秒、割合は0〜65535、dB） |
| エフェクトのライブラリ（`include/`） | 機種らしさを本体の音に加える設定の組。本体の汎用の語だけで書く |
| エミュレータ向けのモデル（`include/`） | レジスタの書込みと時刻の再現（5節） |
| デモ（`examples/`） | ライブラリと本体を使って鳴らす例 |

エフェクトを使わなくても、本体だけで曲と効果音が書ける。エフェクトを読み込むと、同じ曲がその機種らしい音になる。

## 3. 本体の語

### 3.1 標準の音（上位互換）

標準の音は、対象機種のどれより制限がゆるく、どの機種の機能も含む上位互換にする（利用者の決定、2026-11-21）。機種の制限（段階、声の数、解像度など）は、エフェクトが加える（3.5節）。

| 項目 | 標準の音 | 含める機能の出どころ |
| --- | --- | --- |
| 声の数 | 16（3.6節） | 全機種（最大はSNESの8） |
| 波形 | 矩形・パルス（幅は自由）、三角、のこぎり、波形の組合せ | PSG、NES、SID |
| ノイズ | LFSRの長さと帰還の位置、周期を設定できる。短い周期のノイズも出せる | PSG/YM、NES、SID |
| 波形表 | 長さとビット数を自由にする | SCC、CHIP-8のXO-CHIP（1ビット128標本） |
| 標本 | 8・16ビット、ループ、圧縮形式（1ビット差分、BRR）の展開 | Paula、STE、NESのDMC、SNES |
| 音とノイズの混合 | 1声で音とノイズを同時に鳴らせる | PSG |
| エンベロープ | ADSR、繰り返す形（PSGの形を含む）、直線・指数の増減、声ごとに持つ | SID、PSG、NES、SNESのGAIN |
| 音程の変化 | スイープ（範囲を外れたら消音する形を含む）、ポルタメント、ビブラート、別の声による音程の変調 | NES、SNES、Paula |
| 音量 | 段階なし。声ごとに左右を別に指定（逆相を含む）。別の声による音量の変調 | SNES、Paula |
| 変調の源 | 自分は出力せず、変調の源にだけ使う声 | SIDの3声目の消音、Paulaのattach |
| 音の始まりと長さ | 音の開始で位相を戻すかを選べる。決めた長さで自動的に止める | NESのパルスと長さ・linearカウンター、SIDのGATEとTEST |
| フィルター | 声ごとにローパス・バンドパス・ハイパス・ノッチ、共振あり。通す声を選べる | SID（SIDは全体で1つ） |
| 全体の効果 | エコー（遅延、帰還、FIR）、固定のローパス・ハイパス、低音・高音の調整 | SNES、Paula、NES、STE |
| 声の状態の読取り | 発振の値、エンベロープの値、標本の再生位置、鳴り終わり・ループの通知 | SIDのOSC3とENV3、PaulaとNES DMCの割込み、NESの長さの状態 |

- ZX Spectrumのbeeper、Apple IIのspeaker（1ビットの出力を任意の時刻で切り替える）

#### 3.3.1 追加する音色の語（案、2026-11-21）

3.1節の機能のうち、上の表にないものの語。すべて`INSTRUMENT`で選んだ音色に設定し、その音色で始まる音から効く。引数はすべて整数とする（`-Dfloat=false`の構成でも使えるようにするため）。

単位：周波数はHz、時間はミリ秒、割合は0〜65535、音程の差はセント（半音の1/100）、左右は-65535〜65535（負は逆相）。割合を0〜65535とするのは、どの機種より細かくするため（利用者の決定、2026-11-21。SNESのエンベロープは11ビット）。

| --- | --- | --- | --- |

| ビブラート | `VIBRATO` | `( cents hz delay-ms -- )` | 深さ、速さ、始まるまでの時間。0 0 0でなし |
| 音程の変調 | `PITCH-MOD` | `( voice cents -- )` | 源の声と、その出力で音程を変える深さ。声0でなし |
| 音量の変調 | `VOLUME-MOD` | `( voice ratio -- )` | 源の声と、その出力で音量を変える深さ。声0でなし |

### 3.5 エフェクトの受け口

本体は、機種らしさを作る汎用の加工を音色ごと・全体に持つ。ライブラリはこれを設定するだけで、合成は本体のZigで行う（音のスレッドで動き、Forthを呼ばない）。

### 3.6 声の数と声のまとめ方（検討、2026-11-21）

標準の音は、対象機種より制限のゆるい上位互換とする（利用者の指示）。

今の声は3つの仕組みに分かれている（`src/core/sound_engine.zig`）。

| 仕組み | 声の数 | 持てる機能 |
| --- | --- | --- |
| `PLAY`（MML） | 8（`max_voices`） | 音色のすべて |
| `SFX` | 4（`sfx_voices`）。新しい効果音が最も古いものを置き換える | 標本の再生だけ |
| MOD | 4（`sound_mod.zig`、ProTrackerの4チャンネル） | 標本の再生とMODの効果 |

対象機種の声の数は、AY/YM 3、SID 3、Paula 4、SCC 5、NES 5（DMCを含む）、SNES 8。今の`CHIPS`でMSXとSCCを合わせると8になる。

**決定：1つの声の集まりにまとめ、16声にする（利用者の決定、2026-11-21）**

- `PLAY`、`SFX`、MODが同じ声の集まりから声を使う。効果音も音色のすべて（エンベロープ、フィルターなど）を使え、MODの声も同じ標本の再生と混合を通る。
- 16は、今の3つの仕組みを同時に最大まで使った数（8+4+4）である。最大の8声の曲に、効果音とMODを重ねても足りる。
- 声の割当ての規則を決める必要がある。案：`PLAY`は声1から、MODは決めた4声、`SFX`は残りの声を使い、空きがなければ最も古い効果音を置き換える（今の`SFX`と同じ）。曲の声は効果音に取られない。
- **割当ての決定（利用者の決定、2026-11-21）**：固定で分ける。`PLAY`は声1〜8（`PLAYS`は最大8声のまま）、`SFX`は声9〜12（新しい効果音が最も古いものを置き換える）、MODは声13〜16。曲・効果音・MODは互いに声を取り合わない。`PLAY`の声は8のままなので、`sounding`は8ビットのままでよい。
- **MODのフィルターの決定（利用者の決定、2026-11-21）**：Amigaのフィルター（A500の固定のローパスとLEDフィルター）は本体から外す。MODの効果`E0x`は、MODの4声にかける汎用のフィルターを入り切りする指示にし、種類と周波数は新しい語（`MOD-FILTER ( mode hz -- )`、既定はなし）で設定する。Amigaらしい値は1190のAmigaのライブラリが設定する。左右の振分け（1・4声は左、2・3声は右）と、周期から周波数への換算（PALの時計）は、MODの形式の決まりとして本体に残す。
- 音のスレッドではメモリーを確保しないので、声の数はビルド時に決める固定の数にする。

**変更が要る箇所**

- 演奏中の声を表す`sounding`は8ビット（`u8`）なので、16ビットにする。`PLAY?`と`PLAYS`の声の範囲も変わる。
- 声ごとの待ち行列（32項目）が16個になる。
- `SFX`とMODを、今の専用の再生器から声の集まりへ移す。

**未確認**

- 16声の合成の負荷は測っていない。測る場合は、利用者に他のアプリを止めてもらってから行う。
- 32声のように更に増やす必要（チャンネルの多い曲の形式など）は、今の対象にない。必要になったらビルド時の数を変える。

### 3.8 声の状態の読取り（案、2026-11-21）

音のスレッドが書く値を、Forthから読む。音のスレッドはForthを呼ばないので、通知は回数として持ち、読む側が前回との差で知る。

| 語 | スタック効果 | 内容 |
| --- | --- | --- |
| `VOICE-OSC` | `( voice -- n )` | 発振の今の値（-32768〜32767） |
| `VOICE-ENV` | `( voice -- ratio )` | エンベロープの今の値 |
| `VOICE-POS` | `( voice -- n )` | 標本の再生位置（標本の番号）。標本でなければ-1 |
| `VOICE-ENDS` | `( voice -- n )` | 標本の終わりとループの回数（増え続ける） |
| `VOICE-ON?` | `( voice -- flag )` | 鳴っているか |

声の番号は1〜16。値は音のスレッドの区切りごとに更新するので、区切りの中の時刻は持たない。

### 3.9 この案で決めてほしい点

1. 単位：決定済み。割合は0〜65535（利用者の決定、2026-11-21）。
2. `NOISE-MIX`のゲート：決定済み。標準に含める（利用者の決定、2026-11-21）。
3. エンベロープ：決定済み。区切りの並び（`ENVELOPE`）とし、`ADSR`はその簡単な書き方とする（利用者の決定、2026-11-21）。
4. 変調の源：決定済み。変調の種類ごとに源の声を指定する（`RING` `SYNC` `PITCH-MOD` `VOLUME-MOD`が源の声を取る。利用者の決定、2026-11-21）。
5. MMLの命令：決定済み。音色の設定は音色の語で行い、`@n`で切り替える（利用者の決定、2026-11-21）。音符ごとに変えたい左右・ビブラートなどの6つの命令は、1186で足すと決めた（[MMLの命令の検討](MML_COMMANDS_STUDY.md)の5節、利用者の決定、2026-11-21）。実装は1189の後（tque 1195）。
7. MMLの`V`：決定済み。`V15`を最大とし、1段ごとに3 dB下げる（`V1`は-42 dB）。`V0`は無音（利用者の決定、2026-11-21）。PSGの段の表は1190のエフェクトで加える。
8. MMLの`S`と`M`：決定済み。MSX BASICのMMLの定義として時間に直し、`ENVELOPE`の区切りで鳴らす。`M`の1段は256×`M`÷1789773秒、1回の上りまたは下りは16段。`S`の8つの形は区切り（直線、繰り返し、留まる）で表す（利用者の決定、2026-11-21）。PSGの段の再現は1190のエフェクトで加える。
6. 語の名前：決定済み。案の名前を基本とし、サンプルと衝突する名前と一般的すぎる名前だけ長くする（`TONE`→`PLAY-TONE`、`SWEEP`→`PITCH-SWEEP`、`SWEEP-LIMIT`→`PITCH-SWEEP-LIMIT`、`PAN`→`VOICE-PAN`、`EQ`→`TONE-CONTROL`。利用者の決定、2026-11-21）。`ALSO AUDIO`の語は利用者の同名の語より先に見つかるため。エコーの語は、`ECHO`が既存の語（`EMIT`の別名、`src/forth.zig`）なので`REVERB`とした。

### 3.10 実装（1196・1197・1199、2026-11-21）

声の集まり（1196）、音色の語（1197）、機種の語を外すこと（1199）は、音色の型を入れ替えると同時に変わるので、まとめて実装した。

- 合成は`src/core/sound_voice.zig`の16声で行い、`src/core/sound_engine.zig`は声1〜8を`PLAY`、9〜12を`SFX`、13〜16をMODに使う。機種の設定（`sound_psg` `sound_nes` `sound_c64` `sound_scc` `sound_amiga` `sound_parts`）は削除した。
- `SND-SOUND` `SND-CHIP` `SND-CHIPS` `SND-STYLE` `SND-AMIGA-FILTER`は、保存した辞書（イメージ）の語の並びを変えないために名前と位置を残し、呼ぶと-21を返す。`SOUND`、`MSX-SOUND`などの機種名の語、`CHIPS`、`STYLE`、定数`MSX`〜`AMIGA`、`SCC-WAVE`、`AMIGA-FILTER`は音のライブラリから外した。1190でinclude/のライブラリが定義する。
- 3.3.1節の語は1つの基本語`SND-TONE ( ... key -- )`で受け、音のライブラリが語ごとの番号で定義する。`PLAY-TONE`と`MOD-FILTER`は基本語を足した。新しい基本語は、既存の語の番号を変えないように最後に足した。
- 時間の引数は0〜3600000ミリ秒（1時間）。192 kHzでも声の標本数の数え方に収まる範囲である。
- `PLAY-TONE`は`SFX`の声（9〜12）で鳴らす。`WAVETABLE ( addr n -- )`は、n個（1〜65536）のセルの符号付き16ビット値をプールへ写す。ノイズのLFSRは、音の1周期に16回進む。
- MODの再生器は、行と効果の処理と4チャンネルの標本の再生を今のまま持ち、各チャンネルの値を声13〜16へ渡す。声の集まりの左右・フィルター・混合を通る。
- `S` `M`の音は`V`によらず最大の音量で鳴る（今のPSGと同じ）。
- 例（`examples/`）と`try/`のプログラムで、外した語や意味の変わった語を使うものは、1192で書き換えるまで動かない。
- 全体の効果と声の状態（1198）は`src/core/sound_master.zig`と基本語`SND-GLOBAL` `SND-VOICE`で実装した。`REVERB`の遅れは0〜341 ms（48 kHzで16384フレーム）、帰還は±4で飽和させる。`REVERB-FIR`は0〜8個の係数で、帰還にだけかける（最初の響きは遅れた音そのもの）。`MASTER-FILTER`はQ 0.707の2極、`TONE-CONTROL`は約200 Hzと約4 kHzを境に1極で分けて増減する。全体の設定は`BEEP`と停止のあとも残る。声の状態は音のスレッドが出力の区切りごとに書く（`VOICE-POS`は32ビットで返す）。
- 16声の負荷（1201）：`tests/scripts/measure-standard-sound-load.py`で、エンジン単体が48 kHzステレオ10秒を合成する時間を、Windows 11（AMD64 Family 25 Model 97）で測った（利用者が実行、2026-11-21、[docs/measurements/2026-11-21-standard-sound-load.json](measurements/2026-11-21-standard-sound-load.json)）。7回の中央値で、素の矩形波16声は1フレーム112.7 ns（実時間の184.9倍）、全部の機能を使う16声と全体の効果は640.9 ns（32.5倍）、波形表と標本の16声は137.4 ns（151.7倍）である。音の装置とForthのプログラムの時間は含まない。Linux・Macは測っていない。
- 実聴（1201）：`tests/scripts/listen-standard-sound.py`の21のケースを、利用者が聞いて問題がないと報告した（2026-11-21）。
- 矩形波16声を`V12`で同時に鳴らすと、出力が全振幅を超えて切れる。実聴（ケース21、8声を`V15`）で割れは気にならないので、混合の利得もリミッターも変えない（利用者の決定、2026-11-21、1202）。

## 4. エフェクトのライブラリ

- 1つのファイルが1つの機種らしさを表し、3.5節の語で加工を設定する語を定義する（例：`NES-LIKE ( -- )`）。機種名はライブラリの語にだけ現れる。
- 今の`MSX-SOUND` `ST-SOUND` `NES-SOUND` `C64-SOUND` `SCC-SOUND` `AMIGA-SOUND`、`CHIPS`、`STYLE`、定数`MSX`〜`AMIGA`、`AMIGA-FILTER`は、本体から外してライブラリの語にする。
- `SOUND ( reg value -- )`はMSXらしさのライブラリへ移す。ライブラリは、PSGのレジスタの書込みを標準の音の設定（`NOISE-MIX`のゲート、`ENVELOPE`、`NOISE-LFSR`、音程と音量の段階のエフェクト）に置き換えて鳴らすので、音のスレッドで鳴り続ける（利用者の決定、2026-11-21）。置き換えの正しさは、今の試験の波形と比べて確かめる（未確認）。
- `include/`のライブラリを読み込めば、機種ごとのサウンドが使える。本体の語は変わらない。
- 機種の追加は、ライブラリのファイルを足すだけで、本体を変えない。エフェクトとして足せるのは、3.5節の加工の組合せで表せる音に限る。表せない音（FM合成など、本体に部品のないもの）は、本体に機種によらない部品として足す（利用者の決定、2026-11-21）。部品の名前と単位にも機種名を入れない。
- ライブラリは`include/`に置き、ZIPとインストーラーの両方で、`sigma.exe`と同じフォルダーの下に`include\`として入れる（利用者の決定、2026-11-21）。今のインストーラーは`examples/`を入れないが、ライブラリは語を使うのに必要なので入れる。
- 起動時に`FPATH`の既定値を「作業ディレクトリ、実行ファイルのある場所の`include/`」とし、どこから起動しても`REQUIRE msx-sound.fs`の形で読み込めるようにする（利用者の決定、2026-11-21）。今の「起動時・環境変数からの検索パスは設定しない」決まり（`docs/USER_MANUAL.ja.md`）を変える。
- 実装で決める点：各OSで実行ファイルの場所を得る方法、`SAVE`・`SAVESYS`で保存した辞書が持つ`FPATH`と起動時の既定値のどちらを使うか、`-Dfiles=false`の構成での扱い。gforthが同じ形で検索パスを持つかはWSLで確認していない（未確認）。
- `include\`が実行ファイルと同じフォルダーにあれば、実行ファイルの場所と起動した場所によらず読み込める。次の場合は見つからないので、実装で扱いを決める。
  - 実行ファイルだけを別の場所へ移したとき：`include\`も一緒に移すか、`FPATH PATH+`で場所を足す。
  - 開発中のビルド：実行ファイルは`zig-out/bin/`、`include/`はリポジトリの直下にある。リポジトリの直下を作業ディレクトリにすれば見つかる。ビルドで`include/`を`zig-out/bin/`へ写すかを決める。
  - `SAVESYS`で作ったアプリ：アプリの実行ファイルの隣にも`include\`が要る。`SAVESYS`の前にライブラリを読み込めば、語は辞書に保存されるので実行時には要らない。
  - シンボリックリンクから起動したとき（Linux、macOS）：実行ファイルの場所をリンクの場所とするか、リンク先の場所とするかは、OSごとの取得方法で変わる。どちらにするかを決め、各OSで確かめる（未確認）。
- 1191で次のように実装した（2026-11-21）。
  - 起動時の`FPATH`は`~+`、実行ファイルのあるフォルダーの`include`の順。実行ファイルの場所は`SAVESYS`が使うものと同じ取得方法で、LinuxとmacOSではシンボリックリンクのリンク先になる。Windowsでリンクから起動したときと、LinuxとmacOSでの動作は確かめていない（未確認）。
  - `SAVESYS`で作った実行ファイルは、イメージに保存した`FPATH`を使い、既定値で上書きしない。`-Dfiles=false`の構成では設定しない。
  - `zig build`は`include/*.fs`を`zig-out/bin/include`へ写す。ZIP（Windows、各OS、CI）とインストーラーは、浮動小数点の語を除いた版も含めて`include\`を入れる。
  - `include/`のライブラリ同士は`S" ./名前.fs" REQUIRED`（読込み中のファイルからの相対）で読み込む。`FPATH`が空のとき（`FPATH CLEAR-PATH`の後）は`./`がカレントディレクトリ基準になるので、ライブラリを読むには`FPATH`の設定が要る。

## 5. エミュレータ向けのレジスタ単位のモデル

`examples/`のNES・SID・Paula・YM・CHIP-8・ZX・SNESのモデルは、エフェクトではなく、レジスタの書込みと時刻を再現するライブラリである。出力はPCMで本体へ渡す。これも`examples/`から`include/`へ移し、デモ用の`*-DEMO-SETUP`と`*-play.fs`だけを`examples/`に残す。

各モデルの語の名前と形をそろえる（利用者の決定、2026-11-21）。どのモデルも`*-RESET` `*-WRITE ( value target tick -- )` `*-EVENT! ( value target tick -- )` `*-READ ( target tick -- value )` `*-RUN ( clocks -- )` `*-RENDER ( addr frames -- )`を持ち、書く対象の種類（ZXのポートとAY、SNESのレジスタとARAMなど）は`target`の番号に割り当てる。接頭辞（機種名）は残す。ZXのモデルの番号のように初期化に要る設定は、別の語で先に設定する。機種を選んで共通の語で操作する層（記述子とハンドル）は、必要になったときに別に検討する。

1187で実装した（2026-11-21）。足した語は`NA-READ` `YM-REG@`（旧`YM-READ`）`C8-EVENT!` `C8-READ` `ZX-MODEL!` `ZX-EVENT!` `ZX-READ` `SD-EVENT!` `SD-READ`で、`YM-WRITE` `YM-EVENT!` `YM-READ`は`target`（0〜15はレジスタ、16・17は外部pin、18はselect、19はdata）を取る形に変えた。`ZX-RESET`は引数を取らず、機種は`ZX-MODEL!`で先に設定する。機種固有の語（`ZX-OUT` `SD-REG!`など）は残す。検査は`tests/scripts/verify-model-common-words.py`。
