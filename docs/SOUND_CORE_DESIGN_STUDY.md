# 本体のサウンド機能の設計検討（1184）

2026-11-21、基点main b5e25e4。これは検討の記録で、実装はしていない。名前はすべて仮。

## 1. 方針（利用者の指示、2026-11-21）

- 本体は機種を持たない。語の名前にも値にも機種名を入れない。
- 本体には、単独でも使いやすい語を用意する。
- 機種らしさは、エフェクトとしてライブラリで用意する。
- `examples/`はデモの置き場所で、ライブラリを置かない。
- ライブラリは`include/`フォルダを作って、そこへ入れる。

## 2. 構成

| 置き場所 | 持つもの |
| --- | --- |
| 本体（`AUDIO`語彙） | 演奏、音色、効果音、曲、PCM、出力。単位は機種によらない（Hz、ミリ秒、割合は0〜65535、dB） |
| エフェクトのライブラリ（`include/`） | 機種らしさを本体の音に加える設定の組。本体の汎用の語だけで書く |
| エミュレータ向けのモデル（`include/`） | レジスタの書込みと時刻の再現（5節） |
| デモ（`examples/`） | ライブラリと本体を使って鳴らす例 |

エフェクトを使わなくても、本体だけで曲と効果音が書ける。エフェクトを読み込むと、同じ曲がその機種らしい音になる。

## 3. 本体の語

### 3.1 標準の音（上位互換）

標準の音は、対象機種のどれより制限がゆるく、どの機種の機能も含む上位互換にする（利用者の決定、2026-11-21）。機種の制限（段階、声の数、解像度など）は、エフェクトが加える（3.5節）。

| 項目 | 標準の音 | 含める機能の出どころ |
| --- | --- | --- |
| 声の数 | 16（3.6節） | 全機種（最大はSNESの8） |
| 波形 | 矩形・パルス（幅は自由）、三角、のこぎり。SIDの波形の組合せは波形表で鳴らす（11節） | PSG、NES、SID |
| ノイズ | LFSRの長さと帰還の位置、周期を設定できる。短い周期のノイズも出せる | PSG/YM、NES、SID |
| 波形表 | 長さとビット数を自由にする | SCC、CHIP-8のXO-CHIP（1ビット128標本） |
| 標本 | 8・16ビット、ループ。圧縮形式（1ビット差分、BRR）の展開は1188の部品で扱い、それまではForthで展開して`SAMPLE`に渡す（11節） | Paula、STE、NESのDMC、SNES |
| 音とノイズの混合 | 1声で音とノイズを同時に鳴らせる | PSG |
| エンベロープ | ADSR、繰り返す形（PSGの形を含む）、直線・指数の増減、声ごとに持つ | SID、PSG、NES、SNESのGAIN |
| 音程の変化 | スイープ（範囲を外れたら消音する形を含む）、ポルタメント、ビブラート、別の声による音程の変調 | NES、SNES、Paula |
| 音量 | 段階なし。声ごとに左右を別に指定（逆相を含む）。別の声による音量の変調 | SNES、Paula |
| 変調の源 | 自分は出力せず、変調の源にだけ使う声 | SIDの3声目の消音、Paulaのattach |
| 音の始まりと長さ | 音の開始で位相を戻すかを選べる。決めた長さで自動的に止める | NESのパルスと長さ・linearカウンター、SIDのGATEとTEST |
| フィルター | 声ごとにローパス・バンドパス・ハイパス・ノッチ、共振あり。通す声を選べる | SID（SIDは全体で1つ） |
| 全体の効果 | エコー（遅延、帰還、FIR）、固定のローパス・ハイパス、低音・高音の調整 | SNES、Paula、NES、STE |
| 声の状態の読取り | 発振の値、エンベロープの値、標本の再生位置、鳴り終わり・ループの通知 | SIDのOSC3とENV3、PaulaとNES DMCの割込み、NESの長さの状態 |
| 出力 | 48 kHz、16ビット、ステレオ | 今と同じ |

音のスレッドはForthを呼ばないので、鳴り終わりなどの通知は、Forthから読む状態として持つ。

次の音は、決まった波形の声ではなく、時刻を指定した出力の切替えや音量・DACの書換えで作る。標準の音ではPCM（3.4節）で扱う。

- ZX Spectrumのbeeper、Apple IIのspeaker（1ビットの出力を任意の時刻で切り替える）

#### 3.3.1 追加する音色の語（案、2026-11-21）

| ビブラート | `VIBRATO` | `( cents hz delay-ms -- )` | 深さ、速さ、始まるまでの時間。0 0 0でなし |

### 3.5 エフェクトの受け口

本体は、機種らしさを作る汎用の加工を音色ごと・全体に持つ。ライブラリはこれを設定するだけで、合成は本体のZigで行う（音のスレッドで動き、Forthを呼ばない）。

| 加工 | 内容 | 例（ライブラリでの使い方） |
| --- | --- | --- |
| 音程の段階 | 周波数を「時計÷整数」に丸める。時計は整数でない値（有理数）も扱う | 時計1.79 MHz、周期11ビット、ZX 128KのAYのCPU/2 |
| 音程の範囲 | 周期の最小・最大 | Paulaの周期の下限 |
| 音量の段階 | 音量とエンベロープを段数に丸める、段の表 | 16段・32段、対数の表、3 dB刻みの表 |
| 波形の解像度 | 波形表の長さとビット数 | 32標本、4ビット |
| ノイズの作り方 | LFSRの長さと帰還の位置 | 15ビット |
| 出力の解像度 | 出力のビット数とrate | 8ビット、28 kHz |
| フィルター | 固定のローパスなど | 4.4 kHz |
| 左右 | 声ごとの振分け | 左・右・右・左 |
| 声の数 | 使える声を減らす | 3声 |
| ミキサーの特性 | 声を混ぜるときの非直線の式や表 | NESの式、PSGの対数の表 |
| 標本の補間 | なし、線形、決まった係数の補間 | 補間なし、SNESのガウス補間 |

本体に置く語は、削除した機種の設定（`sound_psg.zig`ほか、`e90b6f6`の時点）が使っていた加工から、次の8語に決めた（利用者の決定、2026-11-21、1190）。clockは1/1000 Hz単位で、整数でない時計（ZX 128KのCPU/2など）も表す。

| 語 | 範囲 | 内容 |
| --- | --- | --- |
| `PITCH-PERIOD ( clock divider offset min max -- )` | 音色 | 周波数を「clock÷(divider×(周期＋offset))」に丸め、周期をmin〜maxに限る（min＋offsetは1以上）。標本の音色では再生のrateを丸める。clock 0で丸めない |
| `PITCH-STEP ( clock bits -- )` | 音色 | 周波数を「clock×n÷2^bits」に丸める（SIDの周波数レジスタの形） |
| `VOLUME-STEPS ( addr n -- )` | 音色 | 音量とエンベロープを、昇順のn段（0〜128）の表（0〜65535）のうち、デシベルで最も近い段に丸める。0段で丸めない |
| `DUTY-STEPS ( n -- )` | 音色 | デューティーをn段に丸める |
| `INTERPOLATION ( mode -- )` | 音色 | 波形表と標本の読み方：0は補間なし（今の音、既定）、1は線形 |
| `VOICE-LIMIT ( n -- )` | 全体 | `PLAY`の声1〜nだけを鳴らす（1〜8、既定8） |
| `MIXER ( mode -- )` | 全体 | 0は直線、1は声1〜5をNESの式で混ぜる（声1・2を矩形波、声3を三角波、声4をノイズ、声5をDMCの組とし（声5は1239で追加）、声の左右・フィルター・リバーブへ送る量は使わない） |
| `OUTPUT-BITS ( bits rate -- )` | 全体 | 最後の出力（16ビットの全振幅）をbitsビットの符号付きの段（0で切る）に丸め、rate Hz（0で出力のrate）ごとに更新する |

左右の振分け、固定のフィルター、ノイズのLFSRは、`VOICE-PAN`（声ごと、1239）、`INSTRUMENT-PAN`（音色ごと） `FILTER` `MASTER-FILTER` `NOISE-LFSR`を使う。

MMLの`V`を機種の音量の段に直接対応させるため、`V-STEPS ( addr n -- )`も足した（利用者の決定、2026-11-21、1206）。設定した音色では、`V0`〜`V15`がaddrの16個の値（0〜65535）をそのまま選ぶ。nは16か0（なし、1段3 dB）。`S` `M`のエンベロープには使わない。

`SOUND`（PSGのレジスタの書込み）を表すため、次の2語も本体に足した（利用者の決定、2026-11-21、1190）。

- `VOICE-HOLD ( instrument hz volume voice -- )`：声1〜16で、音色0〜63をhz（1/1000 Hz）と音量0〜65535で次の指示まで鳴らし続ける。鳴っている声に同じ音色を指定すると、位相とエンベロープを続けたまま、音程と音量を変え、音色の今の設定（波形、デューティー、フィルターなど。エンベロープを除く）を取り込む（1239、11節）。別の音色では最初から鳴らす。エンベロープが0で終わっても声を止めず、0のまま保つ。音量0でその場で止める。`PLAY`・`SFX`・MOD・停止は、それぞれの声を使うと取り戻す。
- `NOISE-RATE ( hz -- )`：音色のノイズが1秒に進む回数（1/1000 Hz）。0で今までどおり音の1周期に16回。PSGの共有のノイズ周期を表す。

### 3.6 声の数と声のまとめ方（検討、2026-11-21）

標準の音は、対象機種より制限のゆるい上位互換とする（利用者の指示）。

今の声は3つの仕組みに分かれている（`src/core/sound_engine.zig`）。

| 仕組み | 声の数 | 持てる機能 |
| --- | --- | --- |
| `PLAY`（MML） | 8（`max_voices`） | 音色のすべて |
| `SFX` | 4（`sfx_voices`）。新しい効果音が最も古いものを置き換える | 標本の再生だけ |
| MOD | 4（`sound_mod.zig`、ProTrackerの4チャンネル） | 標本の再生とMODの効果 |

対象機種の声の数は、AY/YM 3、SID 3、Paula 4、SCC 5、NES 5（DMCを含む）、SNES 8。今の`CHIPS`でMSXとSCCを合わせると8になる。

**決定：1つの声の集まりにまとめ、16声にする（利用者の決定、2026-11-21）**

- `PLAY`、`SFX`、MODが同じ声の集まりから声を使う。効果音も音色のすべて（エンベロープ、フィルターなど）を使え、MODの声も同じ標本の再生と混合を通る。
- 16は、今の3つの仕組みを同時に最大まで使った数（8+4+4）である。最大の8声の曲に、効果音とMODを重ねても足りる。
- 声の割当ての規則を決める必要がある。案：`PLAY`は声1から、MODは決めた4声、`SFX`は残りの声を使い、空きがなければ最も古い効果音を置き換える（今の`SFX`と同じ）。曲の声は効果音に取られない。
- **割当ての決定（利用者の決定、2026-11-21）**：固定で分ける。`PLAY`は声1〜8（`PLAYS`は最大8声のまま）、`SFX`は声9〜12（新しい効果音が最も古いものを置き換える）、MODは声13〜16。曲・効果音・MODは互いに声を取り合わない。`PLAY`の声は8のままなので、`sounding`は8ビットのままでよい。
- **MODのフィルターの決定（利用者の決定、2026-11-21）**：Amigaのフィルター（A500の固定のローパスとLEDフィルター）は本体から外す。MODの効果`E0x`は、MODの4声にかける汎用のフィルターを入り切りする指示にし、種類と周波数は新しい語（`MOD-FILTER ( mode hz -- )`、既定はなし）で設定する。Amigaらしい値は1190のAmigaのライブラリが設定する。左右の振分け（1・4声は左、2・3声は右）と、周期から周波数への換算（PALの時計）は、MODの形式の決まりとして本体に残す。
- 音のスレッドではメモリーを確保しないので、声の数はビルド時に決める固定の数にする。

**変更が要る箇所**

- 演奏中の声を表す`sounding`は8ビット（`u8`）なので、16ビットにする。`PLAY?`と`PLAYS`の声の範囲も変わる。
- 声ごとの待ち行列（32項目）が16個になる。
- `SFX`とMODを、今の専用の再生器から声の集まりへ移す。

**未確認**

- 16声の合成の負荷は測っていない。測る場合は、利用者に他のアプリを止めてもらってから行う。
- 32声のように更に増やす必要（チャンネルの多い曲の形式など）は、今の対象にない。必要になったらビルド時の数を変える。

### 3.7 全体の効果（案、2026-11-21）

すべての声を混ぜた後にかける。音色ではなく全体の設定で、すぐ効く。

| 語 | スタック効果 | 内容 |
| --- | --- | --- |
| `REVERB` | `( delay-ms feedback volume -- )` | エコーの遅れ、帰還（-65535〜65535）、出力の量（0〜65535）。量0でエコーなし |
| `REVERB-FIR` | `( addr n -- )` | エコーの帰還にかける係数の並び（符号付きの整数、128を1とする）。n=0で係数なし |

### 3.8 声の状態の読取り（案、2026-11-21）

音のスレッドが書く値を、Forthから読む。音のスレッドはForthを呼ばないので、通知は回数として持ち、読む側が前回との差で知る。

## 4. エフェクトのライブラリ

- 1つのファイルが1つの機種らしさを表し、3.5節の語で加工を設定する語を定義する（例：`NES-LIKE ( -- )`）。機種名はライブラリの語にだけ現れる。

## 5. エミュレータ向けのレジスタ単位のモデル

`examples/`のNES・SID・Paula・YM・CHIP-8・ZX・SNESのモデルは、エフェクトではなく、レジスタの書込みと時刻を再現するライブラリである。出力はPCMで本体へ渡す。これも`examples/`から`include/`へ移し、デモ用の`*-DEMO-SETUP`と`*-play.fs`だけを`examples/`に残す。

各モデルの語の名前と形をそろえる（利用者の決定、2026-11-21）。どのモデルも`*-RESET` `*-WRITE ( value target tick -- )` `*-EVENT! ( value target tick -- )` `*-READ ( target tick -- value )` `*-RUN ( clocks -- )` `*-RENDER ( addr frames -- )`を持ち、書く対象の種類（ZXのポートとAY、SNESのレジスタとARAMなど）は`target`の番号に割り当てる。接頭辞（機種名）は残す。ZXのモデルの番号のように初期化に要る設定は、別の語で先に設定する。機種を選んで共通の語で操作する層（記述子とハンドル）は、必要になったときに別に検討する。

1187で実装した（2026-11-21）。足した語は`NA-READ` `YM-REG@`（旧`YM-READ`）`C8-EVENT!` `C8-READ` `ZX-MODEL!` `ZX-EVENT!` `ZX-READ` `SD-EVENT!` `SD-READ`で、`YM-WRITE` `YM-EVENT!` `YM-READ`は`target`（0〜15はレジスタ、16・17は外部pin、18はselect、19はdata）を取る形に変えた。`ZX-RESET`は引数を取らず、機種は`ZX-MODEL!`で先に設定する。機種固有の語（`ZX-OUT` `SD-REG!`など）は残す。検査は`tests/scripts/verify-model-common-words.py`。

## 10. 音符の始まりのエンベロープ（2026-11-21）

- 利用者が`examples/pastoral.fs`を聞いて、音が濁っていること、音の出始めのノイズが気になることを報告した（Windows 11、2026-11-21）。
- 再設計の前（`b5e25e4`）と今の両方で、試験用のホストを使い、音を出さずに`pastoral.fs`を合成して波形を比べた。
  - 単音4つと4声の和音2つの伸ばした部分は、音量・音程・倍音が前とほぼ同じで、上限で切れた標本はなかった。
  - 曲の冒頭15秒では、音符が始まる瞬間に音量が急に落ちる箇所（4ミリ秒の間に25%未満へ落ちる箇所、右側）が、前は1か所、今は26か所あった。
- 原因：`src/core/sound_voice.zig`の`startEnvelope`が、音符を始めるたびにエンベロープの値を0に戻していた。前の実装（`sound_parts.zig`の`Adsr.start`）は、アタックを前の音符が残した音量から続けていた。
- 対応：鳴っている声で音符が始まるときは、今の音量からエンベロープの最初の区切りを始める。鳴っていなかった声は0から始める。直したあとの冒頭15秒では、上の箇所は1か所で、前と同じになった。試験は`src/tests/sound_voice_test.zig`の「a note on a sounding voice starts its envelope from the level the note before left」。
- この動きは標準の音の全部の音色に効く（`ADSR`、`ENVELOPE`、MMLの`S`）。`S`のエンベロープのうち最初の区切りが時間0のものは、これまでどおり最初の値から始まる。
- 直したあとの冒頭15秒（合成した結果のWAV）を利用者が聞き、よくなったと報告した（Windows 11、2026-11-21）。そのあと実行ファイルで`examples/pastoral.fs`を最後まで鳴らし、利用者が問題がないと報告した（Windows 11、2026-11-21）。`fur-elise.fs`、ゲーム4本、`try/`のmarioは聞いていない（未確認、tque 1237）。

### 11.2 満たせない点

1. PSGの共有：エンベロープとノイズは声ごとに別に進む。3声で1つを共有して位相がそろう動きは出ない。
2. PSGの短い周期のエンベロープ：`ENVELOPE`の時間は1 ms単位である。エンベロープを音として使う技法（Sync-Buzzerなど）は音程が合わない（周期20の1回は2.86 msで、3 msになる）。
3. STE：標本はモノラルで読み込む（`sound_pcm.zig`の`convertFrames`）ので、ステレオは2声に分けて鳴らす。低音・高音は`TONE-CONTROL`で設定できる。`st-sound.fs`はどちらも設定しない。
4. 鳴っている音の途中の変更：1239で対応した（11.3節のA）。
5. NESのDMC：`MIXER 1`の式は声1〜4だけで、DMCの項がない。1ビット差分の展開の語もない。Forthで展開して`SAMPLE`に渡せば、直線の混合で鳴る。
6. 全体のフィルター：`MASTER-FILTER`は1つで、2極（Q 0.707）である。NESのハイパス90 Hzとローパス14 kHzの組は表せず、`nes-sound.fs`は設定しない。Amigaの実機はRCのローパス（1極）にLEDフィルターが直列に入るが、`AMIGA-FILTER`は4900 Hzと3275 Hzを切り替える。

8. SIDの波形の組合せ：本体の波形は1種類を選ぶ形で、組合せはない。
9. SIDのフィルターのモード：ローパス＋ハイパスのノッチはあるが、ほかの足し合わせ（ローパス＋バンドパスなど）はない。`c64-sound.fs`はフィルターを設定しない。

- **A（4）：決定済み。鳴っている声の音色を変える手段を足す（利用者の決定、2026-11-22）。** `VOICE-HOLD`で、鳴っている声に同じ音色を指定したとき、位相とエンベロープを続けたまま、音色の今の設定（波形、デューティー、フィルター、変調、段階など）を取り込む。エンベロープの区切りは、音の始まりのものを使い続ける。フィルターが既にかかっている声は、フィルターの状態を保ったまま係数だけを変える。標本の音色で標本が変わったときは、新しい標本の先頭から鳴らす。SIDのパルス幅の変調とフィルターのスイープ、NESの途中のデューティーの切替、SCCの波形の書換えは、Forthのプログラムが音色を設定し直して`VOICE-HOLD`を呼ぶ形で書く。MMLの音符の途中では変えられない。実装は`sound_voice.zig`の`retone`、試験は`src/tests/audio_test.zig`の「VOICE-HOLD with the same instrument takes its settings as they are now, and the envelope goes on」。音は聞いていない（未確認）。
