# Linux Tkの描画完了の残作業（1303）

2026-11-23。これは実装案と未完了条件の記録であり、受け入れ完了の記録ではない。

現在の共通語はTk表示中もnativeの描画番号と待機を返す。再現は
`python3 tests/scripts/verify-linux-tk-frame-gap.py`。
Tk単独では画像が表示されていても0/0と偽、native併用時はnativeの番号と真になる。
[実機記録](measurements/2026-11-23-linux-tk-frame-gap.json)を参照。

`src/graphics/sigma_tk.tcl`の`sigma_show`はphotoの更新と配置を行うが、
そのコマンドの応答は描画完了の通知ではない。`update idletasks`だけでも、
Xサーバーが処理を完了したことや物理画面への提示は保証しない。
別のX接続の往復を、wishの接続上の描画要求の完了として扱わない。

実装と検証が必要な条件：

- Tkへ渡した画像に番号を付ける。完了番号は描いた枚数ではなく、最後に描いた画像の番号とする。連続SHOWの途中の画像は集約できる。
- Tkの再描画と同じ接続のサーバー処理完了を識別する方法を確認する。Tkのidle処理、X要求送信、サーバー処理、物理的な提示を区別する。
- 最小化・withdraw・破棄中の画像を完了扱いせず、復帰時に保留画像が再描画されてから完了を進める。XWaylandではTkの最小化キャッシュだけでは不足することが1298で分かっている。
- 待機は期限を持ち、ウィンドウやwishを失ったら偽で終了する。通常イベントや制御通知を失わず、利用者のTCL-EVAL結果を上書きしない。
- Tclのstop/restart、実行中のSAVE/復元、新しいState、保存アプリの新規起動で、セッションの番号を取り違えない。
- 公開語を表示先に対応させ、nativeとの併用と切替えを検証する。Tkでnativeの待機成功が返る現状を受け入れ値にしない。
- 通常・最小化・復帰・閉じる要求・連続SHOW・期限切れ・異常終了を実機で確認する。VSYNCと実際の画面提示について、取得できないものは保証しない。
