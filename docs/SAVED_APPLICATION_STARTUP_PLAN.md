# SAVESYSで保存したアプリの起動基盤

2026-11-19。利用者の指示を受け、1003の段階で整備する共通基盤として追加する。状態：計画を登録、設計・実装・受け入れは未着手。LOGO機能をSigmaへ組み込む計画ではない。

## 範囲と分担

管理タスクは1066（親1003、祖先613）。設計1067、実装1068、受け入れ1069へ分ける。

| 配置 | 担当するもの |
|---|---|
| Sigmaの本体コア・ネイティブホスト | 保存した起動語の登録と識別、SAVESYS実行体の起動順、引数の受渡し、終了と診断、辞書の保存・復元・再配置との整合 |
| graphics/audio | アプリから明示的に利用する表示・音の機能。起動基盤そのものの必須条件にしない |
| extension | アプリが必要なら利用する拡張語。起動基盤の利用をREQUIRE-EXTENSIONの有無に依存させない |
| 外部のForthアプリ | LOGOの字句・構文解析、手続き・変数・言語仕様、タートル描画、UI、エミュレータのCPU・機種固有処理、起動語の本体 |

LOGOの実装に専用のZigコード・組込みForthライブラリ・ビルドオプションは追加しない。Sigma側に追加するのは、LOGO以外の保存アプリにも使える共通の起動基盤である。アプリはその基盤へForthの起動語を登録する。

## 確認済みの現状

`src/main.zig`のrunは埋込みイメージを復元し、現在のコマンドラインをsetArgumentsで設定した後、通常のファイル引数と`-e`を処理する。引数を処理し終えると対話プロンプトへ進む。保存したアプリの起動語を自動実行する入口は現状にない。

`logo.exe -e "起動語"`、起動用Forthソースの指定は現状でも可能だが、引数なし起動の共通基盤とは別である。これはソースと[利用者マニュアル](USER_MANUAL.ja.md)で確認した現状で、今回新しい動作を実行検証したものではない。現行main.zigは埋込み辞書の復元失敗を表示して処理を続ける。また、--formatの早期終了や保存実行体の-m/-l拒否は復元前に起きる。新しいアプリ起動での扱いは1067で明示的に定める。

## 必要な機能と設計で決めること

| 論点 | 必要な機能・確認条件 | 1067で決める細部 |
|---|---|---|
| 起動語 | 登録・照会・解除ができ、SAVESYS実行体の実起動時に一度呼ぶ。未登録時は既存の通常起動を維持 | 語名、スタック効果、登録可能な実行トークンの種類・検査、設定の保存範囲 |
| 起動順 | 辞書復元・現在の引数設定・必要なホスト準備の後、通常のForth引数消費より前にアプリへ渡す | 復元前に解析するホストオプションの範囲とアプリ引数の境界、初期化失敗時の扱い |
| アプリ引数 | ロゴのソースやROMなどをアプリのデータとして渡せる。Forthソースとして自動的にINCLUDEDしない | ARGC/ARGV等の既存契約との関係、`--`、`-e`、空白・日本語・空文字・先頭ハイフンの保持 |
| 終了 | 正常復帰、BYE、THROW、Ctrl+Cの扱いを定め、終了コードと後始末を明確にする | 復帰時に終了するか対話へ戻るか、エラーの表示とコード、スタック契約 |
| 診断起動 | 起動語が壊れていてもアプリの自動起動を回避できる | 回避のオプション、対話・`-e`の優先順位、無効な登録を検出したときの動作 |
| 保存と追加 | 起動語を名前検索順に偶然依存させず保存できる。SAVE/LOADとSAVESYS実起動を区別する | 完全復元と追加時の登録の維持・置換、語IDの再配置、FORGET/MARKER、再保存、破損・未解決参照の拒否 |
| 資源 | 画像・音・入力・外部プロセス・一時バッファを起動後に初期化し、失敗・中断・終了で回収する | 本体共通の後始末とアプリ自身の初期化・解放の境界。過去のOSハンドルや実行途中の状態は復活させない |
| 機能除外 | audio/graphics/extensionを使わない保存アプリでも動く | image=falseで除く語と埋込みイメージの扱い。files/debug除外で使える引数・診断経路 |

ここでは機能要件を追加する。API名や登録形式、正常復帰後の動作、具体的な診断オプションはまだ採用していない。保存時点のプログラムカウンターから実行を再開する機能や、タスクスケジューラは対象に含めない。

通常のLOAD-DICTIONARYなどで読み込んだだけで起動語を実行する仕組みにはしない。従来の、起動語を登録していないSigma・SAVESYS実行体のファイル引数・`-e`・対話動作も維持する。

## 受け入れで必要なケース

実際にSAVESYSで生成した実行体を別プロセスで起動し、出力と終了コードを確認する。

- 起動語の未登録・登録・変更・解除、引数なし起動、一度だけの呼出し、再保存した実行体。
- 空白・日本語・空文字・オプション風の引数。Sigmaと同名の`-m`・`-l`・`-d`・`--format`・`--lint`・`--trace`等も、区切り`--`の有無それぞれで仕様どおりアプリへ渡るかホストが処理するかを検査する。アプリへ渡したソースをForthとして自動実行しないこと。
- 正常復帰、BYE、THROW、Ctrl+C、起動回避、無効・忘却済みの参照と破損イメージ。復元失敗時に起動語を呼ばないこと、仕様で定めた終了・診断動作と終了コードを確認する。
- 完全復元・追加読込みと起動登録の再配置。LOADしただけでは自動起動しないこと。追加先の設定や既存定義が失敗で壊れないこと。
- audio/graphics/extensionの8通りとimage/files/debug除外の代表構成。image除外は仕様で定めた語・動作の除外を確認する。
- 表示・音などの初期化と、途中の失敗・終了後の回収。過去の画像やOS資源を引き継がないこと。
- Windows・Linux・macOSそれぞれの実行とコンパイルを区別して記録する。CLIの自動試験と、ウィンドウ・音の実機確認も区別する。
- 入力待ちや描画に依存しない小さなForthアプリを基盤の受け入れ例にする。LOGO処理系をSigmaのテスト前提にしない。
