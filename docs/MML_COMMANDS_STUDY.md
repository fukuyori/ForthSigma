# MMLに音色の命令を足すかの検討（1186）

2026-11-21、基点main 5ef0955。1〜4節は検討の記録、5節は採否（利用者の決定、2026-11-21）、6節は実装（1195）の記録である。3.1節の`P`の案（1つの数で位置を指定する）は、5節で左と右の大きさを指定する形に決めた。

## 1. 今の状態

`src/core/sound_mml.zig`のMMLは、MSX BASICの`PLAY`に合わせている（`docs/DECISIONS.md`の「MSX の MML」）。

| 種類 | 文字 |
| --- | --- |
| 使っている命令 | `A`〜`G`（`+` `#` `-` `.`）、`N` `R` `O` `L` `T` `V` `S` `M` `<` `>`、Sigmaで足した`@` |
| MSX BASICにあるが扱わない命令 | `X`と`=変数;`（BASICの変数を使う） |
| 使っていない英字 | `H` `I` `J` `K` `P` `Q` `U` `W` `Y` `Z` |

1184の設計では、MMLの命令は足さず、設定は音色の語で行って`@n`で切り替える（`docs/SOUND_CORE_DESIGN_STUDY.md` 3.9節の5）。`@`で選べる音色は64個（`instrument_count`）。

## 2. 音色の語だけで書くときの不便

音色の語は音色ごとの設定なので、曲の途中で1音だけ変えるには、その設定の音色を別に作り`@n`で切り替える。

- 左右を曲の中で動かすと、位置の数だけ音色が要る。
- ビブラートを長い音だけにかける、1音だけ音程をずらす、2つの音をなめらかにつなぐ、といった音符ごとの変化も、同じく音色を増やして切り替える。
- 音色は64個までなので、組合せが増えると足りなくなる。

逆に、波形、エンベロープ、フィルター、ノイズ、変調の源のように、楽器そのものを決める設定は、音色の語で足りる。

## 3. 案

### 3.1 足す命令の候補

音符ごとに変えたくなるものだけを候補とする。楽器を決める設定はMMLに入れない。

| 機能 | 案の文字 | 引数 | 対応する音色の語 |
| --- | --- | --- | --- |
| 左右 | `P` | `P-64`〜`P64`（負で左、0で中央） | `VOICE-PAN` |
| ビブラート | `Y` | `Y深さ,速さ`（深さはセント、速さはHz。`VIBRATO`と同じ単位）。`Y0`で止める | `VIBRATO` |
| 音程のずれ | `K` | `K-100`〜`K100`（セント） | なし（新しい設定） |
| 次の音へなめらかに移る | `_` | 音符の後に書き、次の音へポルタメントで移る | `PORTAMENTO` |
| 音を切らずにつなぐ | `&` | 音符の後に書き、次の音を鳴らし直さない | なし（新しい設定） |
| 音の長さの割合 | `Q` | `Q1`〜`Q8`（音符の長さの8分のいくつ鳴らすか） | `NOTE-LIMIT`（固定の長さ） |

- `P` `Y` `K` `Q`の値は、その声の次の音から効き、`PLAY`をまたいで残る（`O` `L`などと同じ）。音色を`@`で選び直しても消えない。`BEEP`で初期値に戻る。`_`と`&`は、書いた音符とその次の音符の間にだけ効く。
- 他のMMLの方言で同じ文字が同じ意味かは確かめていない（未確認）。
- `&`と`_`は、今のMMLではどちらも誤りになる文字である。MMLの外では、`&`はSigmaの数の書き方の10進数の接頭辞だが、MMLの文字列は別に読むので衝突しない。

### 3.1.1 足すときに決める細部

1. 構文
   - 今の数の読み取り（`number()`）は符号なしなので、`P-64` `K-100`には符号付きの読み取りが要る。音符の直後の`-`はフラットのまま残す。
   - `.`は付点として続けて読む。`Y`の速さに小数を認めるか（認めるなら付点と区別する方法）。
   - 空白は、`C-`と`C -`、`C4.`と`C4 .`で結果が変わる。`Y10,5`と`Y10 , 5`、引数の省略、余分な`,`の扱い。`,`を使わず、`Y`（深さ）と別の文字（速さ）に分ける案もある。
2. `_`と`&`
   - `&`は同じ高さの音だけをつなぐ（タイ）か、違う高さの音もつなぐ（スラー）か。
   - `C_R D`のように休符を挟む場合、`PLAY`の最後の`C&`、間の`@`、次の`PLAY`へつなぐ場合を許すか。今は`PLAY`の終わりで必ず音を止める（`src/core/sound_engine.zig`）。
   - `_`の移る時間：`PORTAMENTO`の時間を使うか、`_`に時間を書くか、次の音の長さ全体で移るか。
3. `P`と`VOICE-PAN`：`P`は1つの位置、`VOICE-PAN`は左右別の音量（負で逆相、既定65535 65535）。位置から左右の音量への変換の式、中央での音量、音色の逆相を残すか、端での制限を決める。
4. `Y`と`VIBRATO`：`VIBRATO`の始まるまでの時間を`Y`でも使うか。`Y0`で音色のビブラートも止めるか。
5. `Q`と`NOTE-LIMIT`：`Q`は音符の長さの割合、`NOTE-LIMIT`は開始からのミリ秒。両方あるときの優先、付点を含む長さを基準にするか、`&` `_`でつなぐ音に`Q`を効かせるか。
6. 音色の語の値と命令の値の関係：足し合わせるか、置き換えるか。2〜5の決め方で、命令ごとに変わる。

### 3.2 MODの効果との対応

`src/core/sound_mod.zig`の効果のうち、上の命令や音色の語に関係するものの抜粋。ほかに5・6・9・B・D・F、E0・E1・E2・E6・E9・EA・EB・EC・ED・EEを実装している（ECのノートカットは`Q` `NOTE-LIMIT`に関係する）。実装していないのは8、E3・E4・E5・E7・E8・EF。E5はないが、標本の見出しのfinetuneは使う。MODの再生は、MML（`PLAY`）とは別に効果を処理しているので、命令を足してもMODの再生は変わらない。

表の対応は機能が似ているという意味で、動きが同じという意味ではない。

| MODの効果 | 実装 | MMLの命令（案） | 音色の語 |
| --- | --- | --- | --- |
| 0 アルペジオ | あり | なし | なし |
| 1・2 音程を上げ下げ | あり | なし | `PITCH-SWEEP` |
| 3 次の音へ移る | あり | `_` | `PORTAMENTO` |
| 4 ビブラート | あり | `Y` | `VIBRATO` |
| 7 トレモロ | あり | なし | `VOLUME-MOD`（源の声を使う） |
| 8 左右 | なし | `P` | `VOICE-PAN` |
| A 音量を上げ下げ | あり | なし | `ENVELOPE` |
| C 音量 | あり | `V` | なし |
| E5 音程の微調整 | なし | `K` | なし |

- MODの1・2はtickごとに周期の値を増減し、3は周期の差を速さの指定で詰め、4は周期の値と位相の増分で揺らす。セントとミリ秒で表す`PITCH-SWEEP` `PORTAMENTO` `VIBRATO`とは、単位だけでなく進み方が違う。Aは今の音量を少しずつ変えるもので、`ENVELOPE`へ置き換える条件は決めていない。
- 1189でMODの声を声の集まりへ移しても、MMLの命令とMODの効果が同じ処理を使えるかは、上の違いがあるため確かめていない（未確認）。
- アルペジオとトレモロをMMLの命令にするかは、候補に入れていない。

## 5. 決定（利用者の決定、2026-11-21）

4節の4点を次のように決めた。実装は1189の後に別の作業として行う（tque 1195）。`P`は、左と右の大きさを別々に指定する。1つの数で位置を指定する形では片側が必ず100%になり、定位を設定できないためである（利用者の決定、2026-11-21）。

| 項目 | 決定 |
| --- | --- |
| 足すか | 足す。音符ごとに変えたいものだけを命令にし、楽器を決める設定は音色の語に残す |
| 命令と文字 | 3.1節の6つを案の文字で足す：`P`（左と右の大きさ）、`Y`（ビブラート）、`K`（音程のずれ、セント）、`_`（なめらかに移る）、`&`（つなぐ）、`Q`（長さの割合） |
| 負の数 | `P`と`K`の直後、`P`の`,`の直後の`-`は符号。音符の直後の`-`はフラットのまま |
| `Y`の引数 | `Y深さ,速さ`。速さは整数のHzだけ。速さの省略と余分な`,`は誤り |
| 空白 | 命令と数の間、`,`の前後の空白は読み飛ばす |
| 省略 | `P`は`P100,100`、`K`は`K0`、`Y`は`Y0`、`Q`は`Q8` |
| `&` | 鳴らし直さずにつなぐ。同じ高さならタイ、違う高さならスラー（エンベロープはやり直さない） |
| `_` | 鳴らし直さずにつなぎ、高さを前の音から次の音へなめらかに移す。移る時間は音色の`PORTAMENTO`、0なら次の音の長さ全体 |
| `&` `_`の誤り | 次が休符、`PLAY`の最後、次の音との間の`@`は誤り。次の`PLAY`へはつながない |
| `P` | `P左,右`。左と右の大きさを、それぞれ-100〜100の百分率で指定する（負は逆相）。`P100,0`は左だけ、`P100,100`は中央。音色の左右（`INSTRUMENT-PAN`。1239で`VOICE-PAN`から改名）と掛け合わせる。右の省略、余分な`,`、範囲の外は誤り |
| `Y` | はじめは音色の`VIBRATO`に従う。`Y深さ,速さ`は深さと速さを置き換え、始まるまでの時間は音色のものを使う。`Y0`は音色のビブラートも止める。音色に従う状態へは`BEEP`で戻る |
| `Q` | 付点を含む音符の長さ×`Q`/8だけ鳴らし、残りは休符と同じ。`NOTE-LIMIT`もあれば短い方。`&` `_`でつないだ音は最後の音にだけ効く |
| `K` | 音程に足す（対応する音色の語はない） |
| 値の保持 | `P` `Y` `K` `Q`は次の音から効き、`PLAY`をまたいで残り、`@`で消えず、`BEEP`で初期値に戻る |
| 時期 | 1189（標準の音の実装）の後に別の作業として行う（tque 1195） |

## 6. 実装（1195、2026-11-21）

- `src/core/sound_mml.zig`：命令を読み、音符ごとの値（`pan_left` `pan_right` `detune` `vibrato` `gate_ticks` `join`）を`Event`に入れる。声部が持ち続ける値は`Voice`にあり、`BEEP`と停止で初期値に戻る（`State.audio_voices`の初期化）。`&` `_`の次の音符へつなぐ状態はパーサーが持ち、`PLAY`をまたがない。
- `src/core/sound_engine.zig`：音符を始めるときに、音色の左右へ`P`を掛け、`Y`で音色のビブラートの深さと速さを置き換え、`K`を周波数に掛ける。`Q`は1/50秒の刻みで数え、`gate_ticks`で音符を止める（音符の終わりと同じ扱いで、音色のリリースが続く）。
- `src/core/sound_voice.zig`：`retune`（`&`。高さと音量だけを変える）と`glideTo`（`_`。音色の`PORTAMENTO`の時間、0なら渡した標本数で高さを移す）。
- 決めた細部：
  - `Y`の深さは0〜65535セント、速さは1〜65535 Hz。`Y0,速さ`は`Y0`と同じに扱う。
  - `Q`で鳴らす長さは、1/50秒の刻みで`長さ×Q÷8`の端数を切り捨て、1刻み未満は1刻みにする。
  - `&` `_`の間には、休符と`@`を除く命令を書ける。つないだ先の音符は、新しい音量と`K`で鳴り、`P` `Y`と音色は最初の音符が始まったときのままである。
  - 最初の音符がすでに終わっているとき（エンベロープが0で終わった、`NOTE-LIMIT`で止まった）は、つないだ先の音符は鳴らない。
  - `S`と`M`のエンベロープの音符をつないだ先は、最初の音符のエンベロープを続ける。
- 試験：`src/tests/sound_test.zig`の「MML's commands for a note at a time」の9件（値の保持と省略、`&` `_`と`Q`の関係、誤り、`Q`で止まる時刻、`&`で鳴らし直さないこと、`_`の移る時間、`P` `K` `Y`の声への反映、`P100,0`で右が無音になること）。
- 使った例：`examples/pastoral.fs`と`examples/fur-elise.fs`は、8声を`P100,0`と`P0,100`で左・右・右・左に置く（再設計の前のAmigaの設定と同じ並び）。
- 音は聞いていない（未確認）。Linux・Macでは実行していない（未確認）。
