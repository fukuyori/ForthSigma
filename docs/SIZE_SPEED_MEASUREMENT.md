# サイズ測定・速度比較（2026-11-17）

対象はSigma 0.11.0、コミット`f1d641c`。現在の実行体を新しくビルドして測定した。アプリケーションの実装コードは変更していない。前回（2026-11-15、Sigma 0.10.0、コミット`50e661e`）と同じビルド条件・測定条件で取り直し、前回の値を比較用に併記する。

## 結果

Windows通常版は**1,809,408バイト（1.73 MiB）**、Linux通常版は**1,891,456バイト（1.80 MiB）**。今回の8つの診断カーネルでは、SigmaはGforth 1.0.2通常版・fast版の両方より遅かった。所要時間比の幾何平均は通常版比**2.59倍**、fast版比**7.46倍**。実用アプリケーション全般の速度を表す値ではない。

前回との比較では、Sigmaの所要時間は8項目すべてで短くなり、短縮率は15.8〜34.9%、幾何平均で25.7%だった。通常版のサイズはWindowsで2,560バイト、Linuxで3,456バイト増えた。この間には12コミットがあり、差は速度改善だけによるものではない。

### 各構成の動作確認

前回と同じ確認を、今回の実行体で両OSについて行い、すべて期待値と一致した。

- グラフィックス・浮動小数点なし（`-Dgraphics=false -Dfloat=false`）：F+の未登録、OPEN-FILEの登録維持、REQUIRE-GRAPHICSが-270になること。
- グラフィックスだけなし（`-Dgraphics=false`）：浮動小数点加算の結果4とファイル語の登録、REQUIRE-GRAPHICSが-270になること、REQUIRE-AUDIOの読込み成功。
- サウンドだけなし（`-Daudio=false`）：浮動小数点加算の結果4とファイル語の登録、REQUIRE-AUDIOが-275になること、REQUIRE-GRAPHICSと2×3画像の生成・寸法取得の成功。
- 浮動小数点なし（`-Dfloat=false`）：8×8画像の生成、画素の設定と読戻し、整数座標のLINE、FILL-RECTの成功と画素値の一致、F+と浮動小数点描画語PLOTの未登録。

実装は`graphics.fs`を常に、`graphics_float.fs`をfloat有効時だけ読み込む構成である（src/core/words_graphics.zig）。従って浮動小数点なしでも整数座標の描画は利用でき、X-RANGE/Y-RANGE/MPSET/MLINE/AXES/PLOTは除かれる。確認はオフスクリーン描画であり、ウィンドウ・Sixelなどの実表示、音声再生、グラフィックス全機能を検証したものではない。通常版以外の構成の速度は測定していない。ソース・期待値・実出力は生データに保存した。

## 速度の測定条件

- AMD Ryzen 7 7700、WSL2 Ubuntu、Linux-6.18.33.2-microsoft-standard-WSL2-x86_64-with-glibc2.43、Python 3.14.4。CPU親和性は0に固定。
- Sigmaは上記Linux通常版。比較対象は既存インストールのGforth 1.0.2 amd64通常エンジンとfastエンジンで、実行体のSHA-256は前回と同じ。Gforth側を同じコンパイラー・最適化フラグで再ビルドした比較ではない。各実行体のSHA-256を生データへ記録した。
- `scripts/benchmark-runtime.py`のschema version 2を使用。各カーネル1億反復、各エンジン1回のウォームアップを除外し、その後7回測定。ラウンドごとに実行順を反転した。
- READY/DONEの入力ハンドシェイク間の子プロセスCPU時間を測定。起動・ソース読込み・コンパイル・終了を除き、境界の入出力は含む。ビルド・テストを測定と同時実行していない。
- 計算結果の整数チェックサムは全エンジン・全試行で一致。測定前に`python3 tests/scripts/test-benchmark-runtime.py`の3件が成功した。

Gforth側の中央値は、前回との差が通常版で−0.04〜+1.14%、fast版で−0.69〜+1.02%だった。Sigmaの7回の最小・最大の開きは、シフト・ビット演算で11.6%（947.0〜1056.7 ms）、+LOOPで4.8%、他の6項目は2.5%以下だった。各試行のCPU時間、最小・最大、経過時間、プロセス全体CPU時間は[生データ](measurements/2026-11-17-size-speed.json)に収録した。前回の生データは[2026-11-15の記録](measurements/2026-11-15-size-speed.json)。

幾何平均は8項目を等しい重みで集約した比であり、合計実行時間の比や実用処理の混合比ではない。Windows版の速度、最小構成の速度、起動時間、メモリー使用量は測定していない。前回との比較は、同じ環境・同じGforth実行体・同じ手順による別の日の測定どうしの比較であり、同時に交互測定した結果ではない。

## 前回からの変更との関係

前回のコミット`50e661e`から今回の`f1d641c`までに、VMの速度改善としてPC/endPCの局所保持と、単純なdata wordの早期`.call`経路を採用した（コミット`7b1295f`）。経緯と個別の評価は[改善計画](VM_PERFORMANCE_PLAN.md)を参照する。今回の測定は2つの時点の実行体全体の比較であり、個々の変更の寄与を分離したものではない。

VALUE経路とセル型localの追加候補は採用していないため、今回の実行体には含まれない。

## 測定器と除外対象

`tests/scripts/test-benchmark-runtime.py`は、起動・終了・sleepの除外、不正出力の拒否、早期終了の拒否を確認する。前回の測定時にテスト用子プログラムの起動方法を修正しており、今回は変更していない。測定本体のアルゴリズムも変更していない。

Gforth 0.7.9_20260410は、前回`libgfdisasm2.la`欠落により`40 2 + . bye`が終了コード1で失敗したため除外した。今回は再確認しておらず、比較対象に含めていない。

## 再実行

サイズ測定のビルド例（ターゲットとprefixを各構成で変更する）：

```powershell
zig build -Dtarget=x86_64-windows-gnu -Doptimize=fast -Dcpu=baseline -Dstrip=true --prefix .work/measure-20261117/x86_64-windows-gnu-full
zig build -Dtarget=x86_64-linux-musl -Doptimize=fast -Dcpu=baseline -Dstrip=true --prefix .work/measure-20261117/x86_64-linux-musl-full
```

グラフィックス単独除外は`-Dgraphics=false`、サウンド単独除外は`-Daudio=false`、同時除外は`-Dgraphics=false -Dfloat=false`、浮動小数点なしは`-Dfloat=false`、最小構成には8群すべての`-D<群>=false`を付ける。12構成の完全なコマンドとハッシュ、ビルドと確認に使ったscriptは生データを参照する。

```sh
cd /mnt/d/home/source/zig/forthz
python3 tests/scripts/test-benchmark-runtime.py
taskset -c 0 python3 scripts/benchmark-runtime.py \
  --sigma sigma=./.work/measure-20261117/x86_64-linux-musl-full/bin/sigma \
  --gforth gforth-1.0.2=/usr/local/bin/gforth-1.0.2-amd64 \
  --gforth gforth-fast-1.0.2=/usr/local/bin/gforth-fast-1.0.2-amd64 \
  --iterations 100000000 --rounds 7 --output .work/measure-20261117/benchmark.json
```

ローカルのビルドログ・実行体は`.work/measure-20261117/`。共有可能な数値・環境・チェックサム・ハッシュは上記JSONへ保存した。測定の依頼に基づく作業であり、速度改善や機能追加は実施していない。
