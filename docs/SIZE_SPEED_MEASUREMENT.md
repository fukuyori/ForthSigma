# サイズ測定・速度比較（2026-11-15）

対象はSigma 0.10.0、コミット`50e661e`。582〜584は見送り済みであり、未実装機能を追加した場合のサイズ増加量を測ったものではない。現在の実行体を新しくビルドして測定した。アプリケーションの実装コードは変更していない。

## 結果

Windows通常版は**1,806,848バイト（1.72 MiB）**、Linux通常版は**1,888,000バイト（1.80 MiB）**。今回の8つの診断カーネルでは、SigmaはGforth 1.0.2通常版・fast版の両方より遅かった。所要時間比の幾何平均は通常版比**3.50倍**、fast版比**10.06倍**。実用アプリケーション全般の速度を表す値ではない。

## ビルド条件とファイルサイズ

Windows 11 Pro（10.0.26300）上のZig 0.17.0で、両ターゲットを`-Doptimize=fast -Dcpu=baseline -Dstrip=true`に統一。Linux版はx86_64-linux-muslへのクロスビルド。独立した.work配下のprefixへ出力し、既存リリース成果物は置き換えていない。署名・インストーラー・パッケージ作成は行っていない。

MiBは1,048,576バイト。最小構成はfloat/files/help/tools/image/graphics/audio/debugの8群をすべて無効化する。全12実行体で`40 2 + . BYE`の出力42と正常終了を確認した。測定値は実行ファイル単体の容量であり、ライセンス文書、依存ライブラリー、インストール容量、実行時メモリーを含まない。

追加測定の「グラフィックス・浮動小数点なし」は、利用者の指定どおり`-Dgraphics=false -Dfloat=false`を同時に指定した構成。その他の機能群は既定の有効状態を維持する。両OSでF+の未登録、OPEN-FILEの登録維持、REQUIRE-GRAPHICSが-270になることも確認した。浮動小数点だけを外した構成からは、Windowsで245,248バイト、Linuxで234,704バイト小さくなる。この同時除外構成の速度は測定していない。

### グラフィックス単独除外・サウンド単独除外の追加測定

「グラフィックスだけなし」は`-Dgraphics=false`だけを指定し、float・audioを含む他の機能は既定の有効状態にした。「サウンドだけなし」は`-Daudio=false`だけを指定し、graphics・floatを有効のままにした。両構成・両OSで浮動小数点加算の結果4とファイル語の登録を確認した。

グラフィックス単独除外ではREQUIRE-GRAPHICSが-270になり、REQUIRE-AUDIOは読込みに成功。サウンド単独除外ではREQUIRE-AUDIOが-275になり、REQUIRE-GRAPHICSと2×3画像の生成・寸法取得が成功した。サウンドあり構成での音声再生や、画像のウィンドウ表示は行っていない。単独除外構成の速度は測定していない。

### 浮動小数点なし・グラフィックスありの動作確認

`-Dfloat=false`だけを指定した既存の測定用実行体で、Windows/Linuxの各2ケース、計4ケースを実行した。8×8画像の生成、画素の設定と読戻し、整数座標のLINE、FILL-RECTが成功し、読戻した画素値が期待値と一致した。F+と浮動小数点描画語PLOTが未登録であることも確認した。

実装も`graphics.fs`を常に、`graphics_float.fs`をfloat有効時だけ読み込む構成である（src/core/words_graphics.zig）。従って浮動小数点なしでも整数座標の描画は利用でき、X-RANGE/Y-RANGE/MPSET/MLINE/AXES/PLOTは除かれる。この確認はオフスクリーン描画であり、ウィンドウ・Sixelなどの実表示やグラフィックス全機能を検証したものではない。ソース・期待値・実出力は生データのno_float_graphics_checksに保存した。

## 速度の測定条件

- AMD Ryzen 7 7700、WSL2 Ubuntu、Linux-6.18.33.2-microsoft-standard-WSL2-x86_64-with-glibc2.43、Python 3.14.4。CPU親和性は0に固定。
- Sigmaは上記Linux通常版。比較対象は既存インストールのGforth 1.0.2 amd64通常エンジンとfastエンジン。Gforth側を同じコンパイラー・最適化フラグで再ビルドした比較ではない。各実行体のSHA-256を生データへ記録した。
- `scripts/benchmark-runtime.py`のschema version 2を使用。各カーネル1億反復、各エンジン1回のウォームアップを除外し、その後7回測定。ラウンドごとに実行順を反転した。
- READY/DONEの入力ハンドシェイク間の子プロセスCPU時間を測定。起動・ソース読込み・コンパイル・終了を除き、境界の入出力は含む。ビルド・テストを測定と同時実行していない。
- 計算結果の整数チェックサムは全エンジン・全反復試行で一致。1百万反復・1回の事前試行でも8項目が一致した。

## 測定器の確認と除外対象

後続の原因調査では、f1140c7の直前・直後を同じ環境・ビルド条件で測定し、整数演算+59.0%、LOOP+37.9%の時間増加を確認した。これは2千万反復・5回の別系列であり、上表の1億反復・7回と絶対時間を混ぜない。コミット全体の差は確認済みだが、個別の生成命令の原因は未特定。[改善計画](VM_PERFORMANCE_PLAN.md)と[原因調査の生データ](measurements/2026-11-15-vm-diagnosis.json)を参照する。

事前に`python3 scripts/test-benchmark-runtime.py`を実行したところ、テストがPythonへ非対応の`-e`を渡しており、意図したプロトコル検査に到達しなかった。テスト用子プログラムを実行可能なPythonスクリプトとして起動するよう修正し、3件すべて成功した。起動・終了・sleepの除外、不正出力の拒否、早期終了の拒否を確認した。測定本体のアルゴリズムは変更していない。

過去の比較対象Gforth 0.7.9_20260410も確認したが、`libgfdisasm2.la`欠落により`40 2 + . bye`が終了コード1で失敗したため、本測定から除外した。失敗の標準出力・標準エラーは生データに保存した。既存インストールやキャッシュを修復・変更してはいない。

## 再実行

サイズ測定のビルド例（ターゲットとprefixを各構成で変更する）：

```powershell
zig build -Dtarget=x86_64-windows-gnu -Doptimize=fast -Dcpu=baseline -Dstrip=true --prefix .work/measure-20261115/x86_64-windows-gnu-full
zig build -Dtarget=x86_64-linux-musl -Doptimize=fast -Dcpu=baseline -Dstrip=true --prefix .work/measure-20261115/x86_64-linux-musl-full
```

グラフィックス単独除外は`-Dgraphics=false`、サウンド単独除外は`-Daudio=false`、同時除外は`-Dgraphics=false -Dfloat=false`、浮動小数点なしは`-Dfloat=false`、最小構成には8群すべての`-D<群>=false`を付ける。12構成の完全なコマンドとハッシュは生データを参照する。

```sh
cd /mnt/d/home/source/zig/forthz
python3 scripts/test-benchmark-runtime.py
taskset -c 0 python3 scripts/benchmark-runtime.py \
  --sigma sigma=./.work/measure-20261115/x86_64-linux-musl-full/bin/sigma \
  --gforth gforth-1.0.2=/usr/local/bin/gforth-1.0.2-amd64 \
  --gforth gforth-fast-1.0.2=/usr/local/bin/gforth-fast-1.0.2-amd64 \
  --iterations 100000000 --rounds 7 --output .work/measure-20261115/benchmark.json
```

ローカルのビルドログ・実行体・事前試行は`.work/measure-20261115/`。共有可能な数値・環境・チェックサム・ハッシュ・除外理由は上記JSONへ保存した。測定の依頼に基づく作業であり、速度改善や機能追加は実施していない。
