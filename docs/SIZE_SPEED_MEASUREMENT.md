# サイズ測定・速度比較（2026-11-28、0.13.0）

対象は版0.13.0のコミット`f8fd8f0`。比較の基準はv0.12.0で、`git archive`で取り出したソースを同じZig 0.17.1でビルドし直した。測定作業ではアプリケーションのコードを変更していない。署名・インストーラー・配布パッケージの作成は行っていない。生データは[2026-11-28-size-speed.json](measurements/2026-11-28-size-speed.json)。

## 結果

- Windows通常版：**2,465,792バイト（2.352 MiB）**。0.12.0比+628,224バイト（+34.2%）。
- Linux通常版：**2,701,928バイト（2.577 MiB）**。0.12.0比+570,608バイト（+26.8%）。
- 8カーネルの所要時間は、0.12.0比の幾何平均でLinux **-18.6%**（短縮）、Windows（参考値） **+7.9%**（増加）。両OSとも「定数・変数」が増加した（Linux +17.5%、Windows +28.6%）。
- LinuxでのGforth通常版比は**2.65倍**、fast版比は**7.59倍**の所要時間。Gforthの方が速い。

サイズの増加は、0.12.0の後に加えたタスク制御・保存アプリ・ネイティブウィンドウ・音などの機能を含むコミット全体の比較で、機能ごとの寄与は分離していない。速度は小さな診断カーネルの結果であり、実用アプリケーション全般の速度ではない。WindowsとLinuxで向きが逆になった原因と、「定数・変数」の増加の原因は特定していない。

## 生データと再実行

```powershell

zig build -Dtarget=x86_64-linux-musl -Doptimize=fast -Dcpu=baseline -Dstrip=true --prefix .work/measure-20261120/x86_64-linux-musl-full
```

比較用ソースは`git archive 8f4a968`でリポジトリ内の別作業領域へ展開し、同じZig/フラグでビルドする。Linux測定のコマンド：
