# サイズ測定・速度比較（2026-11-20）

対象はコミット`789420e`。変更前の`8f4a968`も同じZigで別の作業領域にビルドし直した。今回の測定作業ではアプリケーションのコードを変更していない。署名・インストーラー・配布パッケージの作成は行っていない。

## 結果

- Windows通常版：**2,099,712バイト（2.002 MiB）**。変更前比+55,808バイト（+2.73%）。
- Linux通常版：**2,332,912バイト（2.225 MiB）**。変更前比+45,936バイト（+2.01%）。
- 8カーネルの所要時間は、変更前比の幾何平均でLinux **-24.4%**、Windows（参考値） **-14.6%**。負数は時間短縮。
- LinuxでのGforth通常版比は**2.53倍**、fast版比は**7.27倍**の所要時間。今回もGforthの方が速かった。

これは小さな診断カーネルの結果であり、実用アプリケーション全般の速度ではない。変更前後の差はコミット全体の比較で、grapheme・ファイルシステム・実行制御の各変更や生成命令ごとの寄与を分離したものではない。

## 条件と確認

- AMD Ryzen 7 7700、8コア/16論理CPU、Windows 11。Zig **0.17.1**。両OSとも`-Doptimize=fast -Dcpu=baseline -Dstrip=true`。Linuxはx86_64-linux-muslへのクロスビルド。
- 出力先は`.work/measure-20261120/`。現行16構成と比較用通常版2構成、計18実行体で`40 2 + . BYE`の42と正常終了を確認。機能除外など48照合も成功。
- 最小構成はfloat/files/help/tools/image/graphics/audio/debug/extensionの9群をすべて無効化。2026-11-17の最小構成は8群無効でEXTENSIONを残しており、同じ構成として比較しない。
- サイズは実行ファイル単体。ライセンス文書、依存ライブラリー、インストール容量、実行時メモリーを含まない。
- 速度は通常版でCPU親和性0。各カーネル1億反復、各エンジン1回warmupを除外し、その後7回。ラウンドごとにエンジン順を反転。ビルド・テストと速度測定を同時実行せず、LinuxとWindowsも順番に測定。
- 既存schema version 2の測定器を変更せず使用。READY/DONEの入力ハンドシェイク間の子プロセスCPU時間を測定し、起動・ソース読込み・コンパイル・終了を除く。境界の入出力は含む。測定器テストはWindows/Linuxとも3件成功。
- 整数チェックサムは各OSの全エンジン・全試行で一致。`--max-steps`やEXEC-LIMITEDは使っていない。652のCLI計数・入口付き処理の測定とは条件が異なる（[別記録](EXECUTION_CONTROL_IMPLEMENTATION.md)）。
- WSL Linux 6.18.33.2、glibc 2.43、Python 3.14.4。既存Gforth 1.0.2 amd64通常/fastエンジンを使用。同じコンパイラー/フラグで再ビルドした比較ではない。実行体のSHA-256を記録。

## 生データと再実行

[2026-11-20の生データ](measurements/2026-11-20-size-speed.json)にビルドコマンド、機能確認、各実行体/測定器のSHA-256、全試行、環境、補助scriptを保存した。[前回2026-11-17の記録](measurements/2026-11-17-size-speed.json)は別のソース/ツールチェーンの測定として残す。

ビルド例（target/prefixと機能フラグを各構成に変更する）：

```powershell
zig build -Dtarget=x86_64-windows-gnu -Doptimize=fast -Dcpu=baseline -Dstrip=true --prefix .work/measure-20261120/x86_64-windows-gnu-full
zig build -Dtarget=x86_64-linux-musl -Doptimize=fast -Dcpu=baseline -Dstrip=true --prefix .work/measure-20261120/x86_64-linux-musl-full
```

比較用ソースは`git archive 8f4a968`でリポジトリ内の別作業領域へ展開し、同じZig/フラグでビルドする。Linux測定のコマンド：

```sh
python3 tests/scripts/test-benchmark-runtime.py
python3 scripts/benchmark-runtime.py --cpu 0 \
  --sigma current=./.work/measure-20261120/x86_64-linux-musl-full/bin/sigma \
  --sigma before=./.work/measure-20261120/x86_64-linux-musl-full-baseline/bin/sigma \
  --gforth gforth-1.0.2=/usr/local/bin/gforth-1.0.2-amd64 \
  --gforth gforth-fast-1.0.2=/usr/local/bin/gforth-fast-1.0.2-amd64 \
  --iterations 100000000 --rounds 7 --output .work/measure-20261120/benchmark-linux.json
```

Windowsも同じ測定器の`--cpu 0`を使い、`--sigma`へ2つのWindows実行体を指定する。正確なコマンドはJSONのbenchmark_commandsを参照。測定作業によるコミット・pushは行っていない。
