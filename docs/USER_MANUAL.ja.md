# FORTH/Σ Zig版 ユーザーマニュアル

英語版（正）: [USER_MANUAL.md](USER_MANUAL.md)。この日本語版は英語版の訳です。内容が異なる場合は英語版に従ってください。

この文書は、現在のZig移植版の使い方を説明します。誌面に掲載された機能でも、現在の実装にないものは含めていません。FORTH/Σの仕様整理は[仕様書](SPEC.ja.md)、各語の掲載状況は[互換性一覧](COMPATIBILITY.ja.md)を参照してください。

この版は、FORTH/Σのワードを残しながら、数値まわりと基本ワードをGforthに合わせています。セルは64ビット、真の値は-1、浮動小数点数は専用スタックで扱います。誌面の16ビット仕様との違いは[決定事項・保留事項](DECISIONS.md)にまとめています。

## 起動と入力

リポジトリのルートで次のようにビルド・起動します。

```powershell
zig build
.\zig-out\bin\sigma.exe
```

`zig build -Dfloat=false` でビルドすると、浮動小数点数を扱わない小さい版になります（[浮動小数点数](#浮動小数点数)の章を参照）。同じように、`-Dfiles=false` はファイルを開く・読む・書く・取り込む語（`INCLUDE`、`REQUIRE`、`OPEN-FILE`、`STDIN`、`SLURP-FILE`、`$...SLURP` の語など）を、`-Dhelp=false` は `HELP` と `LICENSE` を、`-Dtools=false` は `SEE`、`LOCATE`、`WHERE` を、`-Dimage=false` は `SAVE`、`LOAD-DICTIONARY`、`SAVESYS` を、`-Dgraphics=false` は `REQUIRE-GRAPHICS` とグラフィックスの語（[グラフィックス](#グラフィックス)を参照）を、`-Ddebug=false` はデバッグ機能（[コンパイルしたコードの中のエラー](#コンパイルしたコードの中のエラー)を参照）を除きます。除いた語は辞書になく、名前は `名前 ?` のエラーになります。グループはそれぞれ独立しているので、ファイルの語を除いても、`SAVE`・`LOAD-DICTIONARY`・S01の組込辞書・メモリー配置変更前のイメージは拒否します。このビルドで作り直してください。アドレス再配置用の新形式は後続フェーズの作業です。

`SAVESYS` はイメージのファイルを書き読みし、`LOCATE` はソースファイルを読みます。組み込み語の実行トークンはどの版でも同じなので、ある版で保存したイメージは、グループの違う版でも読み込めます。その版で除いた語を実行すると `INVALID EXECUTION TOKEN` のエラーになり、`SEE` はその語を名前で表示します。グループを除いた以前の版（`-Dfloat=false` など）で保存したイメージは、組み込み語の実行トークンが違うので `INVALID IMAGE` になります。

対話プロンプトの前に、次の2行（`-Dhelp=false` の版では1行目だけ）を表示します。版番号はルートの `VERSION` ファイルの値です。

```text
FORTH/Sigma 0.10.0  MIT License
Type `help' for basic help
```

コマンドラインの引数は、Gforthと同じように扱います。引数はそれぞれForthソースファイルの名前で、左から順に `INCLUDED` と同じように読み込みます。`-e 文字列`（または `--evaluate 文字列`）は、その文字列を1行の入力として実行します。スタックは引数から引数へ引き継ぎます。`BYE` を実行すると、そこで終了コード0で終了します。引数でエラーが起きると、エラーを表示し（開けないファイルは `名前: NO SUCH FILE OR DIRECTORY !` のように名前の後に表示します）、残りの引数は処理せずに終了コード1で終了します。それ以外の場合は、最後の引数の後に上の2行と対話プロンプトが続きます。

プログラムは、Gforthと同じく `ARGC`、`ARGV`、`ARG`、`SHIFT-ARGS`、`NEXT-ARG` で引数を参照できます。引数は処理する前に取り除くので、ファイルからはそれより後ろの引数だけが見え、ファイルが `NEXT-ARG` で取った引数はファイルとして処理しません。たとえば `NEXT-ARG TYPE CR BYE` と書いたファイル `greet.fs` を `sigma greet.fs world` で起動すると、`world` と表示します。引数0は、起動したときのプログラム名です。引数は256個、合わせて約10 KBまで持てます。

```powershell
.\zig-out\bin\sigma.exe examples\demo.fs        # ファイルを読み込み、対話プロンプトへ
.\zig-out\bin\sigma.exe -e "12 DUP * . BYE"     # 144 を表示して終了
```

### 対話入力の行編集

macOSとLinuxの対話プロンプトでは、次のキーを使えます。Windowsは引き続きコンソール標準の行編集を使います。

| キー | 操作 |
| --- | --- |
| 上 / 下 | 古い / 新しい履歴を選択。最新より下へ進むと、入力途中の行とカーソル位置に戻る |
| 左 / 右 | UTF-8の文字単位で移動 |
| Home / End、Ctrl+A / Ctrl+E | 行頭 / 行末へ移動 |
| Backspace / Delete | カーソルの前 / 後の文字を削除 |
| Ctrl+K | カーソルから行末まで削除 |
| Ctrl+U / Ctrl+W | 行全体を消去 / カーソルの前の単語を削除 |
| Ctrl+D | 空行なら入力を終了。それ以外ではカーソルの後の文字を削除 |

文字はカーソル位置に挿入します。長い対話入力と `ACCEPT` の回答は、プロンプトの後に残る端末の幅に合わせて横スクロールします。端末の幅が取得できない場合や不適切な値の場合は80桁として扱います。入力開始位置はSigma自身の出力から追跡し、端末へのカーソル照会は行いません。外部プログラムの出力や対応していないカーソル制御で位置が不明になった場合や、残りの幅では全角文字を表示できない場合は、新しい行で編集を始めます。履歴は、空でない入力行を最新128件まで、起動中だけ保持します。連続する同じ行と、長さの上限を超えた行は登録しません。ファイルには保存せず、辞書イメージにも含めません。コマンドラインの `-e`、ソースファイル、パイプ、`ACCEPT` で入力した回答はコマンド履歴に入りません。`ACCEPT` では、入力と出力が端末の場合に行編集を使えます。

### メモリとスタックの大きさ

コマンドラインの先頭のオプションで、メモリとスタックの大きさを指定できます。名前と単位はgforthと同じです。オプションはほかの引数より前でだけ読み、`--` で打ち切ります。`--` より後の引数は通常どおり扱います。オプションは `ARGC` と `ARGV` には含まれません。

| オプション | 指定する大きさ | 既定値 |
|---|---|---|
| `-m SIZE`、`--dictionary-size=SIZE` | 辞書（システム領域16 KiB、入力領域64 KiB、実行時ブロック領域40 KiB、`HERE` が使うデータ領域）。`ALLOCATE` のヒープも同じ大きさになります。1 MiB以上 | 32 MiB |
| `-d SIZE`、`--data-stack-size=SIZE` | データスタック | 4096セル |
| `-r SIZE`、`--return-stack-size=SIZE` | リターンスタック | 4096セル |
| `-f SIZE`、`--fp-stack-size=SIZE` | 浮動小数点スタック | 4096個 |
| `-l SIZE`、`--locals-stack-size=SIZE` | ローカル変数の領域。4 KiB以上 | 64 KiB |

`SIZE` は数と単位です。単位は、なしまたは `e` が要素数（セル数、または浮動小数点数の個数）、`b` がバイト、`k`、`M`、`G`、`T` がKiB、MiB、GiB、TiBです。単位の大文字と小文字は区別します。バイトで指定した大きさは要素の単位に切り上げ、`0` は既定値のままにします。値はオプションの後（`-d 1000`）、オプションに続けて（`-d1000`）、長い名前では `=` の後（`--data-stack-size=1000`）に書けます。スタックは各16〜134,217,728要素で、`-m` の大きさの2倍と `-l` の大きさの合計は4 GiB未満です。範囲外の大きさは `-m: INVALID SIZE !` のようなメッセージを表示して終了コード1で終了し、メモリを確保できないときは `OUT OF MEMORY !` で終了します。

```powershell
.\zig-out\bin\sigma.exe -m 256M -d 64k examples\demo.fs   # 256 MiB、データスタック64 KiB（8192セル）
```

データ領域の残りは `UNUSED`、スタックの大きさは `ENVIRONMENT?` の `STACK-CELLS`、`RETURN-STACK-CELLS`、`FLOATING-STACK` で調べられます。メモリは起動時に全体を予約しますが、物理メモリはプログラムが使った分だけ割り当てられます。既定値はビルド時に `-Dmemory-mib=`（`-m` の大きさ、MiB単位）、`-Dlocals-kib=`、`-Dstack-cells=` で変えられます。辞書の語の数（`-Dwords=`、1024〜65535かつ全組込み枠を収められる値、既定65535）と名前の領域（`-Dnames-kib=`、既定1024）はビルド時にだけ指定できます。

### コンパイルしたコードの中のエラー

コロン定義の実行中に、`CATCH` が捕まえなかったエラーが起きると、メッセージの後にバックトレースとスタックを表示します。

```text
prog.fs:42: DIVISION BY ZERO !
BACKTRACE:
  AVERAGE prog.fs:12
  REPORT prog.fs:30
STACK: <2> 10 20
```

`BACKTRACE:` の後の行は、実行中だった定義で、内側が先です。最初がエラーの起きた定義、次がそれを呼んだ定義、という順に並びます。定義をファイルからコンパイルした場合は、その定義が実行していた語のファイル名と行番号が付きます。プロンプトで入力した定義と `-e` に渡した定義は、名前だけです。いちばん外側の定義を呼んだ場所は、メッセージの前の `ファイル名:行:` です。`STACK:` は、エラーが起きたときのデータスタックを `.S` と同じ形で示します（表示の後、これまでどおりスタックは空になります）。浮動小数点スタックに値があるときは、`FLOAT STACK:` が続きます。

- 呼び出す代わりに呼び出し元へコードを写した短い定義には、`(INLINE)` が付きます。
- `DOES>` の後のコードは、定義語の名前で表示します。`:NONAME` で作った定義は `:NONAME` と表示します。
- 再帰のように同じ場所が続くときは、1行にまとめて回数を付けます（`DEEP prog.fs:4 *32`）。内側から32か所までを保持し、それより外側の呼び出し元は `... 4064 MORE` のように数だけを示します。
- 定義の外で起きたエラー、`ABORT`、`QUIT`、`CATCH` が捕まえたエラーでは、バックトレースを表示しません。
- デバッグ機能を除いた版（`zig build -Ddebug=false`）では、これまでの版と同じく、メッセージだけを表示します。

コマンドラインの先頭のオプション `--max-steps N`（または `--max-steps=N`）は、自分では終わらないプログラムを終わらせます。コンパイルしたコードが実行できる命令の数を、引数1つごと、入力した1行ごとに `N` 個までにします（定義の中の語1つ、数1つ、制御構造の分岐1つを、それぞれ1個と数えます）。それを超えると、エラー `STEP LIMIT !`（THROW の番号 -280）で終わり、バックトレースでプログラムがどこを実行していたかが分かります。このエラーは `CATCH` では捕まえられません。`0` は制限なしで、これが既定です。制限を付けると、プログラムは少し遅くなります。デバッグ機能を除いた版（`-Ddebug=false`）には、このオプションはありません。

```powershell
.\zig-out\bin\sigma.exe --max-steps 100000000 prog.fs -e "MAIN BYE"
```

### トレースとデバッグの語

コマンドラインの先頭のオプション `--trace` は、コロン定義が始まるとき（`>`）と終わるとき（`<`）に、その名前、データスタックの深さ、上から9個までの値を標準エラーに表示します。語の入れ子の深さだけ字下げします。

```text
> SUMSQ <2> 3 4
  > SQUARE <2> 3 4
  < SQUARE <2> 3 16
  > SQUARE <2> 16 3
  < SQUARE <2> 16 9
< SUMSQ <1> 25
```

`--trace-limit N`（または `--trace-limit=N`）は、`N` 行を表示したところで `TRACE LIMIT` と表示してトレースを終えます。プログラムはそのまま続きます。エラーで終わった語には、終わりの行がありません。`DOES>` の後のコードは、語として表示しません。`--trace` を付けると、短い定義を呼び出し元に写さずに呼び出すようになり、プログラムは遅くなります。

```powershell
.\zig-out\bin\sigma.exe --trace --trace-limit 200 prog.fs -e "MAIN BYE" 2> trace.txt
```

次の gforth の語も、標準エラーに表示します。

| 語 | スタック | 動作 |
|---|---|---|
| `~~` | `( -- )` | 定義の中で使う。そこを実行したときに、ソースの中の場所（`ファイル名:行:桁:`）とデータスタックを表示する。 |
| `~~BT` | `( -- )` | `~~` と同じ表示（場所とデータスタック）の後に、`BACKTRACE:` と、その定義を呼んだ語を、エラーの後と同じ形で内側から表示する。 |
| `~~1BT` | `( -- )` | `~~BT` と同じことを、最初の1回だけ行う。 |
| `ONCE` | `( -- )` | 定義の中で使う。`THEN` までの部分を、最初の1回だけ実行する（`ONCE ~~ THEN`）。 |
| `~~VALUE` | `( x "name" -- )` | `TO` で書き換えるたびに表示する `VALUE` を定義する。表示は、`TO` の場所、新しい値をいちばん上に持つデータスタック、`` `name `` の順。 |
| `~~VARIABLE` | `( "name" -- )` | 名前を使うたびに表示する `VARIABLE` を定義する。アドレスを積む前に、名前の場所、データスタック、`` `name `` を表示する。`'` や `[']` の後の名前は、使ったことにならない。 |
| `+LTRACE` | `( -- )` | 次の行から、取り込むファイルの各行を、解釈する前に表示する。表示は、行の先頭に `~~` を書いたときと同じ（`ファイル名:行:1:` とデータスタック）。 |
| `-LTRACE` | `( -- )` | `+LTRACE` で始めた表示をやめる。 |
| `ASSERT(` | `( "code)" -- )` | 定義の中で使う。`)` までのコードは真を残さなければならない。偽を残したときは、`)` の場所を表示し、`THROW` -2（assertion failed）で終わる。 |

これらの語は、定義を実行したときの処理を、括弧の付いた語としてコンパイルします。`(~~)`、`(ASSERT)`、`(ONCE)`、`(~~BT)`、`(~~TO)` と、後で述べるステップ実行の `(BREAK:)`、`(BREAK")` です。`WORDS` には出ますが、プログラムが直接使う語ではありません。

デバッグ機能を除いた版（`-Ddebug=false`）には、トレースもこれらの語もありません。ただし `~~` と `ASSERT(` は残ります。

### メモリの監視

`WATCH ( a-addr -- )` は、それ以後、`a-addr` のセルの値が変わるたびに、変えた定義と、その語のファイル名と行番号を、標準エラーに表示します。

```text
WATCH: 1048632 changed from 7 to 9
  in UPDATE prog.fs:12
```

どんな方法で変えても見つかります。変数の名前を通した書き込みでも、計算したアドレスへの書き込みでも、`MOVE` や `FILL` などでそのセルを上書きした場合でも同じです。変わるはずのないセルを何が変えているかを調べるためのものです。プロンプトで入力した語（またはファイルの定義の外の語）による変更には、2行目がありません。`UNWATCH ( a-addr -- )` は、そのセルの監視をやめます。監視できるセルは8個までで、それを超えるとエラー `too many watched cells` になります。`--debug-log` を付けると、変更はログの `watch` という出来事にもなります。

```forth
SCORE WATCH   MAIN   SCORE UNWATCH
```

- セルは、コンパイルしたコードの命令を1つ実行するたびに調べます。最初の `WATCH` 以後、プログラムは遅くなります（`UNWATCH` の後も同じです）。
- そのセッションで最初の `WATCH` を実行したときにすでに実行中だった定義の中は、調べません。`WATCH` は、プログラムを始める前に、定義の外で使ってください。
- gforth にはこれらに当たる語がなく、FORTH/Sigma 独自の語です。デバッグ機能を除いた版にはありません。

### プロファイル

コマンドラインの先頭のオプション `--profile` は、プログラムが終わるとき（`BYE`、エラー、入力の終わりのどれでも）に、コロン定義ごとの呼び出し回数と実行した命令の数を、標準エラーに表示します。

```text
PROFILE: 164 OPERATIONS
     CALLS        SELF       TOTAL  WORD
        20          60          60  SQUARE prog.fs:1
         1          54         164  RUN prog.fs:3
        10          50         110  SUMSQ prog.fs:2
```

命令は、`--max-steps` と同じく、定義の中の語1つ、数1つ、制御構造の分岐1つを、それぞれ1個と数えます。時間ではなく命令の数を数えるので、同じプログラムを2回実行すれば同じ数になります。`SELF` はその定義自身のコードが実行した命令の数、`TOTAL` はその定義が始まってから終わるまでの命令の数で、呼び出した語の分を含みます。定義は `SELF` の大きい順に並び、それぞれに定義の始まるファイル名と行番号が付きます。呼び出されたか、命令を実行した定義だけを表示します。

- 自分自身を呼ぶ定義では、内側の実行を `TOTAL` に重ねて数えません。
- `DOES>` の後の命令は、定義語の `SELF` に数えます。
- 組み込み語は、何をする語でも1命令です。組み込み語の中で使った時間（描画、待ちなど）は、プロファイルに表れません。
- `--profile` を付けると、短い定義を呼び出し元に写さずに呼び出すようになり、プログラムは遅くなります。

```powershell
.\zig-out\bin\sigma.exe --profile prog.fs -e "MAIN BYE" 2> profile.txt
```

デバッグ機能を除いた版（`-Ddebug=false`）には、このオプションはありません。

### ステップ実行デバッガー

`DBG name` は、コロン定義 `name` を、gforth のデバッガーと同じように1命令ずつ実行します。命令を実行する前に、その命令と `->` を表示してキーを待ちます。キーを押すと命令を実行し、同じ行に、その命令が書いたものとデータスタック（`[ 深さ ]` と上から9個までの値）を続けて表示します。

```text
2 DBG BADWORD
: BADWORD
[ 1 ] 2
0              -> [ 2 ] 2 0
DO             -> [ 0 ]
I              -> [ 1 ] 0
INNER          -> [ 1 ] 1
.              -> 1 [ 0 ]
LOOP           -> [ 0 ]
```

| キー | 動作 |
|---|---|
| Enter | その命令を実行する。命令が呼ぶ語は、止まらずに実行する。 |
| `n` | 命令が呼ぶコロン定義の中に入る。`:` の後にその名前を表示し、その中の命令を1つずつ進める。その定義の `;` で、呼び出し元のステップ実行に戻る。ほかの命令では Enter と同じ。 |
| `u` | 定義の残りを、止まらずに実行する。`n` で入った定義なら呼び出し元のステップ実行に戻り、そうでなければステップ実行を終える。 |
| `d` | `Done...` と表示してステップ実行を終え、残りを実行する。 |
| `s` | エラー `debugger aborted` で実行を中止する。 |

キーは `KEY` と同じ方法で読むので、パイプやファイルからも送れます（`printf '2 DBG BADWORD\n\n\n\nd' | sigma prog.fs`）。入力が終わると、`d` と同じようにステップ実行を終えます。

定義の中の `BREAK:` は、そこからステップ実行を始めます。定義がそこまで進むと、データスタックを表示し、その後の命令を1つずつ進めます。`BREAK" text"` は、その前に `BREAK AT: text` と表示します。

```forth
: WITHBREAK ( n -- n ) 1+ BREAK: 2* ;
```

- 表示するのは、コンパイルした命令です。数はその数、`IF` と `WHILE` は `?BRANCH`、`ELSE`・`AGAIN`・`REPEAT` は `BRANCH`、定義の終わりは `;` と表示します。
- 呼び出し元にコードを写した短い定義は、呼び出しと同じく1つの命令として扱います。`n` で、写した命令の中に入れます。
- そのセッションで最初の `DBG` か `BREAK:` に出会ったときにすでに実行中だった定義は、`BREAK:` で止まりません。
- gforth（デバッガーは `gforth-itc` でだけ動きます）と違い、命令のアドレスは表示せず、スタックは現在の基数で、先頭の0を付けずに表示します。
- デバッグ機能を除いた版（`-Ddebug=false`）には、これらの語はありません。

### プログラム向けのログ

コマンドラインの先頭のオプション `--debug-log FILE`（または `--debug-log=FILE`）は、デバッグ機能が表示する内容を、JSON Lines の形（1行に1つの JSON オブジェクト）で `FILE` に書きます。プログラム（やエージェント）が読むためのものです。ファイルは起動時に新しく作り、各行はその出来事が起きたときに書き出します。

```powershell
.\zig-out\bin\sigma.exe --debug-log run.jsonl --trace --profile prog.fs -e "MAIN BYE"
```

```text
{"event":"start","version":"0.10.0"}
{"event":"enter","word":"SUMSQ","depth":0,"stack_depth":2,"stack":[3,4]}
{"event":"exit","word":"SUMSQ","depth":0,"stack_depth":1,"stack":[25]}
{"event":"error","message":"top.fs:3: DIVISION BY ZERO !","code":-10,"file":"top.fs","line":3,"backtrace":[{"word":"AVERAGE","file":"bt.fs","line":3},{"word":"REPORT","file":"bt.fs","line":6}],"more":0,"stack_depth":2,"stack":[10,20],"float_stack_depth":0,"float_stack":[]}
{"event":"profile","operations":177}
{"event":"profile_word","word":"SQUARE","file":"tr.fs","line":1,"calls":21,"self":63,"total":63}
```

| `event` | 書くとき | 項目 |
|---|---|---|
| `start` | ログを開いたとき。 | `version` |
| `error` | エラーがインタプリタまで届いたとき（`ABORT`、`QUIT`、`CATCH` が捕まえたエラーは書かない）。エラーは、ログがないときと同じように画面にも表示する。 | `message`（表示と同じ文。入力の `ファイル名:行:` があればそれを前に含む）、`code`（THROW の番号）、`file` と `line`（入力の行がファイルの中のとき）、`backtrace`（内側が先。それぞれ `word`、分かるときは `file` と `line`、呼び出し元に写した短い定義では `inline` が true、同じ場所が続いたときは `times`）、`more`（保持した分より外側の呼び出し元の数）、`stack_depth` と `stack`、`float_stack_depth` と `float_stack` |
| `enter`、`exit` | `--trace` のとき、コロン定義が始まるときと終わるとき。 | `word`、`depth`（トレースした語の入れ子の深さ）、`stack_depth`、`stack` |
| `trace_limit` | `--trace-limit` でトレースが終わったとき。 | `lines` |
| `lint` | `--lint` のとき、指摘ごとに1つ。 | `check`、`word`、`file`、`line`、`message` |
| `lint_end` | `--lint` のとき、指摘の後。 | `findings`、`unchecked`（スタックの効果を検査しなかった定義の数） |
| `watch` | `WATCH` のセルの値が変わったとき。 | `address`、`old`、`new`、`in`（定義と場所。表示と同じ形。インタプリタによる変更にはない） |
| `profile` | `--profile` のとき、プログラムが終わるときに1回。 | `operations` |
| `profile_word` | `profile` の後に、定義ごとに1つ。プロファイルと同じ順。 | `word`、`file` と `line`（定義の始まる場所。分かるとき）、`calls`、`self`、`total` |

`stack` はデータスタックの上のほうの値で、いちばん上が最後です。`enter` と `exit` では9個まで、`error` では64個までで、`stack_depth` がスタック全体の深さです。ログがあるときは、トレースとプロファイルはログに書き、標準エラーには書きません。項目や `event` は後から増えることがあるので、ログを読むプログラムは、知らないものを読み飛ばしてください。デバッグ機能を除いた版（`-Ddebug=false`）には、このオプションはありません。

### プログラムの検査（lint）

コマンドラインの先頭のオプション `--lint` は、その後に指定したファイルの定義を検査します。Forth のソースは実行しないと読めないので、ファイルはふだんどおりに読み込みます（定義の外のコードは実行されます）。その後、対話プロンプトに入る代わりに、指摘を1行に1つ、`ファイル名:行: 検査名: 説明` の形で表示します。

```text
prog.fs:1: UNUSED: SQUARE is not used in the files
prog.fs:2: REDEFINED: SQUARE was defined at prog.fs:1
prog.fs:4: UNREACHABLE: code in AFTER that is never reached
prog.fs:5: STACK DEPTH: paths in UNEVEN meet with different stack depths
prog.fs:6: RETURN STACK: KEEPS ends with 1 more on the return stack
prog.fs:7: STACK EFFECT: WRONG is declared ( 2 -- 1 ) but its code is ( 2 -- 2 )
LINT: 6 FINDINGS
```

| 検査 | 見つけるもの |
|---|---|
| `REDEFINED` | 同じ語彙の、前からある語（組み込み語を含む）と同じ名前の語。 |
| `UNREACHABLE` | コロン定義の中の、どの経路からも届かないコード。`EXIT` や `AGAIN` の後の語など。 |
| `STACK DEPTH` | 定義の中で、スタックの深さが違う経路が合流するところ。`ELSE` のない `IF` がセルを1つ残す、など。 |
| `RETURN STACK` | 終わったときに、リターンスタックのセルが始まったときより多い、または少ない定義（`R>` のない `>R`）。自分で入れていないセルをリターンスタックから取る定義（`>R` のない `R>`）。 |
| `STACK EFFECT` | 名前の後のスタックコメントとコードが合わない定義。深さの変化が違うか、コメントにある数より多くのセルを必要とする。2つ目のコメント `( F: r1 -- r2 )` があれば、浮動小数点スタックも検査する。 |
| `UNUSED` | どのファイルからも使われていない語。コマンドライン（`-e`）やプロンプトからだけ使う語も、指摘される。 |

終了コードは、指摘がなければ0、指摘があれば2、ファイルがエラーになれば1です。`--debug-log` を付けると、指摘はログの `lint` という出来事にもなり、`lint_end` がその数を示します。

スタックの検査の方法と、検査できないものは次のとおりです。

- スタックコメントは、名前の後の最初のコメントです（`: NAME ( a b -- c )`）。項目1つを1セルと数えます。`d`、`ud`、`xd`（後ろに数字が付いてもよい）は2セルと数えますが、1セルと数えて合う場合も指摘しません（`d` はふつうの名前のこともあるため）。引用符や山かっこで囲んだ項目（`"name"`）は入力から読むものなので、数えません。`|`、`...`、`..` のあるコメントは数が決まらないので、検査しません。
- コードの効果は、その中の語から求めます。組み込み語は `HELP` のスタックコメントから、呼び出す語はその語のコードから求めます。
- 効果が決まらない語を含む定義は、`STACK DEPTH`、`RETURN STACK`、`STACK EFFECT` を検査しません。`EXECUTE`、`CATCH`、`EVALUATE`、`?DUP`、`PICK`、`N>R`、`DEFER` の語、`DOES>` の定義語で作った語、再帰、終わりのないループなどです。その数は最後に表示します（`LINT: 12 DEFINITIONS WITHOUT A FIXED STACK EFFECT WERE NOT CHECKED FOR IT`）。そのような定義を呼ぶ定義は、スタックコメントがあれば、そのコメントのとおりと見なして検査します。
- `ABORT`、`QUIT`、`BYE`、0以外の数の後の `THROW`（`1 THROW`）で、経路は終わります。
- FORTH/Sigma に付属するライブラリの語は、指摘しません。
- `HELP` を除いた版（`-Dhelp=false`）は組み込み語の効果が分からないので、ほかの検査だけを行います。デバッグ機能を除いた版（`-Ddebug=false`）には、このオプションはありません。

### プログラムの整形

コマンドラインの先頭のオプション `--format` は、その後に指定したファイルの字下げを整え、行末の空白を取り除きます。ファイルは文字として読むだけで、実行しません。行が変わるときだけファイルを書き換え、ファイルごとに1行を表示します。

```powershell
.\zig-out\bin\sigma.exe --format prog.fs lib.fs
```

```text
prog.fs: 12 LINES FORMATTED
lib.fs: FORMATTED ALREADY
```

`--format-check` は何も書き換えず、`--format` が変える行の数を表示します（`prog.fs: 12 LINES TO FORMAT`）。変わる行のあるファイルがあれば、終了コードは2です。どちらも、ファイルを読めない、または書けないときの終了コードは1です。`--format-indent N` は字下げ1段の空白の数で、指定しなければ3です（0〜16。0では、構造の中の行をそれを開いた行と同じ位置に置きます）。

変えるのは、行の最初の文字の前と、最後の文字の後の空白だけです。その間は1バイトも変えないので、プログラムの語、文字列、コメントは元のままです（FORTH/Sigma では文字列も `( コメント )` もその行で終わるので、行全体が文字列やコメントの中身ということはありません）。規則は次のとおりです。

```forth
: CLASS ( n -- )
   DUP 1 = IF
      ONE
   ELSE DUP 2 = IF
      TWO
   ELSE
      MANY
   THEN THEN DROP ;
```

- コロン定義や制御構造の中の行は、それを開いた行より1段深く置きます。`IF`、`BEGIN`、`DO`、`?DO`、`CASE`、`OF` が構造を開き、`THEN`、`UNTIL`、`AGAIN`、`REPEAT`、`LOOP`、`+LOOP`、`ENDOF`、`ENDCASE` が閉じます。
- 閉じる語、`ELSE`、`WHILE`、`DOES>`、`;` で始まる行は、その構造を開いた行と同じ位置に置きます。ループの条件や増分を、それを受け取る語の前に書いた行（`DONE @ UNTIL`、`2 +LOOP`、`DUP WHILE`）も同じです。
- 1行で開いた構造は、まとめて1段です（`h 0 DO  w 0 DO` を `LOOP LOOP` で閉じる）。定義の名前の行で開いた構造は、定義とは別に1段です（`: T ( -- )   10 0 DO` を `   LOOP ;` で閉じる）。`x IF y ELSE` で終わる行の後の行は、1段深くせず、その行と同じ位置に置きます（条件の連なり）。
- これらの語で始まらず、前の行より深く字下げしてある行は、長い行の続きと見なし、前の行との距離を保ちます（構造を開いた行や閉じた行の後では、3段以上深いときだけ続きと見なします。それより浅いものは、別の幅で字下げしたファイルの字下げです）。
- どの構造の中でもない行は、字下げを変えません（`CREATE` の後の表など）。`[IF]`、`[ELSE]`、`[THEN]` は字下げしません。
- 字下げのタブは空白にします（構造の中では1段、外では8の倍数の位置まで）。行末（LF か CR LF）は元のままです。
- 整形済みのファイルをもう一度整形しても、何も変わりません。

語は名前で見分けます。自分で `IF` を定義したプログラムも、ふつうの `IF` と同じに字下げします。行の残りや次の行を、閉じる `"` なしに文字として読む語を自分で定義している場合は、その文字の先頭や末尾の空白が変わることがあります。デバッグ機能を除いた版（`-Ddebug=false`）には、これらのオプションはありません。

### カバレッジ

コマンドラインの先頭のオプション `--coverage` は、コードの各部分が何回実行されたかを数えます。gforth の `coverage.fs` の語で表示します。数える単位は gforth と同じ基本ブロックで、コロン定義の名前の後、`IF`、`ELSE`、`THEN`、`BEGIN`、`WHILE`、`REPEAT`、`UNTIL`、`AGAIN`、`DO`、`?DO`、`LOOP`、`+LOOP`、`CASE`、`OF`、`ENDOF`、`ENDCASE`、`DOES>` の後、および定義の2行目以降の各行の先頭から始まります。

```powershell
.\zig-out\bin\sigma.exe --coverage prog.fs -e "RUN .COVER-RAW COV% CR .COVERAGE BYE"
```

| 語 | スタック | 動作 |
|---|---|---|
| `.COVER-RAW` | `( -- )` | ブロックごとに `ファイル名:行:桁: 回数` を表示する。桁は、ブロックを始める語の後の空白の位置で、1から数える（行の先頭は1）。 |
| `COV%` | `( -- )` | 1回以上実行されたブロックの割合を、`88.8% coverage` の形で表示する。 |
| `.COVERAGE` | `( -- )` | 各ファイルの文を、ブロックを始める語の後に ` ( 回数) ` を入れて表示する。 |

```text
: pick-one ( 1)  ( f -- n ) if ( 0)  1 else ( 1)  2 then ( 1)  ;
```

表示するのは、取り込んだファイルのコロン定義のブロックです。プロンプトで入力した定義、`-e` に渡した定義、FORTH/Sigma に付属するライブラリの定義は表示しません。`--coverage` を付けていないと、これらの語はエラー `no coverage: start with --coverage` になります。

`--coverage` を付けると、ブロックの始まりに何もしない命令をコンパイルします（gforth が `require coverage.fs` の後、そこにカウンターをコンパイルするのと同じです）。プログラムは遅くなり、`SEE` はこの命令を `BRANCH n` と表示します。位置と回数は、同じ文に対して gforth 0.7.9 が示すものと同じです。ただし gforth は `ENDCASE` の後のブロックを2回表示します。`NOCOV[`、`]NOCOV`、`COV+`、`?COV+`、`BW-COVER`、`COLOR-COVER`、`ANNOTATE-COV`、`SAVE-COV`、`LOAD-COV` は実装していません（表示は常に `BW-COVER` の形です）。デバッグ機能を除いた版（`-Ddebug=false`）には、これらはありません。

`HELP` は基本的な使い方を、`HELP 語名` は語のスタックの変化と1行の説明を英語で表示します（例: `HELP DUP`）。名前は同じ行から読みます（`EVALUATE` の文字列でも、改行の先は読みません）。定義の中に書いた `HELP` は、その定義を実行したときに名前を読みます。利用者が定義した語は、`SEE` で中身を見るよう案内します。知らない名前は `名前 ?` のエラーです。`LICENSE` はライセンスの全文と、組み込んでいるCORE-MATHの著作権表示を表示します。

入力行を処理すると、成功時には `OK` が表示されます。たとえば次の入力は、12の二乗を表示します。

```forth
: SQUARE DUP * ;
12 SQUARE . CR
```

結果は `144 ` です。`.` は数値の後ろに空白を1個付けますが、改行は付けません。改行が必要なときは `CR` を続けます。複数行のForthソースは標準入力から渡せます。

```powershell
Get-Content .\examples\demo.fs | .\zig-out\bin\sigma.exe
```

`BYE` で処理系を終了します。未定義語などのエラーが起きた場合は診断を表示し、すべてのスタックを空にして次の入力行へ戻ります。

LinuxとmacOSの端末では、対話プロンプトと `ACCEPT` の行は、Sigmaが自分で編集します。Backspace（Ctrl+H も）は1文字を消し、全角の文字は2桁分戻します。Ctrl+U は行全体を、Ctrl+W は直前の語を消します。Ctrl+D は空の行で入力の終わりになり、対話プロンプトでは終了します。Ctrl+C、Ctrl+\、Ctrl+Z は、端末の設定を戻してから、端末のときと同じく終了・中断します。カーソルキーなどのエスケープシーケンスとその他の制御文字は入力に入れません。Tab は入力に入れ、空白1つで表示します。キーは端末の設定（`stty`）のものを使います。標準出力が端末でないときは、これまでどおり端末の行入力で読みます。Windowsでは、コンソールが行を編集します。`KEY` と `XKEY` は、これまでどおり端末の行入力から読みます（Enter を押すまで届きません）。

`( ... )` は同じ行の `)` までを、`\` は行末までをコメントとして読み飛ばします。

## スタック操作の追加語

| 語 | スタック効果 | 動作 |
|---|---|---|
| `2NIP` | `( x1 x2 x3 x4 -- x3 x4 )` | 最上位の組の直下にある2セルを除きます。 |
| `2TUCK` | `( x1 x2 x3 x4 -- x3 x4 x1 x2 x3 x4 )` | 最上位の2セルを直下の組の下にもコピーします。 |
| `THIRD` | `( x1 x2 x3 -- x1 x2 x3 x1 )` | 上から3番目のセルを複製します。 |
| `FOURTH` | `( x1 x2 x3 x4 -- x1 x2 x3 x4 x1 )` | 上から4番目のセルを複製します。 |
| `RDROP` | `( -- ) ( R: x -- )` | 利用者のリターンスタックから1セルを除きます。 |
| `2RDROP` | `( -- ) ( R: x1 x2 -- )` | 利用者のリターンスタックから2セルを除きます。 |

`1 2 3 4 2TUCK`は`3 4 1 2 3 4`を残します。`: T 10 >R 20 >R RDROP R> ; T`は10を残します。リターンスタックの出し入れは同じ定義・ループ内で釣り合わせてください。Sigmaでは利用者のリターンスタックと呼出フレーム・DOループの添字は別管理のため、釣り合った削除はI/Jを変更しません。データ不足は-4、リターンスタック不足は-6をTHROWします。2TUCKは移動前に2セル分の空きを確認します。

Sigmaの`RDROP`/`2RDROP`は利用者のリターンスタックだけを操作し、DOループ制御情報や呼出フレームは除きません。Gforthの内部配置を利用してDOループから`2RDROP EXIT`で抜ける書き方には互換性がありません。`UNLOOP EXIT`を使ってください。利用者セルがない場合、前者はSigmaでは-6をTHROWします。

## 数値

整数は64ビットの符号付き値です。範囲を超えた加算・減算・乗算は折り返します。`/`、`MOD`、`/MOD` は床関数除算（負の無限大方向への切り捨て）で、`-7 2 /` は `-4`、`-7 2 MOD` は `1` です。0で割るとエラー `DIVISION BY ZERO !` になります。最小値（-9223372036854775808）を-1で割ると、商が1セルに収まらないため、`MOD` も含めて `RESULT OUT OF RANGE !`（例外コード-11）になります（Gforthと同じ）。

`*/`（( n1 n2 n3 -- n4 )）と `*/MOD`（( n1 n2 n3 -- 余り 商 )）は、n1×n2を倍長で計算してからn3で割るので、積が1セルを超えても正しい商が得られます（床関数除算）。`U<` `U>` は符号なしで比べます。`?DUP` は0でなければ複製します。

比較の結果は、真が `-1`（全ビット1）、偽が `0` です。`IF` などの条件は0を偽、0以外を真として扱います。

数値の前に接頭辞を付けると、現在の基数に関係なく基数を指定できます。

| 書き方 | 意味 |
| --- | --- |
| `$FF` | 16進数 |
| `#10`、`&10` | 10進数 |
| `%101` | 2進数 |
| `0xFF`、`0XFF` | 16進数。gforthと同じく、現在の基数でそのまま読めないときに使えます（36進では `0x10` は36進の数です） |
| `'a'`、`'a` | 1文字のコードポイント（UTF-8なので `'日` は26085）。閉じる `'` は省けます。`''` は引用符そのものです |

`-` は接頭辞の前にも後にも付けられます（`-$10`、`$-10`、`-0x10`、`0x-10`、`-'a`）。両方には付けられません。
### 整数比較の追加語

| 語 | スタック効果 | 動作 |
|---|---|---|
| `0<=` | `( n -- flag )` | 符号付きセルが0以下なら真。 |
| `U<=`、`U>=` | `( u1 u2 -- flag )` | 最上位ビットも大きさとして扱う符号なし比較。 |
| `UMAX`、`UMIN` | `( u1 u2 -- u )` | 符号なしの最大／最小。元のセルのビット列を保持する。 |
| `D0<=`、`D0<>`、`D0>`、`D0>=` | `( d -- flag )` | 符号付き倍長整数と0を比較する。 |
| `D<=`、`D<>`、`D>`、`D>=` | `( d1 d2 -- flag )` | 符号付き128ビット比較。 |
| `DU<=`、`DU>`、`DU>=` | `( ud1 ud2 -- flag )` | 符号なし128ビット比較。 |

比較結果は真が-1、偽が0です。倍長整数は既存と同じ下位セル・上位セルの順で積みます。浮動小数点・ファイル・描画・イメージ機能を除いた構成でも利用できます。

### 倍長整数

数字の間に `.` を含む数は倍長整数（128ビット）になり、スタックに下位セル、上位セルの順で2個積まれます。`123.` は123、`12345.123` は12345123です（小数点の位置は記録しません）。

```forth
1234567890000000000. 9876543210000000000. D+ D.   \ 11111111100000000000
-7 S>D DABS D.                                    \ 7
```

### 2セルの格納とセル回転

`2,` `( x1 x2 -- )`はHEREから16バイトを確保し、2!と同じくx2を先に、x1を次に格納します。自動整列は行わず、HEREが未整列ならそのままです。書込前に2セル分をまとめて確保するため、容量不足ではHEREと元のデータを変更しません。格納先は辞書データで、FORGET/MARKERで解放されます。アドレスのような数値でも、通常の生セルとして格納した値は辞書の追加読込で自動再配置しません。

`ROL`と`ROR` `( u count -- u2 )`は、セルを符号なし64ビットのビット列として左右に回転します。回転数は64を法として扱い、0/64/128は元の値を保ちます。負の生セル値も下位6ビットを使用します。例えば`1 65 ROL`と`1 -1 ROR`はともに2です。境界値は指定の64ビットGforth比較環境と一致します。シフトと異なり、押し出したビットは反対側へ戻ります。

## ワードの定義と辞書

利用者定義語は `: 名前 ... ;` で作ります。ワード名は名前全体で照合し、ASCII英字の大文字・小文字は区別しません。既存名を再定義すると警告が出ますが、新しい定義が優先されます。組み込み語と同じ名前で定義した場合も、利用者の定義が優先されます。

```forth
: DOUBLE 2 * ;
21 DOUBLE . CR
```

`WORDS` は現在の辞書の登録語を表示します。`FORGET 名前` は指定語と、それより後に登録された利用者定義語を削除します。そのため、後から同名定義を追加したあと新しい方を `FORGET` すると、古い定義が再び使われます。削除対象より後に定義した別の語も一緒に削除される点に注意してください。

`IMMEDIATE` は直前に定義した語を即時語にします。`POSTPONE 名前` は、定義中の語に「名前のコンパイル」を組み込みます。`RECURSE` は定義中の語自身を呼び出します。

### 遅延語とコンパイルの語

## 変数・定数・配列

```forth
VARIABLE COUNT
10 COUNT !
COUNT @ . CR
42 CONSTANT ANSWER
ANSWER . CR
5 VALUE LIMIT
8 TO LIMIT
4 ARRAY TABLE
CREATE BUF 16 ALLOT
```

`VARIABLE`（別名 `VAR`）は変数を作り、`CONSTANT`（別名 `CONST`）はスタック先頭の値を定数として登録します。`VALUE` は値を返す語を作り、`TO 名前` で値を変更します。`ARRAY` は要素数を受け取り、1要素8バイトの配列を作ります。配列添字は0からで、`添字 配列名 A@`、`値 添字 配列名 A!` で読み書きします。`CREATE 名前` はデータ領域の現在位置を返す語を作ります。

1セルは8バイトです。`CELLS` で要素数をバイト数に変換できます。メモリ操作ではアドレスと範囲を利用者が管理してください。論理メモリの外を読み書きすると `INVALID MEMORY ADDRESS !` になります。

## 制御構造

制御構造は定義内で使います。

```forth
: ABS-VALUE DUP 0 < IF NEGATE THEN ;
: COUNT-UP 5 0 DO I . LOOP ;
: GRADE CASE 1 OF ." ONE" ENDOF 2 OF ." TWO" ENDOF ." OTHER" ENDCASE ;
```

利用できる構造は次のとおりです。

- `IF ... ELSE ... THEN`
- `BEGIN ... END`（`END` の別名 `UNTIL`）、`BEGIN ... AGAIN`、`BEGIN ... WHILE ... REPEAT`
- `CASE ... OF ... ENDOF ... ENDCASE`（Gforthの `?OF`、`CONTOF`、`NEXT-CASE` も使えます）
- `DO ... LOOP`、`DO ... +LOOP`、`?DO`

`IF ... ENDIF` も使えます（`ENDIF` は `THEN` の別名）。`DO` は開始値と終値が等しくても本体を1回実行します（FORTH/Σの仕様）。`?DO` は等しい場合に本体を実行しません。`LEAVE` は直ちにループを抜けます。ループの途中で `EXIT` するときは、先に `UNLOOP` でループを片付けます。`?EXIT`（( flag -- )）は真のとき `EXIT` し、`?LEAVE`（( flag -- )）は真のとき `LEAVE` します。`?OF`（( flag -- )）は値と比べる代わりに真偽で選ぶ `OF`、`CONTOF` は `CASE` の先頭へ戻る `ENDOF`、`NEXT-CASE` は選択値を捨てずに先頭へ戻る `ENDCASE` です（Gforthと同じ）。`I`、`J`、`K` は内側からそれぞれ1段目、2段目、3段目のループ添字を返します。

## 浮動小数点数

`zig build -Dfloat=false` でビルドした版には、この章の語（語の一覧の「浮動小数点」の行の語、`FVARIABLE` `FCONSTANT` `FVALUE` `FLITERAL` `>FLOAT`、`FFIELD:` `SFFIELD:` `DFFIELD:`、`FLOAT%` `SFLOAT%` `DFLOAT%`）、浮動小数点数のリテラル、`F:` `F^` のローカル変数がありません。`1e` のような数は未定義の語として扱われ、`ENVIRONMENT?` は `FLOATING-STACK` と `MAX-FLOAT` に偽を返します。浮動小数点数を含む版で保存したイメージを読み込むと、浮動小数点の語の実行は `INVALID EXECUTION TOKEN` のエラーになります。

浮動小数点数は64ビット（倍精度）で、整数とは別の浮動小数点スタックに積みます。ソース中では、基数が10のときに `e` または `E` を含む数が浮動小数点数になります。

```forth
1E 2E F+ F.          \ 3.
1.5e0 F.             \ 1.5
3.1415926535E FCONSTANT PI
: AREA ( f: r -- f: area ) FDUP F* PI F* ;
5E AREA F.           \ 78.5398163375
10 S>F 4E F/ F>S .   \ 2
```

`1.5` のように `E` を含まない数は浮動小数点数として扱いません。

## 文字（UTF-8）

文字列はバイト列で、ASCII以外の文字はgforthと同じくUTF-8で入ります。`S" 日本語"` の長さは9で、`TYPE`、`/STRING`、`COMPARE` などの文字列の語はバイト単位で働きます。`KEY` は1バイトを返します。`CHAR`、`[CHAR]`、`'日'` のような文字リテラルは先頭の文字のコードポイントを返し（`CHAR 日` は26085）、次の語で1文字ずつ扱えます。

```forth
S" 日本語" X-WIDTH .            \ 6（端末での桁数）
S" 日本語" +X/STRING TYPE        \ 本語
26085 XEMIT                      \ 日
```

| ワード | スタック | 説明 |
| --- | --- | --- |
| `XC-SIZE` | ( xc -- u ) | xcをUTF-8で表したときのバイト数です。 |
| `X-SIZE` | ( addr u -- u2 ) | 文字列の先頭の文字のバイト数です（空の文字列ではgforthと同じく1）。 |
| `XC@+`, `XC@` | ( addr -- addr2 xc )、( addr -- xc ) | addrの文字（とその次のアドレス）を取り出します。 |
| `XC!+`, `XC!+?` | ( xc addr -- addr2 )、( xc addr u -- addr2 u2 flag ) | xcをUTF-8で書きます。`XC!+?` はuバイトに収まるときだけ書き、書いたかどうかを返します。 |
| `XC,` | ( xc -- ) | xcをUTF-8でデータ領域に加えます。 |
| `XCHAR+`, `XCHAR-` | ( addr -- addr2 ) | 次の文字、または前の文字のアドレスです。 |
| `XEMIT` | ( xc -- ) | xcを表示します。`EMIT` はこれまでどおり下位8ビットを1バイトとして書きます。 |
| `XKEY`, `XKEY?` | ( -- xc )、( -- flag ) | 1文字（`KEY` で読むそのバイト）を読みます。`XKEY?` は読めるかどうかを返します。文字の続きでないバイトは、次に入力を読む語（`KEY`、`ACCEPT`、`READ-LINE`、`INKEY` など）のために残します。 |
| `X-WIDTH`, `XC-WIDTH` | ( addr u -- n )、( xc -- n ) | 文字列や文字が端末で占める桁数です。`XC-WIDTH` は0、1、2か、表示しない文字（制御文字や文字のないコードポイント）なら-1です。`X-WIDTH` はそれらを0と数えます。 |

標準キー定数は`EKEYS`語彙にあり、起動時はFORTHの後、ROOTの前に検索します。ONLYの後は`ONLY FORTH ALSO EKEYS`で戻せます。EKEYSはRootからも見えるため、`ONLY ALSO EKEYS`でも定数を選択できます。`ALSO GRAPHICS`では従来のGRAPHICSキー値を優先します。標準修飾マスクはShift `0x10000000`、Alt `0x20000000`、Ctrl `0x40000000`です。単独Escは既知の列を合計最大50 ms待ちます。不明・未完の列の残りのバイトは保持します。

正しいUTF-8は、gforthと同じ値になります。冗長な形やサロゲートも同じです。それ以外は1つの規則に従います。先頭になれないバイト、途中で切れた文字（続きでないバイトか文字列の終わりで切れたもの）、U+10FFFFを超える値はU+FFFDとし、先頭のバイトとその続きのバイトだけを読み進めます（先頭になれないバイトは1バイト）。U+10FFFFを超えるコードポイントは、U+FFFD（3バイト）として書きます。桁数はUnicode Character Database 15.1.0から作り、すべてのコードポイントでLinux（glibc 2.39）のgforthと同じです。

Windowsでは、Sigmaの実行中、コンソールの表示と入力がUTF-8になります。出力のコードページをUTF-8（65001）にし、終了時（Ctrl+Cのときも）に元に戻します。キーボードから入力した文字もUTF-8として読みます。`SYSTEM` で起動したプログラムは、元のコードページで動くので、メッセージやファイルをSigmaを使わないときと同じように表示します。ファイル名と `SYSTEM` のコマンドは、WindowsでもUTF-8です（WindowsではUTF-16にして渡します）。

## 数値の書式（pictured numeric output）

`<<#` と `#>>` の間で、数値を右端から1桁ずつ文字列にします。

```forth
: dollars-and-cents ( u -- )
  0 <<# # # [CHAR] . HOLD #S [CHAR] $ HOLD #> TYPE SPACE #>> ;
1234 dollars-and-cents   \ $12.34
: my-. ( n -- ) S>D SWAP OVER DABS <<# #S ROT SIGN #> TYPE SPACE #>> ;
-123 my-.                \ -123
```

| ワード | スタック | 説明 |
| --- | --- | --- |
| `<#` | ( -- ) | 変換を開始し、入れ子を含む保持領域をすべて空にします。 |
| `<<#` | ( -- ) | 入れ子にできる変換を開始します（16段まで）。`#>>` と対にします。 |
| `#` | ( ud -- ud2 ) | 最下位の1桁を変換します。 |
| `#S` | ( ud -- 0 0 ) | 残りの桁をすべて変換します。 |
| `HOLD`, `HOLDS` | ( c -- )、( addr u -- ) | 文字または文字列を先頭に加えます。 |
| `SIGN` | ( n -- ) | nが負なら `-` を加えます。 |
| `#>` | ( ud -- addr u ) | 変換を終了し、文字列を返します。 |
| `#>>` | ( -- ) | `<<#` で始めた保持領域を解放します。 |

## ローカル変数

```forth
: SUM3 { a b c -- sum } a b + c + ;
1 2 3 SUM3 .                          \ 6
: COUNTDOWN { n -- } BEGIN n . n 1- TO n n 0= UNTIL ;
5 COUNTDOWN                           \ 5 4 3 2 1
: AREA { F: w F: h -- F: a } w h F* ;
2E 3E AREA F.                         \ 6.
: SWAP2 { W^ a W^ b } b @ a @ ;       \ W^ はアドレスを積みます
```

`{` と `}` の間に名前を書くと、スタックの値をその名前で使えます。最後の名前がスタックの一番上の値を受け取ります。

| 書き方 | 意味 |
| --- | --- |
| `{ a b -- c }` | aとbをスタックから受け取ります。`--` から `}` まではコメントです。 |
| `{ a \| b c }` | `\|` の後のbとcは0で始まり、スタックからは受け取りません。 |
| `W:`（省略可）, `D:`, `F:`, `C:` | 名前を書くと、それぞれセル、倍長整数、浮動小数点数、文字の値を積みます。`TO 名前` で値を変更できます。 |
| `XT:` | 名前を書くと、受け取った実行トークンを実行します。 |
| `W^`, `D^`, `F^`, `C^`, `XT^` | 名前を書くと、値を入れた場所のアドレスを積みます。`@` `!` `F@` などで読み書きします。 |
| `{: a b :}` | 標準Forthの書き方です。`{ }` と同じです。 |
| `LOCALS\| a b \|` | 標準Forthの古い書き方です。最初の名前（a）がスタックの一番上を受け取ります。 |
| `(LOCAL)` | これらの書き方の下にある標準の語 ( addr u -- ) です。コンパイル中に、その名前のローカル変数を宣言します。`0 0` で宣言を終えます。最初に宣言した名前がスタックの一番上を受け取ります。 |

ローカル変数は定義の途中や制御構造の中でも宣言できます。名前を使えるのは、必ずその宣言を通ってからたどり着く場所だけです（Gforthと同じ）。たとえば `IF` の中で宣言した名前は、`ELSE` の側や `THEN` の後では使えません。`BEGIN ... UNTIL` や `DO ... LOOP` の本体で宣言した名前は、ループの後でも使えます（`?DO` や `WHILE` の後で宣言した名前は使えません）。再帰呼び出しでは呼び出しごとに別の値を持ちます。アドレスの型で得たアドレスは、その定義を抜けると無効になります。定義の外では使えません。

## ファイルと例外

```forth
: MAKE-FILE
  S" data.txt" W/O CREATE-FILE THROW >R
  S" line 1" R@ WRITE-LINE THROW
  S" line 2" R@ WRITE-LINE THROW
  R> CLOSE-FILE THROW ;
: SHOW-FILE ( addr u -- )
  R/O OPEN-FILE THROW
  BEGIN PAD 80 2 PICK READ-LINE THROW
  WHILE CR PAD SWAP TYPE
  REPEAT DROP CLOSE-FILE THROW ;
MAKE-FILE S" data.txt" SHOW-FILE
```

ファイル語は結果のほかに **ior**（0なら成功、0以外ならエラー番号）を積みます。`THROW` に渡すと、エラーのときだけ処理を中断してメッセージを表示します（例: `NO SUCH FILE OR DIRECTORY !`）。

| `RENAME-FILE` | ( addr1 u1 addr2 u2 -- ior ) | 1つ目の名前のファイルを2つ目の名前に変えます。2つ目の名前のファイルがあれば置き換えます（Windowsでも同じ）。 |

| `BIN` | ( fam -- fam' ) | バイナリのファイルを指定します。ファイルはいつもバイトのまま読み書きするので、動きは変わりません。 |
| `INCLUDE-FILE` | ( fileid -- ) | 開いたファイルを解釈し、閉じます。エラーの表示では、ファイル名は `*file*` になります。 |
| `SLURP-FILE` | ( addr u -- addr' u' ) | 名前のファイルを丸ごと、改行も含めてそのまま読み、`ALLOCATE` で確保した領域に置きます。使い終わったら `FREE` で解放します。開けなければ `THROW` します。 |
| `STDIN`, `STDOUT`, `STDERR` | ( -- fileid ) | 標準入力、標準出力、標準エラー出力のファイル番号です。 |
| `THROW` | ( n -- ) | nが0なら何もしません。-1なら `ABORT` と同じです。それ以外は、`CATCH` で捕まえていなければエラーとして表示し、入力待ちに戻ります。 |
| `CATCH` | ( xt -- 0 \| n ) | xtを実行し、正常に終われば0を、`THROW` やエラーが起きればその番号を積みます。例外のときはスタックの深さをCATCHの時点に戻します。スタック不足は-4、ゼロ除算は-10、未定義語は-13です。 |

同時に開けるファイルは64個までです。終了時に開いたままのファイルは閉じます。`CATCH` で `THROW` を捕まえられます（下の表）。

## 動的メモリと動的文字列

```forth
VARIABLE MYSTRING
S" Hello, World!" MYSTRING $!
7 MYSTRING $!LEN  S" land" MYSTRING $+!  '!' MYSTRING C$+!
MYSTRING $.                     \ Hello, land!
VARIABLE NAMES
S" Alice" 0 NAMES $[]!  S" Bob" 1 NAMES $[]!
NAMES $[].                      \ Alice と Bob を1行ずつ表示
100 CELLS ALLOCATE THROW  FREE THROW
```

文字列変数は `VARIABLE` で作ります。中身はヒープに置かれ、長さに合わせて自動的に確保・解放されます。

| ワード | スタック | 説明 |
| --- | --- | --- |
| `ALLOCATE` | ( u -- addr ior ) | uバイトの領域を確保します。足りなければiorが-524です。 |

| `RESIZE` | ( addr u -- addr2 ior ) | 領域の大きさを変えます。内容は保たれ、アドレスが変わることがあります。 |
| `$!` | ( addr u $var -- ) | 文字列を文字列変数に格納します。 |
| `$@`, `$@LEN` | ( $var -- addr u )、( $var -- u ) | 文字列、または長さを返します。空の変数では `0 0`、`0` です。 |
| `$!LEN` | ( u $var -- ) | 長さを変えます。伸ばした部分は0です。 |
| `$+!`, `C$+!` | ( addr u $var -- )、( c $var -- ) | 文字列、または1文字を末尾に追加します。 |
| `$.` | ( $var -- ) | 文字列を表示します。 |
| `$INS`, `$OVER` | ( addr u $var off -- ) | off文字目に挿入、または上書きします。 |
| `$DEL` | ( $var off u -- ) | off文字目からu文字を削除します。 |
| `$FREE`, `$INIT` | ( $var -- ) | 文字列を解放して変数を0に、または空の文字列にします。 |
| `$SPLIT` | ( addr u c -- addr u1 addr2 u2 ) | 最初の文字cの前後に分けます。 |
| `$ITER` | ( $var c xt -- ) | 文字cで区切った各部分 ( addr u ) についてxtを実行します。 |
| `$TMP` | ( xt -- addr u ) | xtを実行し、その間の出力を文字列として返します。 |
| `$SUBSTITUTE` | ( addr1 u1 -- addr2 u2 n ) | `SUBSTITUTE` の結果を、専用の文字列に入れて返します。`$TMP` が順に使う文字列の1つです。 |

| `$[]FREE` | ( $[]var -- ) | 全要素と配列を解放します。 |

## 辞書の探索と入力の解析

```forth
: SQUARE ( n -- n^2 ) DUP * ;
SEE SQUARE                         \ : SQUARE / DUP * / ; と表示
S" DUP" FIND-NAME NAME>STRING TYPE \ DUP
: SHOW BL WORD FIND IF EXECUTE . ELSE COUNT TYPE ." ?" THEN ;
42 CONSTANT ANSWER
SHOW ANSWER                        \ 42
```

短い呼び出しの展開に対応する前の版と保存イメージを交換すると、同じ動作をする定義でも `SEE` の表示が変わる場合があります。旧版で新イメージを読むと、余分な `BRANCH` や空の `ELSE` が表示されることがあります。現行版で旧イメージを読むと、空の `ELSE` や直後の命令へ飛ぶ分岐が省略されることがあります。表示差だけで実行結果が変わったとは限りません。元のソースの保存には `SEE` を使わず、ソースファイルを残してください。

| ワード | スタック | 説明 |
| --- | --- | --- |
| `SEE 名前` | ( -- ) | 定義の内容を表示します。コロン定義は命令列から再構成するので、ソースと完全には一致しません。 |
| `FIND-NAME` | ( addr u -- nt \| 0 ) | 名前で辞書を探し、名前トークンを返します。見つからなければ0です。 |
| `NAME>INT` | ( nt -- xt ) | 名前トークンから実行トークンを得ます。 |
| `NAME>STRING` | ( nt -- addr u ) | 名前を文字列で返します。結果は8回分まで有効です。 |
| `WORD` | ( c -- c-addr ) | 入力から文字cで区切られた次の語を読み、数え付き文字列で返します。 |
| `SYNONYM 新しい名前 元の名前` | ( -- ) | 元の語の別名を作ります。即時語なら別名も即時語で、`TO` や `>BODY` も元の語に働きます。 |
| `TRAVERSE-WORDLIST` | ( xt wid -- ) | 語彙の語を新しい順に、名前トークンを渡してxt ( nt -- flag ) を実行します。偽が返るとやめます。 |
| `NAME>INTERPRET` | ( nt -- xt ) | `NAME>INT` と同じです。 |
| `LATEST` | ( -- nt ) | いちばん新しい語の名前トークンを返します。いちばん新しい定義に名前がなければ0です。 |
| `LATESTXT` | ( -- xt ) | いちばん新しい定義の実行トークンを返します。名前のない定義でも返します。 |
| `>NAME` | ( xt -- nt \| 0 ) | その実行トークンを持つ語の名前トークンを返します。名前がなければ0です。 |
| `ID.`, `.NAME` | ( nt -- ) | 語の名前と空白1つを表示します。2つは同じです。 |
| `ALIAS` | ( xt "name" -- ) | xt と同じことをする語 name を定義します。`' name` は xt を返します。新しい語は即時語になりません。 |
| `FIND` | ( c-addr -- c-addr 0 \| xt 1 \| xt -1 ) | 数え付き文字列の名前を探します。即時語なら1、それ以外は-1です。TO・IS・+TO・ACTION-OFも辞書検索でき、即時フラグ1を返します。 |
| `PARSE` | ( c -- addr u ) | 入力の続きを文字cの手前まで返します。 |
| `SOURCE` | ( -- addr u ) | 今の入力行（`EVALUATE` では文字列）のアドレスと長さです。 |
| `>IN` | ( -- addr ) | 入力行の中で次に読む位置（先頭からのバイト数）を持つセルのアドレスです。書き換えると、読む位置が変わります（行の長さ以上なら行の残りを読み飛ばし、負の値は `STRING TOO LONG !`）。 |
| `SOURCE-ID` | ( -- n ) | 端末なら0、`EVALUATE` なら-1、ファイルの読み込み中はそのファイルの番号です。 |
| `REFILL` | ( -- flag ) | 端末または読み込み中のファイルから次の行を読み、それを入力にして真を返します。入力の終わりと `EVALUATE` の中では偽です。 |

## 語彙（ワードリスト）と条件付きコンパイル

```forth
VOCABULARY MY-WORDS
ONLY FORTH ALSO MY-WORDS DEFINITIONS
: HELLO ." Hello, My Words!" ;
ORDER                \ MY-WORDS Forth Root     MY-WORDS
ONLY FORTH DEFINITIONS
HELLO                \ HELLO ?（見えなくなる）
WORDLIST CONSTANT UTIL
UTIL SET-CURRENT : TWICE 2 * ; FORTH DEFINITIONS
UTIL >ORDER 5 TWICE .   \ 10
1 [IF] ." yes" [ELSE] ." no" [THEN]
```

語は「語彙」に属し、検索順序に並んだ語彙から探されます。新しい語は定義先の語彙に入ります。起動時の検索順序は `Forth Forth Root`、定義先は `Forth` です。

| ワード | スタック | 説明 |
| --- | --- | --- |
| `VOCABULARY 名前` | ( -- ) | 語彙を作ります。名前を実行すると、検索順序の先頭をその語彙に置き換えます。 |
| `WORDLIST` | ( -- wid ) | 名前のない語彙を作り、その番号を返します。 |
| `FORTH`, `FORTH-WORDLIST` | ( -- )、( -- wid ) | 検索順序の先頭をForthにする、またはForthの番号を返します。 |
| `ONLY` | ( -- ) | 検索順序を最小（`Root Root`）にします。続けて `FORTH` と書くのが普通です。 |
| `ALSO`, `PREVIOUS` | ( -- ) | 検索順序の先頭を複製する、または先頭を取り除きます。 |
| `>ORDER` | ( wid -- ) | 語彙を検索順序の先頭に加えます。 |
| `DEFINITIONS` | ( -- ) | 検索順序の先頭の語彙を定義先にします。 |
| `GET-CURRENT`, `SET-CURRENT` | ( -- wid )、( wid -- ) | 定義先の語彙を取得、または変更します。 |
| `GET-ORDER`, `SET-ORDER` | ( -- wid... n )、( wid... n -- ) | 検索順序を取得、または設定します。`-1 SET-ORDER` は `ONLY` と同じです。 |
| `ORDER` | ( -- ) | 検索順序と、空白をあけて定義先を表示します。 |
| `SEARCH-WORDLIST` | ( addr u wid -- 0 \| xt 1 \| xt -1 ) | 1つの語彙だけから名前を探します。 |
| `[IF]`, `[ELSE]`, `[THEN]` | ( flag -- )、( -- )、( -- ) | flagが0なら、`[ELSE]` か `[THEN]` までの入力を読み飛ばします。行をまたいでも使えます。 |
| `[DEFINED] 名前`, `[UNDEFINED] 名前` | ( -- flag ) | 名前が検索順序で見つかるかどうかを返します。 |
| `[IFDEF] 名前`, `[IFUNDEF] 名前`, `[ENDIF]` | ( -- ) | `[DEFINED] 名前 [IF]`、`[UNDEFINED] 名前 [IF]` と同じです。`[ENDIF]` は `[THEN]` と同じです。 |
| `[DO]` … `[LOOP]`, `[?DO]`, `[+LOOP]`, `[I]` | ( limit start -- )、( n -- )、( -- n ) | 解釈中に、入力の範囲を繰り返します（Gforthと同じ）。`[?DO]` はlimitとstartが等しければ1回も実行しません。`[I]` は一番内側の `[DO]` か `[FOR]` の添字です。ファイルでは行をまたいでも使えます。 |
| `[BEGIN]` … `[UNTIL]`, `[AGAIN]`, `[WHILE]` … `[REPEAT]` | ( flag -- ) など | 解釈中の不定回の繰り返しです。 |
| `[FOR]` … `[NEXT]` | ( n -- ) | 添字をnから0まで減らしながら、n+1回繰り返します。 |

検索順序は16段までです。`WORDS` は検索順序の先頭の語彙の語だけを表示します。`ONLY` の後でも `FORTH` `ONLY` `ALSO` `ORDER` などは使えます。TO・IS・+TO・ACTION-OFは検索順序に従い、同名の定義で上書きできます。

## ソースファイルの読み込み

```forth
INCLUDE mylib.fs          \ ファイルを読み込んで実行します
REQUIRE mylib.fs          \ まだ読み込んでいなければ読み込みます
S" mylib.fs" INCLUDED? .  \ -1（読み込み済み）
LOCATE SQUARE             \ mylib.fs:2 と定義の行を表示
MARKER SAFE  : TEMP ." Hello" ;  SAFE   \ TEMP は消えます
```

| ワード | スタック | 説明 |
| --- | --- | --- |
| `INCLUDE ファイル名` | ( -- ) | ファイルを1行ずつ読み込んで実行します。 |
| `INCLUDED` | ( addr u -- ) | 文字列で指定したファイルを読み込みます。 |
| `REQUIRE ファイル名`, `NEEDS ファイル名` | ( -- ) | まだ読み込んでいないファイルだけを読み込みます。 |
| `REQUIRED` | ( addr u -- ) | `REQUIRE` の文字列版です。 |
| `INCLUDED?` | ( addr u -- flag ) | そのファイルが読み込み済みなら真を返します。 |
| `SOURCEFILENAME` | ( -- addr u ) | 読み込み中のファイル名です。端末では `*the terminal*` です。 |
| `SOURCELINE#` | ( -- u ) | 読み込み中の行番号です。端末では0です。 |
| `LOCATE 名前` | ( -- ) | その語を定義したファイルと行、定義の内容を表示します。 |
| `WHERE 名前` | ( -- ) | 読み込んだファイルの中で、その語を使った箇所を `ファイル:行:桁: 行の内容` の形で一覧します（Gforthと同じく、各行は80桁で、右端に通し番号が付きます）。`'` や `[DEFINED]` で名前を探した箇所も含みます。端末や `EVALUATE` の文字列での使用は記録しません。 |
| `MARKER 名前` | ( -- ) | 名前を実行すると、その語と以後の定義を消し、以後に読み込んだファイルを未読み込みに戻します。 |

`FPATH` が未設定または空なら、ファイル名はカレントディレクトリからの相対パスです。`REQUIRE` は元の名前を比較し、`./a.fs` と `a.fs` は別扱いです。読み込み中にエラーが起きると、`mylib.fs:3: ...` のようにファイル名と行番号を付けて表示します。ファイルの中で始めた定義は、同じファイルの中で終える必要があります。入れ子は8段まで、記録できるファイルは64個までです。

`FPATH ( -- owner )` は、ソース検索用の動的文字列所有セルを返します。`FPATH PATH= ~+|lib` でカレントディレクトリ、`lib` の順に検索します。`FPATH .PATH` で表示、`FPATH PATH+ other` で追加、`FPATH CLEAR-PATH` で従来動作へ戻せます。起動時・環境変数からの検索パスは設定しません。空でない設定では `OPEN-PATH-FILE` と同じ検索を使い、`./` は読込中ソース基準（ファイル外ではカレント基準）、通常の相対名は設定順、空の要素で検索終了となり、暗黙の追加検索はありません。

設定済みの `REQUIRE` は先に開いて、字句的に正規化した返却名を履歴と比較します。重複ハンドルは閉じます。そのため、以前読み込んだファイルでも削除後にはエラーになり得ます。シンボリックリンク、inode、大文字小文字による同一視はせず、相対名と絶対名は別扱いになり得ます。`INCLUDED?` は記録名との完全一致です。ソース名の上限255バイトは維持します。`SAVE`・全体復元は設定を保持し、`LOAD-DICTIONARY` は宛先の設定を維持します。取り込んだ定義内の `FPATH` も宛先設定を参照します。


## グラフィックスとサウンド

グラフィックスの語（`REQUIRE-GRAPHICS`: メモリ上の画像、写し合う画像、画像ファイル、文字、Tcl/Tk、キー、マウス、アニメーション。`REQUIRE-GUI`: ボタン、入力欄、リスト、メニュー、ダイアログ。`REQUIRE-GAME`: スプライト、タイルマップ、パレット、行ごとの効果）と、サウンドの語（`REQUIRE-AUDIO`: MSX BASIC の `PLAY`、`SOUND`、`BEEP`、音源、録音した音、モジュール）は、この移植版の拡張です。[グラフィックスとサウンドのマニュアル](GRAPHICS_AND_SOUND.ja.md)で説明します。

端末のEKEY/EKEY?ではCtrl+Cを割込み（UserInterrupt、THROW -28）として扱います。Gforth実測を踏まえた利用者の選択です。パイプ・ファイルからのバイト3は文字値3のままです。GRAPHICSの入力動作は変更しません。

## 標準ブロック操作

`LOAD`は番号付きブロックを実行します。辞書イメージの読込は`LOAD-DICTIONARY filename`です。

| 語 | スタック効果 | 動作 |
|---|---|---|
| `BLOCK`、`BUFFER` | `( u -- addr )` | 1024バイトを32バッファーのいずれかへ読み込みます。BUFFERも既存内容を読みます。 |
| `UPDATE` | `( -- )` | 最後に選択したバッファーを変更済みにします。 |
| `SAVE-BUFFERS`、`FLUSH`、`EMPTY-BUFFERS` | `( -- )` | 変更を保存／保存して割当解除／保存せず破棄します。 |
| `BLK`、`SCR` | `( -- addr )` | 実行中のブロック番号（それ以外は0）／最後にLISTした番号の変数です。 |
| `LOAD`、`THRU`、`LIST` | `( u -- )`、`( first last -- )`、`( u -- )` | 単独ブロック実行／両端を含む範囲実行／64文字×16行を行番号付きで表示します。 |

既定ファイルは作業ディレクトリの`blocks.fb`で、初回アクセス時に開くか作成します。EOFで不足するバイトは空白にします。既存のファイルの穴はGforthと同じくNULバイトであり、実行可能な空白ブロックではありません。空白ソースとして使うブロックは`1 BLOCK 1024 BL FILL UPDATE`などで明示的に初期化してください。読み取り専用の既存ファイルも取得できますが、変更の保存は権限エラーをTHROWします。BLOCK/BUFFERは0〜0x1fffff、LOAD/THRUは1〜0x1fffffを受け付け、範囲外はTHROW -35です。THRUの開始が終了を超える場合は何も実行しません。番号を32で割った剰余が同じバッファーを共有し、変更済みなら再利用前に保存します。編集後はUPDATEが必要です。入出力エラーはiorをTHROWし、保存失敗時は変更状態を保持します。

LOAD中のSOURCE-IDは2、SOURCEは1024バイトです。バックスラッシュコメントは次の64文字境界までです。REFILLは次のブロックを選択します。SAVE-INPUTは`( blk cursor 2 )`を返し、ブロック入力中のRESTORE-INPUTはこの形式を受け付けます。入れ子のLOADやTHROW後は呼出元の入力とBLKを復元し、EVALUATE中はBLKを0にします。

BYEと入力終端による通常終了では変更を書き戻します。SAVESYSで作った実行体も同じです。書戻し失敗は報告し、バッチ処理の終了コードは1になります。異常終了時の未保存内容は保証しません。`-e`やソースファイル内の未捕捉エラー、シグナルによる終了も含みます。バッファーと入力スナップショットは辞書イメージに含めず、同じプロセス内の辞書復元では現在の未保存バッファーを保持します。辞書データの前に40 KiBを予約します。USEなどGforth固有のブロック拡張は未実装です。

## 辞書の保存と単独実行ファイル

この移植版の `SAVE` と `LOAD-DICTIONARY` は利用者定義語の辞書イメージを扱います。誌面のエディットバッファ操作とは異なります。

```forth
SAVE words.sigma
LOAD-DICTIONARY words.sigma
```

`LOAD-DICTIONARY` は保存した利用者定義語を現在の辞書の後ろに追加します。同名語は読み込んだ新しい定義が優先されます。以前の形式の辞書イメージ（`SIGIMG44` 以前）と、壊れた辞書イメージは読み込めません（`INVALID IMAGE !`）。入力領域を辞書の前に移し、メモリの配置が変わったためです。この版は `SIGIMG45` で保存します。`REQUIRE-GRAPHICS` でグラフィックスの語を読み込んだ辞書は `SIGIMG46` で保存し、`FORGET` や `MARKER` でグラフィックスの語を消したあとも同じです。`REQUIRE-AUDIO` で音の語を読み込んだ辞書は、グラフィックスの語の有無によらず `SIGIMG47` で保存します。どれも0.8.0までの版では読み込めません。辞書イメージには保存したときの `-m` と `-l` の大きさを記録します。`LOAD-DICTIONARY` は、大きさの違うSigmaで保存したイメージも読み込めます。辞書イメージにはチェックサムが付いており、偶然の破損は読み込む前に見つかります。読み込むのは、Sigmaの `SAVE`・`SAVESYS` で作ったファイルだけにしてください。定数や変数に保存した実行トークン（`:NONAME` の結果など）と、`LITERAL` で定義に埋め込んだ実行トークンやアドレス（`[ ' X ] LITERAL` など）は、すでに利用者定義語がある辞書へ `LOAD-DICTIONARY` すると別の語や場所を指すことがあります。`['] X` で埋め込んだ実行トークンは正しく付け替えられます。`SAVESYS` は語IDを保持しますが、生のヒープ番地を保持することは保証しません。

`SAVESYS` は、現在の辞書・コンパイル済み定義・データを含む、実行中環境向けの単独実行ファイルを作ります。

```forth
SAVESYS demo.exe
```

生成したファイルはその辞書を持って起動し、Sigmaと同じコマンドラインの引数を受け付けます（[起動と入力](#起動と入力)を参照）。引数なしなら対話プロンプトを開きます。生成物は作成元と同じ実行環境向けです。生成したファイルは保存したときの `-m` と `-l` の大きさで起動します。スタックの大きさ（`-d`、`-r`、`-f`）は指定できますが、`-m` と `-l` を指定すると `A SAVED PROGRAM KEEPS ITS MEMORY LAYOUT !` を表示して終了コード1で終了します。

## 数値演算・数値入出力の拡張（P02）

次の語は組込みです。浮動小数点の語はfloat有効構成で使用でき、浮動小数点の引数は独立したFスタックに置きます。各スタック効果はHELP、境界仕様と比較元との差は[実装・検証記録](P02_IMPLEMENTATION.md)を参照してください。

- **整数除算とビット演算**: `*/F`, `*/MODF`, `*/MODS`, `*/S`, `/F`, `/MODF`, `/MODS`, `/S`, `>POW2`, `ARSHIFT`, `CTZ`, `DARSHIFT`, `DLSHIFT`, `DROL`, `DROR`, `DRSHIFT`, `DU/MOD`, `LOG2`, `LROL`, `LROR`, `MODF`, `MODS`, `MUX`, `POW2?`, `U*/`, `U*/MOD`, `U/`, `U/MOD`, `UD/MOD`, `UMOD`, `WROL`, `WROR`.
- **浮動小数点演算**: `-INF`, `-INFINITY`, `1/F`, `F*+`, `F2*`, `F2/`, `FAXPY`, `FCOPYSIGN`, `FFOURTH`, `FTHIRD`, `F~ABS`, `F~REL`, `INF`, `INFINITY`, `NAN`, `V*`.
- **変換・表示・乱数**: `RANDOM`, `RND`, `SEED!`, `>FLOAT1`, `BASE-EXECUTE`, `CONVERT`, `DEC.`, `DEC.R`, `DPL`, `E.`, `E.EXACT`, `E.P`, `FP.`, `H.`, `HEX.`, `UD.`, `UD.R`.

F系の除算は負の無限大へ、S系は0方向へ丸めます。剰余を先、商を上へ返します。ゼロ除算は-10、セル商の範囲外は-11です。DU/MODは符号付き二倍長と符号なし除数、UD/MODは符号なし二倍長商を扱います。

幅（64/128）以上のシフト数は、論理シフトで0、算術シフトで符号埋めです。回転数は幅で剰余を取り、W/L回転は上位を0にします。Gforthの一部の境界結果とは異なります。

F*+はr1+r2*r3を融合丸めします。F~ABS/F~RELは厳密な不等号で判定し、相対誤差はabs(r1)+abs(r2)で尺度を取ります。V*/FAXPYのストライドは符号付きバイト数で、負数・0を許します。要素数0ではメモリーを参照せず、FAXPYは書込み前に両ベクトルの範囲を検査します。重複領域は要素順に処理します。

BASE-EXECUTEは正常終了・THROWの双方でBASEを復元します。DEC.は符号付き、DEC.Rは仕様書に従う符号なし10進です。H./HEX.は$接頭辞付き16進です。明示基数の表示はBASEを変えません。UD./UD.Rは符号なし128ビット全域を表示します。右寄せ表示には末尾空白を付けません。CONVERTは先頭1バイトを飛ばし、DPLは最後の整数変換の最終小数点以降の桁数（小数点なしは-1）を示します。

>FLOAT1は小数点文字を指定できます。E.は往復可能な短い値、E.EXACTは完全な十進値、E.Pは指定した有効桁数（1〜1000、範囲外-11）で表示します。この3語は末尾空白を付けません。FP.は工学表記とSI接頭辞を使い、末尾空白を付けます。

SEED!は0を含む64ビットの種を設定し、RNDは生セル、RANDOMは符号なし上限未満（上限0では0）を返します。同じ種でSigma内の列を再現しますが、Gforthの列との一致は要求しません。乱数状態は辞書イメージに保存しません。

P02レビュー補足：起動時の乱数種はホスト時刻から設定し、時刻を取得できなければ0です。RNDの生LCG状態は下位ビットが弱く、範囲選択にはRANDOMを使ってください。debug有効構成では、V*/FAXPYとDEC.R/UD.Rの長い内部ループも--max-stepsの対象です（256回以下の処理を1単位）。既定値0は無制限で、中断前の変更は戻しません。FP.はNaN・無限大にも末尾空白を付けます。HEX下でE./DEC.を数値として使う場合は$E./$DEC.と書いてください。

## 固定幅メモリー操作（P03a）

`!@`, `*ALIGN`, `*ALIGNED`, `+!@`, `/L`, `/W`, `/X`, `C>S`, `CELL/`, `CHAR-`, `DFLOAT/`, `FLOAT`, `FLOAT/`, `L!`, `L>S`, `L@`, `LALIGN`, `LALIGNED`, `LBE`, `LLE`, `MAXALIGNED`, `SFLOAT/`, `TH`, `TH!`, `TH@`, `W!`, `W>S`, `W@`, `WALIGN`, `WALIGNED`, `WBE`, `WLE`, `X!`, `X>S`, `X@`, `XALIGN`, `XALIGNED`, `XBE`, `XD!`, `XD>S`, `XD@`, `XDBE`, `XDLE`, `XLE`

W/L/Xは16/32/64ビットのリトルエンディアン論理メモリーを扱い、未整列を許します。読込はゼロ拡張、格納は下位ビットのみで、全幅を検査してから書きます。XD@/XD!も8バイトですが、スタックは二倍長です。XD>Sは1セルを二倍長へ符号拡張します。BEは下位ビットをバイト反転し、LEは恒等演算です。!@/+!@は古いセルを返す置換／加算で、原子操作ではありません。TH系はbase+index*8を使います。W/L/X整列は2/4/8、最大整列は8。明示整列は非0の2の累乗が必要です。詳しいスタック効果はHELP、境界と検証は[P03記録](P03_IMPLEMENTATION.md)を参照してください。

### 辞書データ配置（P03bの実装済み部分）

`W,`、`L,`、`X,`は下位16/32/64ビットを自動整列せずに格納します。`XD,`は2セル入力の下位64ビットを8バイトだけ格納します。`WFIELD:`、`LFIELD:`、`XFIELD:`は自然整列した幅2/4/8のフィールド、`2FIELD:`は8バイト整列・16バイトのフィールドです。`MAXALIGN`はHEREを8バイト整列します。

`MEM, ( addr u -- )`は指定領域をHEREへ重なりを考慮してコピーし、`SAVE-MEM-DICT ( addr1 u -- addr2 u )`はコピー先も返します。`->HERE ( addr -- )`はデータ領域内でHEREを設定し、辞書の語は削除しません。名前付き語が使う領域をこの語で回収しないでください。容量・入力・範囲の検査で失敗した場合はHEREと入力を保持します。生数値のアドレス自動判定は行わず、型付きアドレスの永続化はまだ実装していません。詳しくは[P03記録](P03_IMPLEMENTATION.md)。

### 型付きアドレス（P03b）

`A, ( addr -- )`、`ACONSTANT ( addr "name" -- )`、`AVARIABLE ( "name" -- )`はアドレスを明示登録します。AVARIABLEの初期値は0です。通常の数値セルに型を推測して付けません。全セル更新は型を維持し、部分書込みは破損状態にします。MOVE系は全登録セルのコピーなら型も移し、FREE・縮小・FORGET/MARKER・HERE巻戻しは参照の寿命を追跡します。解放した番地を再利用しても参照は自動復活しません。登録上限はVMごとに2,048件です。

型付き参照はSIGIMG45/46/47で保存・復元・追加できます。明示登録から到達するヒープだけを取り込み、生セルからアドレスを推測しません。破損・無効参照は-9、形式不正や追加先の固定システム登録との競合は-264、容量不足は対応する容量エラーです。旧形式SIGIMG44以前は拒否します。[形式](IMAGE_FORMAT45.md)、[P03記録](P03_IMPLEMENTATION.md)。

### ヒープと伸長バッファー（P03c）

SAVE-MEM ( addr1 u -- addr2 u ) は所有するヒープコピーを返します。EXTEND-MEM ( addr1 u1 u -- addr addr2 u2 ) は領域をuだけ拡大し、追加部分の番地、新番地、合計長を返します。返却領域は呼出側がFREEし、移動後の新番地を使います。

BUFFER% ( -- alignment size ) は8と24を返します。3セルは長さ・番地・容量です。INIT-BUFFER ( descriptor -- ) で新しい記述子を初期化し、ADJUST-BUFFER ( u descriptor -- ) で長さを変更します。拡大は内容を保持し、縮小は容量を解放しません。番地セルは保存・復元に対応する型付き参照です。

FREE-MEM-VAR ( descriptor -- ) は最初の2セルの領域を解放して0にします。NULLなら変更しません。3セル記述子の容量は残るので、再使用前にINIT-BUFFERを行います。INIT-BUFFER自体は古い領域を解放しません。割当失敗はIORをTHROWし、元領域と記述子を保持します。

P03の型付き登録はVM全体で2,048件です。文字列配列は外側の所有セルと初期化済み要素の所有セルをそれぞれ使うため、他の登録がなければ通常は最大2,047要素です。一時文字列等もこの枠を使います。表が満杯ならMemoryExhaustedで停止し、型を捨てて続行しません。移動するヒープの登録は純移動し、移動中だけ倍の件数を要求しません。

解釈時の`S" hello" 2CONSTANT G`や、ALLOCATEの返却値を普通のVARIABLE/カンマ/数値LITERALへ格納した生番地は、SAVE/SAVESYSを越えて有効ではありません。対象が省略されたり、復元で詰め直した別のブロックと旧番地が一致したりします。永続化する場合は`S" hello" SWAP ACONSTANT G CONSTANT G-LENGTH`のように番地を明示登録してください。

無効な値のA,/ACONSTANTは登録できても保存時に拒否します。A,のセルは完全な!で修復できます。既存の型付きセル全体へのMOVEは完全な!と同様にその型を保ち、元が未登録の数値でも値を再検査します。部分書込みは同じバイトでも破損です。LOAD-DICTIONARYは既存登録を全件保持するので全件検査し、SAVEは到達可能な登録だけを取り込むため、孤立したヒープの破損登録を無視します。

### P04a 基本文字と借用文字列

#BELL/#BS/#CR/#DEL/#EOF/#ESC/#FF/#LF/#TABは7/8/13/127/4/27/12/10/9、INVALID-CHARはU+FFFDです。NEWLINEは借用のLF一文字（長さ1）を返します。

TOUPPERはASCIIのa-zだけを変換します。CAPSCOMPARE・CAPSSTRING-PREFIX?・CAPSSEARCHもASCIIだけを大文字小文字なしで扱います。検索成功時は借用の部分文字列、失敗時は元の文字列と偽を返します。STR<とSTRING-SUFFIX?はバイト比較です。SAFE/STRINGはスキップを0から長さまでへ制限し、SCAN-BACKは最後の一致バイトまでの長さを返します。NOSPLIT?は両記述子を保って末尾の空文字列か調べます。TYPEWHITEはTABを保ち、それ以外の各バイトを空白にします。所有する新しい文字列は確保しません。[P04記録](P04_IMPLEMENTATION.md)。

### P04a 所有文字列と編集

S+は連結した新しいヒープ文字列を返し、呼出側がFREEします。APPENDは第1文字列を再確保するので、移動後の返却番地を使います。第1領域内を指す第2文字列も移動をまたいで保持します。CSTRING>SSTRINGはNUL終端文字列の借用参照を返し、論理メモリー内に終端がなければInvalidAddressです。

INSERTは固定長の第2バッファーを右へずらしてから、長さを切り詰めた第1文字列を読み込んでコピーします。重複時はシフト後の内容を読みます。DELETEは先頭を削り、残りを左へ移動して末尾を空白にします。STRING,は長さの下位8ビットと全バイトを辞書へ格納し、整列しません。255バイトを超える場合も全バイトをコピーします。複数コピーに必要な型登録は書込み前に検査します。XC@+?も実装済みです（下記）。[P04記録](P04_IMPLEMENTATION.md)。

XC@+? ( addr u -- addr2 u2 xc ) はX@+/STRINGと同じ規則で、長さの範囲内から先頭のUTF-8文字を取得します。空入力ではメモリーを読まずU+FFFDを返し、番地を1進め、残長を-1にします（利用者が選択したSigma仕様）。負の残長を有効な入力文字列として再使用しないでください。範囲・出力容量のエラーでは入力を保持します。指定Gforthとは非空入力が一致しますが、空入力の返却コードポイントはGforthの0と異なります。

### 文字列値（P04b）

S" initial" $VALUE NAMEは入力をコピーして所有する文字列値を定義します。NAMEは借用の番地・長さを返します。S" new" TO NAMEで置換し、S" more" +TO NAMEで追記します。定義内のTO/+TOでも使えます。MACRO:は現在の語彙に$VALUEと同じ値を定義します。失敗時は旧内容を保持し、置換すると旧領域への明示参照は無効になります。

' NAME >BODYで所有セルを取り出し、$FREEへ渡せます。FORGET/MARKERは辞書領域と永続化の根を除去するため、不要な所有領域は事前に解放します。明示参照から到達するヒープは保存・復元・追加読込に対応します。MACROS-WORDLIST・REPLACER:・.SUBSTITUTEも利用できます（下記）。[P04記録](P04_IMPLEMENTATION.md)。


### 置換マクロ

`MACROS-WORDLIST ( -- wid )`は大文字・小文字を区別するマクロ語彙です。`REPLACER: NAME ... ;`は`( -- addr u )`のコールバックをそこへ定義し、本体コンパイル前に元のCURRENTへ戻します。REPLACESは所有文字列値を作成・更新しますが、コールバック定義の上書きは警告して保持します。MACRO:で直接登録するにはCURRENTを保存してMACROS-WORDLISTへ設定し、定義後に戻してください。TO/+TOでは検索順序へ追加します。名前はSigmaの辞書制限（1〜255バイト）に従います。

`.SUBSTITUTE ( addr u -- n )`は置換結果を表示し、置換数を返します。`%%`は`%`、未知・未閉鎖の名前は元の文字列を保ちます。各出現のコールバックは一度だけ実行し、THROWは3種類すべての置換APIから呼出元へ伝播します。表示済みの文字列は戻りません。$SUBSTITUTEとSUBSTITUTEはコールバック内のTYPE等も結果へ取り込み、$TMPとの入れ子に対応します。入力は実行前に複製し、結果は成功後に反映します。SUBSTITUTEは容量超過時に切り詰めて-78を返しますが、全出現を実行し、途中で結果全体のヒープ領域を必要とします。マクロ・所有値・コールバックは保存・復元と繰り返し追加読込に対応します。

コールバックは呼出元の既存スタック値と、SUBSTITUTEの出力先の寿命を保つ必要があります。実行時検査はスタック深さと戻り範囲であり、任意のForthコードから既存セルの変更を隔離するものではありません。%を含むマクロ名も辞書には登録できますが、置換構文の区切りを含むため%name%からは参照できません。所有セルを生の!等で別名化した場合、所有権の一意性は画像検証では保証されません。


### P05a ファイルストリーム補助

`EMIT-FILE ( c fileid -- ior )`はcの下位8ビットを1バイト書き、ホストのエラーを返します。改行・フラッシュ・クローズは行いません。`SLURP-FID ( fileid -- addr u )`は現在位置からEOFまでを新しい所有ヒープ領域へ読み、ファイルを開いたまま返します。空入力でもFREEできる領域を返します。使用後はaddrをFREEしてください。ファイルサイズやシークは不要で、短い読取も継続します。エラー時はTHROWし、途中の領域を解放しますが、既に進んだファイル位置は戻しません。-Dfiles=falseでは両語を除外します。[P05記録](P05_IMPLEMENTATION.md)。


### ファイル入力とEOF（P05a）

`KEY-FILE ( fileid -- c )`は1バイト（0〜255）を読み、EOFでは-1、I/OエラーではTHROWします。STDINはEnterを待たない文字入力とし、端末のCtrl+CはEKEY同様の割込みです。リダイレクト入力のバイト3は通常データです。WindowsコンソールはUTF-8の文字バイトを返し、文字以外の拡張キーイベントは読み飛ばします（拡張キーはEKEYを利用）。

`KEY?-FILE ( fileid -- flag )`は待機せず、未読・Cバッファ内の文字も考慮して判定します。入力を消費せず、EOF指示子も変更しません。指定Gforthで観測した未読文字の誤判定は再現しません。`FILE-EOF? ( fileid -- flag )`は読取で観測したEOFを返します。最後の1バイトを読んだだけではEOFにならず、末尾を越える読取で真になります。通常ファイルでは成功したREPOSITION-FILEで解除され、FILE-SIZEや長さ0の読取では保たれます。STDINは共有の入力・先読み状態を追跡します。

3語はfiles機能群に属し、`-Dfiles=false`では除外されます。カスタムホストはFileOpsのkey/ready/eofを実装してください。未対応フックはFileUnavailableとなり、ブロッキング読取や位置比較で代用しません。主ホストは通常ファイルのバッファリングを保ち、Windowsパイプのみ待機判定用のstdio設定を使います。WindowsのSTDIN以外の文字デバイスでは待機判定に未対応のI/Oエラーを返す場合があります。[実装・検証記録](P05_IMPLEMENTATION.md)。


### 作成権限と読込履歴・ファイル終了（P05a）

`+FMODE ( fam mode -- fam2 )`は、R/O・R/W・W/O（BIN併用可）へ9ビットのrwxrwxrwxを指定します。例：384（十進数、八進数0600）は所有者の読書きです。CREATE-FILEではPOSIXのumaskに従って作成時に適用し、既存ファイルの権限を指定値へ変更しません。OPEN-FILEでは権限フィールドを無視します。WindowsはCRTの所有者read/writeへの対応で、POSIXのgroup/executeやACL設定とは異なります。カスタムホストはFileOps.create_modeが必要です（標準0666以外の指定）。

`.INCLUDED ( -- )`は現在の読込済み登録名を各1回、登録順で表示します。各名前の前に改行を置き、末尾には追加しません。MARKER・保存・復元・追加読込の既存履歴に従います。Gforthのように同じ名前をINCLUDE回数分表示しない方針です。

バックスラッシュ3個の即時ワードは、読込中のファイルを末尾へ進め、現在行を含む残りを読み飛ばします。親ファイル・呼出元は続行します。埋込ソースにも対応し、端末・EVALUATE・ブロックではスタックを変えず何もしません。シーク等ができないファイルではI/Oエラーが伝播します。ファイル内で開始した未完の定義を許さない既存規則は変わりません。[P05記録](P05_IMPLEMENTATION.md)。

### パス記述子（P05a）

`VARIABLE P`等の動的文字列所有セルをパスとして使います。`P CLEAR-PATH`で空にし、`P PATH= one|two`で全体を設定、`P PATH+ three`や`S" a dir" P ALSO-PATH`で追加できます。内部はNUL区切りで、`P $@`で借用参照できます。変更後の借用領域は無効になるため、不要な所有領域は`P $FREE`で解放してください。PATH=は入力ソースを変更しません。

`P .PATH`は各成分と空白を表示し、最初の空成分で終了します。`ABSOLUTE-FILE? ( addr u -- flag )`は先頭/・~・./、または3バイト以上で第2文字が:かを調べるGforthの構文判定です。OS上の絶対パス正規化ではありません。空文字列はメモリーを読まず偽です。検索2語は次節を参照してください。空でないFPATHを設定した場合は、INCLUDE/REQUIREもこの検索を使用します。[P05記録](P05_IMPLEMENTATION.md)。

### パスからの検索

`S" name" P OPEN-PATH-FILE`は成功時に`( fid addr u 0 )`、失敗時にはiorだけを返します。読み取り専用で開くため、使用後にCLOSE-FILEしてください。最初の成功または空成分で検索を終了し、空パスは-37を返します。`S" name" P FILE>PATH`は`( addr u )`を返してファイルを閉じ、開閉エラーをTHROWします。

先頭/・~・./・ドライブ形式は検索リストを迂回します。./は現在の物理ソースファイルのディレクトリ基準（端末/EVALUATEでは作業ディレクトリ）、~+/は作業ディレクトリ基準です。開く際は~/をHOMEで、POSIXの~userをユーザーデータベースで展開します。返却文字列には~表記を残します。ネイティブホストはGforth同様に書込可能なホームを選択します。WindowsではHOME未設定時にHOMEDRIVE+HOMEPATH、TEMP、TMPへフォールバックし、名前付きユーザー展開は未対応です。字句的な圧縮はシンボリックリンクを解決しません。

返却結果は最大1,024バイトのシステムバッファを借用し、次のパス検索まで有効です。リセット・イメージ復元後も無効です。保持する場合はコピーし、FREEしないでください。長すぎる候補はStringTooLong、NULを含む名前は引数エラーとなります。INCLUDE/REQUIREへの接続は別タスクです。[P05記録](P05_IMPLEMENTATION.md)。

### ファイル名の成分

`BASENAME ( addr u -- addr2 u2 )`は最後の`/`より後、`DIRNAME ( addr u -- addr u2 )`は最後の`/`を含む先頭部分を返します。どちらも元のバイト列を借用し、変更・メモリー確保を行いません。結果の利用中は元データを保持してください。`a/b`なら`b`と`a/`、`a/`なら空と`a/`、`file`なら`file`と空です。正規化は行わず、Gforthの定義に合わせてWindowsでもバックスラッシュを通常の文字として扱います。

### ファイル名パターン

`FILENAME-MATCH ( name u pattern u2 -- flag )`はファイルシステムを参照せず、名前全体を照合します。大文字小文字を区別し、`*`は0個以上、`?`は1個のUTF-8コードポイントに一致します。/と先頭の.も対象です。角括弧は文字集合、`[a-z]`等の範囲、先頭!/^による否定、`[[:digit:]]`等のASCII文字クラスに対応します。バックスラッシュで記号をエスケープできます。末尾バックスラッシュ、閉じていない括弧、未知の文字クラス、未対応のロケール照合・同値構文は不一致です。リテラルの[はエスケープしてください。

ASCII文字クラスはalnum・alpha・blank・cntrl・digit・graph・lower・print・punct・space・upper・xdigitの12種です。範囲はOSロケールによらずコードポイント順です。日本語は???、éは?に一致しますが、éはASCIIのalphaクラスには一致しません。結合文字は別に数え、正規化・大文字小文字の同一視はしません。不正UTF-8は各バイトを独立した1単位として扱い、NULを含む引数は引数エラーをTHROWします。ヒープ確保やホスト機能は不要で、有効な実行ステップ上限も照合に適用されます。

### 作業ディレクトリ

`GET-DIR ( addr capacity -- addr u | 0 0 )`はプロセスの作業ディレクトリを呼び出し側のバイトバッファへ書き込み、終端NULを付けます。uはNULを含みません。パスのバイト長+1以上を確保してください。容量不足・容量0・ホストエラーでは0 0を返します。`PAD 1024 GET-DIR TYPE`で、収まる場合にcwdを表示できます。

`SET-DIR ( addr u -- ior )`はプロセス全体のcwdを変更します。./を含む相対名は、ソースファイル内でもcwd基準です。~/・~userはパス検索同様に展開し、~+/はcwd相対です。シンボリックリンク/..の扱いはOSに従います。以後の相対ファイル・INCLUDE・イメージ操作は新しいcwdを使用し、既存の開いたストリームは維持されます。既存パスヘルパーにより展開名は最大1,024バイトで、超過はStringTooLong、NULは引数エラーのiorです。VMヒープ確保は不要です。ホスト機能がなければFileUnavailableをTHROWします。cwdはOS資源であり、辞書イメージの復元対象には含みません。

### ディレクトリの作成

`=MKDIR ( addr u mode -- ior )`は1個のディレクトリを作成します。`MKDIR-PARENTS ( addr u mode -- ior )`は/で区切った親成分から順に、同じmodeで作成します。modeにはrwxrwxrwxの9ビット、例えば10進493（8進0755）を指定します。POSIXでは作成時のumaskに従い、既存の権限は変更しません。Windowsの_wmkdirではmodeを無視し、OSの権限継承に従います。

中間のEEXISTは許容しますが、最後のmkdir結果はそのまま返すため、最後が既存ディレクトリでもEEXISTです。末尾/がある場合は、葉を中間成分として作成した後、最後にEEXISTを返すことがあります。これはGforthに合わせた動作です。他のエラーでは以後の作成を止め、作成済みの親を残します。場所を空けるためのファイル削除は行いません。ホーム展開と最大1,024バイトのパス制限はSET-DIR同様で、./・..・シンボリックリンクはOSのcwd相対解釈を維持します。Windowsでも親の分割はバックスラッシュではなく/です。=MKDIRの~+/childは使えますが、MKDIR-PARENTSでは途中の~+が空へ展開され、失敗する場合があります。VMヒープ確保や永続リソースの返却はありません。

### ディレクトリ列挙

`OPEN-DIR ( addr u -- dir ior )`はSET-DIR同様のホーム展開・最大1,024バイトの名前制限で列挙を開始します。`READ-DIR ( addr capacity dir -- length flag ior )`はNULなしで名前を書き込みます。収まれば長さ/真/0、切り詰めれば項目を消費して容量/真/ENAMETOOLONGを返し、容量0でも同様です。バイト単位のためUTF-8の途中で分割する場合があります。終端は0/偽/0でバッファを変更せず、ハンドルは開いたままです。項目・ドット名・順序はOSに従います。

`CLOSE-DIR ( dir -- ior )`はネイティブの解放エラー時もIDを無効化するため、同じIDで再試行しないでください。古いIDやファイルIDはEBADFです。ネイティブホストの同時列挙上限は64で、残りはプロセス終了時に解放します。通常のForthエラーでは自動解放しないため、アプリの終了・エラー経路で明示的に閉じてください。バッファは呼び出し側が用意し、VMヒープ確保は不要です。辞書イメージには列挙資源・位置を保存しません。状態保存前に閉じ、後で名前から開き直してください。数値IDはプロセス内の資源を表し、移植可能な保存値ではありません。

### 実時刻とCPU時間

`NTIME ( -- dtime )`はUnix epochからのナノ秒数をダブルセルで返します。UTIMEと同じ実時計で、システム時刻変更により飛ぶ場合があります。単位がナノ秒でもナノ秒精度を保証しません。`CPUTIME ( -- duser dsystem )`はプロセスの累積user/system CPU時間を、それぞれマイクロ秒のダブルセルで返します。全スレッドと起動時のCPU時間を含み、子プロセスを除外します。待機を含む経過時間ではなくCPU消費を測ります。

両ワードはfiles/float無効構成でも利用できます。必要なホストフックがなければHostUnavailable、ホストの取得失敗はHostFailedとなり、途中の結果はスタックに追加しません。ヒープ確保は不要です。各ダブルセルの表示にはD.を使い、CPUTIME直後の最上位ペアはsystem時間です。

### ナノ秒待機

`NS ( dnanoseconds -- )`は符号付きダブルセルのナノ秒数を消費します。0以下は即時終了し、`1000000. NS`はOSのスケジューリングに従って少なくとも1ms待機します。正値は単調時計を基準に分割待機し、端末のCtrl+CをUserInterrupt(-28)として返します。他の入力は既存のキューに保持し、NS自身は標準入力の読み取りやイベント処理を行いません。端末・コンソール設定とハンドラを復元し、MSの既存動作も変更しません。

上限は(2^63-1)秒+999,999,999nsで、超過はResultOutOfRange(-11)です。実際の精度はOSに依存し、Windowsの正のSleep区間はミリ秒へ切り上げます。正値にはホストのsleep_nsフックが必要で、未提供ならHostUnavailableです。ネイティブ待機はプロセス内で同時に1個のみで、並行・入れ子呼び出しはHostFailedになります。通常のcanonical編集は維持し、raw入力から新たに有効になるCtrl+C以外のシグナル文字は一時無効にしてキーを保持します。すでにキューにあるrawのバイト3も読み取りません。files/float無効構成でも利用でき、VMヒープ確保は不要です。

### Unix秒から日時・タイムゾーンへの変換

`>TIME&DATE&TZ ( dseconds -- second minute hour day month year dst offset addr u )`は符号付きUnix秒を変換します。epochなら`0. >TIME&DATE&TZ`です。NTIMEのナノ秒値は先に1,000,000,000で除算してください。月は1..12、年は西暦全体、dstはOSのDST判定によるForthフラグです。offsetはDST込みのUTCから東向き正の秒数で、東京は通常32400、ニューヨークは通常-18000または-14400です。

addr/uは取得可能なOS/CRTのTZ名を最大256バイトで借用し、次の成功した変換・リセット・イメージ復元まで有効です。長く保持する場合はコピーし、FREEやNUL終端の想定はしないでください。名前は略称・表示名の場合があり、取得不能なら空も許容します。GETENV・パス検索とは専用バッファを分けています。日付範囲とTZ環境変数の構文はOS/CRTに依存します。範囲外・OS暦範囲超過はResultOutOfRange、その他の失敗はHostFailed、フック未提供はHostUnavailableです。エラーでは入力セルと前回のTZ名を保持します。追加スタック8セルが必要ですがVMヒープ確保は不要で、files/float無効構成でも利用できます。既存TIME&DATEは変更しません。

`FPATH`は通常の動的文字列所有セルです。生のメモリー書込でポインタを破損させる操作は所有権規約の範囲外で、`CLEAR-PATH`は有効な所有セルに対する操作です。破損メモリーの修復機能ではありません。記録した相対ソース名は`SET-DIR`後のcwdに依存し、`LOCATE`・`WHERE`での再読込も同様です。読込時のcwdは保存しません。`KEY?-FILE`は通常の入力バイトを保持しますが、端末のCtrl+Cは準備確認中も割込み（UserInterrupt/-28）として消費します。

`LOCATE`・`WHERE`のソース再表示では、記録名のチルダを現在のホーム取得機能で展開します。読込時のHOMEやcwdは保存しません。そのため、従来モードでリテラルの`~`ディレクトリから読んだ場合、異なるソース本文を表示することがあります。ホーム展開ができない場合や失敗した場合は、ファイルを読めない場合と同じく本文を省略します。


### 所有出力の取り込み（P06a）

`>STRING-EXECUTE ( xt -- addr u )`はxtを1回実行し、表示した内容を独立した確保領域で返します。空の出力も含めて、呼出側が`FREE addr`で解放します。例：`: OUT S" hello" TYPE ; ' OUT >STRING-EXECUTE OVER >R TYPE R> FREE THROW`。コールバックのスタック結果はaddr/uの下に残ります。入れ子でも元の出力先へ戻し、THROW・確保失敗・返却用スタック不足では内部領域を解放します。コールバックの副作用は戻しません。実行前に追加1セル、実行後に返却用2セルの空きが必要です。[記録](P06_IMPLEMENTATION.md)。


### 出力ファイルの切替（P06a）

`OUTFILE-ID ( -- fileid )`は現在の出力ファイルを返し、通常はSTDOUTです。`OUTFILE-EXECUTE ( xt fileid -- )`はxtを1回実行して通常出力を借用ファイルへ送り、正常終了・例外とも元の出力先へ戻します。ファイルを閉じたりflushしたりせず、コールバックの結果と書込済みの内容は残ります。入れ子の出力切替・キャプチャも元へ戻します。書込エラーは出力ワード（コンパイル済みのドットクォートも含む）からTHROWし、コールバック内のCATCHで処理できます。WRITE-FILEは明示したファイルへ出力する既存APIのままです。2語ともfiles機能が必要です。[記録](P06_IMPLEMENTATION.md)。

### 入力ファイルの切替（P06a）

`INFILE-ID ( -- fileid )`は現在の入力先を返し、通常はSTDINです。`INFILE-EXECUTE ( xt fileid -- )`は借用入力でxtを実行し、正常終了・例外とも元の入力先と先読み状態へ戻します。ファイルは閉じず、読み進めた位置も戻しません。KEY/XKEY/EKEY・準備確認、ACCEPT、数値INPUT、端末ソースのREFILLに適用します。INCLUDE・EVALUATEの入力源規則は維持します。2語ともfiles機能が必要です。

ファイルのACCEPTはエコーなしの行読取です。LF/CRLF/CRまで行全体を消費し、指定容量と内部4096バイト上限で切り詰めます。ファイルのEKEYはESCを単独のバイトとして扱い、Unicodeは既存Sigmaの復号を使います。KEYの先頭バイトがEOFならInputUnavailable(-262)、EKEYはK-EOF、準備確認は偽、ACCEPTは0を返します。指定Gforthの行編集・エコー、Unicodeの実測差、EOF値とは意図的に異なります。先読みで戻したバイトは借用ファイルに残り、後から読めます。カスタムFileOpsホストはkey/readyと、先読みを戻す場合のunreadを提供してください。必要な機能がない場合はFileUnavailableをTHROWします。[記録](P06_IMPLEMENTATION.md)。


### CSV設定とフィールド出力（P06b）

`CSV-QUOTE`・`CSV-SEPARATOR`はVALUEで、初期値は34（二重引用符）・44（コンマ）です。TOで変更でき、定義内からの変更にも対応します。`.QUOTED-CSV ( addr u -- )`はフィールド全体を引用符で囲み、内部の同じ引用符を二重にします。区切りや改行は追加せず、バイナリー・UTF-8のバイト列を維持します。例：`S" hello" .QUOTED-CSV`。3語ともfiles機能が必要です。全体保存・復元は設定を保存し、辞書追加読込は宛先設定を維持します。出力キャプチャの入力別名にも対応し、通常出力ではヒープ確保を行いません。[記録](P06_IMPLEMENTATION.md)。


### CSV入力（P06b）

`READ-CSV ( filename-addr filename-u xt -- )`は、各フィールドについてxt `( field-addr field-u column row -- )`を呼びます。列は0始まり、行は論理レコード単位で1始まりです。フィールドはコールバック中だけ借用でき、保持する場合はコピーしてください。FREEはしません。正常終了・例外ともファイルを閉じ、元のパーサー入力源へ戻します。入れ子でも外側のフィールドを保持します。コールバックで変更したCSV設定は残ります。

空のFPATHは元の名前でカレント基準、設定済みならソース検索を使います。物理行は4096バイト、ソース名は255バイトまでです。データファイルをソースとして記録しますが、REQUIRE済みにはしません。空行は空フィールド1個、末尾区切りの後の空フィールドは追加しません。引用内の物理改行はLFにします。指定Gforthに合わせ、引用不整合には寛容で、閉じない引用がEOFに達した場合も末尾LF付きのフィールドを通知します。厳密なRFC検証ではありません。コールバックは4引数を消費し、呼出元のデータと読込中のCSVパーサーバッファを維持してください。[記録](P06_IMPLEMENTATION.md)。


### シェルコマンド行（P06b）

`SH command...`は改行を出力し、残りの入力をSYSTEMでシェルコマンドとして実行します。`$?`に既存のプラットフォーム終了値（POSIXのwait状態、Windowsのコマンドプロセッサ終了コード）を保存します。定義内にコンパイルしたSHも実行時に呼出元の入力を解析します。NULは`0 PARSE`同様にコマンドの区切りです。ホスト実行失敗では以前の終了値を維持し、事前の改行出力に失敗した場合はコマンドを実行しません。シェルの出力はホストのストリームを使い、OUTFILEやキャプチャはVMの改行だけに適用します。SYSTEMの既存のコマンド長制限・端末引渡し規則を使います。[記録](P06_IMPLEMENTATION.md)。


### 一方向シェルパイプ（P06b）

`OPEN-PIPE ( addr u fam -- fileid ior )`はコマンドをR/OまたはW/Oで開きます。BINは使用でき、R/Wはエラーです。通常のファイル読書き・キー入力やINFILE/OUTFILEで利用できます。`CLOSE-PIPE ( fileid -- status ior )`は閉じてコマンドの終了を待ち、ネイティブ終了値を返します。`$?`は変更しません。CLOSE-FILEではなくCLOSE-PIPEで解放してください。種類の異なるクローズはエラーとなり、所有権は残ります。サイズ・seek・resizeには対応しません。実行中パイプはイメージに保存せず、終了時に残ったパイプは閉じます。

パイプのコマンドはプロセスの端末状態を共有し、OPEN-PIPE・SH-GETは子へ端末の所有権を引き渡しません。KEY/EKEY/KEY-IORの後では、継承した端末入力がrawのままになる場合があります。対話型の前景コマンドにはSYSTEM/SHを使用してください。実行中のパイプと親との端末読み取り競合は調停しません。

`BROKEN-PIPE-ERROR`はSigmaのEPIPEである-544を返し、Gforthの-2049とは意図的に異なります。SIGPIPEでSigmaを終了させず、書込パイプはstdioのバッファリングを無効にしてエラーを返します。ネイティブコマンドはNULを含まないUTF-8で4095バイトまでです。files機能と、カスタムFileOpsのopen_pipe/close_pipeが必要です。[記録](P06_IMPLEMENTATION.md)。


### シェル出力の借用（P06b）

`SH-GET ( addr u -- addr2 u2 )`はコマンドを実行して標準出力全体を読み、借用バイト列で返します。FREEせず、次のSH-GETや全体復元・リセットを越えて保持する場合はコピーしてください。バイナリー・末尾改行を維持し、空の結果も有効です。読取・クローズ成功後に`$?`へネイティブ終了値を保存します。非ゼロ終了も正常な返却結果です。I/O・確保失敗ではパイプと途中出力を解放し、以前の終了値を維持します。事前検査失敗では旧結果を維持しますが、オープンを開始した呼出しでは失敗時も旧結果が無効になります。前回結果を次のコマンドとして使用できます。辞書追加読込は宛先の借用結果を維持し、結果を暗黙のイメージ保存対象にはしません。files機能とパイプ用ホスト機能が必要です。[記録](P06_IMPLEMENTATION.md)。


### 標準特殊キーと端末情報（P06c）

EKEYSにK-ENTER・K-WINCH・K-PAUSE・K-MUTE・K-VOLUP・K-VOLDOWN・K-BACKSPACE・K-TAB・K-SEL・K-EOFを追加しました。修飾マスク付きも特殊キーとして判定します。GRAPHICSの値は独立したままで、通常のEnter・Tab・Backspaceは従来のバイト値です。Shift+TabはK-TAB K-SHIFT-MASK ORになります。対応する端末リサイズはK-WINCHで通知し、FORMで新しい寸法を取得します。メディアキーの通知可否はホストに依存します。

| ワード | スタック効果 | 動作 |
|---|---|---|
| KEY-IOR | `( -- byte-or-ior )` | 生バイト・負のI/Oエラー・EOFの-512を返す。端末Ctrl+Cは引き続き-28をTHROW。 |
| SIMPLE-FKEY-STRING | `( simple-event -- addr u )` | 小文字名の読取専用借用参照。リセット・復元まで有効。修飾付き・未知コードは-24。 |
| FKEY. | `( event -- )` | 名前、shift/ctrl/altのマスク式の順に表示。末尾空白・改行なし。未知コードは-24。 |
| FORM | `( -- rows columns )` | 標準出力端末の寸法、取得不能時24/80。文字列キャプチャは1/最大符号付きセル、ファイル出力は24/80。 |
| AT-DELTAXY | `( dx dy -- )` | 水平→垂直のANSI相対移動。文字列キャプチャ中は-21。 |

承認方針によりEKEYのEOFはK-EOFへ変更しました。KEYの既存エラー-262と、EOFでのEKEY?の偽は維持します。Unicodeやファイル・パイプのバイト3の扱いも維持します。名前はヒープ確保せず、書換え・FREEはしません。POSIXのリサイズ処理は元のsigactionを復元し、通常の文字・行入力を中断しません。Windows/Linux実機確認は別管理です。[記録](P06_IMPLEMENTATION.md)。

## P07先行：代入語の辞書化

TO・IS・+TO・ACTION-OFは辞書に登録され、通常入力、検索、SYNONYM、再定義に対応します。`'`・`[']`・NAME>INTERPRETで得たトークンは、コンパイル中でもその場で解釈動作を実行します。POSTPONE・NAME>COMPILE・[COMPILE]はコンパイル動作を選びます。COMPILE,は渡された解釈用トークンの実行をそのまま組み込みます。

既存SigmaのISによるFVALUE・2VALUE・$VALUE代入とエラー番号を維持します。ACTION-OFはDEFER専用です。保存形式名はSIGIMG45/46/47のままですが、組み込みABIが変わるため、以前のABIのイメージは作り直してください。[実装と検証](P07_IMPLEMENTATION.md)。

## P07a：コンパイルトークン

COMP'は名前を解析してコンパイルトークン`( xt1 xt2 )`を返します。[COMP']は定義内で名前を読み、そのペアを実行時に返すコードを生成します。POSTPONE,はペアが表すコンパイル動作を作成中の定義へ追加します。EXECUTE-EXITは、実行時にxtを実行して現在の定義を終了するコードを生成します。ループから抜ける場合のUNLOOPは呼出側の責任です。

COMPILE-ONLYとRESTRICTは最後の名前付き利用者定義を制限します。通常の名前解釈は-14で停止しますが、コンパイルや明示的なxt取得・実行は可能です。SYNONYMは制限も引き継ぎます。語本体が持つ実行条件は維持します。[COMP']とEXECUTE-EXITはコンパイル状態専用、POSTPONE,は定義の外ではエラーです。Gforthが警告後に継続する場合もSigmaは停止します。

SELECT `( u1 u2 flag -- u )`は非ゼロならu1、ゼロならu2を返します。[NOOP]は何もしない通常語で、xtを積みません。即時語ではありません。compile_only属性の追加によりWord ABIが変わるため、以前のABIの辞書イメージは作り直してください。[検証記録](P07_IMPLEMENTATION.md)。

## P07b：引用とマクロ

`[: ... ;]`は無名定義の実行トークンを作ります。定義内では実行時にxtを返すコードを生成し、解釈中はその場でxtを返します。入れ子は16段までです。引用内のローカル変数・制御構造・RECURSEは独立し、外側のローカル変数を捕捉しません。引用内のエラーでは、作成途中の外側定義と内部の定義をまとめて破棄します。

NONAMEは次の定義語に名前を読ませず、無名の語を作ります。xtはLATESTXTで取得し、LATESTは0を返します。IN-COLON-DEF?は作成中のコロン定義の有無を返し、[による一時解釈中も真です。

## P07c：ループと制御スタック

+DO/U+DOはstart<limit、-DO/U-DOはstart>limitを符号あり／なしで判定します。-[DO/U-[DOは初期値が等しい場合も実行します。負の+LOOPは下限を含み、-LOOPは符号なしの減分を受け取って下限を含まずに終了します。FOR/NEXTはnから0まで、n+1回実行します。I'は内側ループの上限、DELTA-Iは上限と添字の差を返し、補助語からもVMフレームを参照できます。

## P07d 入力の一時切り替えと前方参照

## P08a 名前トークンと語彙

追加23語：`.ID`・`.VOC`・`COMPILE-ONLY?`・`CONTEXT`・`CS-VOCABULARY`・`CS-WORDLIST`・`CURRENT`・`FIND-NAME-IN`・`IN`・`IN-WORDLIST`・`LATESTNT`・`MAP-VOCS`・`MWORDS`・`NAME>LINK`・`NEXTNAME`・`OBSOLETE?`・`ROOT`・`SEAL`・`TABLE`・`VLIST`・`VOCS`・`WORDLIST-WORDS`・`XT>NAME`。スタック効果は各語のHELPと[実装記録](P08_IMPLEMENTATION.md)を参照する。

NEXTNAME `( addr u -- )` は最大255バイトの次の定義名をコピーし、名前解析を省略する。NONAMEとの後勝ちで指定を置き換える。:NONAME・引用は保留中の指定を消費しない。空文字列はSigmaでは無名定義として扱い、LATESTは0を返す。CATCHはコピー済みの指定を復元し、辞書の完全復元時は指定を解除する。

IN `( "vocabulary" "word" -- )` とIN-WORDLIST `( wid "word" -- )` は、1語だけ定義先を一時変更して実行する。その語がコロン定義を開始した場合も、開始語の復帰直後にCURRENTを元へ戻す。例外時も復元する。INには語彙定義が必要で、widを格納した定数は渡せない。検索順は変更しない。

CURRENT・CONTEXTは定義先・最初の検索先のセルアドレスを返す。有効なwidだけを書き込む。ROOTは検索順の先頭をRootへ置換し、SEALは先頭だけを残す（空ならエラー）。CS-WORDLIST・CS-VOCABULARYは名前のバイト列を区別し、TABLEは再定義警告も抑制する。通常の語彙は従来どおりASCIIの大小文字を同一視する。割当て可能な語彙は64個で、固定Macros名前空間は別枠。

COMPILE-ONLY?は登録された制約フラグを返す。偽でも、語本体が開いた定義やコンパイル状態を要求する場合がある。制御語の属性も整備したが、`]]`は既存方針に従い定義内の一時解釈中にも使えるよう未指定を維持する。OBSOLETE?はntを検証して偽を返す（現時点で廃止予定の印はない）。

MWORDSは大小文字を区別する部分文字列一致で絞り込み、省略可能なパターンは現在行だけから読む。VLIST・WORDLIST-WORDSはSigmaの古い語からの表示順を維持する。MAP-VOCSは割当て済みwidの降順スナップショットとMacrosを列挙し、コールバック `( ... wid -- ... )` を実行する。VOCSには無名の語彙も含める。標準の語彙集合と表示の空白はGforthと異なる。

NAME>LINKは同じ語彙の前の名前付き項目を返す。LATESTNT・XT>NAMEは無名定義も扱う。nt・xtの寿命は辞書項目が残る間だけで、FORGETや辞書置換後の古い数値を再利用しない。辞書追加では語彙定義の参照とケース設定を再配置するが、通常のセル・定数に保持した生のwidは自動変換しない。builtin ABIが変わるため旧ABIのイメージは再作成する。

## P08b アドレス可能な値と遅延語

- AVALUE `( addr "name" -- )`：論理アドレスを明示追跡するVALUEを定義する。参照先の確保・解放は行わない。TO・+TO・セル全体の書込みで登録を更新し、部分書込みで破損した登録は完全なセル更新で修復するまで保存できない。xt・widではなく論理データアドレスを使う。
- ADDRESSABLE: `( -- )`：互換用の指定。Sigmaの値には既に安定した格納領域があり、次の定義への保留状態や警告は追加しない。
- ADDR `( "name" -- addr )`：VALUE/AVALUE・FVALUE・2VALUE・$VALUE・DEFER、またはコンパイル中の値型ローカルの格納先を返す。定数・変数・変数型ローカルは対象外。通常のコンパイルは再配置可能な語参照を生成し、明示的な実行トークンはコンパイル中でもその場でアドレスを返す。ローカルのアドレスは呼出しフレームの寿命内だけ有効。生の返却アドレスを保存する場合はAVALUE・ACONSTANT・A!等で明示登録する。
- :IS `( "deferred" -- )`：無名コロン定義を開始し、正常なセミコロンでDEFERへ代入する（別名も可）。定義中は旧動作を保持するのでDEFERSで参照でき、失敗時は旧動作を変えない。未完の:ISは保存・取込みできない。
- PRESERVE `( compilation: "deferred" -- ; runtime: -- )`：コンパイル時点のDEFER動作を復元する命令を生成する。未初期化の印も保持できる。定義外ではエラー。
- WRAP-XT `( ... action deferred callback -- ... )`：動作を一時変更してコールバックを実行し、正常終了・THROW・割込み・実行制限時に呼出し時の動作へ戻す。コールバックのエラーを優先し、入れ子は64段まで。

WRAP-XTの対象がFORGET/MARKERや辞書の完全復元で無効になった場合、削除・再利用された領域へは書き戻さない。コールバックが正常復帰した場合は-261、既にエラーがあればそのエラーを伝える。無関係な後続定義のFORGETでは復元する。実行中の保護情報はイメージに保存せず、有効なスコープ内のSAVEはその時点の一時動作をスナップショットする。公開6語とADDRの非公開コンパイル動作でbuiltin ABIが変わるため、旧ABIのイメージは再作成する。[検証記録](P08_IMPLEMENTATION.md)。

P08レビュー補足：REQUIRE-*の内部読込みは成功・失敗ともNEXTNAME/NONAMEを保持し、失敗時はケース・TABLE設定も巻き戻す（成功した前提ライブラリは保持）。IN/IN-WORDLIST内で辞書の完全復元が成功した場合は復元後のCURRENTを保持し、事前検証だけの失敗では従来のCURRENTへ戻す。MAP-VOCSはコールバックIDの削除・再利用を検出して-261で停止し、最後のMacros呼出しも確認する。MAP-VOCSとWRAP-XTの保護付きコールバックは合計64段まで。WRAP-XTの呼出し時の動作だけが削除された場合、存続するDEFERを未初期化にし、正常復帰なら-261を返す。コールバックのエラーは優先する。[レビュー記録](P08_REVIEW.md)。

## P09a 例外とアサーション

`CATCH-NOBT ( xt -- 0 | n )`はバックトレース採取を抑えてCATCHを実行する。`FAST-THROW ( n -- )`は採取せず例外を伝播し、0は何もしない。`NOTHROW ( -- )`は保留トレースを消去する。`?IOR ( n -- )`は-1、`?ERRNO-THROW ( flag -- )`は非0の場合だけホストerrnoを確認し、非0のerrnoを-512-errnoへ変換する。

## P09b スタック表示とソース参照

`CLEARSTACK`・`FCLEARSTACK`・`CLEARSTACKS`はデータ・浮動小数点・両スタックを消去し、戻りスタックや呼出し・ループ・ローカルの状態を保つ。`MAXDEPTH-.S ( -- addr )`は初期値9で.S/F.S/`...`の表示件数を制限し、負数は-24。`F.S-PRECISION ( -- width )`は初期値14のVALUEで、TOで変更する（幅1〜4096）。F.Sは従来のフィールド形式を保つ。`...`はBASEに依存しない#付き10進数、VM内の有効な文字列組、簡潔な浮動小数点表示を行い、スタックを変更しない。文字列は制御文字をエスケープし、UTF-8を分断せず80バイトまで表示する。整数と区別できないxtは数値のまま示す。
