# Gforth対応 P00 仕様の確定

対象は未対応名380語と、既存構文IS・ACTION-OF・TO・+TOの辞書化。実装フェーズ、ワードの出典、分類は[GFORTH_WORD_PHASES.md](GFORTH_WORD_PHASES.md)と[一覧](gforth-word-plan.tsv)を参照する。P00は仕様と比較ケースの整理であり、語の実装完了を意味しない。

## 利用者が確定した互換方針

- 辞書イメージ読込はLOAD-DICTIONARYへ変更する。LOADはForth 2012のブロック実行にする。既存サンプル、HELP、マニュアルの辞書読込表記も変更する。
- 保存済みの旧辞書イメージとの互換は考慮しない。必要な保存形式更新を行う。移行読込機能は追加しない。
- GRAPHICSの既存キー定数の値を維持する。標準EKEY用の定数は別の語彙で管理する。異なる表現を数値が同じと仮定して混用しない。
- アセンブラー関連語は今回の対象に含めない。別途の方針検討タスク582で扱う。

## ブロック操作の仕様と比較ケース

Gforthのdoc/gforth.texi.inのBlocks節を比較元とする。1024バイトを1ブロックとし、LISTは64文字×16行で表示する。BLOCKは既存内容を取得する。標準上BUFFERは既存内容の読込を要求しないが、SigmaはGforthに合わせて既存内容を読み込む。UPDATEは現在のバッファーを変更済みにする。SAVE-BUFFERSは変更分を書き戻し、FLUSHは書戻しとバッファーの解放、EMPTY-BUFFERSは書戻しなしで破棄する。

比較ケースは、同一番号の再取得、複数番号の切替、UPDATE前後の再利用、保存後の再読込、書込失敗、空白ブロック、BLK/SCRの変化、LOAD/THRUの入れ子とTHROW後の入力復元を含む。ブロック内は連続した入力とし、バックスラッシュコメントは64文字の行境界までを対象にする。ファイルの選択・初期作成・自動拡張・終了時の保存は、標準語の仕様とGforth拡張の動作を区別して照合する。

## 特殊キーの仕様と比較ケース

Gforthのekey.fsを比較元とする。比較元の修飾マスクはSHIFTが0x10000000、ALTが0x20000000、CTRLが0x40000000。標準側の基本キーとマスクを組み合わせ、EKEY>FKEYで判定する。GRAPHICSの既存イベント表現には変更を加えない。

比較ケースは通常文字、UTF-8、ファンクションキー、各修飾キー、複数修飾、分割された端末入力、単独Esc、キー以外のイベント、入力終端、リダイレクト入力、KEY/ACCEPTと行編集との切替を含む。WindowsのコンソールイベントとPOSIXの端末入力で同じ公開動作を確認する。

## 数値とメモリー

既存のCell=i64、UCell=u64、Double=i128、UDouble=u128、Float=f64と論理アドレスを使う。公開ワードの幅、符号拡張、エンディアン、整列、スタック順序は指定Gforthの個別ワードの記述と照合する。メモリー範囲の検査は既存のSigmaの方式を維持する。範囲外アクセスによるホストメモリー破損は許容しない。

F*+はr1+r2*r3である。比較元primはプラットフォームによって丸めが異なり得ると明記しているため、全環境でGforthの最終ビットと一致する条件にはしない。通常値、NaN、無限大、符号付き0、積と加算の丸めが問題になる値を分けて比較する。

乱数はRANDOMの範囲と、SEED!に同じ種を指定した場合の再現性を比較する。利用者の選択により、Gforth固有の乱数列との一致は要求しない。

A,やアドレスを保持する定義語は、辞書イメージの再配置に影響する。保存形式更新が許可されていても、追加読込先で論理アドレスがずれる問題は別に検証する。利用者の選択により、A,およびアドレス専用の定義語で保持した値は再配置情報を記録する。通常の,で保存した数値には再配置を適用しない。

## 解釈とコンパイル

457はP07の先行作業とする。通常の名前入力、実行トークン、解釈動作、コンパイル動作を区別し、POSTPONEとNAME>COMPILEの動作選択を共通化する。Gforth kernel/comp.fsのTO・IS・+TOと比較し、通常の代入、コンパイル済み代入、コンパイル中に解釈動作をEXECUTEした場合を分けて確認する。

既存のVALUE/FVALUE/2VALUE、DEFER、型付きローカル変数、SYNONYM、再定義、検索順序を検証する。[: ;]の捕捉付きクロージャーへの拡張や、Dの認識器実装は前提にしない。

## 所有権と例外復元

>STRING-EXECUTEが返す文字列は呼出側がFREEする。Gforth str-exec.fsの記述を比較元とする。INFILE-EXECUTE/OUTFILE-EXECUTEはstuff.fsを比較元とし、成功・THROW・入れ子で元の入出力先へ戻す。返却領域を持つ他の語も、各語の資料に従い所有権と寿命を個別に確認する。

ファイル、ディレクトリ、パイプは正常終了だけでなく、途中の例外、作成・読込・書込・closeの失敗を比較する。OSで異なるerrnoやシェル構文は公開結果の差として記録する。時間計測では単位と、実時間・CPU時間・単調時刻の区別を確認する。

## 標準キーの公開方法

利用者が確定した検索順に従い、標準キー定数をEKEYS語彙へ置く。起動時の検索順には既存FORTHの後、ROOTの前にEKEYSを追加する。ALSO GRAPHICSでGRAPHICSが先頭になった場合はGRAPHICSの既存定数が優先する。ONLYで検索順を限定した後はALSO EKEYSで明示的に戻せる。起動時に利用できる語彙として組み込み辞書へ登録し、新形式イメージでも同じ識別・検索順序を維持する。

[標準K-*定数の一覧とGforth実測値](gforth-p00-key-constants.tsv)をS01の対象に含める。同名語がGRAPHICSに存在することは標準EKEY対応済みの根拠にしない。今回の名前の不足380語とは別の、既存同名語の標準イベント体系への対応である。P06cのK-ENTER/K-TAB等も標準イベント用はEKEYSへ置く。GRAPHICSの値は変更しない。

EKEYはGforthと同じく通常文字をUTF-8のコードポイントとして返す。KEYのバイト入力の仕様は維持する。EKEY>CHAR、EKEY>XCHAR、EKEY>FKEYを同じイベント表現へ接続し、ASCII・非ASCII・特殊キーを区別する。標準キーの値は上記実測表、マスクは既述の値とする。

## ブロック比較で確認した動作

指定Gforthで標準語と既存入力語への影響を19ケース実測した。基本語44ケースと合わせて63ケースが期待値と一致した。実測のブロックはテスト専用ファイルをUSEで指定した。これは比較環境の準備であり、保留中のUSEを実装対象へ追加する意味ではない。

GforthのBUFFERは内部でBLOCKを呼び、実際には既存内容を読み込む。標準が初期内容を要求しないことと区別し、SigmaもGforthの取得動作を比較基準にする。FLUSHは書戻し後にバッファーを未割当へ戻す処理であり、ヒープ領域そのもののFREEではない。LOAD 0と上限以上のBLOCKは-35。ブロック実行時のSOURCE-IDは2、SOURCEの長さは1024、BLKは実行中の番号となる。THROW後は元の入力源とBLKへ戻す。

LISTはScreen番号と変更状態の見出し、0〜15の行番号と各64文字を表示する。Gforth固有のUPDATED?を公開しなくても、内部の変更状態を使って同じ表示にできる。既定のファイルはGforth同様のblocks.fb、バッファー数は32、番号を32で割った剰余で対応付ける設計とする。BYEで変更済みバッファーを書き戻す。通常のバッチ終了とSAVESYS実行体の通常終了も同じ終了処理を通す。異常終了時の未書込内容の保存は保証しない。

## アドレス再配置の確定方針

利用者は、アドレス専用の語で保持した値の自動再配置と、通常のカンマで保存した生セルの非再配置を選択した。アドレスらしい数値かどうかを範囲から推測して自動変換しない。

新形式は、再配置対象の格納位置と参照先を区別した記録を持つ。格納位置は辞書項目の値フィールドまたは論理メモリー内のセル、参照先は対象領域とその領域内のオフセットで表す。追加読込では各領域の移動量を求め、データと辞書を配置してから対象セルを更新する。通常の整数値、既存の語IDの再配置、論理メモリーのアドレスの再配置を混同しない。

比較ケースは、既存辞書が空の場合と語・データを持つ場合、同じイメージの2回追加、複数のアドレスが同じ対象を参照する場合、再保存と再読込、FORGET/MARKERで参照元または参照先が消える場合を含む。通常のカンマで同じ数値を保存した対照ケースは数値が変化しないことを確認する。旧形式は互換読込せず、既存のInvalidImageエラーで安全に拒否する。

ヒープ参照、上書き、部分書込、MOVE、無効参照、破損した表の扱いは次節の設計を実装要件とする。

メモリー操作の追加比較で、生成マニュアルのBUFFER%のスタック効果が定義元と逆になっていることを確認した。stuff.fs:730の定義に合わせて「-- alignment size」へ訂正した。基本語・標準語・整数・メモリーの計157ケースを実測済み。メモリーの62ケースは処理後のデータスタック深さ0も確認した。

## 再配置表と読込の実装要件

次はSigma向けの設計であり、Gforthの生メモリーイメージ形式を転用するものではない。

- 現行の3種のマジックSIGIMG42/43/44を、新形式のSIGIMG45/46/47へ更新する。既存ヘッダーに再配置件数・ヒープオブジェクト件数・各節のバイト長を追加し、再配置表をCRCの対象へ含める。旧形式はInvalidImageで拒否する。
- 再配置レコードは32バイト。格納領域種別u8、参照先領域種別u8、予約0のu16、辞書項目IDのu32、格納位置オフセットu64、参照先オフセットu64、セル幅u64をリトルエンディアンで記録する。幅は8のみ許容する。辞書項目の値フィールドでは格納位置オフセットを0とする。領域種別はシステム固定領域・辞書データ・ヒープ・NULLを区別し、ホストポインターは保存しない。
- A,はメモリーセルを登録し、ACONSTANTは辞書項目の値を登録する。AVARIABLE/AVALUEはその値セルを登録する。ADDR/ADDRESSABLE:は値の格納場所を公開する機能であり、返したアドレスを通常のカンマで保存しても型登録へ昇格しない。
- 登録済みアドレスから到達可能な使用中ヒープブロックだけを、オブジェクト番号・サイズ・内容として取り込み、追加読込先では既存ヒープの末尾へ新規ブロックとして配置する。旧ブロックと新ブロックの対応表で内部オフセットを再配置する。NULLは0のまま、システムの固定アドレスは固定のままにする。未使用ブロック、解放済み領域、入力バッファー、ローカルフレーム、ホスト資源は参照先として取り込まない。
- 追加読込時、固定システム領域の型付き格納セルが読込先の既存登録と重複・部分重複する場合は、反映前にInvalidImageで拒否する。既存の参照を上書きしない（2026-11-13利用者確認）。
- 動的文字列など内部でアドレスを持つ既存の組込データ構造も、内部ポインターの格納位置を明示登録する。普通のVARIABLEと!で保存した生セルの数値は自動判定しない。自動再配置が必要な利用者コードはアドレス専用の保存語を使う。
- 登録済みセルへの全セル幅の!やTOは型を維持し、値と参照先を更新する。部分書込は登録を破損状態にし、全セル幅の更新で再検証されるまでSAVEを拒否する。MOVE/CMOVE/CMOVE>は完全な登録セルのコピーなら登録も移し、部分セルなら同じ破損規則を適用する。重なるコピーではコピー前の登録情報を基準にする。普通のカンマによる新しい格納位置には登録を付けない。
- FREEやFORGET/MARKERで参照元が消えれば登録を除去する。参照先が消えれば残る登録を無効にし、同じ数値の領域が再利用されても自動的には復活させない。無効参照を持つSAVEはInvalidAddressで拒否する。
- 読込前にCRC、節の長さと件数、予約値、セル幅、重複する格納位置、辞書項目ID、格納位置と参照先の範囲、使用中ヒープブロックとの対応を検証する。サイズ計算は桁あふれを検査する。検証と容量確保が済むまで現在の辞書を変更しない。追加対象のヒープ総量を末尾配置で事前計算し、容量不足はMemoryExhaustedとして追加前に拒否する。破損した表はInvalidImageとする。

比較ケースは、データ→データ、データ→ヒープ、ヒープ→データ、ヒープ→ヒープ、NULL、固定システム領域、同一対象への複数参照、領域途中への参照、既存データありの追加、2回追加、全セル上書き、部分書込、重なるMOVE、FREE後、FORGET後、破損表、容量不足を含む。保存前後で値・別名関係・失敗時の既存辞書維持を確認する。Gforthの追加読込機構と異なるSigma固有の設計なので、この部分の期待値は上記仕様とし、Gforthの機械アドレス値との一致は求めない。

## 追加の動作選択と比較環境

- EKEY用の単独Escは、既存の端末入力処理と同じ50 msの待機後にEsc文字とする。待機内に到着した既知のエスケープ列は1イベントへまとめる。未完の列は入力を捨てず通常文字へ戻す。これはGforthの非同期入力の判定時機とは区別したSigmaの公開動作である。
- F*+はf64の融合積和、すなわち積と加算を1回の丸めで行う仕様とする。Gforthはプラットフォーム依存で融合を許すため、丸め差が出る入力はGforthとのビット一致ではなくこの仕様を検証する。NaNのペイロード一致は要求しない。
- 起動時の乱数の種はホスト時刻から初期化する。時刻を取得できないテストホストでは0を使う。SEED!以後は同じ種と呼出列から同じ結果を再現する。暗号用途の乱数は提供しない。
- 編集支援の試験ではEDITOR=trueをプロセス環境に設定し、実エディターを起動しない。対話型のafter-lは表示試験ではNOOPへ差し替え、FANCY-AFTER-L自身は改行の入力で終了することを別に試験する。ケース内で行う差替えを本来の公開仕様と混同しない。
- WHEREGは名前を実ファイルから読み取る場合は成功した。-eの疑似入力源から呼ぶ場合は比較用GforthがInvalid memory addressとなり、kernel/paths.fsのabsolute-file?からsourceview表示を通るバックトレースを記録した。Sigmaでは存在しない疑似入力源をファイルとして開かず、表示可能な位置と未取得の位置を区別する。Gforthのこの失敗を模倣する要件にはしない。
- 比較用のgforth-ditcでは、0除算をCATCHしても多くの整数語で0を返し、UD/MODでは-10を返すことを実測した。Sigmaは既存のゼロ除算エラー-10を維持する。移植先のハードウェアやGforthの検査設定による差をSigmaの未定義動作へ持ち込まない。TOの不正対象は今回のGforthでは-21であり、Sigmaの既存のInvalidDefinitionとの差を互換性一覧に記録する。

## 所有権と語彙の補足

- S+、SAVE-MEM、SLURP-FID、>STRING-EXECUTEは呼出側がFREEする領域を返す。APPENDは入力の第1文字列がヒープ領域であることを要求し、再確保後の返却領域を呼出側が所有する。
- SH-GETはGforthではsh$に保持され、次のSH-GETで置き換わる借用結果。呼出側がFREEするAPIとは区別する。永続利用したい場合はSAVE-MEM等でコピーする。
- SAVE-MEM-DICT、MEM,、STRING,、幅別のカンマは辞書データを増やし、FREEの対象にしない。FORGET/MARKER等で辞書領域を破棄するまでを寿命とする。
- CAPSSEARCH、SAFE/STRING、SCAN-BACK、BASENAME、DIRNAME等は元の領域の部分参照を返す。DIRNAMEは末尾の区切り文字を含むことを比較ケースで確認した。
- OPEN-DIRとOPEN-PIPEのハンドルはそれぞれCLOSE-DIR/CLOSE-PIPEで閉じる。INFILE-EXECUTE/OUTFILE-EXECUTEは借りたハンドルを閉じずに入出力先を復元する。EXECUTE-PARSING-FILEはkernel/input.fs:239-250に従い終了時に渡されたファイルを閉じ、入力源を復元する。READ-CSVのフィールド文字列はコールバック内の借用とする。
- スタック効果のrは浮動小数点スタック、d/udは倍長セル、R:はリターンスタックを示す。XD系は固定64ビットの転送と倍長セルの入出力の違いをprim・stuff.fsの定義と実測で確認する。XD>Sは指定ソースではS>Dの別名となる64ビットセル用の定義である。

旧来のForth語彙に属する追加語は原則FORTH、標準キー定数とK-ENTER/K-TAB等はEKEYSへ置く。GRAPHICSの同名語は従来どおりGRAPHICS。局所構文・コンパイル動作はその宣言位置に従う。EKEYSは既存語数380の不足集計を増やす分類ではなく、同名でも意味の違う標準キーへの対応である。
