## 4. 共通データ・エラー・時計

### 4.1 メモリとハンドル

すべてのForthのaddr/lenはStateの論理範囲で検査し、加算・乗算のオーバーフローを先に検出する。配列件数×要素幅、画素行ピッチ×高さ、PCMフレーム数×チャンネル数も同様。空範囲は操作ごとに許可を定義する。非同期操作は呼出し終了後にForthメモリの生ポインターを保持しない。

新しいタスク・プロセス・画面スナップショットなどは型付き台帳で管理する。候補は正のセルへresource-kind/epoch/slot-generation/indexを符号化し、0を無効とする方式。各ビット幅と上限はメモリ見積り後に確定する。世代を折り返して再利用せず、枯渇は明示エラーとする。起動をまたぐ不正参照の確実な拒否をうたうにはepochの一意性と表現幅を別途検証する。それまではイメージ内の古いセルが必ず拒否されるとは保証しない。既存のファイルIDや画像ハンドルは、移行を別に決めずに形式を変更しない。

操作は型・所有者・epoch/世代・状態を検証する。別タスクの論理addr、解放済みハンドル、別種類のハンドルを誤って使ってもOSの生ハンドルとして解釈しない。

### 4.2 結果の種類

新しい語の候補契約では、通常の操作エラーはior、機能自体が利用不能は既存-21、ホスト基盤の破綻は既存-265、中断は既存-28のTHROWを基本とする。新しいior番号は既存表と衝突しない割当てを実装時に行う。予期されるデータ終端・タイムアウト・満杯をOS障害と混同しない。

複合待機の結果タグ案はready/timeout/end/cancelled。iorは別フィールド。新しいタスクへの取消し要求は操作の正常な結果であり、メインVMのCtrl+Cと同じ意味にしない。既存語の戻り方は変更しない。取得結果の出力引数は失敗時にも定義された空値とし、部分書込みだけは進んだ数を保持する。

### 4.3 時計と待機

単調時計は1セル・ナノ秒を第一候補とする。単位と分解能を区別し、起点は公開しない。内部はホスト時計のコールバックへ集約し、失敗を0の成功値として返さない。休止中に進むかをOS別に記録し、復帰時に遅れを解消する方針はアプリが選ぶ。

API案：`MONOTONIC-NS ( -- ns )`、`WAIT-UNTIL-NS ( deadline -- )`。相対msを取る新しい語では0=ポーリング、負=無期限を候補とする。期限の飽和・オーバーフローは入力エラーとする。呼出しの絶対期限は最初に一度だけ計算し、部分入力や偽の起床で延長しない。

待機の共通手順：現在状態の取得→起床世代の記録→条件の登録→状態と世代の再確認→単一期限で待つ→状態の再評価→登録解除。判定と登録の間に起きた通知を失わないよう、状態のロックまたは原子的な世代カウンターをOSごとに実装する。readyは予約ではなく、戻った後に空になる可能性を仕様化する。

同時成立の優先順位案は、ホスト基盤障害→メインの中断→成立済み条件→期限。ただし複数対象のreadyは開始位置を循環させ、公平性を持たせる。EOFはreadyの一種として対象番号とendを返す。待機が中断しても入力と既に受理した出力は自動取消ししない。

信号ハンドラーはホストに一つ置き、メインVMの制御スコープが所有する案とする。ワーカーは端末モードや信号を変更せず、自分の取消し印と起床を使う。既存NSへの移行は別途互換テストを伴う段階作業とし、既存のグローバルactiveをそのまま複数VMで共有する実装は採らない。

起床の実装候補は、POSIXは非ブロッキングのself-pipeとpoll、Windowsは共通の起床Eventとコンソール待機。macOSのウィンドウ子プロセスの通知fdもpollの対象に含める。新しい各キューのOSハンドルを無制限に待機配列へ並べず、共通の状態と一つの集約起床へ接続する。状態更新→世代の増加→起床の順を守り、起床の解除と再確認を同じプロトコルで行う。待機上限は対象OSの公式仕様を実装前に確認し、ハードコードした未確認の上限を仕様にしない。

信号所有（未決18）の実装担当は900・638とする。652はその入れ子利用を検証する。POSIXの新スレッドでは起動直後の競合も避けるよう、生成元で対象信号を一時blockしてmaskを継承させ、メインのmaskだけを復元する案を試す。SIGINT・SIGWINCH・SIGPIPEの配送先とスコープ型sigactionの競合を監査する。SIGPIPEを起動時にignoreしEPIPEで扱う案と、スレッドごとのblock案を比較し、SYSTEM/execした子への継承も含めて決める。既存の音スレッドを含むmask移行とsignal dispositionの変更は、試作・互換性確認なしに適用しない。

## 5. 端末・イベント・物理キー（637・638・997）

端末状態はrequested/applied/suspendedを分け、Raw modeと表示状態を独立管理する。適用に失敗したら適用済みの分だけ戻す。解除は冪等とする。SYSTEM・行入力の前に一時解除し、その後requestedを復元する。要求と実際に有効な状態の取得を区別する。TERM-MODE!/@、COLS/ROWSは既存計画の候補を継続し、Gforthの動作を実装時に再照合する。

端末入力は既存どおりEKEY・INKEY等の一方が一度だけ消費する。二重配信や、使われない消費者が端末を詰まらせる独立カーソルを追加しない。別経路は997のウィンドウ物理キーと既存の文字・マウスの関係に限定し、EKEYやINKEYを読んでも物理キーイベントを消さない。物理キーを読まない利用者がいる場合でも既存入力を止めず、有界キューのあふれ世代と最新状態で復旧する。読まれないマウス通知も既存の有界契約に従い、他経路への逆圧に使わない。

EKEYはセルのイベントを維持する。マウスの付随情報はキュー要素の値を、消費した時点でVMごとのlast-eventへコピーする。EKEY?による先読みではlast-eventを更新しない。新しいイベント範囲とEKEY>FKEYの判定表を一緒に変更する。

EKEY-WAITのデコーダーはidle/escape/utf8/pasteに状態を分け、受信済みバイト・開始期限・貼り付け状態を保存する。部分列で期限になった場合は保持してtimeoutを返す。貼り付け中は終了マーカー以外を通常文字として扱い、値3も中断に変換しない。壊れたUTF-8、閉じない貼り付け、改行変換の具体規則は638の試作で決める。

物理キーはUSB HIDページ0x07の0〜255を候補とし、専用の押下表、押下・解放イベント、あふれ世代を持つ。リピートは状態の押し直しと区別する。フォーカス喪失時は保持状態をクリアし、通知と状態の再取得で復旧する。未対応キー、端末・Tkの能力の差を成功値の0で隠さない。

### キューの規則

| 種別 | 例 | 満杯と復旧の案 |
|---|---|---|
| 元に残る入力 | 端末・パイプ | 読取りを止める。メインの中断検出は別経路で維持する |
| 状態を再取得できる入力 | 物理キー・ウィンドウ状態 | 有界キューとあふれ世代。状態スナップショットと世代を一緒に取得する |
| 復元できない入力 | 確定文字・ホイール | 既存の有界契約に従い、欠落を通知する。文字はスカラー単位で全体を受理または破棄する |
| 集約できる通知 | 移動・サイズ・DPI | 最新状態と世代。閉じる要求は消費するまでラッチし、単なる移動で上書きしない |
| 出力 | PCM・パイプ書込み | 書けた数を返す。空き待機は別操作 |

## 6. I/O・子プロセス・ファイル・Unicode（639・643・646・640）

### 6.1 ファイル記録

FileRecord案：既存fid、OS資源、種類、同期/監視読取りモード、先読み、受信キュー、EOF、最初のエラー、読取り所有者、closing、起床世代。同期READ-FILEと監視側が同時にOSから読まない。監視開始時にCのストリームが持つ先読みを失わない移管方法を試作し、対応できない種類は明示的に拒否する。

API候補：`READ-AVAILABLE ( addr cap fid -- n eof? ior )`、`WRITE-AVAILABLE ( addr len fid -- n closed? ior )`。`WAIT-FILES`は既存候補を精査し、読取り/書込みの種別を含む待機対象配列を使う形へ統合する。未登録・不正fidとEOF、0件・重複対象の扱いを実装前に決める。新語に渡すレコードのForth上の配置はセル単位とし、Zig構造体のメモリを直接公開しない。

POSIXはpollによるread/write readiness、Windowsのパイプは受信スレッドとキュー・起床手段を用いる。書込み側も無期限の同期呼出しでメインを止めないよう、部分送信と取消し可能な送信経路を別に設計する。利用する具体的なWindows APIは試作で確認し、無名パイプが非同期APIに対応する前提を置かない。

同期Cストリームと監視モードの移行は読取り・書込みの両方を扱う。第一案は監視に移したfidについて既存の同期I/Oを混用しようとしたら明示エラーにし、監視終了時のバッファ排出・復元手順を定義すること。切替前の出力をflushし、読取り先読みを移管できない種類は切替を拒否する。共有fdへO_NONBLOCKを設定して既存のfread/fwriteの意味を黙って変更しない。複製fdでもOSの状態を共有する可能性を確認する。

閉じる順序：closingを設定→待機を起こす→受信/送信のブロッキングを解除→スレッド終了を待つ→キューとOS資源を解放→fidを無効化。close後に残るreadyを見ても再検査で切断と分かるようにする。

### 6.2 子プロセス

ProcessRecord案：論理ID、起動中/running/exited/reaped、OSプロセス、stdin/out/errのfid、exit status、所有者、終了要求。引数は長さ付きUTF-8文字列の配列とし、シェル経由と直接起動を分ける。Windowsの引用規則、環境変数、作業ディレクトリ、stderrの独立/合流は643で確定する。

起動は資源の部分取得ごとにロールバックする。POSIXのexec失敗は通知用パイプ等で親へ報告し、終了コード127だけで起動成功と解釈しない。終了通知は保持するが、出力EOFとは別に扱う。終了要求後も出力を排出しながら期限を待ち、必要なら強制終了・回収する。孫プロセスを含める範囲はOS別のプロセス群の調査を経て決める。

起動時の継承は指定したstdin/out/err等に限定する。Windowsの親側端の継承除外、POSIXのclose-on-execを維持・補完し、パイプ作成とfork/execが並行する場合の漏れを試験する。子に不要なfdが残ってEOFを妨げるケースを643の完了条件に含める。

### 6.3 ファイルとUnicode

646は既存RENAME-FILEを再実装せず、COMPACT-FILENAME相当、実パス、更新時刻と大きさの取得を追加する。安全な保存はバッファflush/同一ファイルシステム内の置換/OS同期を分け、原子性・永続性を実測なしで保証しない。実パスの文字列は呼出し側バッファへコピーする案とする。

640はUnicode版・UAX #29改訂と入力ファイルのチェックサムを固定する。先頭・末尾の書記素境界を扱い、末尾操作には文字列の先頭を渡す。空文字、不正UTF-8、境界でない開始位置、長い結合列を定義する。UCDのライセンス表示を既存THIRD_PARTY_NOTICESへ追記し、配布試験データの条件も確認する。クラスタ幅と単語境界は境界抽出とは分けて扱う。

## 7. 実行制限（652）

EXEC-LIMITEDの案は実行トークン・予算を受け、数える入口を明示する。0=中断確認のみとする案で、現在のstep_limit=0なら何もしない経路とは分離する。CLI予算と入口ごとの予算を別のスタックにし、各操作は外側の全予算にも計上する。

尽きた予算の所有入口を内部の終了理由に保持する。内側は外側の予算切れを自分のiorへ変換しない。CLI予算切れは既存どおり外へ伝える。入口予算切れは該当入口まで戻り、データ/リターン/浮動小数点スタック、呼出し、ローカル、例外深さ等をCATCH相当の規則で復元する。保存したスタック内容の保証は別途定義する。

ネイティブの長いループはcheckWorkBlock相当へ予算と中断の確認を追加する。描画の途中で中断した場合は部分更新かトランザクションかを操作ごとに明記し、自動巻戻しを保証しない。通常ループは変更せず、debugなしではこの語群を除外する。タスクランタイムの取消しを652必須として実装しない。

u=0でも入口が有効な間は数える経路を保つ専用状態を持ち、入れ子のEXECUTE等で通常ループへ抜けないことを試験する。現在のin_countedやhaltedを取消し印へ転用しない。

## 8. PCMと条件付きエミュレータ拡張（998〜1001）

PCMは形式・周波数・チャンネル・容量を開始時に指定し、受理済みフレーム数を返す専用の有界リングへコピーする。フレームは全チャンネル一組。読取り側は音のスレッドのみとする。初期の入力形式案は符号付き16ビットのmono/stereo。周波数変換、MML/SFXとの混合、飽和処理をエンジン側で行う。

API候補：`PCM-OPEN`、`PCM-WRITE`、`PCM-QUEUED`、`PCM-WAIT`、`PCM-STOP`、`PCM-CLOSE`。開始の構成レコードは形式・Hz・channels・capacity-frames。WRITEはコピーしたフレーム数とior。STOPはdrain/discardの明示モードと期限を取る。中断で受理済み標本を自動破棄しない。空のリングは無音を出し、underrun回数を観測可能にする案とする。

残量・エンジン取得位置・装置へ渡した位置・実再生位置を区別する。装置が実再生位置を返せない場合は能力として示す。プロセスの終了だけに頼らず、音のスレッドの停止要求、装置待機の解除、コールバック停止、join、解放を実装する。

999はForthで音源を合成してPCMへ流す例を先に作り、必要な機種だけ本体へ移す。1001もタイル一行・ビットプレーン変換をForthで試す。測定条件・入力・版・音と表示を含むかを記録し、測定を実施する際は既存の確認方針に従う。不要と判断した場合も理由を残す。

1000のRGB転送案はaddr/width/height/stride/format/destinationを受け、RGB24/BGR24などの形式を明示する。負のstrideは初期案では拒否し、行ごとの必要バイト数と末尾行の範囲を検証する。1046のRGBAとの相互変換を定義し、転送中は呼出し側メモリを借り、戻った後は参照しない。

## 9. ディスプレイとウィンドウ（1038〜1043）

### 9.1 画面スナップショット

列挙は一貫したスナップショットを返す。レコード案：id、configuration-generation、pixel-rect、work-rect、scale-x/y、refresh-numerator/denominator、primary、valid-fields。解像度・矩形は物理ピクセル、倍率は有理数、リフレッシュレートも有理数とし、整数Hzへ丸めない。DPIが物理値か論理値かを区別し、取れない値はvalid-fieldsで示す。

API候補：`DISPLAYS-OPEN ( -- snapshot ior )`、`DISPLAYS-COUNT ( snapshot -- n ior )`、`DISPLAY-INFO ( index snapshot addr -- ior )`、`DISPLAYS-CLOSE ( snapshot -- ior )`。レコード幅・フィールド定数を公開し、呼出し側バッファの容量を検査する形へ詳細を詰める。接続変更後もスナップショットの情報は保持するが、古い画面への配置は再検査してstaleとする。

画面をまたぐウィンドウの所属は最大交差面積を候補とし、同面積時の規則を固定する。負の座標を許可する。Wayland/XWayland・Tk・リモート環境で全画面の情報が取れるとは前提にしない。

| 表示方式 | 初期調査で扱う能力と確認担当 |
|---|---|
| Windows native | 既存のウィンドウスレッドのDPI文脈で列挙する案と、一時的なDPI文脈切替を比較。矩形・倍率の非仮想化を実機で確認する |
| Linux X11/XWayland | 現状のXineramaによる矩形を出発点とする。RandR等の追加実装の要否を調査し、主画面・DPI・Hz・作業領域・IDが未対応ならvalid-fieldsを外す |
| Linux x11=false・端末 | ネイティブ画面情報なしを能力として返す。表示方式の自動選択で値を捏造しない |
| Tk | Tkの取得範囲と画面列挙の制約を調べ、nativeと同じ能力を前提にしない |
| macOS native | 子プロセスとの要求・返答・フレーム通知を拡張する。CIで確認できる部分と、利用者によるMac実機確認を分ける |

### 9.2 表示先・サイズ・状態

表示先指定はウィンドウ作成前はrequested、作成後はOSへ要求してactualの更新を待つ。指定画面が消えたら成功したふりをせず、操作のstale結果と現在の配置を取得可能にする。復旧先の第一候補は主画面だが、APIの失敗と自動復旧通知を分ける。

ウィンドウ状態案：requested size、client pixel size、scale、display id、focused、minimized、close-requested、destroyed、generation。状態通知は最新値と世代、閉じる要求はラッチ。閉じる要求の拒否/遅延をOS別に調べ、既存の閉じる動作を無断で変更しない。DPI変更時のOS自動サイズ変更とアプリ指定のどちらを優先するかを1041で決める。

### 9.3 表示領域と座標変換

policy案：fit-aspect、integer-fit、native、stretch。余白色とnearest/linearを指定する。原画像と実表示矩形を別に取得できるようにする。integer-fitで1倍も入らない場合は縮小fitを明示モードで選ぶ案とし、無断で整数倍保証を破らない。

入力はclient physical→表示矩形内の位置→原画像座標へ変換する。既存のwindow_layoutの変換と範囲外座標・余白内のボタンイベントは維持し、MOUSE/MOUSE-EVENTの通知を抑制しない。新しい変換APIではoutsideを付随情報として返す。画像内へクランプして別のクリックに変換しない。DPIと矩形の同一generationで変換し、境界の丸めを画像テストで固定する。

### 9.4 フレーム提示

FrameRecord案：id、window generation、accepted/rendered/presented/dropped/failed、source-owned-copy、timestamp-valid、error。SHOWの既存契約を変更せず、新しい明示的なsubmit/query/wait操作を候補とする。要求受理・描画完了・実提示を別能力とし、OSが提供しない実提示時刻を推計で成功扱いにしない。

submitは画面画像のコピーを所有して戻る案とし、メインが描画元を変更・解放しても影響しない。保留フレームは有界とし、reject/latestの方針を選ぶ。latestで落とした古いフレームもdroppedの終端状態を保持し、待機を永久に残さない。コピーの上限と費用は実装時に確認する。

ウィンドウの破棄・表示方式変更で保留中を終端化し、waitを起こしてから画像を解放する。垂直同期の要求と実際の対応能力を区別する。時計待機が60回成功したことは60フレームの提示を証明しない。

## 10. 描画（1044〜1046）

クリッピングは描画先画像ごとの半開矩形[x0,x1)×[y0,y1)とする案。画像境界との交差を保持し、空矩形は描画なし。PSET・線・塗り・文字・コピー・回転転送を適用対象として一覧化する。COPYの入力領域の検査と出力クリップは別の工程にする。画像切替で各画像のclipを復元し、FREEで破棄する。

回転転送の候補引数はsource rect、destination center、angle、scale-x/y、filter。角度単位と固定小数点かfloatかはfloat除外構成を含めて比較し、float必須と無断で決めない。逆写像で参照位置を求め、出力のbounding rectを計算してクリップする。端数・負倍率・0倍率の扱い、出力のサイズ上限、長いループの中断を定義する。

画素保存形式の第一案はstraight RGBA8とし、既存RGB値を保つ。合成・補間の一時値だけpremultiplyする案と、画像ごとに形式を区別する案を1046で比較する。既存の画素取得・RGB色キー・コピーの結果を変えないことを受け入れ条件とする。source-over、IMAGE-ALPHAによる全体の濃さ、色キー、加算・XORの組合せを表にして定義する。色キーは転送時の判定で、元画像を書き換えない。補間の一時サンプルだけalpha=0として扱う。PNG等の読込時のalpha保持と、alpha非対応の保存形式への背景色合成を明示する。window_fn等へ渡す画素のアルファの扱いはソースと実機で確認してから変換境界を確定する。

## 11. タスク制御（1049〜1054）

### 11.1 採用方式の比較ゲート

| 候補 | 継続・応答性 | 実装前に検証する事項 |
|---|---|---|
| Zigネイティブジョブのみ | Forthはメインだけで動かす元企画の初期案。ジョブ自身の確認地点で取消す | 許可ジョブの有限性、入出力コピー、ネイティブ待機の解除、計算をForthで書けない制約 |
| 小さな協調ジョブ | アプリが状態を保持して毎回戻る。任意位置の再開はない | 長い処理の分割可能性、待機中にメインが止まらない形 |
| スタック等の継続保存 | Forthの途中で待機・再開する | Zigのネイティブ呼出しをまたぐ継続、全スタック・例外・ローカルの保存、辞書変更との整合 |
| 独立ワーカーVM | 別VMで計算し結果を渡す。任意のメインVMの続きは移さない | State以外のグローバル状態、ホスト権限、辞書同期、VM初期化・再利用の費用 |
| 独立プロセス | 別プロセスへ入出力をコピーし、停止不能時のプロセス終了を境界にする | 起動・転送・回収の費用、子の権限、辞書形式、643との連携 |

初期案として、メインの短いジョブとネイティブジョブのみを比較の基準にする。独立Forth VMを採る場合は取消しつき専用実行経路も同時に成立させる。継続保存を初期の必須条件にしない。採用は1049の隔離・停止試作とレビュー後とし、本書だけで確定しない。任意の既存ワードを安全に並列実行できるとは保証しない。

1049の試作より前に、試作で許可する最小の語と静的・動的な到達先、ホスト参照を限定して監査する。1053で全許可語とState内部の再帰監査へ広げる。1053の隔離・停止試験が成立しなければForth VMの公開を止め、ネイティブジョブ限定案または独立プロセス案へ戻して1049の判断を見直す。監査の完了を方式採用後だけの作業にしない。

### 11.2 状態とAPI案

TaskRecord案：handle、owner、dictionary-generation、state、cancel-requested、input-owned-bytes、result-owned-bytes、error、completion-generation、references。状態はcreated→runnable→running↔waiting→succeeded/failed/cancelled。cancel-requestedは終端状態にせず、終端への遷移は一回だけとする。

| 操作の候補 | 契約の案 |
|---|---|
| TASK-SUBMIT | 許可された語の指定と入力バイト列をコピーしIDを返す。任意のメインVMのxtをそのままワーカーで使わない |
| TASK-STATE | 現在状態・取消し要求・結果サイズ・世代を取得。消費しない |
| TASK-CANCEL | 取消し要求をラッチして起床する。停止完了を意味しない。終端済みは状態を変更しない |
| TASK-WAIT | 単一期限まで終了を待つ。メインのUIを止める同期待機は制限し、複合待機の対象として使う |
| TASK-RESULT | 呼出し側バッファへ結果をコピーする。容量不足は必要量を返し、結果を保持する |
| TASK-RELEASE | 呼出し側の参照を解放。実行中の所有者参照があれば資源は残す。孤児タスクを無制限に残さない方針を決める |

実際のスタック効果はレコード形式と最大入力・結果サイズを1049〜1050で決めてから公開する。結果はスナップショットとして再取得可能とする案。通知を失っても状態は残る。完了と取消しの競合は、終端化のロック内で一回の決定として確定する。取消しが先に要求されても正常終了を許すかは操作契約として明示する。

### 11.3 スケジューリング・待機・権限

メインは入力・描画・通知の処理を一巡ごとに上限付きで進め、入力だけ、完了通知だけで占有しない。タスク間の公平性はrunnableの循環キューを候補とする。優先度やプリエンプションを初期必須にしない。待機対象はkind/id/generation/eventsからなる値で表し、OSポインターを公開しない。

Forthワーカー案では新しいStorageとState.initから作り、Stateをコピーしない。[フィールド別の隔離監査表](CORE_EXTENSION_WORKER_STATE_AUDIT.md)に従い、ワーカー専用Writerを与える。許可しないoptional callbackはnullとし、必須write_fnは上限付きのタスク専用出力バッファへコピーする。出力上限超過は記録して失敗へ変換し、メインの出力へ触れない。nullだけで禁止できない語・fallbackもあるため、語の許可検査を実行の入口と動的な呼出し先へ適用し、間接EXECUTE等で迂回できないことを試験する。入力、UI、メインのファイル、音、コンパイル、辞書変更、同期MS、SYSTEM、タスクの投入・同期待機は初期許可に含めない。TASK-SUBMIT/TASK-WAITは初期案ではメインのみとし、ワーカー間waitを構造上作らない案を比較する。

さらに静的なコロン定義の呼出し、直接のbuiltin Op、短い定義のインライン展開後のOpも対象にする。第一案は投入前に入口から到達可能なコードを走査して許可を検証し、動的な行先と直接builtin Opはworker専用実行経路でも検査する二段構成。静的走査だけでは解けない行先は実行時に拒否できる経路を必須とし、入口名の許可だけで内部の禁止語を実行させない。ループ最適化やspecializeCall後も検査対象が保存されるかを試験する。例として、許可された入口の内部にTYPE・SYSTEM・MSがコンパイルされている場合と、短い定義へ展開された場合の拒否を確認する。

辞書と入力データのスナップショットは、第一案ではアプリの明示操作で一貫した状態を取得し、その版を指定して投入する。取得後のメインの変数変更は反映しない。ワーカーの書込みもメインへ返らず、結果として明示したコピーだけを返す。投入ごとにスナップショットを取る案とも費用を比較する。既存image_generationだけで通常の変数更新を検出したり、通常の!に更新監視を追加したりしない。

初期化候補はencodeImageと新規StateへのrestoreFreshを用いる既存の検査・再配置経路。ただしイメージに含まれないデータとホスト参照、既存の画像解放、インライン呼出し復元を照合し、全メモリの完全コピーと同等とは保証しない。入力契約は「明示取得した辞書・その保存範囲のデータ＋投入データ」と定義し、全論理メモリを使う場合は別のコピー経路を設計する。費用の基準は数MBのStateとStorageのサイズ・初期化・保存範囲の転送量を分ける。

restoreFresh案では現在のpreflightがメモリ形状m/lとbuiltin_countの一致、ヒープ容量を検査するため、単に「大きいStorageなら使える」としない。addressesの再配置記録は復元結果から再構成し、空の初期値のまま残さない。Stateの新規初期化とスナップショット復元後の論理状態を区別する。

投入時のエントリーをそのスナップショット版で解決し、実行中は版を保持する。FORGET/MARKERや変数更新の後は、再取得した版だけを新規投入へ使う。VM再利用時は監査表の全状態を初期化し、前タスクの状態が漏れないことを検証する。省略する最適化は測定後とする。

親子タスクの初期案は所有者による終了時の取消しとjoin。切離しを許可するかは1052で決める。タスク間waitの循環を検出して拒否するか、仕様で禁止して診断するかも決める。結果の待ち合わせでワーカー全員が停止し、新しい仕事が実行されない場合を試験する。

### 11.4 取消しと通常ビルド

タスク取消しの確認はタスク用入口と許可したネイティブの境界に限定する。通常のメイン実行ループへ確認を足さず、debugなしでも使える専用経路を設計する。652の予算による巻戻しを継続保存や通常ビルドの取消しの代用にはしない。

具体案は(a)有限で取消し確認を持つZigジョブのみ、(b)comptimeのworker専用実行ループで各操作の境界にatomic取消し確認、(c)独立プロセス、(d)取消し不能を明示した有界の処理だけ、を1049で比較すること。(b)ではメインのfast/countingループの本体を変えず、ワーカー入口とネイティブループだけを別のコンパイル経路へ分ける。間接呼出しでもworkerモードを保持する。debugなしの通常ネイティブループへ無条件のatomicを追加しない。

workerモードは652のin_counted/keep_countingとは別の不変な実行文脈として入口から入れ子のexecuteOperationsへ引き継ぐ。debug除外でも消さず、単にStateの動的フラグを変更して既に走るfastループを切り替えようとしない。採用時は入口選択と静的・動的呼出しの全経路を照合する。

ただし「通常ループを変えない」という決定が別ループの追加・バイナリ増加・入口分岐をどこまで許容するかは利用者の判断事項として1049に残す。方針の解釈を本書で採用済みにはしない。(a)なら無限のForthを投入できず、(b)ならBEGIN AGAINを確実に停止できること、(c)なら回収可能なことを、公開前の必須試験にする。haltedは非atomicなBYE用状態でCATCHとの意味も違うため取消し印には使わない。

取消しは待機解除→安全な境界で停止→結果/エラーを終端化→所有資源の後始末→所有者へ通知の順を候補とする。期限を過ぎても停止しないワーカーは共有状態を壊す強制スレッド終了をせず、未完了・利用不可を明示する。プロセスを越えた隔離が必要なら別方式として比較する。終了が必ず有限時間で終わるという保証は、許可語と解除可能な待機の範囲を限定してから判断する。

## 12. 終了・辞書復元・資源上限

| 場面 | 新しい資源の設計案 |
|---|---|
| CATCHで捕捉した通常エラー | 資源を自動で全解放しない。操作の未公開な部分取得だけをロールバックする |
| QUITへ戻る | 端末表示を一時解除。タスク・プロセスを残すかは所有スコープで決め、再対話時の列挙・取消し手段を提供する |
| 通常終了・BYE | 新規投入停止→タスク取消し→子プロセス終了要求と出力排出→I/Oとワーカー回収→表示・音停止→画像等の解放→端末復元 |
| 解除不能なワーカーが残る終了 | 参照されるStorage・辞書・台帳を解放してdeferを進めない。未回収を診断し、参照対象を保持したままホストの最終プロセス終了経路へ移る案を検証する。通常のjoin完了・後始末成功と記録しない |
| 既定のSIGINT・強制終了・クラッシュ | 通常回収は保証しない。常設の信号配送へ移行する範囲は別に決め、子プロセス群の残存・端末復旧の制約を明記する |
| 完全な辞書復元 | 新しいタスク・表示保留・PCM等が活動中なら初期案ではbusyで拒否し、明示停止後に復元する。既存ファイルとブロックの保存契約は別途維持する |
| 辞書の追加 | 実行中タスクの世代を保持したまま追加の可否と新規投入の世代更新を検証する |
| SAVE/SAVESYS | 実行時資源そのものを保存しない。保存されたセルのハンドルの再利用問題は4.1の制約を明記する |

停止処理は複数の所有者をまたいでロックを保持したままjoinしない。取消し・完了通知・画像解放の順序をテストで再現する。回収中にエラーになっても残りの資源の回収を試み、最初のエラーと未回収一覧を診断できるようにする。

停止不能の最終終了経路では通常のdefer任せにしない。所有が独立している子への終了要求・音装置への停止要求・端末復元を明示的に呼び出す。停止不能ワーカーと共有するロック・Storage・辞書・台帳へは解放や無期限待機を行わず、それぞれの独立した後始末に期限を付ける。試行済み・失敗・未回収を記録してOSのプロセス終了へ移る。これらの試行も既定SIGINT・強制終了で保証されるものではない。

資源上限はVMメモリ、タスク数、待機対象数、キュー容量、入力・結果バイト、フレーム保留数・画像コピー、PCM、OSスレッドを別々に設定・検査する。開始時に見積りを提示する。プロセス全体の予算と所有者ごとの上限を検討し、上限まで無制限にOS資源を取得する実装を避ける。
