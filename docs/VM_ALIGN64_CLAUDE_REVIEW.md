## A. 必須の訂正

1. **基準側の mod 64 が表にない。**
   - 非counted基準 `0x14003d650` は mod 64 = 0x10、counted基準 `0x140046300` は既に mod 64 = 0 です。
   - つまり「指定で入口が整列した」のは非countedだけ(+0x30)で、countedは整列済みのまま+0x40移動しただけです。
   - `src/forth.zig:1783` を見る限り、countedは `step_limit`・trace・profile等が有効なときだけなので、計時経路は非counted側と読めます。計時対象がどちらかを文書に明記してください。
   - 表のVAはPDB版です。計時版の基準側VAと mod 64 も併記するか、未記録と書いてください。

2. **「入口の整列」と「内部位相の移動」を分けて書く。**
   - 入口が+48バイト動くと、関数内の全分岐先・ディスパッチ先の位置も mod 64 で48、mod 32 で16ずれます。
   - 末尾段落の「他の関数やデータの位置も変わり得る」に加え、計時対象関数の内部ラベル全部の位相が変わったことを明記してください。
   - この実験が示すのは「この1行を加えたこのビルドの配置全体が遅い」までで、「64バイト入口整列が遅い」ではありません。

3. **31行目の段落が古いまま現在形で残っている。**
   - 「A/Aが2%を超え…校正できていない条件で合否を決めない」は、後段の通過・判定と矛盾して読めます。「初回screen時点の状態」と時点を明示してください。

4. **42行目の停止規則との関係を「プロトコル改定」と明記する。**
   - 当初の規則は「未達なら候補比較を行わない」でした。追加ログ版は同じNでの2回目の校正機会にあたります。
   - 経緯は隠されていませんが、「当初規則では候補は未測定で終わる。追加ログ版は候補測定前に別途固定した改定」と書くべきです。
   - 事前固定の証跡も引用してください。`protocol.json` 自体には時刻もハッシュもなく、私は順序を確認できていません。

## B. 記述が支持されるか

- **不採用：支持されます。**
  - 6000.000→6718.750 と 5937.500→6828.125 は、+11.979%/+15.000%と算術的に一致します。
  - 両系列で範囲が重なりません。基準最大 6171.875 < 候補最小 6640.625、基準最大 6140.625 < 候補最小 6531.250 です。
  - 悪化はδ(1.295%、5刻み)と量子化を大きく超えています。
  - 交互順序、warmup 1回の除外、checksum assert、実行体ハッシュのassertはコード上にあります。

- **早期停止：支持されます。**
  - `protocol.json` の gate に「未達なら不採用、残り33条件は未測定」とあります。
  - 残り33条件を測っても、標準候補としての不採用は変わりません。完走を求める理由はありません。
  - 文書も、Linux・LOOP・CATCHは未測定で全項目悪化とは主張しないと書いており、適切です。

- **CPU指標を変えていない：コード上は支持されます。**
  - `worker.py:40-50` の `read_ns` は GetProcessTimes を最初に読み、kernel+user を返します。thread/cycleの追加クエリはその後に記録されるだけです。
  - δは系列ごとの `|x−y|/min(x,y)` で、1.295% = 78.125ms/6031.25ms と一致します。wall/cycleは判定に入っていません。
  - READY/DONE区間の取り方は `benchmark-runtime.py` 側にあり、私が確認したのはハッシュassertの存在と `timing` 文字列までです。
  - `samples_us` と `total_process_cpu_samples_us` は1〜2刻み違う試行があります。前者が区間差、後者がプロセス全体で、矛盾ではありません。

- **追加クエリの負荷：子のCPU時間にはほぼ入らない構造です。**
  - クエリは親プロセス側で走ります。影響し得るのはwallと、親子が同じCPU 0に固定されている点です。
  - 「観測負荷あり」という限界記述は妥当ですが、分散が下がった理由とは言えません。文書もそう主張していません。

- **因果の主張：過剰主張はありません。**
  - 正規化照合は外部call/dataを抽象化しており、完全な意味証明ではないという但し書きは適切です。A-1とA-2を加えれば十分です。
