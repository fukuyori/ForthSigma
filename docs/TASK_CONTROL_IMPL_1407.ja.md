# tque 1407：Windowsのネイティブ描画の組の測り直し

2026-11-26、Windows 11 Pro 26300、AMD Ryzen 7 7700、Zig 0.17.1、main `0fc4888`。[1397](TASK_CONTROL_IMPL_1397.ja.md)で未確認とした60 Hzのフレーム期限の比較を、[1405](TASK_CONTROL_ACCEPTANCE_MANUAL.ja.md)の道具（負荷ありを先に実行し、その送信フレームを基準で再生、各1,200フレーム）と計画v8（各フレームの要求→完了が1/60秒以内）で測り直した。[英語版](TASK_CONTROL_IMPL_1407.md)も参照。

## 道具の修正

最初の実行（`.work/1407/load`）は、G1の1,200フレームのうちフレーム37の`NATIVE-DRAW`の行を数えられず失敗した。ConPTYが行の中の空白をカーソル右移動（`ESC[1C`）として送り、`manual-acceptance-tty.py`の`clean()`がこれを空白に戻さずに取り除いていた。`ESC[nC`をn個の空白に置き換えるように直し、自己試験に例を加えた。

## 結果

証拠は `.work/1407/load2`・`baseline2`、取り込みは `.work/acceptance/20261126T061424Z-2d7f5b3a`（経路）・`20261126T061425Z-c3f5a345`（検索）。

|---|---:|---:|---|
| フレーム数・入力数 | 1,200・6（基準と一致） | 1,200・6（基準と一致） | 比較の条件を満たす |
| 各フレームの期限超過（負荷あり／基準） | 0／0 | 0／0 | 合格 |

Windowsでも、各フレームの期限の超過はなく、タスクによる追加の超過もない。1397の未確認項目は、これで確認済みとする。
