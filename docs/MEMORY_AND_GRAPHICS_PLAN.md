# メモリ上限の緩和とグラフィックス拡張の計画

2026-11-10 作成。論理メモリなどの上限を実行時・ビルド時に指定できるようにし、GUI メニューとスプライト・画像操作を加えるための計画。作業は tque #418 以下で管理する。

- この文書の内容は実装前の計画であり、語の名前と数値は実装時に変わることがある。
- コードで確かめられなかったことは「未確認」、推測は「※推測」と書いた。
- 手本にする機種の機能は一般的な知識によるもので、資料では確かめていない（未確認）。機種の制約を正確に再現する段階（G9）では、実装の前に資料で確かめる。
- gforth は GPL なので、合わせるのは動作だけで、コードは参照しない。

### 論理メモリの配置

`m` は `-m` の値、`l` は `-l` の値（バイト）。

| 領域 | 範囲 | 値の種類 |
|---|---|---|
| システム | `0x0000`〜`0x3FFF`（16 KiB） | コンパイル時の定数 |
| 入力 | `0x4000`〜`0x13FFF`（64 KiB） | コンパイル時の定数 |
| データ | `0x14000`〜`m` | 上限は実行時の値 |
| ヒープ | `m`〜`2m` | 実行時の値 |
| ローカル変数 | `2m`〜`2m+l` | 実行時の値 |

- 入力領域を下の固定番地に移すことで、入力バッファ、ソースファイルの表、引数の領域の番地はコンパイル時の定数のままにできる。
- 既定の合計は 64 MiB + 64 KiB（`m` が 32 MiB、`l` が 64 KiB）。
- 範囲は、`m` が 1 MiB 以上、`l` が 4 KiB 以上、`2m+l` が 4 GiB 未満（イメージの `HERE` が `u32` のため）。範囲外はエラーを表示して終了する。確保に失敗したときも同様である。

### 起動オプション

gforth と同じ名前、意味、単位にする。Sigma の起動引数は gforth と同じ扱いで、現在のオプションは `-e` / `--evaluate` だけなので衝突しない。

gforth の使い方（`gforth [engine options] ['--'] [image arguments]`）に合わせて、サイズの指定は引数の先頭でだけ読む。`--` で打ち切り、それ以降は Sigma の引数として扱う。読み取った指定は `ARGC` / `ARGV` から除く。

| オプション | 指定する大きさ |
|---|---|
| `-m SIZE`, `--dictionary-size=SIZE` | データ領域（ヒープ側は同じ大きさ） |
| `-d SIZE`, `--data-stack-size=SIZE` | データスタック |
| `-r SIZE`, `--return-stack-size=SIZE` | リターンスタック |
| `-f SIZE`, `--fp-stack-size=SIZE` | 浮動小数点スタック |
| `-l SIZE`, `--locals-stack-size=SIZE` | ローカル変数 |

`SIZE` の書式は、WSL の gforth 0.7.9（`0.7.9_20260410`）で次のとおり確かめた。

| 指定 | gforth の動作 |
|---|---|
| 単位なし、`e` | 要素数（`-d 1000` は 1000 セル） |
| `b` | バイト（`-d 1000b` は 125 セル） |
| `k`、`M` | 1,024 倍、1,024² 倍（`-d 64k` は 65,536 バイト、`-d 1M` は 131,072 セル） |
| `1K`、`1m`、`1g` | エラー（`invalid unit`）。単位の大文字と小文字は区別する |
| `1.5k`、`abc` | エラー（`invalid unit`） |
| `0` | 既定値を使う（`-d 0` は 4,096 セル） |

`G` と `T`、負の数は未確認で、実装時に gforth で確かめて合わせる。

### 実装の要点

| 項目 | 内容 |
|---|---|
| 配置の一元化 | 上の配置式を1か所で算出し、重なりと整列をコンパイル時に検査する。実行時の値は `State` に持つ。入力領域を移すと番地が変わるので、この段階で `SIGIMG` の番号を更新する。 |
| スライス化 | `State.memory` と各スタックをホストが確保するスライスにする。定数 `memory_size` などを参照する箇所は、`src` 以下の18ファイルにある。 |
| 起動順序 | 現在は `State` を作り、埋め込みイメージを復元してから引数を処理している（`src/main.zig`）。未知の引数はファイル名として読まれる。新しい順序は、サイズの指定の解析、埋め込みイメージの配置の読み取り、領域の確保、復元、残りの引数の `ARGC` / `ARGV` への設定とする。 |
| 保存イメージ | データ中の絶対番地は配置に依存するので、イメージの見出しに配置の値（`m`、`l`）を記録し、新しい `SIGIMG` にする。見出しの値は 2節の範囲で検証し、範囲外は `INVALID IMAGE` とする。`dictionary_image.zig` の固定の境界は、見出しの値に置き換える。保存範囲は `0〜0x3FFF`、`0x14000〜HERE`、ヒープの使用部分とソースファイルの表とし、入力領域の残りを含めない。`SAVE` の一時領域は、使用範囲の分だけ確保する。 |
| `SAVESYS` | 実行ファイルは保存時の配置で起動する。`-d -r -f` は有効で、`-m -l` はエラーで終了する。 |
| `LOAD` | ファイルの見出しの配置で一時的な `State` を作り、`appendImage` で追加する。データ領域は既存の処理で番地が補正されるので、配置が違っても追加できる見込みである（※推測、M4 で確かめる）。 |
| テスト | `src/tests/support.zig` の `createMachine` と `destroyMachine`、`src/main.zig` のテストの `State` の生成を、スライスの確保と解放に対応させる。上限の固定値に依存する4つのテストファイル（`core_words_test`、`dictionary_test`、`files_and_heap_test`、`float_test`）を更新し、既定値を確かめるテストと、指定した値を確かめるテストを分ける。 |
| `ENVIRONMENT?` | `STACK-CELLS` などは定数の `max_stack` を返しているので、実際の値を返すようにする。 |
| freestanding | `zig build freestanding` は 2 MiB のままとし、ホストがバッファを渡す形にするか、ビルド時の固定値を使う。 |
| ビルドオプション | `-Dmemory-mib=` などを、既存の `-Dgraphics` と同じ仕組み（`b.option` と `build_options`）で加える。 |
| Tcl の上限 | Tk 表示は `max_message` を超えるとエラーになるので、画面の上限と合わせて変える。 |
| インライン展開 | `call_colon` の値には語番号、長さ、必要な呼び出しの深さを 16 ビットずつ詰めている。スタックを 65,535 より大きくするには形式の変更が必要である。 |
| コード領域の `u32` 化 | `pc`、`end_pc`、`Word.code_start`、`Control.address`、`Loop.exit_pc` などの `u16` を広げる。`Op` は `kind` と 64 ビットの `value` なので大きくならない。語番号の `u16` とは分けて扱う。測定の結果、サンプルの最大使用量は上限の 19% なので、今は行わない。 |
| 速度 | スライスにするとアクセスのたびに間接参照が増える。変更前後でベンチマークを比べ、低下が大きければスタックは固定配列のビルド時指定に戻す。 |

`State` は本体も `LOAD` 用もヒープに確保している。現在の `init` は `State` 全体を初期化するので、固定配列のまま大きくすると、小さいプログラムでも全域の物理メモリを使う（測定結果を参照）。

### 画像プールの仕様の方針（G5-0 で確定する）

| 項目 | 方針 |
|---|---|
| 置き場所 | 論理メモリの外。`State` の管理下にプールを置く。 |
| ハンドル | 世代番号を持たせ、解放済みや復元前のハンドルを検出する。 |
| 保存 | `SAVE` と `SAVESYS` では保存しない。復元後のハンドルは無効になる。プログラムは起動後に作り直す。 |
| 寿命 | `FORGET`、`MARKER`、`CATCH` の巻き戻しと画像の寿命は別のものとして規則を定める。 |
| 描画先と画面 | 描画先と画面を分け、`SHOW` は常に画面を渡す。ウィンドウ、Tk、端末は `SHOW` の時点の内容を使う（ウィンドウは `show` でコピーしている）。 |
| `GFX-INIT` | 描画先がオフスクリーン画像のときの動作を定める。現在はホストが古い画面を解放する。 |
| G5-0 で決める項目 | ハンドルの再利用、二重解放と無効なハンドルのエラー、画像の大きさを変えるときの古い領域の扱い、画像の枚数と容量の上限の値と、超えたときのエラー、`State` とホストのどちらがバッファを解放するか。 |

### 画像プールの仕様（G5-0、2026-11-10 に利用者が決定）

今の画面（`GFX-INIT` の画像）は、ホストの `framebuffer_fn` が1枚だけ確保し、新しい画像を渡すときに古い画像を解放している。オフスクリーン画像はこれとは別の表で持つ。

| 項目 | 仕様 |
|---|---|
| 確保と解放 | ホストに `image_alloc_fn(context, pixels) ?[]u32` と `image_free_fn(context, []u32)` を加える（フォントの `font_buffer_fn` と同じ形）。どちらかがないホストでは、オフスクリーン画像の語は `HOST FUNCTION UNAVAILABLE`（-21）。バッファの解放は、コアが `image_free_fn` を呼んで行う。プログラムの終了時はホストがまとめて解放する。 |
| 表 | `State` に固定の大きさの表を置く。各項目は、画素のスライス、幅、高さ、世代番号（16 ビット）。論理メモリの外にあり、辞書イメージには入らない。 |
| ハンドル | 1 セルの値で、`世代番号 × 65536 + 表の位置`。表の位置は 1 から数える。0 は画面を表す。 |
| 再利用 | 解放した位置は再利用し、そのとき世代番号を1つ進める。古いハンドルは世代番号が合わないので無効になる。世代番号は 65,536 回で一周する。 |
| 無効なハンドル | 範囲外、空いている位置、世代番号の違うハンドル、解放済みのハンドルの二重解放は、新しいエラー `INVALID IMAGE HANDLE`（-278）。 |
| 大きさ | 1 枚の大きさの上限は `GFX-INIT` と同じ（各辺 1〜16,384、1 GiB）。範囲外は `NUMBER ERROR`（-24）。作った後で大きさは変えない。変えるときは解放して作り直す。 |
| 枚数と容量 | オフスクリーン画像は 256 枚まで、合計 1 GiB まで。超えたとき、またはホストが確保できなかったときは `OUT OF MEMORY`（-257）で、何も変わらない。画面は合計に含めない。 |
| 中身 | 作ったときは黒（不透明）。 |
| 描画先 | 描画の語は描画先に描く。描画先は初め 0（画面）。描画先の画像を解放すると、描画先は 0 に戻る。 |
| `GFX-INIT` | 画面だけを作り直す。描画先がオフスクリーン画像なら、描画先はそのまま。 |
| `SHOW` | 常に画面を表示する。描画先は関係しない。 |
| `FORGET`、`MARKER`、`CATCH` | 画像を解放しない（`ALLOCATE` のヒープと同じ扱い）。 |
| `SAVE`、`SAVESYS` | 画像を保存しない。 |
| 復元（`SAVESYS` の起動、イメージの復元） | オフスクリーン画像をすべて解放し、描画先を 0 に戻す（画面を忘れる今の動作と同じ）。保存した変数に残ったハンドルは、その位置が空いていれば無効になる。新しく作った画像が同じ位置と世代番号になると、古いハンドルがその画像を指す。これは制限として記録し、仕組みは加えない（プログラムは起動後に画像を作り直す）。 |
| `LOAD` | 画像には触れない。 |

### 語彙の読み込み

`REQUIRE-GRAPHICS` はそのまま残す。`REQUIRE-GUI` と `REQUIRE-GAME` は、`REQUIRE-GRAPHICS` が済んでいなければ先に読み込む。サンプルの `BLIT` などは利用者の定義なので、所属は変わらない。

G5-1（#437）で、読み込みの仕組み（`src/core/library_loading.zig`）を次のように広げた。

- `Group` は組み込み語がなくてもよい（Forth だけのライブラリ）。読み込み済みかどうかは、語彙の次の語がそのライブラリで定義した語であることで判断する。同じ名前の語彙を利用者が作っても、読み込み済みにはならない。
- 組み込み語のない語群は新しい組み込み語を持たないので、イメージの形式を変える印のセルは使わない（`image_address` を省略できる）。
- `prerequisites` に挙げた語群を先に読み込み、ライブラリはその語彙の語を自分の語彙の次に探す。後の語群の読み込みに失敗しても、先に読み込んだ語群は残る。
- `LOAD` での語彙の番号の付け替えを `appendLoaded` にまとめた。G7 と G8 で語群を加えるときは、`appendImage` にこの呼び出しを加える。
- 語彙の語番号のセルは、`REQUIRE-GUI` が `0x2F0`、`REQUIRE-GAME` が `0x2F8`。どちらも組み込み語を持たない前提なので、印のセルは要らず、システム領域の並びは変えていない。

M2〜M5 で決めたこと（2026-11-10）:

- 画像の各辺の上限は、容量の上限 1 GiB に合わせて 16,384 にした（利用者の決定）。`WINDOW-SIZE` の各辺も同じ上限になる。
- 語の数（`-Dwords`、1,024〜65,535）と名前領域（`-Dnames-kib`）はビルド時に指定する。語の番号は `u16` のままにした。
- 語の検索は新しい語から順に比べる方式のままなので、語が数万になると定義が遅くなる。60,000 語の定数の定義に約 8.3 秒かかった（`-Doptimize=fast`、Windows）。サンプルの語数（最大 1,520）では問題にならない。
- M5 の後の測定（M4 の版との比較、`-Doptimize=fast`）: 起動時間 7.13 ms から 7.06 ms、ワーキングセット 5,464 KiB から 6,344 KiB、プライベート 69,612 KiB から 73,064 KiB。実行ファイルの大きさは変わらない（1,100,800 バイト）。
