レモン、`SD-ASR` を `ARSHIFT` に置き換えると、使われている全シフト量で結果が完全に同じになります。ネイティブ移行の前に、この置き換えを先に評価することを勧めます。編集・実行・ネットワークアクセスはしていません。以下はファイルを読んだだけの判断です。

## 判定

| 項目 | 判定 | 根拠 |
|---|---|---|
| 置き換えても結果が同じか | **H** | 下記「同値性」 |
| 速くなる方向に効くか | **M** | 1 回あたりの処理が大きく減るのは確かです。全体でどれだけ速くなるかは未測定です |
| これだけで全負荷が実時間に届くか | 未確認 | 下記「採否の注意」 |

## 同値性

- **今の実装**（`examples/snes-dsp-audio.fs:19`）: `n S>D 1 bits LSHIFT FM/MOD SWAP DROP`。割る数 2^bits は正なので、結果は floor(n / 2^bits) です。
- **`ARSHIFT`**（`src/core/words_arithmetic.zig:35-39`）: 64 ビット符号付き整数の算術右シフトで、これも floor(n / 2^bits) です。シフト量が 63 を超えると 63 に抑えられますが、今回の使い方では関係しません。`docs/WORD_REFERENCE.md:11316-11320` にも「64 ビットの算術右シフト」と書かれています。
- **使われているシフト量**: 呼び出し側はすべて定数で、実際に使っているのは 1・4・5・6・7・10・11 だけです（行 41, 43-45, 103-104, 107, 115, 119, 132, 137-138, 142-143, 147, 170）。どれも 0〜63 に収まります。
- **端の値**: 負の奇数、-1、最小値、最大値を含め、どの 64 ビット値でも一致します。今の実装でも商が桁あふれすることはありません。
- **スタック効果**: どちらも `( n bits -- q )` で同じです。案のとおり `: SD-ASR ARSHIFT ;` とすれば、呼び出し側は 1 行も変わりません。

## 速さへの効き方

- 今の `SD-ASR` は 1 回の呼び出しで、ローカル変数 2 個の確保、`S>D`、`LSHIFT`、倍長の除算 `FM/MOD`、`SWAP DROP` を実行します。置き換え後は、呼び出し 1 回と `ARSHIFT` 1 回だけです。
- 呼び出し回数は多いです。1 声の補間で 5 回、音量・出力・ピッチで 4 回、ミックスで 1 声あたり 2 回、エコーで 1 フレームあたり 22 回あります。BRR のデコードでも 1〜4 回呼ばれます。
- 計測記録（`2026-11-20-snes-dsp-os-acceptance.json` の `adoption`）では、最も遅い負荷の実時間比が Windows 0.425、Linux 0.503 です。Windows で 1.0 に届くには約 2.35 倍の高速化が要ります。`SD-ASR` の置き換えだけでそこまで届くかは疑わしいと推測されます。ただし計測するまで分かりません。

## 勧め

**ネイティブ移行を決める前に、この置き換えを評価することを勧めます。**
- Forth のソースを 1 行変えるだけで、新しいネイティブ API も既存の仕組みへの変更も要りません。
- 「まず Forth で詰め、遅ければネイティブへ」という方針どおりの最初の一手です。
- ネイティブ移行するかどうかの判断材料が 1 つ増えます。

## 必要な試験（タイミング計測を除く）

1. 新旧の `SD-ASR` を、シフト量 1・4・5・6・7・10・11 と境界値（0、±1、負の奇数、-2^bits±1、最大値、最小値）で突き合わせます。
2. `tests/scripts/verify-snes-dsp-audio.py` と `verify-snes-dsp-audio-stream.py` を実行します。
3. 計測スクリプトがタイミングの外で行っている検査（PCM 全体、266 項目の状態、キュー、ARAM 全体）が、6 つの負荷すべてで今の記録と完全に一致することを確かめます。

## 再計測と採否の注意

- **再計測**: 上の試験が通った後に行います。始める前にレモンの開始承認をあらためて取ります。前回の承認は使い回しません。
- **記録の扱い**: 今の記録は、変更前の `.fs` での計測結果です。再計測の結果は別の記録として追加し、今の記録は上書きしません。ネイティブのソースは変わらないので、バイナリのハッシュは同じままの見込みです（※推測です）。
- **それでも足りない場合**: 置き換え後も 1.0 に届かない負荷が残れば、Forth での最適化をさらに続けるか、ネイティブへ移行するかを、レモンに判断してもらいます。Forth で続ける場合の候補は、ほかの補助ワードのローカル変数や、補間処理の `CASE` などです。
- **適用範囲**: `ARSHIFT` は 64 ビット環境が前提の forthz 拡張ワードです。このモデルが forthz 専用であれば問題ありません。他の処理系との互換性が必要かは未確認です。
- **評価の範囲**: 今回の評価は S-DSP のコア部分だけです。SPC700、ROM、実機デバイス、音切れが起きないことは対象外です。耳で聴いての確認と Mac での確認も、まだ済んでいません。
