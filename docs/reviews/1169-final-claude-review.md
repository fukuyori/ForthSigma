## 前回の Medium 4 件はすべて対応済み

**M1. 時刻上限の事前検査**（verify:179-186）
- `CYCLE = MAX−73` から 1 frame 進める場合、48K では 72 tick、128K では 73 tick です。128K はちょうど MAX に届きます。どちらも `ZX-MAX-FRAMES` が 1 を返すので成功し、テストは clock と fraction の値も確かめています。
- 2 frame では -24 になり、41 項目の SNAP が前後で同じであること、buffer の両端が 42 のままであることも確認しています。
- 1 frame が成功し 2 frame が失敗することを両方見ているので、上限の off-by-one はどちら向きでも検出されます。

**M2. error の優先順位**
- 文書 :48 に API ごとの検査順を書きました。この順序は、コードの `ZX-OUT`/`ZX-CHECK`（:79-80）、`ZX-AY!`/`ZX-AY@`（:119, :125）、`ZX-IN`（:127-128）、`ZX-QUEUE`（:100-102）と一致します。
- 複数の不正が重なる場合も検査しています。
  - `256 15 -1 ZX-AY!` → -21
  - 48K で過去の tick → -24
  - queue 満杯と逆順が重なる場合 → -528（verify:177）

**M3. 宣言した復号規則の検査**
- select が 15〜255 の 241 件すべてで、data の書き込みが無視されること（R8 が 11 のまま）と、IN が 255 を返すことを確認しています（verify:159）。
- 48K の `ZX-IN` と `ZX-INPUT!` が -21 になることを error 表に追加し、state と queue 全体が変わらないことも確認しています（verify:172-174）。

**M4. period0／短縮の直接検査**（verify:138-143）
- 次の手計算の値は、どれもコードの step 計算をたどった結果と一致しました。
  - tone と noise の period 0 → [0,0,0,-1,65536]
  - tone の短縮 → [9,0,-1]
  - envelope の短縮と R13 での再始動（共有 divider はリセットされない）→ [9,0,30,31,30]
  - noise の短縮（half の位相を含む）→ [9,1,0,65536]
  - EP0 → [30,29]
  - R12 の上位 byte（EP=256）→ [31,30]
- 16 shape × 96 level の手書き期待列も、32 状態 >>1 の hold／alternate の終端と一致することを確認しました。

**その他（L1〜L3 の対応）**
- stream 検査は独自の RAM callback で 11 ケースです。mock を AUDIO wordlist に先に定義してから play.fs を読むので、mock が使われます。期待値（3 回の書き込み、オフセット 0/10/10、コピーが一致、出力が非ゼロ、overflow なら open 前に -24）はコードと合っています。
- RESET で SLOW を FALSE に戻すこと、R13 未書込みのとき level 15 を保持することは、文書 :23 に書かれています。
