## High

**H-1. 待ち行列の上限 1024 が「同時に待てる数」ではなく「リセット後に受け付けた総数」になっている**
- 場所: `examples/nes-apu.fs:167`、`:176-181`
- `NA-EVENT-COUNT` は減らず、反映済みの書込みも数に残ります。そのため、`NA-RESET` から数えて 1025 件目の `NA-EVENT!` は、待ち行列が空でも -528 で拒否されます。
- 影響: 描画しながら書込みを入れ続ける使い方は、1024 件で止まります。避けるには `NA-RESET` が必要ですが、APU の状態まで消えてしまいます。
- 修正案: 次の語を加えます。

```forth
: NA-COMPACT ( -- )
  NA-EVENT-INDEX @ 0= IF EXIT THEN
  NA-EVENT-INDEX @ 3 * CELLS NA-EVENTS +  NA-EVENTS
  NA-EVENT-COUNT @ NA-EVENT-INDEX @ - 3 * CELLS MOVE
  NA-EVENT-INDEX @ NEGATE NA-EVENT-COUNT +!  0 NA-EVENT-INDEX ! ;
```

- `NA-EVENT!` の中の順序は次のとおりです。
  1. `NA-CHECK-WRITE`
  2. 容量の検査を `NA-EVENT-COUNT @ NA-EVENT-INDEX @ - 1024 >=` に変える
  3. 時刻の順序の検査(既存のまま、末尾の要素と比べる)
  4. `NA-COMPACT`
  5. 追加する
- 待ち行列が空になって順序の検査が飛ばされても問題ありません。反映済みの書込みの時刻はすべて `NA-CYCLE` 以下で、`NA-CHECK-WRITE` が「時刻 ≥ `NA-CYCLE`」を検査しているためです。
- 検証スクリプトの直し方:
  - `SNAP` の `EVENT-COUNT` / `EVENT-INDEX` を、待ち件数 `COUNT-INDEX` に置き換えます。
  - Python の `snapshot` も `len(events)-index` に置き換えます。
  - 試験を足します: 1024 件を入れて全部描画し、さらに 1 件入れて受け付けられることを確かめます。

## Medium

**M-1. 丸めのコメントと実装が合っていない**
- 場所: `examples/nes-apu.fs:200`、`:204-212`
- コメントは `floor(level*32767)` ですが、実装は `floor(pulse·32767) + floor(tnd·32767)` です。この二つは 1 ずれることがあります。
- Python も同じ式なので、試験ではこのずれを見つけられません。
- 修正案: コメントを次のように変えます(仕様の文書も同じにします)。

```
\ Output = floor(pulse*32767) + floor(tnd*32767), each from exact rational LUT.
```

- 合計してから切り捨てるには倍長の演算が必要です(`Np·Dt` は 64 ビットを超えます)。そのため、今の実装に合わせて仕様側を直すのが妥当です。

**M-4. 「基準実装」が独立していない**
- Forth の `NA-SLOW` は、`NA-CLOCK`(1 クロックずつ)、`NA-FRAME-END`、`NA-STORE`、`NA-TARGET` を高速版と共用しています。違うのはループの部分だけです。
- 独立した照合相手は Python だけで、その Python もフィールドの配置と分岐の構造が Forth と同じです。
- 両方が NESdev を同じように読み違えていても、試験では見つかりません。
- 報告では「NESdev から独立に書いた手計算の期待値は 3 件のみ」と書くべきです(パルス、エンベロープ、IRQ の 3 回、スイープ)。
- 加えたい手計算の期待値:
  - ミキサーの表の 2 点(例: `NA-PULSE-MIX` の 15 → 4894)
  - LFSR の数ステップ(mode 0 と mode 1)

## 問題なしと判断した点

- 分周器: パルスとノイズは偶数の CPU サイクル、三角波は毎 CPU サイクルで進みます。`NA-CLOCK` の一括計算(`rest/(period+1)+1`、`period - rest mod (period+1)`)は、1 クロックずつ数えた場合と一致します。
- `NA-FAST` で 1 回に進める区間は、次のフレームの段か `RESET-AT` までで、どちらか近い方で切ります。進める量は必ず 1 以上なので、無限ループになりません。
- `NA-RENDER` のスタックの動き、端数の引き継ぎ、frames が 0 や負のときの扱い。
- ミキサーの式と表の添字。最大値の和は約 20702 で、s16 の範囲に収まります。
- 状態とエラーの順序:
  - `NA-EVENT!` は、すべての検査が終わるまで状態を変えません。
  - `NA-WRITE` は、検査してから時間を進めます。
  - `NA-STATUS` は IRQ を消し、`NA-IRQ?` は消しません。
- 停止したチャンネルは長さカウンターを装填しません。
- `$4017` の inhibit で IRQ をその場で消します。
- スイープのミュートは、スイープが無効でも判定します。
- 矩形波1の減算は 1 の補数、矩形波2は 2 の補数です。
- ベンチマーク:
  - 4 声が鳴っている状態で、時刻を指定した書込み 128 件を含みます。
  - 試し実行(warm-up)と再設定は計測の外です。
  - fast と reference の両方で、最後のバッファの和と最終サイクルを検査しています。
- 待ち行列が満杯のときの -528 は、エラーコード表では「Busy」の意味です。設計レビューの案は -257 でした。どちらにするかは M-2 の文書に明記してください。
