# 1179 Apple IIレビューへの対応

レビューの原文は[1179-claude-review.md](1179-claude-review.md)。レビューしたのは、設計の経緯を見ていない別のClaudeのエージェントで、コード・検査・仕様書・資料を読み、3つの検査をDebugの実行ファイルで実行し、自分で乱数の比較と変異の実験をした。音声装置は開いていない。行番号と「19群」「27件」は、レビューを受けた時点のものである。

Highはなく、Mediumが1件、Lowが11件だった。

## Medium

- **M1（ピンでリセット中のAY）**：コードを直した。PB2が0の間、AYは初期の状態のまま進まず、6522を通す書込みも直接の書込みも受け付けない。独立モデル（Python）も同じ誤りを持っていたので、そちらも直した。手計算の検査を足した（リセット中のAYが進まないこと、直接の書込みが入らないこと、もう1個のAYは進むこと、離したあとは動くこと）。仕様書に、資料にあるのはレジスタが0になることまでで、残りは宣言だと書いた。

## Low

- **L1（長い進行の時間）**：ノイズは131071回、止まらないエンベロープは64回で元に戻ることを使い、繰返しの回数を抑えた。10億サイクルの進行は7.6秒から約0.02秒になった。
- **L2（大きなまとめの検査）**：予定を挟まない10000〜3000001サイクルの進行を6回、2個のAYのレジスタを乱数で変えながら、標本と全状態を独立モデルと照合する検査を足した。3000001サイクルはノイズの1巡（周期1で2097136サイクル）を超える。
- **L3（誤りの検査の順）**：カードなしで過去の時刻へ直接アクセスする4件を足した（誤りの件数は27から31）。
- **L4（`A2-RESET`と`A2-SLOW`）**：仕様書に書き、検査を足した。
- **L5（フレーム数の上限）**：5つの状態で`A2-MAX-FRAMES`を整数の探索（その数は収まり、1つ多いと収まらない）と照合し、1つ多いフレーム数が-24で何も変えないことを検査に足した。
- **L6（リセット後のエンベロープ）**：仕様書に宣言として書き、検査を足した。
- **L7（資料より強い記述）**：16以上のアドレスの扱い、リセットで初期化する範囲、ピンの対応とBC2を、宣言または推論として書き直した。「書込みで2回切り替わる」は、原本を確かめていないと書いた。
- **L8（リンク先がない）**：測定記録とレビューの2つの文書を作った。
- **L9（選んでいるチップ）**：仕様書の説明を直し、検査の該当箇所に`0 A2-CHIP!`を足した。
- **L10（自前の6522を持つエミュレータ）**：先に方向レジスタを設定することを書いた。
- **L11（2つの再生ラッパーを同時に読むと語が二重になる）**：直していない。ZXなど既存のラッパーと同じ形で、この作業の範囲では変えない。

## 疑いとして挙げられた点

- 独立モデルがForthと似た形で宣言を実装しているので、宣言そのものの誤りは両方を通る。これは残る。宣言は仕様書に「宣言」と書いて区別してあり、実機との照合はしていない。
- 実機の音声出力への無音の送出は、レビューでは実行していない。作業した側で、直したあとにもう一度実行し、ReleaseFastでアンダーラン0・ハンドル0だった。

## 対応後の確認

`verify-apple2-audio.py`（20群）、`verify-apple2-audio-stream.py`（19件）、`verify-model-common-words.py`（42件）がすべて成功した。直したあとのコードを、レビューした側がもう一度見たわけではない。
