# Tk状態通知のレビュー対応（1298、2026-11-23）

[Opus 5.5レビュー原文](2026-11-23-tk-state-opus55.md)。公開4語の名前とスタックは維持し、Tkを選択中はTkについて答える。Windows1295の実機待ちを共通実装の着手条件にせず、Linuxで先行した。Windows1295/macOS1299の実行確認は残す。

| 指摘 | 対応 |
| --- | --- |
| 内部evalが利用者の結果・エラー文字列を上書き | Rを内部requestから直接受ける。ユーザーのresult/error_textは触らず、文字列寿命の回帰テストを追加 |
| Wのヒープ確保・partial破棄でcloseを失う | 19バイト固定バッファに独立させ、数字とCell上限を検査。SAVE/restore・ヒープ枯渇のテストを追加 |
| 状態応答Rのヒープ確保でwishが終了する | 内部Rも96バイト固定バッファに。枯渇状態でもWと状態応答が成功することを確認 |
| stopがK/E/Mをdispatchし、ヒープやCtrl+Cの影響を受ける | 非Wは確保・dispatchせずskip。部分Eの後のW、ヒープ枯渇、64KiBの読捨て上限を確認 |
| cleanup失敗が握りつぶされる | cleanup_failedを保持。stopのプロトコル失敗も返し、次のstop/startで再試行する。起動前の再試行と失敗をテスト |
| 同じstop操作でcleanupを2回呼ぶ | lostで実施済みなら再度呼ばず失敗を保持。1操作での呼出し回数1を検査 |
| 送信エラーでwithdrawに到達しない | キー解放とW送信をcatchし、withdrawを実施 |
| XWaylandでTkのwm stateがnormalのまま | 祖先のWM_STATEを2秒・32段以内で照合。取得できたtrue/falseを優先し、nullはTkへフォールバック。実機と3値の単体テストを追加 |
| 「補う」という説明とfalseの上書きが不一致 | WM_STATE優先と明記。要求直後の通常状態、およびフォーカスも一時的に偽になる場合を説明 |
| 過大な内部Rでwishを終了 | 本文をskipして状態なしを返す。次の正常応答、最初の偽、ユーザー結果とTCL-ERROR$の保持を検査 |
| 4値のpush中のoverflow | 4セル分の空きを問い合わせ前に確認 |
| 送信待ち・通常イベントキューでWが落ちる懸念 | WをR/Uと同じ非破棄通知に。実機で通常イベント80件を発生させ、イベントキュー満杯でもcloseを取得することを確認 |
| 表示先変更でclose counterが変わる | backendごとの値であることをHELP・英日文書・リファレンスに明記。nativeとTkの切替えを実機で確認 |

最終再確認の結論は「3点とも妥当。ブロッカーになる欠陥はありません」。最後に残ったLowの指摘に合わせ、移行中のフォーカスの説明、過大応答時の最初の偽とエラー文字列のアサーションも補強した。

接続ごとのコストと上限、TCL-STOPの有界drain、ユーザーによるWM_DELETE_WINDOWハンドラー置換、固定待ちの実機試験条件、Windows/macOS未実行は制限として記録する。状態応答自体はヒープを使わないが、待機中に届くユーザーイベントによる資源例外やCtrl+Cは伝播し、応答の取り違えを防ぐためwishが終了する場合がある。native専用のWINDOW-CLOSE/KEEP-OPEN/CHANGES/FRAMES/PAINT-WAITをTk対応したとは扱わない。
