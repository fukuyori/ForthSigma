# NES APU Forth試作1134：レビュー評価と採否

2026-11-20。[設計提案原文](1134-design-claude-review.md)、[実装原文](1134-implementation-claude-review.md)、[補強後の最終原文](1134-final-claude-review.md)を分け、この文書に採否を記録する。Claudeは読み取り専用で、コマンドや試験を実行していない。資料照合と実行結果は[実装記録](../NES_APU_FORTH.md)に分ける。

## 設計レビュー

- H1採用。NA-EVENT!の予定表を追加し、NA-RENDER/NA-RUNの進行中にCPU時刻順・同時刻の受付順で適用する。NA-WRITEは指定時刻まで進めて設定する状態検査用として残し、音を連続生成する経路では予定表を使う。音を格納しない語で時間を進めたことを、連続した音声出力と扱わない。
- H2採用。NA-STATUS (cycle -- status)でframe IRQをclearし、NA-IRQ?は非破壊で読む。resetは決定的な試作位相で、実機のpower-on再現とは主張しない。
- H3採用。1クロック版を残し、まとめ処理版と独立Pythonの状態・PCM一致を入口にする。速度不足だけから本体へ移さず、まずイベント単位の処理を試す。今回のまとめ処理版は測定した4声の範囲で実時間を上回るため、その範囲ではForthを維持する。DMC/CPU/PPUを含む結論は出さない。
- M1採用。noiseも偶数CPU時刻でclockし、CPU単位の周期表を2で割って使う。
- M2採用。近似の3t+2n表を使わず、資料の近似DAC式をDMC=0で有理数化したtriangle/noiseの256項目表を使う。pulse/TNDをそれぞれfloorして加算する。
- M3〜M8採用。4017の即時inhibit・遅延reset、sweepの恒常mute/negate差、triangle DAC保持、disableとlength、事前検査、標本端数を具体化した。resetとframe clock衝突はreset優先のモデル規則とし、半サイクルの実機保証をしない。
- 初期提案にあった追加の測定許可は導入しない。セッション中の測定・継続指示に従い、他アプリを停止せず測定している。

## 実装レビュー

- H-1採用。累計1024件で止まる仕様を、未処理1024件に改めた。全引数・順序・空きの検査が成功してから、物理末尾に達した場合に処理済み領域をMOVEで回収する。完全消費後と部分消費後の再追加を検査し、APUをRESETせず使い続けられることを確認する。
- M-1採用。コメントはfloor(pulse×32767)+floor(TND×32767)と明記し、合計後のfloorとは区別する。Pythonも同じ出力契約である。手計算したpulse tableの2点を追加した。
- M-2はレビュー進行中に[詳細記録](../NES_APU_FORTH.md)を作成して解決。原文の不存在指摘は書き換えず、時点の違いをここに記録する。詳細設計を日本語で残す既存形式に合わせ、利用案内・コマンドは既存の英日マニュアル/試験READMEの両方へ追加した。新しい詳細記録すべてに対となる翻訳が必須という指示は現行にはない。
- M-3採用。描画の間に新規enqueueして一括版と照合する試験、同時刻のqueued→immediate順、過去STATUS、負/overflow RUN、4017の上限、stack不足の事前状態保持、unused番地/enable上位bit無視、実PCM生成中エラーで所有handleが0になる試験を追加した。AUDIO?は0/-1、underrunは非負も検査し、回数そのものは環境によるため0を要求しない。
- M-4採用。Forthの2版がdivider/frame/storeを共有することを明記し、独立した照合相手はPythonだけとした。手計算値としてpulse/envelope/IRQ/sweepに加え、LFSRとミキサー2点を確認する。実機/ROM試験を通したとは主張しない。

## 判断の範囲

1クロック版とまとめ処理版の同値試験は、このモデル内の最適化の確認である。資料の解釈の共通誤りや未実装の実機機能は除去できない。今回の採否は「NTSC 4声の定義したサブセットはForthのまま維持」で、NES全体の実時間動作、DMCを加えた負荷、実際に聞こえる音には結論を出していない。DMC等は1135に残す。
