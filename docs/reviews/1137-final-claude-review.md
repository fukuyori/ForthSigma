**手計算で追った内容**(`examples/paula.fs:35-60`、`tests/scripts/verify-paula-stream.py:28`)
- 設定: ADKCON `0x8011` で voice0 が音量と周期の両方を voice1 に渡す状態。周期 123、長さ 3。メモリ上の語は 64 / 123 / 32 の順です。
- 1語の処理に 246 tick かかります。tick 493 で3語目、739 で4語目(先頭に戻って 64)、985 で5語目(123)を読み込みます。
- 位相リセットがある場合:
  - 493 では 32 が音量に入ります。位相は 1 に切り替わった後、`PA-RELOAD`(35行)で 0 に戻ります → `32 123 0`
  - 739 では 64 が音量に入り、位相は 1 → `64 123 1`
  - 985 では 123 が周期に入り、位相は 0 → `64 123 0`
  - 丸め(PER clamp)は 0 回です。期待値と一致します。
- 位相リセットを外した場合:
  - 493 の時点で位相が 1 のままになり、期待値の 0 と違います。
  - 739 では 64 が周期側に入り、123 未満なので 123 に丸められます。丸め回数は 1 になり、音量は 32 のままです。
  - つまり 493 の位相、739 の音量、最後の丸め回数の3か所で値が食い違います。出力値の比較だけで検出でき、スタックエラーには依存しません。
- 他の壊し方も検出できます。リセットを `PA-START` だけで行う場合は上と同じ結果になります。読み込みのたびに位相をリセットする場合は、493 の周期が 65536 になるため検出できます。
