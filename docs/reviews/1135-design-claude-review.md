**NESdev と一致していることを確認した項目**

**合成（ミキサー）の表**
- index の並びは `(t*16+n)*128+d` で、初期化と `NA-SAMPLE` で一致しています。
- `UM*`/`UM/MOD` で 64bit の溢れを避けています。分子は約 1e19 で 2^63 を超えるので必要です。
- d=0 の値は旧4声の表と floor まで一致します（分子と分母に同じ 22638 を掛けたため）。DMC が 0 のままなら、旧4声のbyte列はそのまま回帰試験に使えます。

**Medium（設計上の決め事）**
4. **`NA-MEM!` の時刻:** `NA-MEM!` は予定表を通らず、現在の `NA-CYCLE` の時点ですぐ反映されます。先に描画を進めてから書いた場合の意味を明記してください。
   - `NA-RESET` はメモリを消しません。メモリを0で埋めるのは読み込み時だけです。
   - 試験はケースごとに新しい process で動かすか、メモリを明示的に書いてください。
5. **1134 の語の契約が変わる:** `NA-IRQ?` が frame|DMC を返すようになり、`NA-STATUS` に bit4 と bit7 が加わり、-21 で拒否していた処理がなくなりました。これを語表に反映してください。
6. **Python モデルの独立性:** Python モデルは Forth と同じ状態配置と手順（`nd[0..14]`）をなぞっています。仕様の読み違いが両方に入れば検出できないので、NESdev の文章から作った手計算の値を主な根拠にしてください。例を2つ挙げます。
   - **rate 15:** cycle 0 で `4010=0F`、`4013=0`、`4015=10` を書き、C000=FF とします。取り込みは cycle 1、出力の clock は 2, 56, 110, … です。9回目の clock（cycle 434）で初めて DAC が +2 されます。
   - **IRQ:** `4010=8F` にすると、`STATUS(0)` は bit4=1・bit7=0、`STATUS(1)` は bit4=0・bit7=1 になります。
7. **測定の比較条件:**
   - 無音PCMの全 process 時間には、32k項目の表の初期化と 32KB の fill が加わります。1134 の値とそのまま比べないでください。
   - 表は 256KiB です。debug/graphics/extension を除いた構成で読み込めるかは未確認です。
8. **負荷の追加:** 5声の負荷には、次の2つも入れることを勧めます。
   - rate 15 で loop する最悪条件
   - 4011 への高頻度の時刻指定書込み（例：8kHz、予定表は最大1024件）。実機の音楽でよく使う使い方で、予定表の処理に負荷がかかります。
