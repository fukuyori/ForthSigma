# 1037 Windows表示支援：Claude Codeレビューへの対応

2026-11-23、利用者の依頼によりClaude Codeへ固定スナップショットの静的レビューを依頼した。
4回ともRead/Grep/Globだけを渡し、実行・編集・ネットワーク操作は依頼していない。
レビュー原文、実行メタデータ、スナップショットの指紋は
[メタデータ](../measurements/2026-11-23-windows-native-review-metadata.json)を参照する。

| 指摘 | 対応 |
|---|---|
| M1 全画面のままclose後の再表示で通常配置が壊れる | 修正前の実行体でモニター矩形2560×1440のままになることを再現。新しいHWND作成前と破棄時にfullscreen_onをリセット。通常表示・全画面での再表示と解除を各画面で追加確認 |
| M2 構成変更で全画面を掛け直さない、画面外の通常復帰位置 | 通知後の専用メッセージで現在の画面矩形を再取得。消えた画面の通常復帰位置は残る作業領域へ補正。合成通知で掛け直しを実行確認。物理切断は未確認 |
| M3 期待値側がSigma自身の画面情報 | Pythonで独立に列挙し、MONITORINFOEXとDEVMODE、MonitorFromWindow、DPI、client寸法で照合。事前・事後の構成も確認 |
| M4 VSYNC-WAITが常に偽でも合格 | DWM有効時は成功を必須にした。別スクリプトで通常構成と75Hz/60Hz構成の呼出し周期を測定 |
| 作業領域変更の通知不足 | SPI_SETWORKAREAの通知でWINDOW-CHANGESを更新。合成通知で確認 |
| 全画面移動後の通常サイズのDPI換算 | 実際に202×133などのずれを確認。保存した通常矩形のDPIを記録し、通常移動と同じクライアント寸法の換算を実施 |
| 最小化・最大化中の移動 | 通常復帰位置を保存位置APIで変更。復帰中の寸法・再入順序は内部ログで特定し、通常サイズ/DPIの保持とWM_TIMERによる再配置を追加。93段階で通常・全画面・最大化へ戻る最小化まで確認 |
| 古いHMONITORの再利用 | 選択時のGDIデバイス名も保存し、配置時に一致を確認。構成変更後の番号・ハンドルは永続的な物理画面IDとは扱わない |
| N1 再接続の判定がHMONITORの完全一致 | 構成の照合からハンドル・GDI番号を除外し、選び直しは矩形で対応付け。ハンドルと名前の変化を記録。事前確認を通常・全画面で実行 |
| DwmFlush異常系とwatchdog | 実workerによる関数なし・失敗・停止・期限・回復の単体テストを追加。測定親がfinallyを通らず終了した後の独立復元も実行確認 |

初回は中の指摘があり、再レビューでは元のM1〜M4は解消、新たな中は記録スクリプトのN1。
3回目は高・中なしという判定だった。ただし、そのスナップショットより後に、通し検証の内部ログに基づく
WM_TIMERでの復帰再配置、最小化された全画面、最初の復帰サイズの保持、検証の93段階への拡張を加えている。
レビューを実行検証の代用にせず、各結果を[Windows検証記録](../WINDOWS_NATIVE_DISPLAY_VALIDATION.md)へ残す。

DwmFlushの関数差替えは非対応OSの実行確認ではない。全画面の構成通知も物理切断そのものではない。
1344の物理切断と1276の非対応実環境は引き続き未完了とする。

4回目は[復帰順序に絞ったレビュー](1037-windows-native-claude-acceptance.md)で、WM_TIMERへの変更と最小化された全画面を含め、高・中なし。最後の低指摘だった「全画面を最小化中に解除すると保存サイズが全画面矩形になる」経路は、その後、元の通常矩形・DPIを保持するよう修正し、93段階の実行で確認した。
