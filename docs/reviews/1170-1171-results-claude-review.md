## 指定ファイルを読んで確かめたこと
- **中央値と比率**: 2負荷について `wall_nanoseconds` の7値を並べ替えて中央値を出し、記録と一致しました。
  - Windows 48k_beeper: 8662600 ÷ 32768 = 264.36 ns/frame
  - Windows period_zero: 190161900 ÷ 32768 = 5803.28 ns/frame
  - Linux period_zero: 164928950 ÷ 32768 = 5033.23 ns/frame
  - 実時間比は 20833.33 ÷ ns/frame で、78.81倍、3.59倍、4.14倍と一致します。
  - 文書の表の12値は JSON の `median_*` と一致します。`adoption` の最小値（3.5899 と 4.1392）も表と一致します。
- **計測回数**: `range(8)` の round 0 は計時しない検証用で、`timed=round>0` により7回分を記録する構造です。確認した3配列はどれも7要素でした。
- **全PCMと状態の照合**:
  - PCM は全バイトを比較し、`SUM` も照合しています。
  - 状態は前後とも39項目です。queue は前が `[initial,0]`、後が `[final]*2` です。
  - 前処理（`SETUP WORK SETUP`）と A5 の FILL は計時区間の外です。
  - `assert` が1つでも失敗すると、`all_full_pcm_and_state_checks_passed: True` が出力される前に処理が止まります。そのため、この固定値は実態と矛盾しません。
- **サイズとバイナリの来歴**:
  - Windows/Linux の `binary_sha256` は、`binaries` の値および `zx-spectrum-audio.json` 側の8構成の値と一致します。
  - `native_source_sha256_lf` も同じファイルにあり、文書の「native増加0」「HERE増分25160はlogical」の記述と矛盾しません。
- **Forth維持の判断と範囲**: 判断は「この測定負荷に限る」とされています。任意のregister列の最悪値、CPU emulator、underrun なしの再生、Mac での性能は保証外と明記されています。`listening_acceptance: null` で、1168/1170/1171/1172 はすべて `todo` です。実聴、Ctrl+C、Mac は未完了の扱いで整合しています。
