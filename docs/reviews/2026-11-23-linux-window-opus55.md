## 指摘

### 1. 【中】`WINDOW-PIXELS` と `WINDOW-IMAGE-RECT` を呼ぶたびにXの接続を開いて閉じる
- **場所**：`src/host_display_linux.zig:26`、`src/graphics/graphics.fs:394-401`
- **影響**：
  - 1回の呼び出しごとに次のことをしています。
    - socketを作って接続する
    - `~/.Xauthority` を読む
    - バッファを1 MiBずつ2つ確保する
    - 接続時の応答（setup）を全部解析する
  - `(TK-IMAGE-RECT)` は最大3回この処理を繰り返します。
  - サーバーが応答しないと、1回で最大2秒、全体で約6秒止まります。
  - 毎フレームで `WINDOW-IMAGE-RECT` を読むTk表示のプログラムでは、かくつく可能性が高いです。記録にもある通り、速度は測っていないので、どの程度かはまだ分かりません。
- **修正案**（いずれか）：
  - 接続をモジュール内にロック付きで持ち回して再利用する
  - この用途ではバッファを数KBにする
  - X11ではTkの単位がXのピクセルと同じなので、`winfo width/height .` で済ませることも検討する

### 2. 【低】ドキュメントの「物理ピクセル」が実際の値と合わない
- **場所**：
  - `docs/word-reference/translations.ja.tsv` の GFX-WINDOW-PIXELS
  - `docs/WORD_REFERENCE.ja.md:42929`
  - `graphics.fs:330-331`
- **影響**：コード内のコメント（`host_display_linux.zig:22`）は正しく「X server pixels」と書いています。ところが、XWaylandで拡大率が1でないとき（Mutterのネイティブ拡大を使わない場合）、Xのピクセルは論理ピクセルなので、物理ピクセルにはなりません。今回の確認は倍率1だけで行われています。
- **修正案**：Linuxでは「Xサーバーのピクセル。XWaylandで拡大しているときは物理ピクセルと異なることがある」と書く。

### 3. 【低】ウィンドウでないIDでも大きさを返す
- **場所**：`host_display_linux.zig:30`
- **影響**：`GetGeometry` はDrawableなら何でも受け付けます。そのため、ピックスマップのIDではその大きさを、ルートウィンドウのIDでは画面の大きさを返します。Windows側は `IsWindow` で確かめていて、仕様の「ウィンドウがなければ0 0」とも食い違います。普段使うTkのIDでは問題になりません。
- **修正案**：先に `GetWindowAttributes`（opcode 3）を送り、BadWindow なら null にする。応答にあるrootがIDと同じなら弾く、という方法もあります。

### 4. 【低】大きさを聞くだけなのに、表示用の条件で失敗する
- **場所**：`host_x11.zig:167,190,206-208`
- **影響**：`openUntil` は、既定のvisualがTrueColorでない場合や、ビット数が16/24/32以外の場合に `Unavailable` を返します。大きさを聞くだけならこれらの条件は要りませんが、このようなサーバーでは0 0になります。まれな環境の話です。
