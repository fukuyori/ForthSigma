## 計測上の制約(バグではない)

1. **計時区間の Forth 文は事前検証で一度も実行されていません。** 既定モードでは NTIME/CPUTIME の行を通らないためです。スタック効果は合っていて、ほかの measure スクリプトでも同じ書き方をしていますが、この負荷での実行は未確認です。もしずれていても、最初の計時ラウンドで assert が失敗して止まるので、誤った値が黙って記録されることはありません。
2. **ラウンドの順序に偏りがあります。** 計時ラウンドの回転は 1,2,3,4,5,0,1 で、回転 1 だけが 2 回使われます。また `round_order` には未計時の round 0 も入りますが、未計時という印が付いていません。
3. **wall には CPUTIME の 2 回の呼び出しと `D+` も含まれます**(scope の説明に記載あり)。CPUTIME はマイクロ秒単位なので、粒度が粗い可能性があります。
4. **compaction は index==count のときしか起きません。** そのため MOVE の長さは 0 で、未処理エントリを移動する経路は計測に含まれません(scope に記載あり)。
5. **検証はすべて `assert` に頼っています。** `python -O` で実行すると検証が無効になり、それでも `all_full_pcm_state_aram_checks_passed: True` が固定値で出力されます。実行は `-O` なしで行うことが前提です。
6. **`forth_source` には最後のラウンドの文だけが残ります。** ラウンドごとの違いは、生成元のコードから復元できます。
7. **正しさの基準は Python のオラクル(`verify-snes-dsp-audio.py`)です。** オラクル自体の妥当性は 1174 の検証に依存しています。対象は S-DSP コアだけで、SPC700・ROM・実機は含みません。Linux での計測は WSL2 です。
