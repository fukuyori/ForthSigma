# Linux表示支援レビューへの対応（2026-11-23）

レビュアーは利用者指定のClaude Code Opus 5.5。modelUsageも`claude-opus-5-5`で確認した。[初回・1332初稿の原文](2026-11-23-linux-window-opus55.md)。再確認の原文も同ファイル末尾に収録する。実行検証はCodexが行い、Claudeには読み取り専用の確認を依頼した。

| 指摘 | 対応 |
| --- | --- |
| 公開前の最小化・復帰で再描画を取りこぼす | `paint_deferred`で最小化による完了保留を記憶し、通常状態の公開時に再描画。X接続不要の単体テストも追加。再作成時にリセットする |
| 最小化中の保留を100 msのタイムアウトだけで判断 | 最小化中に追加の状態を取得し、提示数2・完了数2未満を照合。復帰後2/2、待機中の閉じる要求で偽も確認 |
| 初回描画前の最小化を保証しない | 「初回描画の完了を明示的に待つ／待たない」と範囲を限定。最小化前に描画が終わる可能性を残す |
| Tkの期待値が実装の式と同じ | 画像160×100から整数倍・間引き・中央配置を独立に計算して照合。倍率1での受け入れと明記 |
| 破棄と問い合わせの競合 | 専用toplevelを作り、`destroy; update`の後に保存したIDを問い合わせる |
| GetGeometryがピックスマップも受理する | GetWindowAttributesを先行し、実在するピックスマップIDで0 0となることを確認 |
| XWaylandで物理ピクセルとは限らない | LinuxではXサーバーピクセルであると英日マニュアル・コメント・全語リファレンスを補足 |
| 毎回のX接続・バッファ確保と待機時間 | 接続ごとの期限2秒、表示領域は最大3回の問い合わせであると明記。毎フレームの問い合わせを避ける説明を追加。接続キャッシュは寿命・障害復旧の設計を伴うため今回導入しない。速度の測定は行っていない |
| visualによる接続条件 | 現在のLinux描画バックエンドと同じ条件を維持。低色数サーバーへの対応は追加しない |
| 文書の未コミット表記・重複ソース・ICCCM/EWMHの区分 | 80aa871の公開済み記録に修正、重複ソースを削除、最小化はICCCM・復帰はEWMHと訂正。今回の検証には実行体のハッシュを記録 |
| テスト中に他クライアントのウィンドウが消える | 探索中のBadWindowを読み飛ばす。自分のSigmaのPIDで対象を選ぶ |

Opus 5.5の再確認は「修正が必要な具体的なバグは残っていません」。残る軽微な指摘は、実機テストの0.5秒待ちと倍率1の前提。これは対象環境と検証の限界として維持する。接続コストの改善・倍率を変えた実機確認・実際の表示到達や垂直同期の測定を完了したとは扱わない。
