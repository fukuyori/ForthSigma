## High

見つかりませんでした。宣言どおりのデジタルモデルとして、次の6点を読み、矛盾はありませんでした。

- **区間のまとめ方:** `SI-STEP-LIMIT` は、各声の ADSR の発火、bit19 の立上り、MSB の立上りのうち最も近いものまでで区間を切ります。立上りは必ず区間の最後の clock に来ます。SYNC、ノイズ、ADSR は、まとめない1clock版と同じ結果になる構成です。
- **予定書込みの境界:** `SI-TO`（`sid.fs:152-158`）は、書込みの時刻までちょうど進めてから書き込みます。
- **エラー時の状態:** `SI-WRITE`、`SI-EVENT!`、`SI-READ`、`SI-RUN` は、検査をすべて済ませてから状態を変えます。`SI-COMPACT` は検査の後にしか走らず、意味も変えません。
- **ADSR:** レートカウンターを wrap で待つ動作、分周を状態として持つこと、sustain を上げても値を上げないこと、0 で止まることは、`SID_FORTH.md:51` の記述どおりです。
- **値の上限:** |input·65536| ≤ 4.03e8、|damping·bp| ≤ 92667·2^33 ≈ 7.96e14、|hp| ≤ 2.11e10、|alpha·hp| ≤ 1.05e15、混合前の |low+band+high|/65536 ≈ 5.8e5 です。位相は 32768·65535 ≈ 2.1e9 が上限です。どれも 2^63 より十分小さく、溢れません。
- **8kHz の補充:** `SI-END` の式は、512 frame 分の clock の合計と正確に一致します。未処理の予定は1ブロックあたり約86件で、1024件の上限より十分少なくなります。`SI-END` と同じ時刻の書込みは、そのブロックの最後の frame で処理されます。次のブロックの最初の書込みは `SI-CYCLE` より後の時刻なので、過去への登録として拒否されることはありません。Python の `to()` も「時刻 ≤ 目標」で処理するので一致します。

## Medium

**M1. 負荷の大きい測定（heavy、8kHz）が、ほぼ無音の状態を測っている**（`verify-sid.py:177-180, 186`）
- **原因:** 3声とも AD=0、SR=0（sustain 0）で、gate を入れるのは1回だけです。8kHz の書込みは `D400` の周波数下位だけで、gate を切り替えません。手計算では、attack 2295 clock と decay 6804 clock を足して 9099 clock で、エンベロープが 0 に固定されます。測定区間 672597 clock のうち約1.35%（約443 frame）にあたり、残りの全 frame で各声の出力は 0 です。
- **影響:** routed が 0 になるので、low と band が 0 になれば `SI-FILTER` は呼ばれません（`sid.fs:219`）。状態が 0 になるかどうかは、実行しないと分かりません。また PW レジスタを設定していないため、声3のパルスは 4095 の直流です。設計レビューが求めていた「gate を繰り返し入り切りする」（`design-review.md:88`）も入っていません。
- **再現例（未実行。期待値は手計算）:** heavy の設定を予定表に入れて `0 SI-RUN 20000 SI-TO 0 2 SI@ . 1 2 SI@ . 2 2 SI@ .` を実行すると、`0 0 0` になるはずです。
- **修正案:** SR を `$F0` にするか、8kHz の書込みに `D404/D40B/D412` の gate の切り替えを混ぜます。PW も設定します。測定の終わりにフィルターの状態とエンベロープの値を出力して、記録に残します。

**M2. 測定の正しさの確認が、最後のバッファのバイト和だけ**（`verify-sid.py:187, 194`）
- **原因:** Forth の出力と比べているのは、最後の1024バイトの和、cycle、clip の数だけです。`oracle_pcm_sha256` は Python 側で計算しているだけで、Forth の出力とは比べていません。
- **影響:** M1 のとおり最後のバッファが 0 なら、和も 0 です。途中で fast 版の出力がずれても、この確認では見つかりません。heavy の構成（3声すべてで rate 0、FFFF のノイズ、SYNC/RING の輪、FC2047/res15）は、PCM 全体を照合する試験のどこにもありません。
- **確かめ方（未実行）:** Python 側で `sum(expected[-1024:])==0` かどうかを見ます。
- **修正案:** 測定とは別の、時間を測らない実行を負荷ごとに1回追加します。32768 frame を1つの領域に生成してファイルに書き、`expected` とバイト単位で比べます（`verify-sid.py:134-139` と同じやり方）。

**M3. ノイズ関係の値の出典が、文書の間で食い違っている**（`SID_FORTH.md:12` と `SOUND_RESEARCH.md:248-249`）
- `SID_FORTH.md` は、bit19 のクロック、feedback 22 XOR 17、seed 7FFFF8 をすべて1995年の報告から採ったと書いています。
- `SOUND_RESEARCH.md` では、bit19 と seed の出典は [R-WAVE]、feedback は [OXY] です。
- 1995年の投稿は今回読んでいないので、どちらが正しいかは未確認です。FREQ=$8000 で32clockごとという報告が bit19 と合う（2^20/2^15 = 32）ことは計算で確かめました。
