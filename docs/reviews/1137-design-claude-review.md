# Paula 設計レビュー（.work/1137/design.md）

ファイルは読むだけで、書き込み・コマンド実行・ネットワーク・git 操作はしていません。HRM の写しは読んでいないので、HRM の記述として挙げた点はすべて未確認です。

## High

**H1. 最小周期が 123 と 124 で食い違っている**
- 既存の `src/core/sound_amiga.zig:18` は `min_period = 124` で、コメントにも「the period at least 124」とあります。設計案は「PAL最小123」です。
- HRM の DMA 最小周期は 124 と記憶しています（※推測です）。
- 案：HRM 写しの該当ページを design.md に書く。根拠が出るまでは 124 にそろえる。拒否範囲（外部 write の -21）と変調時に丸める値（saturate）も同じ値を使う。

**H2. IRQ が1ブロックで2回立つと読める**
- 「最初のfetchとlast-word fetch時にpendingIRQ」のままでは、「最初のfetch」が毎ブロックの先頭とも読めます。
- 案：IRQ は reload のたびに1回だけ立てる、と決める。reload が起きるのは次の2つです。
  - DMA 有効化の立ち上がりでコピーしたあとの最初の fetch
  - last-word fetch の時点（次ブロックの LC/LEN をコピーする時）
- 次ブロックの最初の fetch では IRQ を立てない。
- LEN=1 の場合は、最初の fetch がそのまま last fetch になります。このとき同じ tick で reload が2回起きる扱いにし、pending bit は1つにまとめる、と明記する。

**H3. 同じ tick での write と遷移の順序が決まっていない**
- 「最初のfetchは次tick」や「DATは次tickから」が成り立つかどうかは、この順序で決まります。
- 案：時刻 t の write は、期限が t 以下の遷移をすべて処理したあとに適用する。`SI-TO` は `cycle SI-RAW-TO` のあとで STORE しているので、これと同じ形です。その結果、t で有効化すると最初の fetch は t+1 になる。同じ時刻の READ も queue と遷移を処理したあとに読む。

**H4. DMA の実効的な有効状態の定義がない**
- 案：実効 enable = `DMAEN(bit9) AND AUDxEN` とし、この AND 全体の立ち上がりと立ち下がりで reload と停止を行う。DMAEN だけを切り替えた場合も同じ扱いにする。disable しても INTREQ は変えない。

**H5. ステレオ出力に pcm-synth-play.fs の後始末（cleanup）を流用するとサイズが合わない**
- `tests/audio/pcm-synth-play.fs:21` は `PS-SENT @ 2 *`、`:34` は `1024 0 FILL`、`:31` は 1ch で、どれもモノラル前提です。
- 案：ステレオでは 512 frames × 4 bytes = 2048 bytes のバッファにする。具体的には次の3か所を変える。
  - オフセットを `4 *` にする
  - FILL を 2048 にする
  - `PCM-OPEN` を 2ch にする
- 部分書き込みは frame 単位で数える（バイト数ではない）。
- 例外の扱い（`CATCH >R … R> ?DUP IF SWAP DROP THROW THEN THROW`）と、close に失敗したときにハンドルを残す動きは正しいので、そのまま流用できます。

## Medium

**M1. 19bit LC は A500 を想定したモデル上の選択で、HRM 全体の事実ではない**
- 記憶では、HRM 第3版の LCH は bit0〜4（ECS）です（※推測です）。
- 案：「OCS 512KiB を想定した宣言」と書く。マスクするか拒否するかは、どちらかに統一する。推奨はマスクで、`LCH & 7`、`LCL & 0xFFFE`、VOL の上位を無視するのと同じ方針です。

**M2. 512KiB を超える fetch の扱いが決まっていない**
- LC + 2×LEN が 0x7FFFF を超える場合です。
- 案：fetch するアドレスは `(ptr) & 0x7FFFE` で折り返す、と宣言する。

**M3. PER=0 と LEN=0 の扱いが一貫していない**
- PER 1〜122 は拒否する一方で、PER 0 は 65536 として受け付けています。
- PER=0 と LEN=0 を 65536 とみなす動きは、どちらも実機の挙動として確認していません（未検証のクセ）。
- 案：外部 write は PER 0〜123 をまとめて -21 で拒否する。LEN=0 は「65536 と宣言」か「拒否」のどちらかに決める。推奨は宣言のままとし、未検証であることを明記する。
- 変調で PER 0 が来たときの扱いは、外部 write とは分けて宣言する。

**M4. manual モードが HRM の記述とずれている可能性がある**
- 記憶では、HRM は「DAT の word が出力側に取り込まれた時点で IRQ が立つ」（double buffer 型）と書いています（※推測です。写しとの照合が必要です）。
- 設計案は「2PER 後に IRQ」かつ「上書きすると再開始」なので、CPU が隙間なく word をつないで鳴らすことができません。
- 案：1-word latch にする。
  - 停止中に DAT を書いたら、次 tick で取り込んで IRQ を立てる。
  - 再生中に書いたら latch に入れ、今の word が終わった時点で取り込んで IRQ を立てる。
- 実機の pipeline を再現するとは主張しない、という但し書きはそのまま残す。

**M5. 変調の境界条件が決まっていない**
決めておくべき点は次の4つです。
- 交互（vol/per）の位相は、ブロックの先頭で volume に戻す。
- 変調された PER/VOL と、CPU が対象に write した値のどちらを使うか。推奨は「後に書いた方が有効」。
- attach を解除したあと、対象は最後に変調された値を保持する。
- 変調元のチャンネルは音は出さないが、DMA と IRQ は止まらない。

**M6. レジスタ write のエラー規則が足りない**
決めておくべき点は次の4つです。
- 読み取り専用アドレス（002/010/01C/01E）への write は -21。
- 値が 0〜65535 の範囲外なら -24。
- bit15 が 0 か 1 かに関係なく、許可マスク外の bit は -21。
- `0x8000` 単独（変更なし）は受け付ける。

**M7. RESET でクリアする範囲が決まっていない**
- 案：次をすべて初期化する。
  - queue
  - 全レジスタと内部カウンター
  - pending と mask
  - render の端数
  - 統計
- サンプルメモリだけは保持する。

## 区分の確認
- **メーカー資料に書かれている事実（HRM の写しで出典ページを示すべきもの）**：PAL クロック 3546895、0/3 が L・1/2 が R、レジスタのオフセット、DMACON/INTENA/INTREQ/ADKCON の bit 割り当て、VOL bit6 = 64、変調の vol/per 交互と ch3 は「対象なし」、IRQ が reload 時に立つという趣旨。
- **独自に宣言する近似**：fetch とバイト出力のタイミング、disable 後に DAC 値を保持、同じ tick の 0→3 の処理順、変調を word fetch 時にまとめて適用、point sampling で filter なし、19bit/512KiB。
- **未検証の実機のクセ**：LEN0/PER0 = 65536、短時間 disable の遅延、初回 discard、010/011 request の差。これらは「再現しない」と明記されている今の書き方でよいです。
