### 残っている問題（どれも中未満）

**R1【低〜中】WINDOW-ON で全画面に入り直したあと、`normal_placed=true` が残る（Bが1件だけ残っている）**
- **場所**：1236〜1244行で配置が終わり、全画面に入り直すとき、`normal_placed` が true のままです。1109行は `normal_rect != null` なので取り直しません。このため、次のふつうの解除（1084行）が、また配置済みとして扱われます（1207〜1222行で縮小と移動を送る）。
- **再現**：
  1. `1 WINDOW-ON TRUE FULLSCREEN SHOW`（または、全画面中に `1 WINDOW-ON`）。
  2. 全画面のまま、Mutter の Super+Shift+← で画面0へ移す。または、ここでモニタの構成を変える。
  3. Alt+Enter で解除する。
  - 推測：窓が画面1の古い座標へ引き戻されます。ゲームでよく使う「開くときに画面を指定して全画面」の経路で、最初の解除の1回だけ起きます。
- **理由**：全画面に入り直した時点で、WMは配置した位置を自分の通常の位置として覚えています（推測）。なので、そのあとの解除はWMに任せるべきです。
- **修正案**：1243行で全画面に入り直すとき、`self.normal_placed = false;` とします。今のテストは、移動を送っても送らなくても結果が同じなので、この問題を検出しません。

**R2【低】期限切れのとき、ほかの状態が古いまま残る**
- **場所1**：1072行の時点で、`normal_placed` が残ります。例えば、WINDOW-ON のための解除（1377行）をWMが1秒以上無視すると、`on=true` のまま、`normal_rect` は配置先、`normal_placed=true` になります。あとでふつうに解除したとき、古い配置先へ移動します。
  - **修正案**：期限切れの分岐で `self.normal_placed = false;` とします。
- **場所2**：1070行の `if (!fullscreen_dirty)` は、1048行ですでに消した後の値を見ています。そのため、同じ回に Forth から来た FULLSCREEN の要求を上書きします。
  - **修正案**：1075行と同じように、`!modes_dirty and !fullscreen_dirty` とします。
  - 起きるのは2ms程度の間だけです。

**R3【低】遷移中にフレームの大きさが変わると、全画面が勝手に解ける**
