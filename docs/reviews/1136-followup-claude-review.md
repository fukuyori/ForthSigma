## Medium（未解決）

**N1. 3声が同じ周波数で、3声とも SYNC が立っているため、SYNC/RING とパルスが働いていない**（`verify-sid.py:212-216`）

- **原因:** heavy では、3声とも FREQ=$FFFF（`base`、`base+1` に 255）です。制御値は 131、23、67 で、どれも SYNC（bit1）が立っています。開始時は3声とも位相が0なので、MSB の立上りが3声で同じ clock に起き、`SI-PHASES` の2つ目のループ（`sid.fs:73-75`）が3声とも位相を0に戻します。
- **手計算の結果:** 位相は 0 から 2^23 未満の範囲だけを回り、bit23 は一度も1のまま残りません。2^23/65535 ≈ 128 clock ごとに0へ戻ります。その結果、次のようになります。
  - **声2のパルス:** 上位12bit は最大 2047 で、PW の 2048 に届かないので、出力は常に 0 です。gate が入っている間は (0−2048)·env/255 の直流になります。
  - **声1の RING:** 声0の MSB が常に0なので XOR が効かず、三角波は折り返さない上り傾斜だけになります。
  - **ノイズ:** bit19 は立ち上がるので動きます。
  - **8kHz の負荷:** D400 の書込みで声0の周波数が変わるので、この状態にはなりません。
- **影響:** 計算量は、bit19 によって約8 clock ごとに区間が切れることで決まるので、測定の重さはほぼ変わりません（※推測です）。一方で、M1 の対応で書いた「SYNC/RING/noise 混在」と「PW=2048」は、PCM 全体の照合でも実際には試されていません。このままでは、結果の記録が実際の負荷の中身と合わなくなります。
- **再現例（未実行。期待値は手計算）:** heavy の cycle0 の行を予定表に入れて `0 SI-RUN` を実行します。次に `: CHK 0 20000 0 DO 1 SI-RUN 0 0 SI@ 1 0 SI@ OR 2 0 SI@ OR 8388608 AND OR LOOP . ; CHK` を実行すると、`0` になるはずです。
- **修正案:** 3声の周波数を変えます（例：$FFFF、$7FFF、$5555 のように、比が整数にならない値）。または、SYNC を一部の声だけにします。どちらの場合も、PCM 全体の照合はそのまま使えます。
