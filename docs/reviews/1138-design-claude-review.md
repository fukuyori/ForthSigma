## 1. native の固定音量0がindex 1になる件と、修正案

**【事実】**
- `src/core/sound_psg.zig:173` は固定音量Lを `L*2+1` に変換します。そのためYMで固定0を指定すると `ym_levels[1]` = 10^(-2.25) ≈ 0.00562 になります（`:35` から計算）。
- AY側は `ay_levels[1>>1]` = `ay_levels[0]` = 0 です。モデルによって扱いが食い違っています。
- このため ST の初期状態では音量0でも非0の出力が出ます。
  - ST の初期化では `msxInitialRegisters`（`src/core/sound_engine.zig:211-216`）により R7=0xb8 でトーンが3声とも有効、R0=0x55 になります（適用箇所は `:494`）。
  - チャンネルAは 2MHz/(16×85) ≈ 1470.6Hz の矩形波で、振幅は約0.00562/3 です。
  - チャンネルB/Cは周期0、つまり1扱いのため、毎ステップ反転します。平均すると直流成分に小さなリップルが乗ります。
  - いずれも計算による結果で、実行して確かめてはいません。
- MMLの休符・停止は `sound_engine.zig:559` で音量0を書きます。そのためSTでは休符でも完全な無音になりません。
- 既存テスト `src/tests/sound_test.zig:109-137` はAYの音量0とYMの15/14の比しか確かめていません。YMの音量0の値に依存するテストや固定PCMとの照合は、`src/tests` を検索した範囲では見つかりませんでした。

**修正案の評価（Medium）**: 修正すること自体は妥当です。ただし根拠は次の2点に限ります。
- AYの経路と揃えること
- MMLで音量0を「停止」に使っている、という内部の約束

実機の0レベルの電圧は根拠にしません。

推奨する実装:
- `:173` の固定音量の分岐を `if (L == 0) 0 else L*2+1` に変えます。
- `>>1` してもAYの値は変わりません。モデルを問わない1行の変更で済みます。
- 合わせて `:172` のコメントと `:29-30` の説明（「固定0は無音とする宣言」）を英日両方のdocsで更新します。

推奨する回帰テスト:
- YMの3声それぞれについて、R7=0xff（tone/noise とも off）とトーン有効の両方で、`tone_high` が true/false のどちらでも `channelLevel` が0になること。
- 変えていない部分の確認として、YMの固定1が `ym_levels[3]` のままであること、エンベロープのlevel 1が `ym_levels[1]`、level 0が0のままであること、AYの固定0が0のままであること。
- エンジン単位で、ST選択後に音量がすべて0のまま `sample()` をN回呼び、すべて完全に0になること。これは今回の症状そのものを確かめる試験です。

## 2. Forthモデルの宣言

**【High】3声の合成式が決まっていません。**
- 1声あたりのテーブルは0..32767です。3声をそのまま足すと最大98301になり、s16の範囲を超えます。
- 推奨: 出力 = floor((a+b+c)/3) と宣言する。native の `/3`（`:182`）とも揃います。
- Python参照実装とも、この整数式で完全一致を判定します。

**【Medium】同じtickの順序と、点標本を取る時刻が決まっていません。**
推奨する定義:
- tick はマスタークロックの1周期とする。
- `YM-RESET` で tick=0、分周の位相を0にする。
- 内部ステップkは tick 8k（k≥1）に起きる。
- 同じtick tでは、ステップ → queue（追加順）→ 即時の write/read の順に処理する。
- サンプルnの時刻は t_n = floor(n·2000000/48000) とし、t_n 以下の処理をすべて終えた状態を標本にする。
- 過去のtick（現在時刻より前）は -24、同じtickは即時処理とする。`YM-TO`/`YM-RUN` に過去を指定した場合も -24 とする。

**【Medium】「全regをraw 8bitで読み戻す」とI/Oの規則がぶつかります。**
- R14/R15 は例外として、入力モードならpinの値、出力モードなら latch AND pin を返す、と明記してください。

**【Low】リセット直後の値が native と違います。**
- Forthはレジスタを全部0にし、nativeのSTは R7=0xb8 などMSXの初期値を入れます（`sound_engine.zig:494`）。
- nativeと比べる試験では、レジスタをすべて明示的に書いてください。

**整合している点【事実：nativeと一致】**
- 周期0を1として扱う（`:122`, `:136`, `:145`）。
- R13を書くとエンベロープが初めからやり直しになる（`:96`, `:104-118`）。
- 周期を変えてもカウンタはリセットせず、周期を短くしてカウンタが越えた場合は次のステップで発火する（`:128-131`）。
- ミキサーで tone/noise を両方 off にすると、音量がそのまま直流として出る（`:169`）。

**【宣言として扱う】**
- LFSR 17bit、tap bit0^bit3。出典はデータシートで追えていません。「nativeの既存モデルを採用した」とだけ書き、実機と同じとは書かないでください。
- 音量表を理想的な1.5dB刻みとすること。
- 固定0を0とすること。
- 未使用bitの読み戻し値。

**【Low】noiseの位相を書いておくと、参照実装とずれにくくなります。**
- `noise_half` は false から始まり、1, 3, 5…番目のステップで数えます（`:134-135`）。

## 3. ステップをまとめて進める処理（fast）

**【Medium】まとめて進める幅を次のように決めてください。**
- 次の境界までの数を `remaining = count >= period ? 1 : period - count` で求めます。nativeの「1足してから比べる」と同じ意味になります。
- まとめる上限は次のうち最小のステップ数です。
  - 3声のトーン
  - noise（奇数ステップの位相 ×残りのカウント）
  - エンベロープ（保持中は除く）
  - 次のqueueの時刻
  - 次のサンプル時刻
- 周期が変わるのは書き込みのときだけです。上限がqueue境界を含むので、この方法で正しく進められます。

**【宣言】**
- 点標本なので、周期1のような高い音は折り返し雑音（エイリアシング）が出ます。
- 「全period 1」の測定でこれが出ても、不具合ではなく仕様どおりだと記録してください。
- 平均化するnativeとForthのPCMは一致しません。Forthの受け入れ判定は、Python参照実装と手計算との一致だけで行います。

## 4. エンベロープ16形状・I/O・バスの選択

- **【事実】** nativeの16形状を追ってみました。形状0-7は最後に0、11は31で保持、13は31で保持、15は0で保持、8/10/12/14は繰り返しです（`:105-118`, `:144-156`）。Forthの参照としてそのまま使えます。
- **【Medium】** バスの「最後に有効だった選択regを保持する」は使い道が決まっていません。
  - 上位nibbleが非0のときは非選択で、読むとFF、書いても無視されます。この規則と並べると、保持した値をどこで使うのかがわかりません。
  - 推奨: 状態は select の生バイト1つだけにし、選択中のregは `raw < 16 ? raw : none` で求める。「最後の有効値」は削る。
  - queueの data(19) は、追加したときではなく適用するときの select に従う、と明記してください。
- **【未確認】** 次の2点は宣言のままにしてください。
  - 上位nibbleで選択を判定する規則が YM2149 の資料にあるかどうか。
  - FF8800/FF8802 の番地と、FF8802 を読んだときの値（設計の -21）。設計にも「未照合なら宣言」と書かれています。
- **【Low】** `YM-PORT@` の value が決まっていません。推奨は「常にlatchを返し、mask を 0/FF で返す」です。入力モードでもlatchを保持する、という設計とも揃います。
- **【Low】** `BUS-EVENT!` は他の語と揃えて `YM-BUS-EVENT!` にしてはどうでしょうか。

## 5. エラー時に状態を変えないこと

- 方針（不正を -24/-21 で、時刻や状態を変える前に拒否する）は妥当です。
- 推奨する処理の順:
  1. 引数すべての範囲（reg/値/port/address/tick ≥ 現在時刻）を確かめる
  2. queueの空きを確かめる（-528）
  3. 時刻を進める
  4. 状態を変える
- `YM-RENDER` も、バッファと個数を確かめてから時刻を進めてください。
- **【未確認】** -528 という番号の割り当て根拠と、cellの幅（tickのオーバーフロー余裕）は確認していません。

**結論**: 実装前に決める必要があるのは次の3点です。
1. 合成式（High）
2. tickと標本の順序
3. R14/R15 の読み戻しとバス選択の状態定義
