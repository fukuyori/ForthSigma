## 資料の扱いの前提

`SOUND_RESEARCH.md` の記録では、DS（データシート）が出典なのは主に次の3つです。
- レジスタの配置と Fout の式（`:215-242`）
- ADSR の ms の表（`:258`、出典は複数を併記）
- 合成波形を「論理 AND」とする記述（`:252`）

次の値はすべて [R-WAVE]/[R-ENV]（reSID 系の資料）が出典で、DS の記載ではありません（`:244-251, 256-280`）。
- ノイズのクロックを bit19 で取ること、TEST を戻したときの LFSR の値 0x7FFFF8
- ハードシンクを MSB の立上りで行うこと、リングを MSB の XOR で行うこと
- 周期の表 9..31251、指数近似の分周 1/2/4/8/16/30
- 15ビットのレートカウンター

方針は次のとおりです。
- Oxyron で確認できた項目だけ「資料の値」と書きます。
- 確認できない項目は「決定的近似（実機の値とは主張しない）」と書きます。

## High

**H1. 実機の癖を事実として書かない**
上に挙げた値は、PDF と Oxyron を読んで照合するまで「二次資料の報告値を、この模型の定数として宣言したもの」と書きます。
- 照合の手順は「DS の PDF（取得元と SHA256 を記録）→ Oxyron」とし、項目ごとに「DS／Oxyron／宣言値」のどれに当たるかを表に記録します。
- 9..31251 の表は、DS の ms の表との整合を試験で確かめられます（周期×255÷1MHz を各 ms と比べる。例：31251×255 ≈ 7.97 s に対して DS は 8 s）。ただしこの試験は整合を示すだけで、実機の値の証明にはなりません。

**H2. ノイズの出力ビットは Oxyron 側（20,18,14,11,9,5,2,0）を推奨**
理由は次の3つです。
- 利用者が指定した資料が Oxyron であること。
- 既存の `sound_c64.zig:195` と同じであること。
- 左シフトの LFSR では bit k(t) = bit k−2(t−2) なので、2つの資料のビット番号の違いは「ノイズの2クロック分の遅れ」にあたります。リセットや TEST を戻した直後の最初の数個を除けば、同じ列になります（※ここまでは導出で、どちらが実機に合うかは未確認です）。

この違いが影響するのは、byte 単位で照合する試験と、TEST を戻した直後だけです。定数の表は1か所にまとめ、入れ替えやすくしておきます。

ノイズのクロックは bit19 を推奨します。既存のコードの「16 shifts/cycle」は bit19 と一致します（bit20 では8回になります）。ただし bit19 の根拠は [R-WAVE] だけなので、宣言値として扱います。

**H3. 合成波形の -21 は受付時に検査する**
- 拒否の条件：CONTROL の bit4..7 のうち2つ以上が立っている値。
- 検査は `SID-WRITE` と予定表への登録の時点で、状態・時刻・予定表を変える前に行います。描画の途中では失敗しないようにするためです。
- 波形をどれも選んでいない場合、波形の値は 0x000 と宣言します（実機で値が減衰していく挙動は扱いません）。
- 実際の曲でよく使う $51/$61 などは拒否されることを、文書に明記します。

**H4. 1サイクル内の処理順を固定する**
この順序が決まっていないと、Python と Forth の結果が一致しても意味がありません。次の順序を宣言します。
1. tick N の後、N+1 の前に、時刻 N の予定書込みを適用する（NES と同じ）。
2. 全ボイスについて、TEST=0 なら acc に FREQ を加える（24ビットで折り返す）。同期を掛ける前の値から、MSB の立上りのベクトル r と bit19 の立上りのベクトル n を作る。
3. SYNC=1 かつ r[src] なら acc を 0 にする。r は同期前の値なので、全ボイスに同時に適用する。0 に戻ったことは立上りとして数えない。
4. n[v] なら LFSR を1回 shift する。そのボイス自身が同じサイクルに同期で 0 に戻っていても shift する。TEST の間は LFSR を 0x7FFFF8 に保つ。
5. 各ボイスのレートカウンターを +1 する（15ビットで折り返す）。値が周期と一致したら 0 に戻し、エンベロープを進める。
6. 出力は、区間の最後の tick の後の値を点標本として取る。波形は同期後の acc から作る。リングは相手（src）の同期後の MSB と XOR する（TRI を選んだときだけ）。

PW の比較の向きは、DS の式「デューティ = PW/40.95%」から「上位12ビット < PW なら全1」とします（導出で、極性は未確認）。TEST の間のパルスの値は 0xFFF とし、宣言値として扱います。

**H5. 指数近似の分周を、レベルの関数にするか、通過点で切り替える状態にするか**
アタックの途中で gate を切ると、2つの方式で結果が変わります。例：レベル150でリリースに入ると、レベルの関数なら分周は 1、通過点の状態なら 2 です。資料の書き方（「93 で2」）に合わせて、通過点で切り替える状態の方式を宣言し、この場合を試験に入れることを推奨します。

ほかに次の点も宣言します。
- サステインを現在のレベルより上げても、レベルは上がらない。
- 0 に達したら、次のアタックまで止まる。
- 周期を短くしてカウンターが周期を越えている場合は、0x7FFF の次に 0 へ戻るまで数える（ADSR バグ）。これは報告されている挙動で、実機で確認した値ではありません。

## Medium

1. **読み取り:** OSC3 は、ボイス3の12ビットの波形出力（リングの効果を含む）の上位8ビットにします。ENV3 はボイス3のエンベロープの値です。POT は、固定値 255 を返すとパドル未接続の値を作り出すことになるため、**-21 を推奨**します。書込み専用のレジスタの読み取りも -21 にします。
2. **D419..D41F への書込みは -24 を推奨:** DS は「読み取り専用」と書いているだけで、書込みを無視するとは書いていません。そのため、ここは資料から決められない API の決定です。Forth から呼ぶので、書込みを黙って無視すると呼出し側の誤りが隠れます。
3. **API は NES の契約をそのまま使う:**
   - `SID-WRITE ( value addr cycle -- )` と `SID-EVENT!` の2本にする。
   - 予定表は時刻順の追加だけを受け付ける（時刻が戻る登録は -24。挿入ソートはしない）。
   - 予定表の未処理は1024件まで。満杯は -528。処理済みの領域は回収して使い回す。
4. **PAL のクロック:** 985248 = 20×48000 + 25248 なので、1標本ごとに整数商 20 と端数 25248/48000 を引き継ぎます。実際の 985248.6 Hz との差（約 0.6 ppm）は宣言値として扱います。
5. **折り返し雑音:** 出力は点標本で、帯域制限をしません。既存の MML 用 `sound_c64.zig`（polyBLEP あり）より折り返し雑音が大きくなることを明記します。
6. **DC オフセットは扱わない:** $D418 を書き換えるデジ再生は無音になります。6581 の代表的な手法なので、制限として書きます。
7. **フィルターの代わりの模型（proxy）:**
   - 標本の領域で処理するので、per-cycle の reference 版と fast 版の一致試験からは外れます。両版で同じコードを使います。
   - 係数 F[FC] = round(2·sin(π·(30+5.8·FC)/96000)·65536) の2048項目。FC0 は約129、FC2047 は約4.98万です。
   - 減衰 D[res] = round((1.414−0.08·res)·65536)。res0 は 92668、res15 は 14025 です。
   - 1回のステップ：`hp=in−lp−(D·bp)>>16; bp+=(F·hp)>>16; lp+=(F·bp)>>16`。bp と lp は ±2^23 で clamp します。2ステップの間、入力は同じ値に保ちます。
   - **右シフトは負の値で floor にする必要があります。** RSHIFT は論理シフトで、`/` の丸めの向きは実装依存なので、FM/MOD などで floor を明示します。
   - Forth の FSIN と Python の sin で、2048項目すべてが一致するかを試験します。一致しなければ表を定数として埋め込みます。
   - mode=0 のとき、フィルターに送ったボイスは 0 にします。既存の `sound_c64.zig:155` は通過させるので、動作の違いを明記します。
   - EXT（bit3）は入力 0 として無視します。
   - 3OFF は、ボイス3を直接の経路から外すだけとします（DS の記述は要確認）。
   - 混合は `clamp(floor((direct+filt)·VOL/(15·64)), ±32767)` です。入力は最大でも約 ±1.57M（2^21）なので、64bit で溢れません。
   - 6581/8580 のフィルターとは主張しません。測るのは、この proxy の Forth での処理時間だけです。
8. **最悪の負荷:** 次の条件をすべて含めます。
   - 3声とも rate 0（9サイクルごとのイベント）で、gate を繰り返し入り切りする。
   - ノイズを FREQ=FFFF で鳴らす（16サイクルごとに shift）。
   - sync と ring を3声の輪でつなぐ。
   - フィルターは FC=2047・res15・LP|BP|HP で、3声すべてを通す。
   - 8kHz の時刻指定書込み（予定表の回収を含む）。

   fast 版は、LFSR の状態を保つため、ノイズを選んでいないボイスでも bit19 の立上りの位置で区間を区切ります。
9. **手計算の照合値の例（上の処理順を前提にした導出で、未実行）:**
   - FREQ=$8000 なら、MSB の最初の立上りは tick 256、その後は512ごと。bit19 の立上りは tick 16, 48, …。
   - cycle0 でカウンター0のまま gate を入れ、attack0 とすると、最初の step は tick 9、レベル255 は tick 2295。

## タスクの分割（推奨）

1136 を次の2つに分け、両方を 1140 の依存に加えます。
- **1136a：デジタルの中核**
  - 資料の照合表
  - 発振器・エンベロープ・TEST・リング・シンク
  - 予定表と読み取り
  - 48k の描画、reference 版と fast 版、Python の per-cycle モデル
- **1136b：フィルターの代わりの模型、混合、最悪負荷の測定、採否**

レジスタ対応部分を先に固めることで、フィルターの数値の決定が H1〜H5 の照合を遅らせないようにするためです。
