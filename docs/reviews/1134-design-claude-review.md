# 1134 提案レビュー: Forth で書く NES APU（NTSC、4声）の仕様と、実測結果をどう判断するか

**前提**
- 読んだのはリポジトリ内の文書だけです（`docs/PCM_SYNTH_PROTOTYPE.md`、`src/core/defs.zig:1204` のエラーコード表など）。
- NESdev のページは今回開いていません。下の NES の挙動は私の知識によるもので、**親が NESdev で確かめる必要があります（未確認）**。
- テストは実行しておらず、何も確かめていません。任天堂の公式な裏付けもありません。

## High

**H1. 書込みの時刻と時間を進める語の関係が決まっていない**
- `NA-WRITE` が指定した時刻まで APU を自分で進めると、その間の音が出力されずに消えます。
- 提案: 書込みは待ち行列に入れるだけにします。時間は `NA-RUN` と `NA-RENDER` だけが進め、その中で各書込みを指定した時刻に反映します。
  - 受け付ける時刻の条件: 現在の時刻以上、かつ直前に受け付けた書込みの時刻以上。同じ時刻は受け付けた順に反映します。
  - 規則「時刻 N の書込みは、tick N の後、tick N+1 の前に反映する」はこの中で守ります。
- 待ち行列の容量と、満杯のときに返すエラーコードを決める必要があります。案は既存の -257 です。

**H2. 状態と IRQ を読む語がない**
- $4015 の状態と frame IRQ を仕様に入れても、今の公開 API ではどれも読めません。
- 追加する語の案:

| 語 | 内容 |
| --- | --- |
| `NA-STATUS ( -- u )` | 現在の時刻で読む。frame IRQ を消す。DMC のビット（4 と 7）は常に 0 |
| `NA-IRQ? ( -- flag )` | 読むだけで IRQ を消さない |
| `NA-CYCLE ( -- n )` | 現在の CPU サイクル |
| `NA-RESET ( -- )` | 決まった初期状態に戻す |

- 初期状態の案: レジスタと長さカウンターはすべて 0、LFSR は 1、サイクル 0 は偶数（APU サイクルの中）。これに加えて「サイクル 0 で $4017 に $00 を書いた扱い」にするかどうかを決める必要があります。
- フレームの途中で状態を読むには、そこまで描画しておく必要があります。CPU エミュレータとの同期は範囲外と明記します。

**H3. 実測が実時間を下回ったときの判断の順序（質問への回答）**
- **推奨は、本体への移行の前にイベント単位のまとめ処理を試すことです。**
- 根拠:
  - 1 標本あたり約 37.3 CPU サイクルあります。1131 の単純な4声合成は 1 標本あたり 497〜616 ns でした。
  - 1 サイクルずつ進める基準実装は、実時間を下回る見込みです（※推測です）。
  - その差はアルゴリズムで減らせます。本体へ移しても、結局まとめ処理は必要になります（※推測です）。
- 進め方:
  1. 1 サイクルずつ進める Forth 実装を基準として残します。
  2. まとめ処理は、すべての試験パターンと分割の仕方で基準と**出力がバイト単位で一致した**場合だけ採用します。一致しなければ採用しません。
  3. 本体への移行は、まとめ処理でも実時間を下回る場合に限って検討します。
- 判定のしきい値は、測る前に決めておきます。
- ベンチマークの条件:
  - 4声すべてと、時刻を指定した書込みを含めます。書込みの頻度は事前に決めます。
  - 1 CPU サイクルあたりの ns と、1,789,773 に対する倍率の両方を記録します。
- 時間の測定は、利用者に確認してから行います。

## Medium

**M1. ノイズのタイマーを数える単位**
- NESdev では、三角波以外のタイマーは APU サイクル（CPU 2サイクル）ごとに進むとされています（※要確認）。
- CPU サイクルごとに周期表の値を数えても周期は同じです。ただし、再装填が奇数サイクルに起こり得るため、$400E を書いた後の位相がずれます。
- 案: 偶数サイクルに「周期表の値 ÷ 2」を数えます。今の決定のままにする場合は、差分として明記します。

**M2. ミキサー**
- DMC の出力が常に 0 なので、三角波とノイズの組み合わせ 16×16 の厳密な表（256要素）が作れます。近似の `3t+2n` は使いません。
- 公式の定数を有理数のまま使い、整数だけで表を作れます。
  - 矩形波: `9588·p / (100·(8128+100p))`
  - 三角波とノイズ: `S = 12241·t + 8227·n`、`D = 8227·12241` として `15979·S / (100·(D+100·S))`
- 決めること:
  - 丸め方（切り捨てか、四捨五入か）
  - s16 への変換。案は `floor(level·32767)` で、出力は 0 以上になります。直流分を除かないことを明記します。
- 4声の生の値は、試験パターン用の内部の語として出します。

**M3. $4017 書込みの遅延**
- 「偶数サイクルで3、奇数で4」は、CPU と APU の位相を固定するという取り決めとして記録します。実機ではこの位相が一定でない可能性があります（※推測です）。
- mode1 で四分フレームと半フレームの処理をすぐ行うのは、遅延が終わってリセットが効いた時点です（※要確認）。
- 遅延したリセットとフレームの段が同じサイクルに重なったとき、どちらを先に処理するかを決める必要があります。
- IRQ 禁止のビットを立てたときに IRQ フラグを消すのは、遅延なしでその場で行います。

**M4. スイープ**
- タイマーが 8 未満、または目標の周期が $7FF を超えるとき、スイープが無効でも矩形波を消音します。
- 減算: 矩形波1は1の補数、矩形波2は2の補数です。
- $4001 を書くと再装填フラグを立てます。
- $4003/$4007 を書くと、シーケンサーの位相を戻し、エンベロープを開始し、長さカウンターを再装填します。タイマーの分周は戻しません。

**M5. 三角波**
- 周期 0 と 1 でも段を進め、消音しません。帯域制限がないため折り返し雑音が出ることを明記します。
- 次を決める必要があります:
  - 初期の段
  - 線形カウンター: 再装填フラグを消す条件（control ビットが 0 のとき）

**M6. 長さカウンター**
- $4015 でチャンネルを止めると、長さカウンターをその場で 0 にします。
- チャンネルが止まっている間の $4003/$4007/$400B/$400F 書込みでは、長さカウンターを装填しません。
- 停止フラグは、エンベロープのループのビット（三角波では control ビット）と共通です。

**M7. 入力の検査の順序と、エラーで状態を変えないこと**
- 検査の順:

| 順 | 検査 | 失敗のとき |
| --- | --- | --- |
| 1 | スタックの深さ | -4 |
| 2 | value が 0..255 か | -24 |
| 3 | address の範囲 | -24 |
| 4 | cycle が負でなく、時刻の順を守っているか | -24 |
| 5 | DMC の書込み | -21 |

- DMC の書込みとは、$4010〜$4013 への書込みと、$4015 のビット4を 1 にする書込みです。
- それ以外のアドレス:
  - $4009 と $400D: 受け付けて何もしません。
  - $4014、$4016、$4018 以上: -24 で拒否します。
- どの検査で失敗しても、状態を一切変えずに拒否します。
- $4015 のビット 5〜7 は無視します。

**M8. 描画の標本化**
- 各標本の区間は、累積の境界 `floor((k+1)·1789773/48000)` で決めます。
- 標本の値は、その区間の最後の tick の後の状態から取ります（点標本化）。区間の平均は取りません。
- 端数は `NA-RENDER` を何回呼んでも引き継ぎます。`NA-RUN` は端数を変えません。
- まとめて1回で描画しても、何回かに分けて描画しても同じ出力になることを試験に入れます。
- frames が負なら -24、0 ならメモリに触れません。
