# Linux物理ホットプラグ検証スクリプトの静的レビュー（tque1336/1345）

対象は `.work/1037/hotplug-review/verify-linux-display-hotplug.py` です。依存として `linux_x11_test_support.py`、`linux_x11_probe.py`、`graphics.fs` の語定義、設計文書を読みました。ファイルの編集やコマンドの実行はしていません。

**結論：** 物理操作がなくても合格になる経路はありません。ただし、合格・incomplete の判定を誤りうる点と、証跡の記録の誤りがあり、中程度の問題が6件あります。

## 中程度の問題

### M1. 製品の不具合が `incomplete` として記録される（行206, 245）【コードから確実】
- `wait_for` の時間切れは `TimeoutError` です。`session.line()` がSigmaの無応答で出す例外も、`Connection.read` / `send` の5秒期限切れも `TimeoutError` です。Python 3.10以降は `socket.timeout` も `TimeoutError` の別名です。そのため、Sigmaが固まった場合も `incomplete` になります。
- 次の待ちは利用者の操作を待つものではなく、Sigmaの振る舞いを見るものです。ここで時間切れになっても `incomplete` として扱われます。
  - `missing-preference-opens-on-remaining-monitor`（10秒）
  - `explicit-selection-after-reconnect`（8秒）
  - DRM上はすでに切断されているのにSigmaの状態が条件を満たさない場合（例：窓が残りの画面へ移らない）の `physically-disconnected-live`
- **修正案：**
  - 専用の例外（例：`class PhaseTimeout(Exception)`）を作り、`incomplete` はそれと `KeyboardInterrupt` / シグナルだけにします。
  - `wait_for` を「ハードウェアの条件」と「Sigmaの条件」に分けます。時間切れのときにハードウェアの条件が満たされていれば、その時点の状態を添えて `AssertionError`（`fail`）にします。

### M2. 「再接続しても窓が戻らない」の観察が短すぎ、見逃しによる誤合格がありうる（行229〜235）【観察時間が短いのはコードから確実、遅れた移動が起きるかは推測】
- 再接続の条件を3回続けて満たした最初の行だけで判定し、すぐに `t` で `WINDOW-ON` を送っています。観察するのは約1.2秒と取得にかかる時間だけです。
- Sigma、ウィンドウマネージャー（mutterなどの画面を覚える機能）、デスクトップの構成の再適用が数秒後に窓を戻した場合、それを見逃して合格になります。
- **修正案：** 再接続の条件が成り立ったあと、決めた時間（例：10秒）サンプルを続けます。その間ずっと `display` が副画面にならないことを確かめてから `WINDOW-ON` を送ります。この保持の段階も `phases` に記録します。

### M3. 再接続の判定で `display == -1` を除外していない（行229〜233）【コードから確実、起きる可能性は低い】
- 窓がどの画面にも重ならない場合、Sigmaとscriptの計算はどちらも -1 になり、`consistent` は真のままです。条件に `display >= 0` がありません。
- このとき `raw_monitors[-1]` は Python の負の添字なので、最後の画面を指します。DP-3 が先頭なら、窓がどこにもないまま合格する可能性があります。
- **修正案：**
  - 条件に `r['sigma']['display'] >= 0` を加えます。
  - 判定を `current == reopened` のときの画面名（主画面の名前）に変え、`!=` は使わないようにします。

### M4. `areas` の上書きで `raw_work_areas` の証跡が壊れる（行169, 184, 190）【コードから確実】
- 窓が開いているサンプルでは、`raw_work_areas` に作業領域ではなく窓と各画面の重なりの面積が記録されます。
- 照合は上書きの前に済んでいるので判定には影響しません。ただし記録した証跡は誤りです。
- **修正案：** 184行の変数名を `overlaps` に変えます。

### M5. DRMの `disconnected` だけでは「ケーブルを抜いた」と言い切れない（行220, 219）【一部確実、一部推測】
- 【確実】切断の条件は `status` しか見ていません。EDIDが消えたことは確かめていません。
- 【推測・機種依存】DisplayPortのモニターは、電源を切ったり深いスリープに入ったりするとHPDを落とし、`disconnected` になることがよくあります。
- 【カーネルの仕様として確実だと考えていますが、このリポジトリでは確かめていません】`/sys/class/drm/*/status` にはrootが `off` を書いて強制的に切断できます。
- docstringの「DRMの状態はソフトウェアによる無効化と区別できる」は、`xrandr --off` やデスクトップの設定との区別に限って正しい表現です。
- **修正案：**
  - 切断の条件に `edid_sha256 is None` を加えます。
  - report に `physical_evidence_limits`（電源断や強制切断とは区別できない）と、操作者が申告する欄を入れます。

### M6. `DISPLAYS` が0を返すと `0 DO` が誤動作する（Forthソース 行149）【Forthの意味としては確実、起きる可能性は推測】
- 設計文書（行298）によると、RandRの2秒の期限に間に合わないと `DISPLAYS` は0を返します。
- `0 0 DO` は1回目を実行するので、`0 DISPLAY-RECT` が -24 エラーになります。その後の出力とstdinの扱いは決まっていません。
- 結果は `fail` になり、誤合格にはなりません。ただしホットプラグの最中に一時的に起きると、検証全体がやり直しになります。
- **修正案：** `?DO` に変えます。

## 軽微な問題
- **行242：** `stdout.read()` はEOFまで期限なしで読みます。Sigmaの子孫プロセスがstdoutを持ち続けると、無期限に待ちます【推測：native窓で子プロセスがあるかは確認していません】。`select` で期限付きに読むか、`killpg` のあとに読むようにします。
- **report：** 失敗したときの `session.errors()`（Sigmaのstderr）を保存していません。証跡として加えるべきです。
- **再接続後の検査：** 主画面が以前と同じこと（名前とprimary）を確かめていません。
- **`WINDOW-ON` の結果：** 作業領域の中央に置かれたことと大きさが保たれたことは確かめておらず、画面の番号だけを見ています。
- **行238：** `status='pass'` を `finish` の前に入れています。except で上書きされるので害はありません。ただし、失敗したときに `physical_hotplug_tested=True` と `status=fail` が同時に記録されます。
- **画面名：** RandRの出力名とDRMのコネクタ名が同じであることを、名前の文字列だけで仮定しています。amdgpuのDDXやPRIMEでは名前が違うことがあります。その場合は `next()` が `StopIteration` を出して `fail` になるので、誤合格にはなりません。
- **preflight：** `t` の結果を確かめていません。今の画面と同じ番号なので、何も起きません。`preflight-pass` は物理検証の合格とは別の扱いなので問題ありません。
- **シグナル：** 片付けの途中で最初の SIGTERM が届くと `stop_process_group` が途中で止まり、子プロセスが残る可能性があります（非常にまれ）。

## 問題がないことをコードで確認した点
- **スタック効果：**
  - `FOUR` は x y w h の順に出力します。
  - `SNAP` の時点の `DEPTH` は1です（`CASE`/`ENDCASE` で選んだ値は消え、残るのは `DISPLAYS` の値だけ）。
  - `t` は `KEY [CHAR] 0 -` で番号を読みます。
  - scale と hz は分子、分母の順です。
  - 起動時の部分も DROP で釣り合っています。`GFX-INIT` だけは定義を確認していませんが、`DEPTH==1` のassertで検出できます。
- **X11の形式：** GetMonitors（1件24バイト、件数は応答の12バイト目）、GetAtomName、GetProperty（`_NET_WORKAREA` の位置は4×desktop）、TranslateCoordinates（12, 14）、GetGeometry（16, 18）、QueryTree の構造体はどれも正しいです。
- **座標：** 主画面を原点にする直し方と、主画面の印がないときに最初の画面を使う扱いは、Sigmaの設計と同じです。
- **期限：** どの待ちにも期限があります。1回のサンプルには最大で7秒と、X11の問い合わせ1回ごとに5秒かかります。
- **子プロセスの回収：** 例外のときも `SigmaSession.__exit__` で行われ、プロセスグループごと終了させます。
- **report：** statusの初期値は `incomplete` です。`physical_hotplug_tested` は非preflightで最後まで通ったときだけ真になります。report.json は finally で必ず書かれます。
- **誤合格の有無：** 物理操作をしなかった場合は、DRMの状態が `connected` のままなので合格しません。デスクトップの設定で画面を無効にした場合も同じです。

**優先度：** 物理検証と並行している今の実行で特に影響が大きいのは、M1（失敗が incomplete に分類される）、M2（戻りの見逃し）、M4（証跡の誤記録）です。今回の結果を読むときは、`raw_work_areas` は窓が開いている行では使えないことに注意してください。
