## 確認した内容(読んだコードの範囲)

- **部分書き込み・書き込み0・オフセット**: `ZX-PRIME-SEND` (`tests/audio/zx-spectrum-audio-play.fs:7-18`) のスタックの流れと集計は、`PS-SEND` (`tests/audio/pcm-synth-play.fs:18-29`) と同じ形です。frames を 512 固定から引数に変えただけで、途中までしか書けなかったときは `ZX-PRIME + PS-SENT*2` から再開します。残りがあるときだけ `PCM-WAIT` を呼び、待ちが失敗すれば -528 にしています。
- **バッファの大きさ**: 先行分は最大 `8*512 = 4096` フレーム = 8192 バイトで、`ZX-PRIME 8192 ALLOT` に収まります。無音のときの `FILL` は `initial*1024` バイトで、描画したバイト数と一致します。容量 4096 で開いた直後のリングにも、4096 フレームが入ります。
- **短い場合・0 ブロック**: 0 ブロックなら `initial=0` で、描画も書き込みもしません。1〜8 ブロックはすべて先行分として送り、9 ブロック以上は残りを 512 フレームずつ送ります。`?DO` の回数 `PS-BLOCKS - initial` は負になりません。
- **事前チェック**: OPEN の前に `blocks > ZX-MAX-FRAMES/512` を調べ、超えていれば -24 にします。このため OPEN した後の `ZX-RENDER` で -24 になることはありません。境界ちょうど(`prime-exact-clock-limit-success`)の期待値 `0 4096 0` も、計算すると合っています。
- **後始末とハンドルの扱い**: `PS-HANDLE` に値が入るのは OPEN が成功した後だけです。描画中や送信中に THROW(割り込みを含む)が起きても、`CATCH` から `PS-SAFE-CLEANUP` を経て閉じます。既存の `PS-STREAM` と同じく、最初に起きたエラーを優先します。
- **入力バッファの所有**: `Stream.write` (`src/core/sound_stream.zig:44-59`) は、戻る前にデータをリングへコピーします。このため `ZX-PRIME` と `PS-BUFFER` を使い回しても問題ありません。
- **アンダーランの数え方**: `sample()` (`sound_stream.zig:84-95`) は、`started` になるまでの無音をアンダーランとして数えません。OPEN から先行分の描画が終わるまでの無音は、数に入りません。
- **テストの期待値**: 5 ケース(mono / 48k / full-ring / prime+following / silent)について、モックの `PCM-WRITE`(5 → 0 → 残り)の動きから期待値を手で計算し、すべて一致しました。`MC-ADDR` は 8 セル分で、最大 4 回の書き込みに足ります。`MC-COPIED` は 12288 バイトで、最大 9216 バイトに足ります。1 ブロックで待ちが失敗するケース(`timeout-closes` など)は、新しい先行送信の経路を通ります。
