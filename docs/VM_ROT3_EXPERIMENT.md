# ROT/-ROT固定3セル化の予備評価（2026-11-16）

**最終判断：第1試作は不採用。本体は採用済み版を維持した。予備比較のWindowsスタック操作が両系列とも悪化上限を超えたため、残る候補比較を打ち切った。**

## 基準と変更範囲

tque #788の着手判断。基準VMは採用済みPC分離＋データ語経路分離のコミット`7b1295fc9c79d3d90db0a56d1408a68004c7b5b1`。不採用のCATCH試作やその追加テストは混ぜず、現行リポジトリから別の作業用コピー`.work/rot3-20261116/`を作った。

runtimeの意味を変える差分はsrc/core/words_stack.zigのROT/-ROT分岐のみ。zig fmtにより同ファイルのbuiltin列挙の空白整形も変わったが、順序は同じ。対象分岐を戻すとファイル全体が空白以外で一致することを照合した。requireDepth(3)と長さ3のsliceを維持し、汎用std.mem.rotateの代わりにセルを直接入れ替える。

| 語 | 変更前後で維持する並び |
| --- | --- |
| ROT | x1 x2 x3 → x2 x3 x1 |
| -ROT | x1 x2 x3 → x3 x1 x2 |

ROLL・2SWAPなど他のrotate利用、スタック容量、State/CallFrameの型、エラーの種類は変更しない。新たなヒープ割当ても追加しない。3セル未満の検査は書込みより前にあり、深さは変えない。

## 現行Linux生成物の計数

両版をLinux x86_64-musl、fast、baseline CPU、シンボルありでビルド。CallgrindでrunOperationsの外側ドライバーを収集し、100反復と200反復の差を100で割った。各関数の自己コスト合計が全体と一致することを確認した。下表はループ制御を含むカーネル1反復の計数で、ROT単体の命令数でも実CPU時間でもない。

| カーネル | Ir命令数 | Dr読込み | Dw書込み | 汎用rotate呼出し |
| --- | ---: | ---: | ---: | ---: |
| ROT | 132 → 55 | 27 → 19 | 11 → 4 | 1 → 0 |
| -ROT | 194 → 137 | 52 → 46 | 31 → 25 | 1 → 0 |
| 既存のスタック操作 | 326 → 249 | 81 → 73 | 33 → 26 | 1 → 0 |

ROTと既存スタック操作では、この計数範囲の反復当たり通常関数呼出しも1→0。-ROTにはbuiltinInLoop→executeBuiltinの既存呼出し経路が残り、すべての関数呼出しが消えたとは扱わない。counted経路やWindowsの生成コード計数へ一般化しない。

専用カーネルは1,2,3を回転させ、終了時に100×底＋10×中央＋上端を返す。100/200反復の期待値はROTが231/312、-ROTが312/231。各ネイティブ出力とCallgrind出力、DEPTH=0、後続計算42を照合した。単純な合計6だけでは順序誤りを検出できないため、最初の合計チェックサムから重み付きチェックサムへ強化し、両版を再計数して同じ差分を確認した。旧記録も作業用フォルダーへ残した。既存スタックカーネルの期待値は独立した3セル状態の式で照合する。

新テスト追加と書式整形後に同条件で再ビルドし、両版とも計数対象の実行体SHA-256が初回と一致した。さらに最終実行体で再計数した。[生成物・計数・ソース差分・コマンド](measurements/2026-11-16-rot3-preliminary.json)を参照。
