## 変更と結果の意味

レビュー済みPC分離候補に9行を追加し、`.constant`・`.array`と、DOES>なしの`.variable`・`.created`を、語の種類による既存のswitchへ入る前に処理する。語IDの検査、DOES>を持つ語のヘルパー経路、保存形式、VM命令、OS共通の実装方針は維持する。既存switchの処理は残した。

これは呼出し経路を変える介入であり、分岐予測などCPU内部の原因を特定した証拠ではない。コンパイラーが周辺のコード配置やレジスター割当も変え得るため、特定の機械命令だけの効果とも断定しない。

## 方法・再現用データ

同じWindows側Zig 0.17.0、fast・baseline CPU・stripでWindows GNU/Linux muslを作成。保存済み基準版と比較した。CPU0固定、ウォームアップ1回除外後5回の中央値。各回で順序を交替し、2系列目は初回順序を逆転した。WindowsはGetProcessTimes、Linuxはclock_getcpuclockid/clock_gettimeでREADYからDONEまでの子CPU時間を測り、起動とコンパイルを除外する。反復数は前調査のWindows条件を固定し、今回の採用用再校正は未実施。`cases-linux.json`内の校正サンプルも過去のWindows値の写しであり、Linuxで校正した値ではない。ビルド・テストと時間測定は重ねていない。

[生データとパッチ](measurements/2026-11-15-vm-data-call-route.json)に集計対象の全試行値、最小・最大、実行順、チェックサム、定義、実行体と入力のSHA-256、テスト記録、作成・測定スクリプトを保存した。作業用の実行体とログは`.work/vm-data-call-route-20261115/`にある。
