# 部分採用評価の継続方針（#880）

2026-11-17。[追補結果](VM_PARTIAL_ADOPTION_FOLLOWUP_RESULTS.md)の校正未達記録を点検し、利用者の承認を得て次の方針を決定した。**VALUEは採用保留のまま評価を終了する。セル型localは、校正未達の扱いを変えた新しい手順で標準32条件の評価を続ける。** 製品VMは変更していない。この文書の時点で新しい計時は開始していない。

これまでの校正は、Windowsが19回中2回未達、Linuxが18回中0回未達である。localの未評価はWindows・Linux各16条件。従来の「最初の未達で候補全体を停止し、再試行しない」規則では、Windowsの16条件を連続で通過する必要がある。標本が少ないため確率は確定できないが、同じ規則のままでは別の条件で停止して未評価が残る可能性が高いと判断した。

## 決定事項

### VALUE

採用保留のまま評価を終了する。実例4条件と標準34条件は測定しない。実例の効果がpinball資産生成（−3.4～−7.5%）とklondike render（−5.3～−7.0%）に限られ、残りの38条件を測る時間に見合わないためである。過去の専用ケースと実例の測定記録は保持する。

### セル型local

標準32条件（Windows LOOPを含む）の評価を続ける。実例18条件すべてで悪化上限を通過し、資産生成で−8.0～−12.2%の短縮を観測しているためである。

従来の手順から変更するのは、校正未達の扱いだけである。

1. 校正未達の条件は「保留」と記録し、候補全体は停止せず次の条件へ進む。
2. 一巡した後、保留の条件ごとに1回だけ再校正する。反復数N・CPU2・標本数（A/A各5標本×2系列）・上限（最大δ2%以下、全arm中央値5秒以上）は変えない。新しいpilotは行わない。
3. 再校正も未達の条件は「未評価」とし、それ以上は繰り返さない。
4. 全試行を保存する。未達だった1回目のA/A記録は別folderへ移し、上書きしない。

Windows LOOPは、前の手順での未達（最大δ2.192%）を1回目として数える。固定済みのN=890,434,783を使い、一巡後に1回だけ再校正する。

維持する条件は次のとおり。

- 採用には、標準の全条件が両OSで悪化上限を通過することが必要。未評価の条件が残れば追加採用は保留。
- 悪化上限：通常項目は`max(3%, 2δ_i)`、CATCH成功等5%、THROW系10%。両系列とも上限内であること。
- 比較は各7標本×2系列、warmup除外、先後交替・系列2反転。
- 比較が上限を超えた場合と、計時基盤の失敗では、その時点で全体を停止する。
- サイズ・安全性の条件、整数・LOOP各10%短縮の標準目標を達成扱いにしないこと。
- 過去系列との混合をしないこと、OS設定を変更しないこと、build/test/profileと計時を重ねないこと。

順序は、LOOP→stacks→calls→variables→plus-loop→extended→float→CATCH系9条件、各Windows→Linux。その後に保留条件の再校正を記録順に行う。
