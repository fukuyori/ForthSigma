# CATCH中間コピー削減のレビュー対応

2026-11-16。[レビュー原文](VM_CATCH_COPY_CLAUDE_REVIEW.md)への対応。

| 指摘 | 対応 |
| --- | --- |
| A1 古い現在状態 | 不採用・本体未反映、CATCH/Linux速度は未測定へ統一 |
| A2 コピー観測の限定 | 冒頭にもLinux fastのmemcpy＋memmove呼出し長の合計と明記。Windowsや総転送量の観測と扱わない |
| A3 残る32条件の表現 | 完了した比較はWindows2条件のみ。残る32条件は未完了で、calls片系列だけは実施済み・判定除外と明記 |
| A4 打切りと上限の出典 | 選定文書の第一候補の実施順・箇条6と、前回採用評価のmax(3%,2δ)へリンク |
| A5 基準と新テスト | 基準コピーは7b1295f＋新テスト1件。基準・候補共通のテストで、runtimeパッチとは別のnew_test_patchを公開したことを追記 |
| A6 CPU列の制御文字 | 指摘とは相違あり。開始時保存文書と現文書の該当セルはASCII 4（0x34）で制御文字なし。採用校正の実系列cpu_affinityも[4]。他33条件は[0]。値を改変しない |
| A7 基準側の捕捉範囲 | 表の基準・候補はいずれもmemcpy＋memmoveを捕捉した修正版の値と明記 |

寿命違反は今回の呼出し元には見つからなかった。将来のAPI再利用では、context/frameの同期利用と寿命の契約、pop済み継続スロットを参照しないことを明示する。今回はruntime候補を本体へ採用しない。

新テストは255バイトを比較するが、Temporaryで上書きする先頭9バイト以外は破壊していない。noname_nextも反転させていない。debug無効・最小構成ではkeep_countingの真偽にかかわらず非counted経路となる。これらを文書へ明記し、全域破壊からの復元や全構成で両ループを保証したという主張を取り下げた。今回の不採用を変更しないため、新テストの強化・本体への追加は行わない。再試行時は、全域を異なる値で上書きし、フラグ反転や入れ子・CATCH-NOBT等と組み合わせる検証を先に補う。

レビューは静的評価。Claude Codeのツール呼出しはRead 7回・Grep 4回で、明示されたアクセス先はいずれもリポジトリ内。テストやハッシュ計算の独立再実行とは扱わない。開始時の6入力ハッシュと対応するバイト列を作業フォルダーへ保存した。レビュー開始後、選定文書の先頭に結果を追記し、監査JSONには本体・実行体の不変照合を追加した。VMコード・測定値は変更せず、開始時スナップショットと実際の読取り記録を区別する。

不採用の確定に残る32条件の比較や悪化の原因特定は必須ではない、というレビュー判断を採用した。このCATCH案の再試行や、悪化原因を他の最適化判断に使う場合は、同じ条件のWindows生成コードを比較してから進める。次のROT/-ROTは独立した評価として扱う。
