# Windowsネイティブウィンドウの受け入れ確認（tque #1012）

2026-11-18。#909の共通契約（[決定事項のG3](DECISIONS.md)、[検討書の10.10節](NATIVE_WINDOW_STUDY.md)）へのWindowsの適合（#1006〜#1011、#1025、#1027）を、実機で確かめた記録。基準コミットは`a4addae`。

環境: Windows 11 Pro 10.0.26300、Zig 0.17.0、`zig build`（Debug）の`zig-out/bin/sigma.exe`。画面は4枚（主画面2560×1440、ほか1920×1080が2枚と1920×1280が1枚）。拡大率は、利用者が左の1920×1080（DISPLAY2）だけを150%（DPI 144）に変え、ほかは100%（DPI 96）。

## 確かめ方

Sigmaの外から、PowerShellのWin32呼出しでウィンドウを探し、`GetClientRect`・`GetWindowRect`・`GetDpiForWindow`で大きさとDPIを読んだ。画素は`PrintWindow`で取り込んだ画像を`GetPixel`で照合した。キーとマウスは`SendMessageW`（ウィンドウへのメッセージ）または`SendInput`（OSの入力）で送った。物理キーボード・物理マウスの操作ではない。

## フルスクリーンとMOUSE-CURSOR（#1016、#1019の一部）

2026-11-18、基準コミット`e181656`。

| 項目 | 操作 | 結果 | 判定 |
|---|---|---|---|
| フルスクリーンで開く | `SHOW` の前に `TRUE FULLSCREEN` | 枠なし（`WS_POPUP`）で主画面2560×1440を覆う | 合格 |
| フォーカス（端末が前面） | Sigmaを新しいコンソールで起動し、コンソールのタイトルバーをクリックして前面にしてから `TRUE FULLSCREEN` | 前面はSigmaのウィンドウ（`GetForegroundWindow`）、キーフォーカスもこのウィンドウ（`GetGUIThreadInfo`）。続けて送った `A` は `INKEY` に97で届いた | 合格 |
| フォーカス（ほかのアプリが前面） | Chromeが前面のまま `TRUE FULLSCREEN` | 前面はChromeのまま（Windowsが拒否） | 仕様どおり |
| Alt+Enterでの解除 | `WM_SYSKEYDOWN`（Alt付き）をウィンドウへ送る | 640×400のウィンドウへ戻り、`FULLSCREEN?` は0、`INKEY` には届かない。Alt無しのEnterと繰り返しでは解除しない | 合格 |
| `F`・`W`・`C`・`Q` | `tests/scripts/check-fullscreen.fs` に `WM_CHAR` を送る | 再びフルスクリーン、ウィンドウへ戻る、カーソル切替、終了 | 合格 |
| `MOUSE-CURSOR` | `FALSE MOUSE-CURSOR` の後、マウスを画像の上とタイトルバーの上へ | 画像の上では `GetCursorInfo` がカーソルなし（flags 0、cursor 0）、タイトルバーの上では矢印。`TRUE MOUSE-CURSOR` で画像の上も矢印に戻る | 合格 |
| Tkのフルスクリーン | `DISPLAY-TK` で `TRUE FULLSCREEN` | Tkのウィンドウが2560×1440を覆う。Tk内の `event generate . <Alt-Return>` で解除し、キーは届かない。フルスクリーンでないときは13が届く | 合格 |

`SendInput` で送ったAltは、この環境では効かなかった（Alt+F4でもウィンドウは閉じず、F4が単独のキーとして `INKEY` に届いた）。そのため、実際のキー操作でのAlt+Enter・Alt+Returnによる解除は、物理キーボードで確かめる（#1019）。

## 物理キーボード・物理マウスでの確認（#1029）

2026-11-18、利用者がこのWindows機の物理キーボードとマウスで行い、すべて期待どおりと報告した（「all ok」）。基準コミット`e33514c`、`zig build`の`zig-out/bin/sigma.exe`。

| 確認 | 起動 | 確かめた内容 |
|---|---|---|
| マウスとウィンドウ操作 | PowerShellで、`.work/check-window.go`ができてから20秒後に終わる入力を `tests/scripts/check-window.fs -e "WINDOW-CHECK"` へ渡す | 画像上の十字の追従、左右ボタンの押下・解放とホイールの出力、ウィンドウ外での解放。入力待ち中と計算中のウィンドウの移動・大きさ変更・閉じる操作。閉じた後の位置が -1 -1 |
| IMEでの日本語入力 | `tests/scripts/check-ime.fs -e "IME-WINDOW"` | 変換中の文字が入力欄に下線つきで出る、候補ウィンドウがカーソルの下に出る、確定した「日本語」がE6 97 A5 E6 9C AC E8 AA 9Eとして出る、Escでの取消で入力欄が変わらない |
| Ctrl+C | `INKEY` を回し続けるプログラムのウィンドウでCtrl+C | `USER INTERRUPT !` |

## 確かめていないこと

- 物理キーのAlt+Enterによるフルスクリーンの解除は、利用者が確認済み（OK）だが、Sigma自身のウィンドウとTkのウィンドウのどちらで確かめたかは未記録（#1031）。
- ウィンドウの作成が実際にOS内で止まる場合（単体テストは作成前のスレッドを止めて確かめた）。
- ネイティブが失敗して自動表示がTk・端末へ進む経路の実機での確認。
- Windows 10 1703より前（DPI非対応のまま動く経路）。
