## 検証

Windowsで`zig build`が成功。生成スクリプトの`--sigma`では、その通常構成実行体から7語彙の辞書名を取得し、文書の語彙別一覧と全件一致することを照合した。内部補助語も含めて1,463項目で記載漏れ・余分な項目・名前の重複はなかった。Syntax40項目は登録表・入力処理・ローカル宣言のソースで確認する対象で、WORDSの出力には含めない。

EKEYS定数35件の実際の値と登録ソースの値も全件一致。ガイドの使用例28件はそれぞれ新規プロセスで実行し、期待出力と終了結果が一致した。追加の単独使用例132件も新規プロセスで正常終了を確認した。これらは対話入力・ファイル保存・シェル起動・画面表示・音声再生を行わない。STDINを読む例には空の標準入力を渡す。`zig build test`も成功した。

各語の例は、上記の単独例または既存テスト・ライブラリからの出典付き抜粋である。抜粋はセットアップを含む参照先で読む。正常系だけでなく、意図して例外を検証する入力もある。内部処理には、それをコンパイルする公開構文での間接使用例を使う。全項目の例を単独で実行した、または全装置を実機検証したという意味ではない。

全体の文書整合チェックは指摘0件、`git diff --check`も成功。原文のDROP（従来語）とF>R（追加語）をそれぞれメモリー上で欠落させる確認でも、どちらも説明欠落として検出した。ソースファイルは書き換えていない。実行時照合と使用例のログは`.work/word-reference-validation.log`、文書整合のログは`.work/word-reference-docs.log`。

再実行：

```powershell
zig build
python scripts/word-reference.py
python scripts/word-reference.py --check --sigma zig-out/bin/sigma.exe
python scripts/check-docs.py
git diff --check
```

生成元は登録一覧、HELP原文、Forthライブラリと`docs/word-reference/`。日本語説明の台帳は`translations.ja.tsv`、個別の単独例は`usage-overrides.json`。定数・ローカル宣言などの規則的な形式は登録値に基づく日本語テンプレートを使い、未登録の一般語へ英語や汎用文を代入するフォールバックは設けない。`--check`は書換えを行わず、説明・使用例の欠落と生成文書の古さを検出する。`scripts/check-docs.py`にも全語の照合を組み込んだ。追加語だけでなく従来の語も対象。実行時の辞書照合には最新の通常構成実行体を指定する。

## 更新時の確認

翻訳元の説明・スタック効果・属性・定義と実装ソースの指紋は`translation-sources.json`に保存する。原文変更時は日本語説明を確認し、必要な修正後に`python scripts/word-reference.py --record-reviewed-sources`を実行する。通常の生成や`--check`では指紋を更新しない。

全1,503項目に日本語説明・空でない使用例・注意点があること、使用例の出典行が存在することを確認した。従来語DROPの翻訳元をメモリー上で変更すると古い翻訳として失敗し、新しい構文の日本語説明・使用例を欠落させた場合もそれぞれ検出した。これらの負の確認はソースファイルを書き換えずに行った。

P10のmacOS確認とは別の作業であり、親542やP10全体の完了を意味しない。本作業の公開状態はgit履歴とリモートで確認する。タグ・パッケージの作成は本作業の対象外。

## 実装照合とレビュー後の修正

初回の構造検査だけでは、説明の意味や使用例の対象語の取り違えを検出できなかった。実装照合と依頼されたClaude Codeレビューの指摘を受け、HELP66件、日本語説明65件、XT:の生成規則を修正した。内部変数・定数の用途はprivate-storage.jsonへ個別に記録し、直前にある別の公開語の説明を流用しない。EKEYSは定型の値だけでなく、個別イベントの説明を保持する。

使用例は文字列・コメント・CHARの引数・定義名・ローカル名・同名の利用者定義を区別して選ぶ。例外を意図する入力、例外を捕捉する例、公開構文による間接使用、内部定義の提示を個別に表示する。抜粋は依然としてリンク先の準備が必要で、全件を単独で実行できるという保証ではない。

`python scripts/test-word-reference.py --sigma zig-out/bin/sigma.exe`で、選択規則と指紋の回帰検査5件、実行時の動作回帰19件が成功。XT:の実行、KEY-IORの1セル結果、UNDER+の加算先、表示設定、ブロックの保存形式・REFILL、CSVの末尾区切り、検索パス迂回、FE./FS.とFP.の空白の違いを確認した。CSV・ブロックの試験は.work内の一時ディレクトリーに専用ファイルを作り、終了時に削除する。

指紋は変更検出と人による再確認のためのもので、全語の意味や全OS・物理デバイスの動作を証明しない。通常の生成や--checkでは確認済み指紋を自動更新しない。詳細は[修正・レビュー記録](WORD_REFERENCE_REVIEW.md)を参照。
