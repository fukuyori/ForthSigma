## Owned output capture (684)

`>STRING-EXECUTE ( xt -- addr u )` executes the callback once, captures its normal interpreter output and transfers an independent raw VM-heap allocation to the caller. The caller must `FREE addr`; empty output also returns a valid allocation. Callback stack results remain below addr/u. No temporary-string owner or persistent root is created. This word belongs to the ordinary strings group and remains available with files/float/graphics/audio disabled.

The implementation reuses the existing private Captured sink. It saves/restores target, sink and failure state through normal return and exceptions, so nested captures and $TMP/$EXEC composition retain their enclosing destinations. THROW propagates after freeing private output. Failed capture allocation becomes the existing out-of-memory THROW; callback side effects are not rolled back. Input token validation and one extra data-stack slot are checked before execution; after execution, two return slots must remain. Callback result overflow also frees captured output. Callback code must preserve the underlying caller stacks and private resource lifetimes, as for existing capture APIs.

After successful capture the length-prefix scratch layout is compacted into a raw FREE-able block and shrunk. Growth, exact-size fallback and cleanup use the existing Captured/heap implementation. Builtin enum tag is appended; startup entry is inserted before the existing final three-backslash entry. Earlier builtin-table images remain outside the strict image ABI contract.

An inner capture overrides file output, while an inner OUTFILE-EXECUTE overrides enclosing capture. OUTFILE-ID continues to describe the selected file during capture, matching the reference.

File write errors are consumed before propagation and do not poison restored scopes. Explicit WRITE-FILE retains its explicit handle/ior API.

## Borrowed input selection (687, approved and implemented)

The user approved retaining Sigma's existing line-read and Unicode processing before implementation. `INFILE-ID ( -- fileid )` returns the selected stream, normally STDIN. `INFILE-EXECUTE ( xt fileid -- )` executes once with borrowed input, restoring the prior selection and scoped pending byte/event state on every exit. It does not close/seek/rewind the stream or undo consumed input. Selecting the already-selected stream shares pending state instead of restoring consumed bytes a second time. Explicit STDIN uses existing terminal hooks.

KEY/XKEY/EKEY/readiness, ACCEPT, numeric INPUT and terminal REFILL/parser continuation share the selection. INCLUDE file input and EVALUATE's no-refill behavior retain their independent parser source identity. Selected file EKEY treats escape bytes literally and uses Sigma's Unicode decoder. ACCEPT reads/drains the entire physical line (LF/CRLF/CR), copies at most the existing internal4096-byte buffer and requested output capacity, and does not echo or perform terminal line editing. Long-line drain periodically checks work limits.

FileOps adds an optional unread callback for selected-stream pushback. The native host uses ungetc, clearing its EOF and marking library lookahead; terminal pushback uses the existing unread mechanism. XKEY/EKEY malformed continuation bytes and CR lookahead are returned to the borrowed file, so later explicit KEY-FILE or re-selection sees them. This avoids discarding private lookahead when a scope ends. Custom hosts need key for reads, ready for readiness and unread when pushback is required; missing capabilities raise FileUnavailable. No unread hook is needed for ordinary ASCII reads without lookahead. Host errors propagate; XKEY's selected-stream continuation errors are no longer mistaken for EOF. ## CSV input (690)

CSV settings/quoted output were committed/pushed as e65d9eb. `READ-CSV ( filename-addr filename-u xt -- )` opens a data file and invokes xt `( field-addr field-u column row -- )` once per decoded field. Column starts0; row starts1 and counts logical records, not physical lines consumed by multiline fields. Blank records yield one empty field. A trailing separator does not add a final empty field. Quotes doubled within a physical fragment decode to one quote; quoted multiline boundaries normalize to LF. Matching follows full CSV-QUOTE/CSV-SEPARATOR cell values, and changes made by a callback affect subsequent fields.

The reader follows the designated Gforth's permissive behavior rather than claiming strict RFC validation: an unquoted initial byte bypasses quote-state scanning, trailing quotes are stripped, text after a closing quote is retained, and unterminated quoted EOF produces the accumulated field with a final LF. These boundaries are covered by observations/comparisons. No GPL implementation code was copied; the Zig reader was independently implemented against public API behavior and recorded tests.

Each field is a private growable VM-heap buffer borrowed only during its callback. Do not FREE it or retain its address; copy via SAVE-MEM or a caller-owned string for later use. Callbacks consume four inputs and preserve the existing caller stack/resource lifetimes. Nested READ-CSV has independent field storage, offsets and row/column state and restores the outer parser source. CSV settings are ordinary global VALUEs and are not restored after callbacks. Direct manipulation of the active CSV source buffer/REFILL by a callback is outside this parser contract; nested scoped source operations are supported.

Name lookup shares Sigma's established source policy: empty FPATH opens the supplied raw cwd-relative name; configured FPATH uses P05a search and resolved spelling. The existing255-byte source-name and8-level include nesting limits apply. Each physical line is limited to4096 bytes; multiline field length is limited by available VM heap. Read loops honor enabled work limits. The source table records the data file without marking it REQUIRE-loaded or clearing an existing loaded flag. Callback SOURCE-ID/SOURCE/SOURCELINE# describe the CSV file/physical line, while the supplied row remains logical. Interactive INFILE selection is independent.

The reader preflights xt/operands and one extra callback stack slot before opening. It owns and closes the opened handle on every path, frees field storage on success/error, and restores parser source kind/line/cursor, BLK, input serial and include depth. Already executed callback effects and source-table identity entries remain after errors. Callback/read errors take priority over close errors; otherwise close errors THROW with CSV source location. Empty/missing files, source-table or allocation failures cannot leave an owned file open. Files support controls word availability, and runtime handles are not serialized.

## SH parsing front end (692 under691)

READ-CSV was committed/pushed as cb95b46. Pipe/shell task691 is split into692 SH,693 OPEN-PIPE/CLOSE-PIPE/BROKEN-PIPE-ERROR and694 SH-GET. The latter remains dependent on pipe support.

`SH ( "command..." -- )` parses the current source remainder, emits a newline and invokes the existing SYSTEM host callback. It saves the returned platform status in `$?`: POSIX retains the wait status, Windows uses the existing command processor's exit code. It does not interpret command text as Forth. Like `0 PARSE`, a NUL ends the parsed command and leaves subsequent source available to the Forth parser. SH is an ordinary compiled word; invoking a compiled wrapper parses the caller's current source at runtime.

The host implementation is unchanged: existing UTF-8/Windows wide-command behavior,4095-byte native command limit, terminal handoff, flushing and failure rules apply. Shell process output remains external host output; only the preliminary VM newline participates in OUTFILE/capture. A failed host call retains the previous `$?`; newline output already produced remains. If writing the newline fails, the error propagates before starting the shell. Missing SYSTEM capability fails before consuming source or emitting output. No new resource or persistent root is introduced. SH uses the system group and is available with files/float/graphics/audio disabled.

Captured output can share an EVALUATE source owner. SH snapshots the parsed command before its newline can resize that owner, freeing the snapshot on success/error. Ordinary output requires no allocation or spare data-stack slots. Native SYSTEM still validates command length/embedded NUL; SH's parsing delimiter behavior is distinct from passing an embedded NUL directly to SYSTEM.
