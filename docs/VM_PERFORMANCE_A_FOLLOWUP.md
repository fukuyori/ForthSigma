# 案Aレビュー後の切り分け（2026-11-15）

## 結論

**案Bは実装候補へ昇格させない。** スタック操作・LOOPでは、境界コピー版もbuiltinInLoop／wordInLoopを反復中に呼んでいない。そこで観測した約59%／28〜33%の所要時間増加を、実行された境界コピー処理のコストでは説明できない。共通ディスパッチと通常関数呼出し前後の生成コードは変わっているが、実CPU上の時間への寄与率は未特定である。

[Claude Codeレビュー](VM_PERFORMANCE_A_CLAUDE_REVIEW.md)のD-2に対応し、既存のCallgrind出力と、実際に時間測定したstrip実行体を調べた。新規ビルド・性能測定・VM実装変更は行っていない。[集計と命令列](measurements/2026-11-15-vm-a-followup.json)に入力ハッシュと抽出結果を保存した。

## 反復中の呼出しと関数別計数

収集範囲は従来と同じrunOperations外側ドライバー。1,000／2,000反復の記録の差を1,000で割った。呼出し数はCallgrindのcalls行を対象関数別に集計し、自己コストは呼出し先込みの行を除いて集計した。

| 項目 | 基準→境界コピー |
| --- | --- |
| スタック操作のbuiltinInLoop／wordInLoop呼出し | 両版とも収集範囲内で記録なし |
| LOOPのbuiltinInLoop／wordInLoop呼出し | 両版とも収集範囲内で記録なし |
| スタック操作のmem.rotate呼出し／反復 | 1→1 |
| LOOPの通常関数呼出し増分／反復 | 0→0 |
| スタック操作のループ自己Ir／Dr／Dw | 234／88／31→248／72／23 |
| mem.rotate自己Ir／Dr／Dw | 66／8／7→66／8／7 |
| LOOPのループ自己Ir／Dr／Dw | 138／53／19→141／43／13 |

スタック操作の合計300→314命令という差はmem.rotate本体ではなく、ループ自己コストにある。これはシミュレーター上の計数の所在であり、所要時間差の全原因を特定したという意味ではない。記録の対象となった非counted経路に限る。全VM経路や任意のプログラムへ一般化しない。

## 時間測定用strip版の確認

既存実行体をobjdump -d -Mintelで逆アセンブルした。16命令の接頭部を相対位置と命令で一意に照合し、続いて非countedループ全体をシンボル付き版と比較した。

| 対象 | 基準 | 境界コピー |
| --- | --- | --- |
| strip版ループ先頭 | 0x1101c60 | 0x1101c80 |
| 対応するシンボル付き版先頭 | 0x1101e90 | 0x1101eb0 |
| ループバイト数 | 8,550 | 9,480 |
| 命令行数 | 1,647 | 1,870 |
| 版内での正規化済み全ループ比較 | 一致 | 一致 |

比較ではローカル分岐先をループ先頭からの相対値へ変換し、外部アドレスを共通記号へ置換した。命令の相対位置も一致したが、外部参照先の意味の全件一致を証明する比較ではない。シンボル付き版の動的アドレスをこの対応でstrip版へ写した。strip版自体をCallgrindで新たに実行したわけではない。

基準の共通ディスパッチ（0x1101d60〜0x1101d87）はpcを[r14+8]から読み、[r14+0xa]のend_pcと比較し、進めたpcを書き戻す。境界コピー版（0x1101da0〜0x1101dc6）はmovd eax,xmm2でend_pcを取り出し、cxと比較し、次pcをr10dへ作る。これらはLOOPで各5回、スタック操作で各9回／反復の経路に対応する。

ROTの通常関数呼出しも差がある。基準（0x1102398）のmem.rotate呼出し後は操作配列基点を作り直してループ先頭へ戻る。境界コピー版（0x1102452〜0x11024ad）では、呼出し前にxmm2・フラグ等を退避し、呼出し後にxmm2、pc、フラグ等を復元する命令がある。mem.rotateを毎反復1回通るため、この退避・復元は実際の反復経路にある。CATCH用ヘルパーとの境界コピーとは異なる通常関数呼出しの保持処理である。

**観測できたのは、境界ヘルパーを呼ばない経路にも生成コードの差が及ぶことまでである。** xmm2からの取り出し、退避命令、分岐配置のどれが何%を占めるかは分からない。WSLのPATHにperfはなく、インストール・権限変更・OS設定変更は行っていない。

## 別ビルド間の差との比較

[実験報告](VM_PERFORMANCE_A_EXPERIMENT.md)に、旧版の資源改行対照実験の8項目を併記した。これは同一実行体のA/A揺らぎとは別の観測であり、案Aの誤差範囲・補正値・採用基準には流用しない。値渡し版の予備短縮と境界コピー版の小幅な短縮を、保持方式そのものの効果とは確定しない。

## 次の判断

計画では、状態引渡し構造の負担に根拠が得られた場合だけ案Bへ進む。今回、実行された境界コピーの負担はスタック操作・LOOPの遅さを説明せず、同じ局所Runningを引き継ぐ案Bが解決する根拠は得られなかった。案Aの不採用を維持する。

次の実装候補を決めるには、通常ディスパッチでのpc／end_pcの保持と、ROT等の通常関数呼出しをまたぐ保持を分ける実験設計が必要である。その際も停止検査・CATCH・counted版の意味を維持し、通常8項目とCATCH9項目、サイズで判定する。今回のデータだけで新しい保持方法や改善率を推測して実装しない。性能実装へ進む条件を満たしていないため、この切り分けの成果は判断根拠の更新であり、速度改善の達成ではない。
