# 計算タスクの利用例

[英語版](TASK_EXAMPLES.md)が主文書である。新規に作成した例であり、
リポジトリの[MITライセンス](../LICENSE)に従う。リポジトリ直下から実行する。
Zig 0.17.1、EXTENSION、filesが必要である。表示には端末を使い、graphicsとaudioは不要である。

## 実行

```powershell
$env:ZIG_GLOBAL_CACHE_DIR = Join-Path $PWD '.zig-global-cache'
zig build -j2
zig-out/bin/sigma.exe examples/task-path.fs
zig-out/bin/sigma.exe examples/task-search.fs
zig-out/bin/sigma.exe examples/task-checksum.fs
```

G1は障害物のない64×64のバイト盤面である。`n`で目的地を変更し、`q`で終了する。
4近傍の最短経路を返し、`*`で経路、`S`で始点、`G`で終点を表示する。
T1は`a`が1 MiB並ぶ本文を検索する。入力した1バイトが
検索語となり、`q`で終了する。重なる一致も数え、先頭1,000件の位置を返す。
例の検索語は1バイトであるが、workerは1〜256バイトに対応する。
I1は`LICENSE`を最大64 KiBずつ読み、塊番号とバイト和（modulo 2^32）を順に表示する。
`q`で終了する。大きなファイルを使う場合はパス文字列を変更する。ファイルI/Oはメインが所有する。

メインの各巡回で入力確認と期限0のタスク照会を行う。世代・適用済み世代・終了状態が
変わったときだけフレーム番号と現在世代を表示する。文字でない入力事象は無視する。
10 MSは端末出力量を抑える待ちであり、フレーム期限の保証ではない。
G1/T1はSnapshotとstream 7を再利用する。新規投入が成功すると旧要求を置き換え、
旧公開IDを解放する。失敗時は旧IDを保持してiorを表示する。
要求世代が変われば旧結果を適用しない。投入時の世代と結果内の世代が両方とも
現在世代と一致した場合だけ表示を更新する。失敗・取消しでは従前の表示を保持する。
メインはCATCHで例外を捕捉し、タスクとSnapshot、I1の開いたファイルを解放してから
元の例外を再送出する。後始末でエラーが起きても他の解放を試みる。BYEも所有者終了処理を行う。

I1は未完了の塊を最大1件とし、順序を保つ。投入失敗・失敗終端・取消し終端ではForthエラーとして停止し、
塊を黙って飛ばさない。待ち4件、非同期ファイル読取り、持続供給率を示す例ではない。

## workerのバイト形式

workerファイルは定義だけを読み込み、UIを開始しない。Snapshot取得前に読み込み、
入口名をTASK-SUBMITへ渡す。メタ情報は当該プロセスのforthzの64 bitセルであり、
移植可能なファイル形式ではない。位置はバイト単位であり、メインVMのアドレスではない。
呼出し側は完全なヘッダー、宣言した本文、用途のサイズ上限を守る必要がある。

| worker | 入力 | 結果 |
|---|---|---|
| `TP-SEARCH` | 世代、幅64〜256、始点、終点；幅の2乗個の地形バイト（0が通行可） | 世代、頂点数；32 bit little-endian頂点IDを終点から始点の順に格納。到達不能・不正盤面は0件 |
| `TS-SEARCH` | 世代、検索語長1〜256；検索語、最大1 MiBの本文 | 世代、総一致数、格納数、切詰めフラグ；最大1,000件の本文先頭からのバイト位置（0起点） |
| `TI-CHECKSUM` | 世代、塊番号；最大64 KiBの本文 | 世代、塊番号、バイト和（modulo 2^32） |

G1はFIFOを用いた幅優先探索であり、各頂点を一度だけ訪問する。
最大経路の結果は262,160 bytesに収まる。始点＝終点は1頂点、
始終点の障害物・非連結盤面は0件である。workerの領域は復元VMが所有する。
反復はBEGIN系を使い、動的実行、CATCH、PAD、DO系、出力、ファイルI/Oを含まない。
workerのnativeメモリ処理は1回64 KiB以下である。Snapshotはロード時に取得する。

## 自動試験

```powershell
python tests/scripts/verify-task-examples.py --sigma zig-out/bin/sigma.exe
zig build runtime-test -j2
```

Pythonは公開語によるForthの結果と3例の操作を検査する。
終わらない計算を動かすプロセスへキーを送り、ファイル読書き・削除と端末表示が
進むことも検査する。置換え・取消し・RELEASE・計算中のBYEを含む。
一時ファイルとログは`.work/`に置く。timeoutはハング検出用であり、時間を記録しない。
ZigではBYE後の台帳・タスク/Snapshotスロット・転送予約・タスクallocator使用量が
残らないことを追加検査する。OSハンドル、commit量、実画面の応答を測る試験ではない。

## 実端末での手動確認

前面端末でG1を動かし、結果の到着中に`n`と他のキーを交互に入力し、計算中に終了する。
入力と状態変更時の表示が続き、結果世代が逆行しないことを確認する。
T1は`a`/`b`を交互に入力し、検索中に終了する。件数（`a`は1,048,576、`b`は0）、
切詰め、入力・表示の継続を確認する。行入力でEnterが必要な端末は区別して記録する。
I1は複数塊のファイルを用い、独立したバイト和との一致と処理中の`q`を確認する。
正常終了とCtrl+Cを繰り返し、OSの確認手段でプロセス・資源の所有を調べる。
1380ではこれらの手動確認は未実施である。

期限、入力から実画面までの応答、資源予算の受け入れは未実施である。
測定は別途許可を得て、[利用条件](../docs/TASK_CONTROL_USAGE_CONDITIONS.md)の入力・条件を
先に固定する。[1380報告書](../docs/TASK_CONTROL_IMPL_1380.md)に自動試験の根拠、
手動手順、Linuxへの引継ぎ、受け入れの残項目を分けて記す。

## メインの巡ごとの回収

回収は、タスクの語を呼んだときにだけ進み、MS・EKEY?・描画の間には進まない。結果をTASK-RELEASEで解放した後も、有効なタスクIDがない巡を含め、アプリのメインの巡ごとにTASK-WAIT-MANY（期限0）などのタスクの語を呼び続ける。時計の対象（kind=4、id=0、arg0=0、arg1=0）とms=0を使えば、解放済みIDを再利用せず回収を進められる。これはworkerの引渡し後の回収を進めるもので、即時の停止完了を保証しない。

```forth
CREATE REAP-TARGET 4 , 0 , 0 , 0 , 0 ,
CREATE REAP-EVENT 4 CELLS ALLOT
: REAP-TICK REAP-TARGET 1 REAP-EVENT 1 0 TASK-WAIT-MANY THROW 2DROP ;
```
