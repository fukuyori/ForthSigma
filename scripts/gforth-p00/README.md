# P00 Gforth比較ケース

リポジトリのルートから実行する。これはSigmaの実装テストではなく、P00仕様の比較基準を指定Gforthで確認するスクリプトである。

```sh
export GFORTH_P00_SOURCE=/path/to/gforth
export GFORTH_P00_BUILD=/path/to/gforth-build
python3 scripts/gforth-p00/run.py
```

SOURCEは参照元のソース、BUILDは同じソースから構築した`gforth-ditc`と`gforth.fi`を含むディレクトリ。既定値は今回指定された`/Users/fuk/source/forth/gforth`と、リポジトリ内の`.work/gforth-audit/gforth-build`である。

今回の比較元はコミット`c479e1eec66dd57a2441c3020177267ba70d3bdc`。元の実行版は`0.7.9_20260610`でソースにある一部の語が未登録だったため、作業用コピーで公式INSTALL.mdのGit版ビルド手順に沿って生成物を更新し、GCC 16で`gforth.fi`を構築した。configure.acの版番号と再構築後の実行版は`1.0.1 arm64`。インストール・パッケージ作成は行っていない。作業用コピーには参照元自身のGit情報も含め、親リポジトリの情報と混同しない。

スクリプトは`docs/gforth-p00-runtime-cases.tsv`を再生成し、470ケースと、仕様索引の384語全てのカバーを検査する。先頭のbasicは結果表を初期化するため、通常はrun.pyで全体を実行する。失敗時は終了コードが非0になり、実測値は結果表に残る。

ファイル・CSV・ブロック入力の一時ファイルは`.work/gforth-audit`に作成して終了時に削除する。結果表のinputにある一時パスをそのまま再利用せず、スクリプトが生成するfixtureと一緒に再実行する。WHEREGはGforth自身が作成する一時ファイルも使う。

通常ケースのexpectedは出力を空白区切りに正規化した値。p00_runnerを使うケースでは末尾にデータスタック・浮動小数点スタックが空であることを示す`-1 -1`を追加する。メモリーの62ケースはデータスタックの検査を付ける。`CONTAINS:xxx -1 -1`は出力がxxxを含み末尾のスタック検査が通ることを表す。表示は一時パスや端末の幅を含むため、全出力の固定文字列一致とは区別する。stdin列の`LF*1000`はページ送り用の改行1000個、`日`はUTF-8の実入力を表す。初期の単純ケースでstdin列が空なら標準入力を使用しない。

EDITORは当該プロセスで`true`、TZはUTCに固定する。実エディターは起動しない。ソース表示試験のafter-lはNOOPに差し替え、対話操作そのものは別ケースで改行入力による終了を確認する。

比較環境はmacOS arm64、64ビットセル、8ビットアドレス単位である。OS依存のerrno、文字列・端末表示、シェルは別環境で再確認する。特に比較用DITCの0除算の戻り方はSigmaの期待する-10と異なる。WHEREGを-eから呼ぶ場合にも比較元の不正メモリーアクセスを確認したため、正常ケースはソースファイルから呼んでいる。これらの差はGFORTH_P00_SPEC.mdに記録しており、Sigmaへ不正動作を移す要件ではない。

470はCSVレコード数であり、引用された入力に改行があるため物理行数とは異なる。LISTのケースは見出しとSCRの値を条件式で検査し、expected欄にはその条件を記述する。
